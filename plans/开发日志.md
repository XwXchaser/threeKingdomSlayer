#### 4.2 BUG 1：无限补齐（Z 轴方向搞反）

| 字段 | 内容 |
|------|------|
| **类型** | fix |
| **范围** | `Enemy.cs` |
| **描述** | 击杀敌人后，后方敌人持续打印 Moving 日志，progress 值递增但永远无法到达 1，无限循环 |
| **详细说明** | **根因**：Z 轴方向搞反。在 Unity 中 -Z 轴是前进方向（朝向玩家），+Z 轴是后退方向（远离玩家）。旧公式 `zPos = -(rowIndex * rowSpacing)` 让 `rowIndex=0` 在 `z=0`，但正确的应该是 `rowIndex=0`（最前排）在 `z=-10`（最靠近玩家）。因为 Z 轴方向反了，`Lerp` 从旧排向新排移动时方向错误，敌人永远无法到达目标位置。**修复**：新增 `GetRowZ()` 辅助方法，公式改为 `(maxVisibleRows - 1 - rowIndex) * (-rowSpacing) + offsetZ`。`rowIndex=0` → `z=-10`，`rowIndex=4` → `z=0`，前进方向为 -Z |

#### 4.3 BUG 2：梯形向内聚拢（isRushMoving 机制引入）

| 字段 | 内容 |
|------|------|
| **类型** | fix |
| **范围** | `Enemy.cs` / `Column.cs` / `ColumnManager.cs` |
| **描述** | 击杀敌人后，后方敌人向中间聚拢（X 轴偏移变化），看起来像梯形向内收缩 |
| **详细说明** | **根因**：引入 `isRushMoving`/`StartRushMoving()` 机制后，`Column.RemoveEnemy()` 先调用 `StartRushMoving()`（保存旧 `rowIndex` 到 `rushStartRow`），再调用 `SetRowIndex()` 更新 `rowIndex`。`UpdateWorldPosition()` 中 Z 轴使用 `rushStartRow`（旧排位置），但 X 轴使用 `rowIndex`（新排位置），X 轴和 Z 轴不同步。**修复**：移除 `isRushMoving`/`StartRushMoving()` 机制，恢复到上一版本的 `ResetMovementState()` + `StartMoving()` 逻辑。`SetRowIndex()` 先更新 `rowIndex`，`UpdateWorldPosition()` 中 X 轴和 Z 轴都使用更新后的 `rowIndex`，完全同步 |

#### 4.4 BUG 3：无限尝试向前补齐（isRushMoving 机制引入）

| 字段 | 内容 |
|------|------|
| **类型** | fix |
| **范围** | `Enemy.cs` |
| **描述** | 击杀敌人后，后方敌人无限尝试向前补齐，日志显示反复触发补齐移动 |
| **详细说明** | **根因**：补齐移动完成后 `state=Idle`，`StartMoving()` 被调用导致常规移动开始，常规移动完成后 `rowIndex--` 触发 `UpdateEnemyRow()`，再次补齐移动，无限循环。**修复**：`UpdateMovement()` 中移动完成后不再调用 `StartMoving()`，避免无限循环 |

#### 1.2 受击抖动效果（DOPunchScale）

| 字段 | 内容 |
|------|------|
| **类型** | feat |
| **范围** | `Enemy.cs` |
| **描述** | 敌人受击时添加大小抖动动效 |
| **详细说明** | 在 `TakeDamage()` 中添加：`transform.DOKill(true); transform.DOPunchScale(new Vector3(0.2f, 0.2f, 0.2f), 0.15f, 8, 0.5f);`。`DOKill(true)` 确保终止任何进行中的缩放动画（如死亡序列），避免冲突。`DOPunchScale` 自动回弹到原始缩放 |

#### 1.3 死亡缩放到 0 动效

| 字段 | 内容 |
|------|------|
| **类型** | feat |
| **范围** | `Enemy.cs` / `FlashThenRelease()` |
| **描述** | 死亡时闪白保持后缩放到 0 消失 |
| **详细说明** | 将 `FlashThenRelease()` 从手动 `while` 循环改造为 DOTween `Sequence`：先 `AppendInterval(HIT_FLASH_DURATION)` 保持闪白 0.15s，再 `Append(transform.DOScale(0f, 0.3f).SetEase(Ease.InBack))` 缩放消失。`WaitForCompletion()` 等待序列结束后恢复 `localScale = Vector3.one`（供对象池复用），再触发 `OnDeath` 事件 |

#### 1.4 前进补齐 Y 轴弹跳动效

| 字段 | 内容 |
|------|------|
| **类型** | feat |
| **范围** | `Enemy.cs` / `StartMoving()` / `UpdateWorldPosition()` |
| **描述** | 敌人向前补齐移动时一边前进一边沿 Y 轴跳动 |
| **详细说明** | 新增 `bounceYOffset` 私有字段（`Initialize()` 中初始化为 0）。`StartMoving()` 中当 `isRush == true` 时，使用 `DOTween.To()` 驱动 `bounceYOffset`：前半段 OutQuad 缓动上升至峰值 0.5（快速起跳），后半段 InQuad 缓动回落至 0（自然下落），总时长 = `config.moveSpeed`。`UpdateWorldPosition()` 中应用：`transform.localPosition = new Vector3(xPos, bounceYOffset, zPos)`。通过驱动字段而非直接操作 transform，与手动 X/Z lerp 移动不冲突 |

#### 1.5 DOTween 清理

| 字段 | 内容 |
|------|------|
| **类型** | feat |
| **范围** | `Enemy.cs` / `ResetEnemy()` |
| **描述** | 对象池回收时清理所有 DOTween 残留动画 |
| **详细说明** | `ResetEnemy()` 中调用 `transform.DOKill(true)` 终止所有与此 transform 关联的 tween（包括缩放动画、弹跳动画），确保对象池复用时不残留任何 DOTween 动画状态 |

### 2. 敌人补齐系统重构与 BUG 修复

#### 2.1 链式补齐改为移动完成时触发（非中点）

| 字段 | 内容 |
|------|------|
| **类型** | fix |
| **范围** | `Enemy.cs` / `Column.cs` / `ColumnManager.cs` |
| **描述** | 敌人逐个向前补齐，后一敌人必须等待前一敌人补齐完毕才开始 |
| **详细说明** | 旧逻辑在 `moveProgress` 达到 0.5（中点）时就触发链式补齐，导致多个敌人同时移动。重构为：`UpdateMovement()` 中移动完成（`moveProgress >= 1`）时调用 `OnRushMoveComplete()` 事件，`Column.cs` 和 `ColumnManager.cs` 中相应逻辑改为在移动完全完成时才触发下一个敌人的补齐移动 |

#### 2.2 添加 rushMoveDelay 配置

| 字段 | 内容 |
|------|------|
| **类型** | feat |
| **范围** | `EnemyConfig.cs` / `StageConfig.cs` / `StageController.cs` / `Enemy.cs` |
| **描述** | 添加 `rushMoveDelay` 延迟参数，控制补齐移动启动延迟 |
| **详细说明** | `EnemyConfig.cs` 新增 `rushMoveDelay`（默认 0.3s）。`StageConfig.cs` 新增 `defaultRushMoveDelay`（默认 0.3s）。`StageController.cs` 新增 `GetRushMoveDelay()` 优先使用敌人配置，否则用关卡默认值。`Enemy.cs.StartMoving()` 中应用延迟：`rushMoveDelayTimer += Time.deltaTime` 倒计时，到达后才开始实际移动 |

| **描述** | 新增 `manualRowHalfWidths` 数组，支持手动微调每排 X 轴间距 |
| **详细说明** | `StageConfig.cs` 新增 `manualRowHalfWidths`（float 数组，长度匹配排数）。`RowFormation.cs` 的 `GetFormationOffset()` 中，若数组不为空且当前排有配置，替换公式计算的 halfWidth，其余排用公式兜底。`StageController.cs` 的 `GetFormationOffset()` 转发该参数 |

#### 2.4 冲刺移动 X 轴间距平滑过渡

| 字段 | 内容 |
|------|------|
| **类型** | feat |
| **范围** | `Enemy.cs` / `UpdateWorldPosition()` |
| **描述** | 移动过程中 X 轴偏移从当前排平滑过渡到目标排 |
| **详细说明** | 原代码 X 轴固定在当前排位置，抵达后再更新到新排。改为在移动过程中使用 `Mathf.Lerp(currentX, targetX, moveProgress)` 从当前排 X 轴偏移平滑过渡到目标排 X 轴偏移。与 Z 轴一样同步过渡，使梯形/扇形展开在移动过程中就正确显示 |
