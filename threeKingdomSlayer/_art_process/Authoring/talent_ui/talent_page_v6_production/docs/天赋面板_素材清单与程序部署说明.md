## 4. 未来导入建议（需先获部署授权）

1. 先检查用户当前工作区和目标文件；最终候选资源目录建议 `Assets/Sprites/UI/Talent/`。现有目录已有 `TT_*` 文件，**不得覆盖、删除或重建已有素材及 `.meta`**。以当前清单的新文件名导入，维持现有 GUID 与 Inspector 引用；若文件名冲突，先对照并征求决定。
2. 使用 Unity Editor 导入为 `Sprite (2D and UI)`、Single、保留 alpha 和 sRGB。UI 素材通常不需要 mipmaps；Wrap 建议 Clamp。先以无损或无压缩检查边缘，移动端压缩格式、Sprite Atlas padding/extrude 需在目标平台另行验证，不应一律套用未验证设置。
3. 插画有明显像素边缘，本地预览使用 nearest-neighbour；Unity 可先用 Point 检查，再与 Bilinear 的目标机实际观感比较，最终以视觉验收为准。不要声称本包已在任一 Sprite 导入参数下验证。
4. `panel_coin_plate.png` 与 A03 完全相同；推荐只导入 A03 并在两处引用同一个 Sprite。A02 也可不导入，前提是用白色 Sprite / UI 默认白图配遮罩色并正确拦截输入。
5. 若需要贴图裁切边距，在 Sprite Editor 逐项配置并验证（见第 5 节）。**不要把文本、价格、图标、页数或节点坐标写回到底图。**
6. 资源引用应通过 Inspector 序列化字段、Prefab / 场景引用或显式的 ScriptableObject 资源连接；不要通过 `Resources.Load`、字符串 ID 或静态缓存暗中寻找资源。

## 7. 不能靠换图解决的交互和数据问题

以下是当前只读代码检查发现的后续开发项，不是本包已实现的功能：

1. `TalentPaginator.Split` 目前只在没有任何前置边跨越的缝隙分页；用户已选 **允许前置链跨页**。必须修改分页及展示，不改变真实解锁条件。
2. `BuildPageContent` 只画两端都在同一页的直线。跨页时至少要让玩家知道存在后续内容和真实关联；节点旁/页边提示的最终造型、目标页说明、是否允许点击跳页仍需确认。页码点只说明还有页，不能单独冒充前置关系。
3. `SelectedNode()` 目前按分类和页内序号寻找，没记录页身份；多页同序号可能取错节点。用稳定的树/节点身份或完整页面身份确认选中、详情与扣钱指向同一对象，禁止仅靠同页序号。
4. 纵向翻页后当前没有主动清空选中并刷新页码；用户已确认：**无选中隐藏详情，上下翻页清空选中并隐藏详情**。
5. 横滑切分类时可能沿用源分类页号；目标分类页数不同时可能落到错误页或空白。页签点击和横滑都应取目标分类合法页，并统一页码记忆策略。
6. 当前 `Refresh` 将未满足前置的节点按钮设为不可交互；用户已确认**锁定节点允许查看详情，但不能购买**。必须分离节点查看权限和购买权限；`TalentTreeState.TryUnlock` 仍负责真实前置、有效载荷、铜钱和存档校验。
7. 当前同页连线从节点中心到中心画直线。要支持折线、分叉及跨页提示，必须根据真实 `GetPrerequisites` 数据实现，避免仅凭装饰图创造假的依赖关系。
8. 分类页签的 Sprite 字段未使用，标签颜色还有重复赋值；节点、详情和购买按钮又会被代码乘色。实现替换时要一起核对，不要只关闭程序化开关或只拖资源。
9. `TalentNodeInfo.ResolveIcon` 优先读节点 `icon`，其次读 `upgradeConfig.icon`。本轮没有技能图标；后续共用局内升级图标还是单独设置节点图标，须按后续产品决定处理，不要用已有旧项目图标推断本包的风格。
10. 只读检查时 `TalentCatalog_Main.asset` 三分类测试数据分别为 5 / 3 / 6 个节点、各 1 页；它不是完整八分支真实内容。不能拿当前数据或静态预览宣称多页、全部流派、购买及真实布局已经验证。

## 8. 建议接入顺序与验收清单（仅供程序执行）

1. **先获授权和视觉验收**：确认新增 13 件、待用/删减范围，以及严格 2×、命名和跨页提示尚未决定的事项。再导入新 Sprite，不覆盖既有 GUID / `.meta`。
2. **先验证生成与显示**：保持外框、顶栏、页签、页码、详情固定；页面内容在 `RectMask2D` 下滑动。检查九宫格角部、像素过滤、状态色和深色板的对比度。
3. **验证输入**：遮罩拦截底层，节点/空白处拖动能识别手势，装饰不拦点击；拖拽不误触节点、购买或返回；关闭后 overlay 正常卸载。
4. **验证选择和购买**：无选中隐藏详情；锁定节点可查看不能购买；可买、铜钱不足、无载荷、已解锁四种情况分别正确；扣钱与目标节点始终一致。
5. **验证分页与关系**：使用临时测试数据覆盖同分类多页、不同分类页数不等、跨页前置、一对多/汇聚、当前页码、切页清空选中；不能只测现有每类一页的数据。
6. **验证内容与尺寸**：手机竖屏多分辨率和安全区、长标题/描述/高额铜钱数值、目标缩放下文字与图标可读性；未来技能图标接入后再验实际图标和边框配合。
7. **保存及证据**：实际修改后按项目流程检查导入、Inspector 引用、场景落盘和 Console；用真实 Unity Game View/目标设备截图说明，不把本目录的静态拼图冒充运行截图。
