## 0. 用户验收基线与本批目标

用户在本次会话开始时确认：**F1 存档解锁、F2 换装 API、F5 天赋解耦、F6 去掉圈数 / 只按击杀计分 / 结算面板、F7 铜钱落盘，以及武器与招式界面均已完成并验收；编译通过、Console 0 错误。** 这些是用户报告的历史验收，不是本计划作者新跑的测试；不要回退或重做。F2 的底层 API 完成 ≠ 满槽 UI、新装备变体 / 同款替换和波末完整链已完成。

**本 P0 目标**：在不新增战斗机制、不擅定数值的前提下，提供由用户填写的正式数据框架，让现有影之武装 / 占槽饰品从精英或 Boss 掉箱、在波末统一选择、按抽中变体装备或替换；同时接入用户新增确认的**经验升级品质 / 全局概率 / 同次不重复**。用户随后填写正式品质、数值、权重、圈数阶段和概率，再进行游戏验收。

## 1. 不可更改的玩法契约

### 1.1 两条来源线、同一波末队列

1. 精英（由敌人资产上的标记决定）/ Boss 掉装备宝箱，箱子到达玩家后排队一次装备选择；战斗中不弹装备选择。
2. 经验升级排队一次属性选择；两类奖励按队列在**波末敌人清空后**依次弹出；当前奖励完成后才处理下一个，全部完成后才允许进入下一波 / 后续节点。
3. 换装发生在波末奖励选择，不新增战斗中背包 / 商店；已有暂停原则是 **游戏内容冻结，UI 继续**（`design/pause-freeze-rule.md`）。不得为了换装改变暂停、取消正在播放的视觉演出或批量清场。
4. 不新增保底、不新增免费开局 Build、不调整精英标记 / 掉箱频率。约 3 分钟出现可选武装的体验目标仍需用户配置并游戏实测，不等于每次候选保底有武装。

### 1.2 装备：玩家可见数据与池内档分离

| 项目 | 用户确认的含义 |
|---|---|
| 种类 | 一件具体影之武装或饰品的身份；所有品质 / 等级的变体同种类；效果近似不自动同款 |
| 可见品质 | 普通 / 精良 / 传说，允许单品质 |
| 可见等级 | 某一品质下玩家看到的等级；同品质不同等级、不同品质相同等级可有不同效果 |
| 变体效果 | 该品质 / 等级对应的完整实际数值及表现配置；玩家自行填写 |
| **池内档位** | 每个变体单独配置，类自走棋“费用”，独立于显示品质 / 等级；不是货币价格 |
| 概率 | 用户配置内部圈数阶段 → 各池内档权重 / 概率；越后可配置更高档概率，**不硬编码数值** |
| 单变体权重 | 档内具体装备变体的相对出现权重，由用户填写 |
| 数量 | 不存在共享棋子库存、个数耗尽、购买或合成 |

执行顺序（思路）：锁定本次奖励所处的内部圈数阶段 → 按该阶段档位权重抽档 → 从对应档的合规装备变体按权重抽 → 构造包含**种类 + 具体变体 + 品质 + 可见等级 + 实际效果**的稳定候选。主动与饰品**统一抽取**，不再交替保底。生成第二 / 第三张时，剔除已出装备种类的所有变体；同一次候选不出现不同品质 / 等级的同款。锁定阶段与生成候选的精确实现时点必须与“波末队列及内部 Circle 不越界”一致；宝箱掉落跨循环的异常不可静默套用错误阶段。

举例（仅阐释，不是正式配置）：`普通 染病 Lv.1` 与 `传说 染病 Lv.1` 各自配置独立的效果、池内档位及权重；它们**不因同为 Lv.1 落同一档**，也不能在同一组三选一同时出现。即便已装染病，也可刷出染病的其他品质 / 等级变体用于替换；不要用旧 `CanAcquire` / 满级过滤挡掉。

### 1.3 装备与换装

- 影之武装和饰品各自有槽，基础各 2，保留现有局外天赋扩槽规则。
- **未有同款且有空槽**：点击候选后直接装备该变体。
- **已有同款**（即使还有空槽）：点击候选后直接替换**原槽**；品质 / 等级 / 效果以新掉落变体为准，原等级不是 +1，不取最高等级，不合成。若新等级比旧等级低，结果仍是新变体。
- **没有同款且该类满槽**：点击上方新候选后，在**下方展示当前同类别装备名单**；单击要换掉的旧装备，替换该槽。选择尚未完成前，整个奖励流程保持等待，不推进队列 / 下一波。不得照搬旧道具弃置弹窗的“双击确认 / 恢复时间”行为。
- 同一影之武装或饰品不得在对应装备栏同时占两个槽；不同品质 / 等级并不改变同款身份。替换不得移除经验成长属性；效果与槽位 / 图标同步，不残留旧装备加成。
- 用户未指定“下方选槽时返回其他候选 / 跳过 / 重抽”等新玩法：不得新增相应规则、按钮或自动处理。异常与销毁安全属于工程处理，不能悄悄消费奖励。

### 1.4 经验升级：独立品质 / 全局概率

经验升级候选可以出现品质不同的同一升级内容，品质对应用户填写的实际效果，如**传说品质的最大生命值提升**；**品质出现概率全局统一**，不依赖装备池内档或内部圈数。一次三选一按**升级内容身份**去重，不同时显示普通 / 传说等同款；不同次奖励仍可继续获得相同属性，按既有本局成长语义积累、不占装备槽。

卡片显示的品质与数值必须等于选择后实际施加的品质与增量；不能仅改颜色 / 文案，不能用旧 `currentLevel + 1` 代替选中品质的数据。现行属性上限、局外软上限及体验未由本轮重新设计：保护已验收行为、尊重已有边界；不擅定每种品质的数值、张数或独立上限。对于旧数据如何迁移，保证不把已有旧档属性变成错误增量，并在不明确时停下报告。

### 1.5 永久解锁、生命周期和非目标

- 既有 `SaveData.unlockedActiveSkills` / `unlockedAccessories`、`EquipmentUnlockService` 用于**种类的永久解锁资格**；不要把局内装备变体误存为永久拥有。解锁后后续宝箱可以抽到其配置允许的变体，不保证立刻获得。
- 本局装备及成长属性在对局结束清空；独立的永久资格不清空。换装不能删掉经验属性。普通路线已有节点检查点恢复，涉及共享模型时不能损坏旧档 / 教学。
- 此批不实现新的永久解锁掉落来源 / 解锁名单和发放概率。已有 `Grant` 仅是 API，**当前未发现掉落链调用，不能宣称发放已接通**。
- **地刺 `spike_trap`、击退波 `push_wave`、聚拢波 `convergence_wave`、反伤 `charge_reflect_shield` 暂不入装备池**。保留资产及 GUID，不删除 / 重建 / 误归为可卸饰品。
- 不做新影之武装（含夺锋）、四件新护符、藤甲兵、关卡卡池随机、额外主武器 / 招式、正式平衡、开局赠送、玩家可见圈数或新付费 / 分享功能。

## 4. 分步实施方案与验证门槛

### P0-A：基线和测试隔离

- 按 §2 复核并记录 Git / Editor / 资产与 `player_save` 风险；建立纯内存或经证实隔离的测试前提。不能证明隔离的真实写档 / Play 验证标记阻塞，不覆盖用户现场。

### P0-B：变体身份和可配置数据

- 分离**装备种类身份**与**具体变体身份**：种类用于同次去重 / 不重复装备 / 永久解锁；变体承载可见品质、可见等级、效果数据、池内档位和权重。保持原有资产 / GUID / Inspector 引用可追踪；不要将同显示名的主动 / 被动误合并。
- 提供用户可填写的“装备变体 / 档内权重”以及“无尽内部圈数阶段 → 各档概率”配置；真实字段、Inspector 结构可按项目风格设计，但必须便于新增行、定位原资产、独立修改效果，不要求用户改代码。不得把具体概率或示例映射写成已确认值。
- 提供独立的“经验升级内容 / 品质 / 效果数值”与**全局**品质抽取配置，不复用无尽装备档。品质抽取和条目权重的具体字段可由实现确定，但效果和概率必须可查可调，不能无意把旧装备分桶概率挪为正式属性概率。
- 配置验证：引用为空 / 重复种类或变体标识、品质 / 等级 / 档位无效、负权重 / 总权重为零、阶段缺失、正权重档无有效物、等级数据不完整、解锁过滤后不足、同次去重后无法满足指定候选数等，给出具体错误对象 / 条目。区分“非零概率但无候选”的真实配置问题，与用户合法配置的零概率档；**明确报问题，不静默降级 / 改权重 / 加补偿 / 造装备**。玩家态发现问题时的退出 / 重试 / 不中断方式未经指定，应报告阻塞，不能虚报奖励成功或默认自行选补偿。
- `UpgradeDefinition.GetAvailableLevelCount()` 对主动仅看 CD 行数，不能因此忽略该类型对应效果行 / 子数据；必要时按实际效果类型核对。留好既有 V1 / 教学用接口和旧数据，不以新模型影响非目标路径。
- 验收门槛：配置界面可见、用户能填且能定位；用隔离内存样本验证同名不同类、同种类多品质 / 等级、单品质、无效配置都能准确识别。

### P0-C：装备抽取与卡片数据

- 将装备候选建模为完整变体实例；按用户填的圈数阶段档概率及档内权重抽样，主动 / 饰品一套候选，不再交替保底。取消“新装备因满槽过滤”“同款因满级过滤”；仍尊重有效永久解锁和用户配置。
- 同一次候选按**种类身份**去重；禁止“普通染病 Lv.1 + 传说染病 Lv.1”同时出现。不同次独立、无限库存；不要增加凑满三张的伪规则。
- 确保 UI 对应实际候选变体：品质 / 可见等级 / 效果 / 冷却等来自同一条变体，已装备同款可比较但不得显示成“Lv.旧 → Lv.旧+1”。需要为旧 `IUpgradeChoiceView` / 教学依赖保留兼容或增量扩展，避免破坏 `OnChoicesReady(List<UpgradeDefinition>)`、`ConfirmChoice`、教学定位 / 强制选择和现有 V1。
- 验收门槛：受控的单次抽样测试（如仅一档非零、指定一件变体）可证明档选择、实际变体和卡片字段一致；完整三选一测试仍须配置至少三个可选种类。圈数改变只影响装备档，不保证两类、不因库存减少；验证同次不重复、跨次仍有资格再次出现。统计权重以测试样本置信区间解释，不将小样本随机结果视为概率证明。
- **校验与去重的时序须精确**：在一组候选开始前，检查各个配置为非零概率的档位有可用变体，并检查整体不同种类足以组成候选。某档原本有效，却因为本组已选同款而在抽第 2 / 3 张时耗尽，属于“同次去重”的动态结果，不能直接宣称配置错误；如何在剩余有效档中重新归一化或以其他方式抽取，会影响最终概率，目前尚未拍板。**实现这个分支前先向用户确认具体规则**；任何方案不得重新抽回同款、静默吞奖励或将示例概率写成正式配置。

### P0-D：波末换装与队列

- 业务入口执行原子 / 可失败的装入或替换：空槽直接装；同款原槽直接替换新变体；异款满槽上方点新、下方同类列表点旧。无成功不触发成功事件、不消费奖励；不存在重复持有。槽位顺序、显示 / 冷却 / 被动注册与实际数据一致，换下旧饰品不动经验属性。
- UI 复用现有三选一视觉 / 素材并在下方表达名单；不引入未授权二次确认、保底、跳过、重抽、动画 / 场景大改。现有 `ItemDiscardPopup` 仅可参考契约与素材，其道具用次数、双击和无条件 `timeScale=1` **不能直接复用为装备规则**。
- 正确解除旧被动登记 / 新被动登记与对象自身持有状态；保留项目既有波末暂停和战斗演出，不为处理理论上的战斗中换装另定玩法。旧效果 / 等级必须不再影响接下来战斗，角色成长属性不受影响。
- 合并处理末杀箱与波末 flush：先验证飞行箱时序，必要时在既有波末结算内确保箱子已到并入队；连续多个箱 / 多次经验升级按队列处理。**不要加入未经授权的自动跳过、随意延时 / 兜底奖励**，也不要擅自把用户已有的流程重排。
- 验收门槛：2 格满槽下 A/B → 新 C 下方选 A → C/B；已有 A Lv.3 → 新 A Lv.1 原槽变 Lv.1 且仅 1 个 A；同等级 A→C 图标更新；被动注册 / 属性持有数值一致；多奖励期间不中断暂停、不提前下一波；精英末杀及 Boss 末波不漏选。

### P0-E：经验升级品质与积累

- 经验候选按独立**全局**品质配置抽取，不看圈 / 装备档；同一次按升级内容身份去重。选择具体品质时直接应用该品质配置的增量 / 效果，后续其他品质仍按项目属性成长语义累积。
- 现有数值实现中既有逐级相加也有覆盖特殊项（例如某些射程效果），不能未经验证一概当作可直接累加。按当前已在池的属性逐项审计，记录原行为和品质变体的兼容；不顺手改掉旧数值 / 范围、设定新的软上限或覆盖用户未定的属性归属。
- 保证先选普通生命提升、之后选传说生命提升，实际属性包含两次已获增量，换饰品后仍在；具体数字只能来自测试样本或用户填写，不能引用为正式平衡。
- 验收门槛：同一种类三选一不重复；相同全局配置在不同圈阶段的品质规则一致；UI 显示 / 实际增量一致；连续多次属性成长、软上限、换装备 / 本局重置、旧档 / 教学按适用范围通过。

### P0-F：内容入池、持久化兼容和整体验证

- 明确列出 10 主动 / 9 占槽被动实际接入状态、原资产路径、哪些变体和权重由用户填写；自动创建或迁移原数据时，仅在 **不臆造品质 / 数值 / 几率**且用户授权的前提下处理，保留原资产 GUID 和数值。
- 初始解锁保留已验收当前 demo 的现有内容全解锁；清理确实残留的旧天赋门槛时，用 Editor API 分别核对目标资产 live / disk、引用和 dirty，避免覆盖用户内存改动；只在当前范围处理，不改其他已验收天赋 / 武器行为。
- 普通路线 / 教学 / V1 与检查点：如果共用代码受影响，验证既有入口、旧存档字段及记录恢复顺序；按既有存档迁移机制扩展必要字段，不能清档或默默丢弃。若无法安全确认迁移，停止该部分并报告，不擅自删除旧数据。
- 汇总未配置列表 / 报错明细；直到用户填写与认可前，将正式池标为**未完成配置**，不要以示例权重当上线配置。执行后完整编译 / 域重载、必要测试与 Console；用户自行按真实流程验收体验和 UI。

## 5. 交付验收矩阵

| 场景 | 必须观察的结果 |
|---|---|
| 配置可编辑 | 用户能找到并填写装备种类 / 变体品质等级 / 效果 / 独立档位与权重、圈数阶段概率、经验品质数值与全局概率；有效 / 无效配置有清楚校验 |
| 独立档 | 相同可见 Lv.1、不同品质变体可在不同池内档；同品质不同等级可各用不同档 / 数值；不会从品质或显示等级推导档 |
| 内部阶段 | 两套阶段配置在不同内部圈中生效，圈只影响装备档；不在 HUD / 结算展示圈数，不改分数 |
| 同次去重 | 一次装备选择同种类最多一张；一次经验升级同一内容最多一张；不同次仍可再出现 |
| 不保底 | 可用配置允许全主动或全饰品候选；系统不强行交替或伪造候选 |
| 无限池 | 已装备或曾抽到不消耗池数量，后续仍能出现同款 |
| 装备换装 | 空槽、同款不同品质 / 等级直接替换、异款满槽下方点旧替换；不能同款双槽，新变体精确生效，旧的停止影响 |
| 属性品质 | 传说生命增量和 UI 一致；普通后传说继续累积；圈数变化不改变全局品质概率；换饰品不丢属性 |
| 配置错误 | 缺档 / 无可抽 / 数据不足 / 候选不能满足去重要求等能定位报告；不默认改概率 / 发钱 / 吞奖励当成功 |
| 波末 | 精英或 Boss 箱飞到玩家并入队；末杀 / 末波 / 多箱 + 多次升级都在当前波末按序选完，才进入下一波或离开节点 |
| 生命周期 | 暂停期间游戏内容冻结、UI 可操作；用户已有场景与表现不被额外清除；重开 / 退出干净，不泄露旧持有或事件 |
| 兼容 | 当前存档 / 剧情节点快照、F1 / F5 / F6 / F7、主武器 / 招式与教学 / V1 在受影响范围不回归；无未经授权的真实存档写入 |

## 6. 待用户填写 / 暂不自定的内容

1. 每件装备的具体品质 × 显示等级 × 效果数值、哪些变体启用、池内档位与档内权重。
2. 每个内部圈数阶段如何分段、档位具体概率；经验升级各品质的效果数值与全局概率。
3. 异常时面向玩家的提示 / 恢复交互、装备选择中的跳过或重抽等尚未授权细节；先报告，不偷偷扩展。**同次去重后某个原本有效的档临时耗尽时，剩余候选如何抽取 / 归一化**也需确认；它不同于预先配置的空档报错。
4. 长线的初始解锁清单、精英 / Boss / 探索宝箱对应的永久解锁发放；新装备 / 效果与各模式平衡。

## 7. 给接手 AI 的启动提示

> 先读 `plan/endless-demo-handoff-20261124.md` §0.8、`design/gameplay-progression-loop.md` §3.3–§3.4 和本文，再确认用户是否明确要求实施。保护脏工作区 / 玩家存档；优先把**装备变体独立档 + 圈数档概率**和**经验品质全局概率**理解为两套规则。同次都按种类去重；满槽异款在原三选一下方点旧装备，同款直接以新品质等级替换，不升级；四项机制暂不入池。正式数值 / 概率由用户配置。先复核现状后执行、验证并交付，不修改其他已验收系统或伪报通过。
