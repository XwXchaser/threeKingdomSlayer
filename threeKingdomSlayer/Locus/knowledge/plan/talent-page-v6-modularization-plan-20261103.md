## 1. 核心设计与滑动边界

```text
TalentScreen（全屏覆盖）
├─ Dim / 遮罩：固定，按 UI 层级拦截底层输入
├─ PanelShell：固定的背景与外框
├─ Header：固定
│  ├─ 标题及可能的装饰
│  ├─ 返回操作
│  └─ 铜钱图标 / 动态数值
├─ CategoryTabs：固定，3 个大分类的文案与选中状态
├─ TreeViewport（RectMask2D）：固定尺寸的中部观察窗
│  └─ PagesRoot：拖拽时沿 X 或 Y 整体移动
│     └─ Page[category,page]：
│        ├─ 可选的本页／分支承托
│        ├─ BranchHeader × N：分支名称与可选标识
│        ├─ Connectors：按真实前置关系动态生成
│        └─ Nodes：框／技能图标／名称／价格／状态／选中
├─ VerticalPageIndicator：固定于视口侧边，按当前分类页数动态更新
└─ DetailArea：固定位置；图标、文案和按钮状态动态变化
```

- **左右手势**：切大分类，视口内容水平移动并吸附；分类栏位置固定，选中态更新。顶部三个分类语义是基础数值／招式解锁／三选一解锁，不是蓄力／水／火。
- **上下手势**：切当前分类内部的页，视口内容竖直移动并吸附；不是自由长滚动。只有多页时才需要页码指示。
- **用户已确认方案 B**：同一分支的前置链可跨页，玩家要能意识到后续还有分支／节点；翻页不得改变真实解锁前置。跨页延续提示及另一页的前置信息如何具体呈现，留待设计与确认，不能只依赖一条裁断后无说明的线。
- 分支标题、其承托、节点与连线属于 Page 内容，应与该页一同滑动和裁切；顶栏与详情**位置**固定，但文字、选中、按钮可随状态变化。
- 触摸从节点、页内空白和边缘开始时都要能正确识别拖拽，点击节点与横竖滑动不能误触购买。不要让装饰 Image 意外拦截输入。

## 2. 从整图到可用模块：处理原则

V6 将框、背景、图标、连线、光效画在同一张不透明 RGB 图内。直接矩形裁切会把背景一起切出，并可能留下压住节点的连线、边缘光晕、被遮挡的残缺部分。**视觉验收方向 ≠ 允许把一张图作为最终整个 UI。**

| 类型 | 建议处理 | 不应烘焙进去 |
|---|---|---|
| 固定外框／卡片 | 整理重绘或精修为独立底板；适用处再按验证结果九宫格 | 数字、名称、节点、分类内容 |
| 分类页签 | 通用底板＋文字／图标；常态与选中共享轮廓家族 | 三个分类拼死成一整条，或把火系图案误作分类语义 |
| 分支标题 | 通用承托（如果需要）＋动态名称＋可选分支标记 | 节点、连线和其他分支 |
| 节点 | 共享三态框＋可替换图标＋文字／价格＋独立选中提示 | 特定技能、数字、固定锁图案或某条连线 |
| 连线 | 白色可染色线段，按数据和布局生成；必要时动态转折 | 分支数量、节点坐标和节点图片 |
| 详情 | 空底板＋动态缩略图／名称／说明／状态／价格／按钮 | 原图火焰图标、固定文案、固定铜钱金额 |
| 页码点 | 独立常态／当前点或程序化绘制 | 固定页数、特定分类 |

九宫格只用于边缘可稳定拉伸的面板、页签、详情卡及按钮等；**切片边界以透明清理后的实际资产验证为准**。节点固定尺寸通常适合 Simple 图像而不是强制九宫格；需求表虽写 B 组边距，实际用途需确认。长线由程序确定长度、位置和朝向，避免将一张烘焙长线缩放到糊。

## 5. 当前二维分页的适配重点（已读代码，非本轮修复）

1. **用户选择方案 B：允许一条分支的前置节点和后续节点跨页，玩家应知道后面还有分支／节点。**当前 `TalentPaginator` 按 `treePosition.y` 归行，只允许在不跨前置连线处切页；`BuildPageContent` 只画两端都在本页的边。两者都与新决定不符，后续必须调整分页及跨页关系呈现；真实 `prerequisiteIds` 与购买校验不得因显示分页而改变。跨页提示的具体形状、文案、位置及是否跳页尚未确认。
2. 当前 `SelectedNode()` 只记分类＋页内序号，未记页号；只读假设中第 2 页点击“海浪”会按第一页同序号解析到“旋风”。必须以节点稳定身份或包含完整页身份查询，确保展示、确认、扣钱对象一致。
3. 横滑切分类时目标页取源分类 `CurrentPageIndex`；两个分类页数不同时，目的页可能不合法或跳空。应统一页签点击与横滑行为，使用目标分类合法页号，再验证切换中间画面；每类是否记住原页依产品要求确认。
4. 纵向翻页后当前代码未主动刷新页码高亮；选中状态不会随页变化而清除，详情内容因此可能继续显示上一页。按用户确认，**上下翻页后清空选中、隐藏详情**，并及时更新页码与高亮。
5. 拖拽主轴、阈值、吸附、中途打断、缩放坐标和按钮点击相互作用应按实际 Game 视图和目标机比例测试；现有 0.22 秒及 18% 阈值是代码现状，不作为新的手感硬指标。
6. `RefreshSelection` 同样只按分类＋页内序号判高亮，多页可能在同一分类其他页误亮；需与选中身份一起处理。
7. 一页按行数分页不自动等于节点及文字真正装得下：需把标题、节点、价格、连线、底部详情实际尺寸纳入可见区域校验。

截至本轮，编辑器连接、处于 Edit Mode，活动场景 `Assets/Scenes/Battle.scene`；天赋 overlay 场景未打开。只读加载 `TalentCatalog_Main` 和分页计算显示三类当前各 1 页（5／3／6 个测试节点）。当前数据尚不是美术需求中的完整八分支，不能据此声称最终分页或交互已验证。

## 6. 设计尺寸与源图几何

- 需求文档设计口径：1080×1920；当前天赋场景节点为 132×132、行距来源于节点资产、`rowsPerPage=8`、详情高 300。源图 1024×1536（2:3），本身不是游戏 9:16 逐像素布局。
- 三连示意只手动裁出中部观察窗表现滑动，坐标是说明性的，不是最终 Unity RectTransform 或切片坐标。
- 图中的标题框、三列轨道、节点和详情无法自动满足所有分类、节点数量与不同手机比例；采用可适配的锚定／九宫格／动态布局，在参考画面方向内重新排版。
- 要求 2×、PNG 透明、可拉伸件九宫格与图标安全边距属于生产约束；**完整尺寸、是否 2×、边距究竟按源图还是设计尺寸计算，应在出件前统一确认**。正式素材不要带白底、棋盘格或背景场景。
- 生成图像的原始颜色不能简单当作每种状态底图；彩色参考的最终渲染由中性贴图、颜色、透明度和 UI 效果共同决定，需验证线条、锁、按钮的对比和缩放。

## 7. 建议实施顺序（需另行批准，非本轮执行）

1. **定交互契约**：用户已确认无选中时隐藏详情、上下翻页后清空选择、允许查看锁定节点但不能购买，并选择允许前置链跨页且提示后续内容；仍需确认具体跨页提示、分类页码记忆、真实新树数据与分页排布。
2. **按参考图出模块规划与透明验证样品**：先验证固定外框、一个节点三态、一个技能图标、详情卡与按钮的可分离与风格；先审查独立素材在深浅底及目标尺寸，不把此步扩展成未经批准的全部 P0 批量产出。
