## 3. 投影模型与屏幕换算

相机固定不动；`YScrollSample` 只推进位姿 `_YSPose`（位置 + 航向），景物 Shader 把每个 Renderer 的**枢轴**重投影到「位姿前方」的坐标：

```
depth = (枢轴 − 位姿) 在航向轴上的分量
anchor = (横向, 枢轴世界Y, depth)      // 无弯曲时
anchor.y -= 0.009·max(0,depth−18)²     // 远景点下弯
fade = saturate((depth+14)/3) · saturate((278.1 − depth)/10)
精灵横轴固定在位姿横轴上：anchor.xy += v.xy·(sx, sy)
```

结论：**在「节点锚点局部坐标系」里，X = 横向（−X 为左，+X 为右，与相机右向量一致）、Y = 高度、Z = 前方深度**，且这个局部坐标与屏幕的换算和「世界坐标」完全一致。因此布景只需在节点锚点下按 (x, y, z) 摆放，锚点自带的 −45° 旋转会把它们贴到正确的车道方向。

## 4. 战斗区在屏幕上的占位（构图禁区）

- `Enemies` 根节点世界位置 **(0, 0, 9)**。
- `StageController.GetFormationOffset` 的 `stageConfig` 为 null → 走**回退分支** `(columnIndex−2)·2.0` → 5 列固定在 x = −4 / −2 / 0 / 2 / 4（**不随排收敛**）；`rowSpacing` 回退 2.5、5 排 → 世界 z = −1 / 1.5 / 4 / 6.5 / 9。
- 即当前阵型是 **x∈[−4,4] × z∈[−1,9] 的矩形**，屏幕占位：脚点 yn ∈ [−0.01, 0.275]，横向 xn = ±0.73（最远排）；含敌人身体高度后轮廓上沿到 yn ≈ 0.50。

**战斗禁带（N3 强制）**：`xn ∈ [−0.80, 0.80] × yn ∈ [−0.05, 0.42]`。

> 注：该回退值依赖 `stageConfig` 为空。若后续某个节点改用带 `formationConfig` 的配置（如 `DefaultFormation.asset`：半宽 2→4.5 的梯形），阵型会收窄/变深，禁带需按同一公式重算。本文按**当前实测状态**给值。

## 6. 构图预算：三条可执行规则

### R1 中央净空（战斗节点强制）

村建（有高度的对象）的横向必须避开战斗禁带：

```
|x| ≥ 0.80 · hw(z) = 2.410 + 0.2197·z      ← 硬规则（完全避开敌人最外列 ±0.73）
|x| ≥ 0.72 · hw(z) = 2.169 + 0.1977·z      ← 可接受下限（允许贴禁带外缘）
```

### R2 近层只能落在侧缘

depth 小的物件横向窗口很窄（z=0 只有 ±3.0 在屏）：**z ≤ 18 的景物一律 |x| ≥ 5.0**。换言之，**N3 画面下半部（yn<0.30）除路面外不应有任何村建**，这是由相机高度/俯角决定的，不是美术选择。

### R3 村建在 J1 机位必须不可见

J1 机位（pose=190、航向 0°）的判据就是「横向出屏」：

```
|X| > hw(max(0, Z − 190))         // X、Z 为景物世界坐标
```

在 **EV 局部坐标** 下可化简为：

```
z > 1.7571·x − 12.428
```

| 侧 | 含义 | 结果 |
|---|---|---|
| x < 0（**外侧，村落主侧**） | 车道左方 | 约束极松：x=−4 需 z ≥ −19.5；x=−6 需 z ≥ −23 |
| x > 0（**内侧，朝岔口**） | 车道右方 | 约束紧：x=5 → z ≥ −3.6；x=7 → z ≥ −0.1；x=10 → z ≥ 5.2；x=15 → z ≥ 13.9 |

| 摆放 (x,z) | xn@190 | 结论 |
|---|---:|---|
| (−4, −19) | −1.04 | 安全 |
| (−4, −20) | −0.96 | **越界，J1 可见** |
| (−5, −19) | −1.18 | 安全 |

**落地建议**：

- **EV/N3 组局部 z 起点 ≥ −18**，近缘小件 |x| ≥ 4.5。
- **外侧（−x）承载村落主体**（与 J1 v3 参考图、J1→EV 视频「右侧断石墙」的分工一致：村庄在车道左外，右内侧只有矮墙/篱笆）。

## 10. 验收方法与数值断言

1. **摆放自检（可脚本化）**：对每个新 Renderer，按 §3 公式复算：
   - `|xn(z)| ≥ 0.72`（R1）
   - `z ≤ 18 ⇒ |x| ≥ 5.0`（R2）
   - `xn@pose190 出屏`（R3）
   - 三项任一不通过即调整位置，不靠目视发现。
2. **采样位姿**：Left、pose = 190 / 200 / 205 / 210 / 215 / 220 / 225 / 235 / 245 / 255 / 262 / 266.1165（建议另补 Right N2 同段对照）。
3. **必查画面**（用户目视，我无法代看）：
   - `pose205` / `pose210`：村建**未**进入 J1 视野，第一批体量恰在左转后出现。
   - `pose225`（EV）：路面开阔、无战斗、中央无遮挡。
   - `pose266.1`（N3）：中央 xn∈±0.80 × yn∈[−0.05,0.42] 无村建；两侧与后方村落可读；建筑不悬空、不穿地。
   - `pose190`：与**已验收的 J1 画面**逐项对照，不得因新增村落而改变既有构图。
4. **保存/重载**：只保存授权 Y 场景；重载后复读 root=(0,0,0)、progress=0、`scenery` 计数、null/dup=0、dirty=false、Battle 未保存、Console error/warning=0。
