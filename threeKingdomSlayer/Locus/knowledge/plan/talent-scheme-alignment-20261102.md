## 3. 三个必须拍板的冲突

### 3-A. 图标：复用现有 `icon_31_*` 还是全部重画？

| | 复用（对方方案） | 全部重画（你上一轮的指示） |
|---|---|---|
| 做法 | 节点内图标**直接用** `Assets/Sprites/31Reward/icon/` 现有图标（已是「三国像素街机剪影」风）+ 招式图标用 `QTE_Slash.png` / `QTE_Stab.png` | 美术重新画全部节点图标 |
| 缺图标的 3 个 | 只需补 `聚拢波` / `击退波` / `连刺` 三个 | 全部 23 个都要新做 |
| 优点 | 零新增、风格天然统一、与局内三选一卡片**同一套符号**（玩家认得出） | 符合「旧素材是凑数的、不能当参考」 |
| 缺点 | **现有图标本身就是旧美术** | 23 个新图要与局内技能图标风格对齐 → 实际是两套活 |

> **冲突根源**：你上一轮说「当前的美术素材很多都是凑数临时的，不能引用作为参考」；对方方案明确「**可直接复用的现有素材（不用重画）**」「节点内图标直接用它」。
>
> **需要你定**：图标这条走「复用」还是「重画」？若走重画，局内三选一卡片图标是否也要一起重做（否则天赋页和局内是两套符号）？

### 3-B. 画风口径：三方不一致

| 口径 | 出处 | 描述 |
|---|---|---|
| **甲** | 对方 `memory/ui-art-style-anchor.md` | **「简洁白边」**：近黑 `#1A1A1E` + 米白细描边 `#F2EDE0`，零材质零笔刷零渐变；并明说「拿战场/角色概念图当 UI 画风锚是错的」 |
| **乙** | 对方 `plan/talent-ui-art-handoff-20261101.md` | **「照刀锋」**：单色**暖铜**描边 `#D9A674` + 平面深底 + 剪影图标 |
| **丙** | 我 `design/art-asset-brief-20261102.md` | 墨色破边笔刷 + 金属黄铜 + 红色危险值（= 落地页 V9 笔刷语言） |

> **甲 vs 乙 本身就有张力**：甲说 UI 只有「近黑 + 米白细描边」两种材质；乙要单色暖铜描边。暖铜属不属于甲说的「暗铜细描边」？甲文里提到「主界面铜牌框 `#201B18`–`#27211D` 暗铜」，但那是**落地页**的。
>
> **丙作废**（且与对方「别加戏 / 不要笔刷纹理」明确冲突）。
>
> **需要你定**：天赋页最终认 **甲（简洁白边）** 还是 **乙（刀锋单色暖铜）**？定了我就改 `art-asset-brief`。

### 3-C. 流派分线在对方结构里没有位置

对方的页 3「三选一解锁」是**扁平的 14 个升级条目**（`upgradeConfig` 直接引用 `UpgradeDefinition`），**没有分支 / 层级概念**；分页是「按行 + 不跨连线」自动切的。

而你的需求明确是「技能解锁要按流派分线 —— 3 种起始分支，而不是十几个技能堆在一条树上由头点到尾」。

| 落法 | 做法 | 代价 |
|---|---|---|
| **A** | 页 3 内**沿用 `col`/`row` 手摆出三条泳道**，靠**视觉分行**表达流派（不改数据结构） | 零代码；但「分支」只是视觉约定，切页算法仍按行 |
| **B** | 给 `TalentNodeConfig` 加一个 `groupId`（流派），面板用它做**同色描边 / 分组标题** | 加一个字段 + 面板小改；分页算法仍按行 |
| **C** | 把流派做成**独立的三选一树资产**（`TalentTree_Pools` 拆成三个） | 与对方「3 树」的分类方式不同构，要重做 `TalentCatalog` |
| **D** | 本期不做流派分组，先把 14 个条目平铺 | 放弃需求 |

> **需要你定**：A / B / C / D。
> 注：对方方案里「类间不做前置」是用户已确认口径；而流派内的**节点间**前置（例：震荡需先有铁壁）仍可用 `prerequisiteIds` 表达 —— 这部分与对方结构兼容。

### 3-D. nodeId 改名会静默清空存档

对方把存档策略定为「**不保留**失效节点，匹配不上即清掉」（跑在 `TalentSaveSection.Migrate`，幂等）。

→ 好处：节点删除 / 改名不用写迁移。
→ 风险：**改名 = 玩家已解锁记录直接消失**（而且没有任何提示，因为是「清掉」不是「迁移」）。

**需要确认**：是否接受？（我倾向：改名时在 `Migrate` 里加一条**别名映射**，把老 id 映射到新 id 再清）
