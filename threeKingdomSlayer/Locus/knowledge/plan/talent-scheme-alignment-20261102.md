### 2.2 数据层：**要做 4 处修正**

| **①** | **加分支/分组概念** | `TalentNodeConfig` 加 `groupId`（流派 / 方向 id）；`TalentPaginator` 切页时**优先不跨 group**，其次不跨边；面板按 group 画分组标题与泳道 | **当前完全没有分支概念** —— 而需求明确是「每页多个起始分支」。我原方案想用「拆成更多树资产」，但那会让「页」和「分支」语义混淆（页是横向切、分支是树内纵向），**改用一个字段更干净** |
| **②** | **定载荷方案** | `flagId` 目前零消费者。三选一：<br>(a) 给每个 flag 建消费点<br>(b) 改成方案稿里的 `statId`/`statAdd` 通用载荷<br>(c) **保留 flag 但只在「需要独立开关语义」时用**（如 `ice_thaw`） | 不定清楚，页 1 的 5 个体魄节点点了也不会生效 |

## 3. 三个页的最终信息架构

```
天赋页（3 页，横向切换）
├─ 页 1 · 基础数值            ← 载荷 statId/statAdd 或 flag（待定 ②）
│   ├─ 分支：战斗向（破阵 / 追击 / 运筹）
│   ├─ 分支：生存向（铁血 / 连击精通 / 不屈）
│   └─ 分支：经济向（聚财 / 巧思 / 博学）
├─ 页 2 · 招式解锁            ← 载荷 moveConfig
│   ├─ 分支：点线（指向突刺 C2 → 枪突收尾 C4）
│   └─ 分支：划线（横扫位移 → Slash 衍生，待定）
└─ 页 3 · 三选一解锁          ← 载荷 upgradeConfig
    ├─ 分支：蓄力流（入门 → 铁壁 / 震荡 / 冲击波）
    ├─ 分支：位移流（入门 → 专注 / 海浪 / 旋风 / 染病）
    └─ 分支：火系（蛇形喷射 → 火龙舌）
```

**8 条分支**，每条一个起始分支点。

**通用技能**（疾风 / 智慧 / 地刺 / 箭雨）**不进天赋页**（常驻局内池）。

## 5. 重排后的执行顺序（关卡整体后移）

> **为什么关卡后移**：天赋解锁未落地 → 玩家在每关实际拿到什么未知 → 关卡编队与 `healthMultiplier` 校准都建立在「玩家有什么」上。
> 现在只有 Stab / Slash / Launch / Parry / C2 / C4 六个招式、池内 14 条技能（且 0 个由天赋解锁），**测出来的倍率放到有构筑时完全不准**，而且编队本身还要按解锁顺序重排。
> → **测关卡有意义的前提是「可用的招式与技能够多 + 解锁链已落地」。**

```
① 数据层对齐（§2.2 的 4 处修正）      ← 不依赖关卡
② 能力天赋消费点 + 槽位 3+3 + 满槽补偿 + 等级上限 + 秘籍   ← 不依赖关卡
③ 招式衍生（Slash 衍生 + 点线/划线补完）  ← 增加可测内容
④ 技能流派分线（requiredTalentIds 批量配置）  ← 让技能真正可解锁
⑤ 画风重定 + 美术全量重做              ← 与 ①③ 并行
─────────────────────────────────────
⑥ 关卡编队（N1 1波 / E0 3波 / N3 5波 + 104 两阶段 + 铜钱）
⑦ 机器人调参 + 难度表脚本基线同步 + XP 投影   ← 等 ③④ 落地后才测
```

> **本轮我原计划里的「先做关卡配置」撤回。** 关卡配置文档（`design/stage-configuration.md`）的**规则与字段说明仍然有效**，但**执行推迟到 ⑥**。
