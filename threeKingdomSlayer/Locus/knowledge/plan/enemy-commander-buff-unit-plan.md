## 0. 这个单位是什么（美术要表达的玩法）

### 0.1 身份卡

| 项 | 内容 |
|---|---|
| 代号 / id | 督战鼓手（**临时名**）/ `enemyId = 1013` |
| 一句话 | **不攻击、给在场敌人叠加攻击力、死后给在场敌人永久减攻的敌方指挥单位** |
| 玩法定位 | 玩家第一个"**必须优先解决**"的目标 |
| 所属支柱 | 支柱四「敌人机制」；服务支柱三「技能组合」与支柱五「分支」 |
| 体量 | 一个**普通单位**（占 1 格 / 150 血 / 经验 150），不是 BOSS、不进 QTE |
| 状态 | 机制与数值已拍板；**未实施**（工程改动清单见 §7.5） |

### 0.2 三个动作 → 视觉上必须读出来的三件事

| 动作 | 机制 | **画面上必须看出来的事** |
|---|---|---|
| **常态** | **不攻击、不造成任何伤害**；正常行军 / 补齐 / 受击 / 被挑飞 / 被眩晕，与普通敌人无异 | ① 他**不是挥剑的兵**；② 他在**发号施令**（不是砍人） |
| **施放（加攻）** | 周期 4.0s（首次前置 2.5s）→ **在场**所有敌人攻击力 +10%，可叠 5 层，永久 | ③ **号令的预警动作要能预判**（0.8s 前摇，玩家要能看见"要来了"并决定打不打） |
| **死亡（减攻）** | 死亡瞬间 → **在场**所有敌人攻击力 −25%，一次性、永久 | ④ 他死时要有**明确的"败退 / 号令中断"读感**（与普通杂兵倒地不同） |

> **一句话教学口径**（玩家要在画面上读懂这句）：*它每号令一次，全场敌人永久变强 10%；它一死，全场敌人永久变弱 25%。所以最好在它号令两次以内点掉它。*

### 0.3 三条设计不变量（改代码 / 改图都不能破坏）

1. **只用既有动词**：威胁必须落在 **{选列 / 换招 / 择时 / 用技能}** 四个动词上 —— 玩家**没有位移动词**。
2. **不新增移动语义**：他正常行军（**不设** `ignoreFillUpOrders`），位移走既有通道。
3. **不改既有平衡口径**：不加新系统、不改通用伤害公式；倍率只作用在"出站伤害"这一层。

## 2. 设计任务：1013 的形象怎么设计（美术 agent 思考的部分）

### 2.1 设计目标（按优先级）

1. **同族**：一眼看出他属于 1012 那一伙（同一阵营、同一兵源），不能像另一个势力。
2. **醒目**：在混战的乱阵里，玩家要能**快速找到他**（他是"先杀谁"的决策对象）。
3. **不攻击**：剪影与姿态里**不能有攻击性**（不要持剑做威胁姿态、不要有挥砍的预备动作）。
4. **发令**：常态姿态里就能看出"他在指挥"（号令姿势或号令道具）。
5. **可打断**：0.8s 的举旗 / 号令前摇要是**连续可打断的动作**（玩家打下去他就中断），不能是瞬间切换的特效。

### 2.2 设计空间：三个方案（**待拍板**）

| 方案 | 形象要点 | 优点 | 代价 / 风险 |
|---|---|---|---|
| **A · 令旗（指挥旗）** | 沿用 1012 的斗笠盔与布衣；**左手 / 背后持一面小令旗**，旗面用新强调色（建议深金或朱红） | ① 剪影最高点有旗 → **远看最醒目**（小尺寸下旗是最容易读出的形状）② 与机制里的"**举旗预警**"完全一致（§0.2 第 ③ 条）③ 号令 = 举旗，动作语义无需解释 | 旗杆与 1012 的剑在剪影上可能撞（需用旗的**展开面**而不是杆来区分）；旗要占一点画面宽度 |
| **B · 战鼓（腰鼓）** | 腰侧挂一面小战鼓 + 鼓槌 | 名字"督战**鼓手**"直接对上；号令 = 击鼓，语义明确 | 鼓是**圆 / 方块**造型 → 远看不如旗醒目；"鼓槌"容易被误读成"他要打"（违背 §2.1 第 ③ 条）；击鼓需要手部大幅动作 |
| **C · 号角 + 披风 / 羽饰** | 胸前挂号角 + 头盔上加指挥羽饰 / 披风 | 改动最小（沿用 1012 全身） | 号令语义**弱**；号角在剪影上几乎不可见 → 违背"醒目"；披风是 1011 的语言（红披巾）→ 混同风险 |

> **推荐 A（令旗）**：唯一同时满足"远看醒目 / 与举旗预警的机制一致 / 不制造攻击性误读"三点的方案。
> ⚠️ 若选 A，**内部临时名「督战鼓手」建议同步改成「督战旗手 / 督战官」**（名字是临时的，见 §0.1）→ **需用户拍板**。

### 2.3 造型细节的开放项（**待拍板，共 5 条**）

| # | 待定 | 选项 | 默认建议 |
|---|---|---|---|
| 1 | 身份符号 | A 令旗 / B 战鼓 / C 号角 | **A 令旗** |
| 2 | 内部名 | 督战鼓手 / 督战旗手 / 督战官 | 随 #1 改 |
| 3 | **手里的剑要不要留** | 留（沿用 1012）/ 换成号令道具 / 空手 | **换成号令道具**（避免"持剑 = 能打"的误读）；但会改变剪影，需与 #1 一起定 |
| 4 | 强调色 | 深金 / 朱红 / 青蓝 | **朱红**（与 1012 的红巾同色系 → 同族感最强）；旗面用**浅色底 + 朱红纹**以保证小尺寸可读 |
| 5 | 专属音效提示 | 出场 / 号令加一声鼓声或号角（Blades 的做法） | 做（比加 UI 省事），但属音频线 |

### 2.4 剪影与配色硬约束

- **只允许一个身份符号**：除它之外，不要再往身上加旗 / 鼓 / 披风 / 羽饰 / 额外武器。
- **只允许新增一个强调色**，且只用在身份符号上；其余部分必须落在 1012 的米白 / 钢灰 / 暖棕 / 红四色家族内。
- **禁止引入 1011 的语言**：不要全身钢甲、不要大红披巾、不要红缨盔、不要发光眼。
- **禁止换阵营气质**：不要兽人 / 山贼 / 异族 / 日本造型 —— 1013 与 1012 是同一伙。
- **正面对称**：正面朝向玩家；武器 / 旗在角色右手侧（画面左）或身后正中，别做成 3/4 侧身。
- **像素语言不变**：粗黑描边 1–3px、硬边色块、**最多两阶阴影**、禁平滑渐变（像素规范 §2）。

### 2.5 号令动作（`Cast`）的视觉时序

| 时点 | 时长 | 画面 | 玩家要读到的 |
|---|---|---|---|
| 预警 | 0.3s | 举旗 / 举号令道具到一半 | "他要发令了" |
| 前摇 | 0.8s（**可被打断**） | 旗举到最高点并**停住**、身体前倾 | "现在打下去能打断" ← **这段必须看得清在举旗，而不是特效** |
| 施放点 | 施放瞬间 | 旗猛地一顿 / 落下 + 一次短促收势 | "加攻生效了" |
| 收势 | 0.3s | 回到 Idle | — |

> ⚠️ 预警与前摇**必须合并成一段连续动作**（0.8s 举旗），玩家才判断得出"打断窗口在哪"。
> 临时替身版本复用 BOSS 的放箭 QTE 三段（见 §7.3），**视觉上不成立** → 正式形象必须补 `Cast`。

### 2.6 不要做的事（明确禁止）

- ❌ 给他做 **attack 动作**（他不攻击）—— 省一支视频，也避免误读。
- ❌ 让他**持剑做威胁姿态**（idle 里举剑威慑会读成"他要砍我"）。
- ❌ 做成 BOSS 级体量 / 加光环 / 加发光。
- ❌ 照搬 BOSS_104 的形象（那只是临时替身，见 §7.3）。
- ❌ 用山贼版 1012 或 1011 当基点。
- ❌ 在 idle 里加入尘土 / 位移（像素规范 §7 Idle）。

## 3. 动作清单与制作方式

### 3.1 需要做的动作（**比 1012 少一支、多一支**）

| 动作 | 帧数参考 | 母本 | 备注 |
|---|---|---|---|
| Idle | 6（1012 同款） | 1012 idle 源片 | 站姿微呼吸 |
| Walk | 周期 16（1012 实测 P=16） | 1012 walk 源片 | 躯干中心 x 锚点，摆幅与旧素材同量级 |
| **Cast（号令 / 举旗）** | **新做**（4–6 帧够） | **无母本** → 单独生成一支 | §2.5 的时序；只描述"举旗"这一个动作 |
| HitFlash | 3（hitHeavy 口径） | 1012 受击源片 | 受击必须身体后仰，不能只换表情 |
| HitLeft / HitRight | 各 1–3 | 1012 对应源片 | 1012 的 controller **没有** HitRight → 会回落 HitFlash；要齐就得补 |
| Dead | 6–8 | 1012 dead 源片 | 失力坠落 ≠ 被击飞 |
| Launched_Rise / Fall / Getup | 击飞链 | 1012 击飞三支源片 | 与 1012 同一套（体型不同会有不匹配，需目视确认） |
| ~~Attack~~ | — | — | **不做**（不攻击） |

### 3.2 动作母本（哪支源片）

见 `Enemy1013ArtSource/00_Index/videos.csv`（母本全部指向 `Enemy1012ArtSource/01_SourceVideos/` 的 9 支动作源片）。

> ⚠️ **母本只认「用户验收的那支 take」**：用 `Tools/visual_brief/compare_video_takes.py` 做绿幕 IoU 对拍确认，
> **不要信文件名与台账记载**（1011 attack 就曾记错成另一支带大回旋弧光的 take）。

### 3.3 制作方式（替换视频工作流）

**一张图 + 一个母本**：`reference_image` = 1013 的新身份图，`reference_video` = 上表的动作母本 → **动作从母本继承**（节拍、幅度、量化参数都不靠文字转述）。

- ❌ 不要用「首尾帧工作流」（身份图当 first_frame/last_frame + 文字描述动作）→ 那等于每次把动作重新定义一遍（1012 那轮 4 支全飘的共同根因）。
- 母本里脸可见时，表情随母本继承即可，**不需要另做表情研究片**（只有母本的脸真被遮住、或本轮要改表情设计时才需要）。
- `Cast` 没有母本 → 只能文字描述，但**只描述这一个动作**，且要写 "game sprite animation / locked camera / fixed position and scale / fully visible / no cropping"。

### 3.4 表情规则（1012 实证）

1. **任何新动作的起手态必须等于游戏内 idle 的实际长相**（先裁头部特写目视确认，再写提示词）。
2. 表情写成**分段时间线**（第 1 秒 → 中段 → 第 3 秒 → 末帧 = 首帧）。
3. 负向词**只留四条不可违反的**：嘴不张开 / 不露下齿 / 不变友善笑 / 不疲惫困倦。
4. **脸是镜头里的主动作**，身体动作压到最低（idle 尤其）。
5. 1013 的表情基调建议：**号令时威严 / 张口喝令**，常态是**冷峻带轻蔑**（与 1012 的怒目同一家族，不要变成另一个兵种的气质）。

### 3.5 落位口径

沿用 1012 管线：idle 用 k=0.92366、脚底 897、中心 521；同动作共用一组偏移；按**可见底行**对齐（PIL 的 bbox 下边是 exclusive）；量位移用**靴子锚点**而不是 bbox 中心。

### 4.3 ⬜ 素材生产顺序（建议）

```
① 拍板 5 条 → ② 画一张「静态定稿」正面站姿（草图即可）
   → ③ 用绿幕身份图 + 静态定稿做「表情研究片 E1」（只做脸）
   → ④ 用 E1 + 身份图做 1 支 **idle** 替换视频 → 出 6 帧 → 目视六帧 + 逐像素核对落位
   → ⑤ idle 过了 → 批量做其余动作（walk / 受击 / 死 / 击飞链 / cast）
   → ⑥ 逐个动作落位 + 写精灵（保留 alpha、保留 .meta）+ 回读核对
   → ⑦ 装进 Unity：prefab + Animator + EnemyPool 注册 → 游戏内验收（可读性 + 0.8s 打断窗口）
```

> **第 ④ 步是唯一的卡点**：idle 不通过就**不要**批量做（1012 的经验：一次动作只生成一次，反复叠轮会让边缘锐度逐轮下降）。

## 7. 工程侧附录（给实现者，美术可跳过）

> 以下是 2026-11-05 定的机制与工程方案，**不随形象改版而变**。

### 7.1 机制规格

| 动作 | 触发 | 效果 | 时长 |
|---|---|---|---|
| 常态 | — | 不攻击、不造成伤害；正常行军 / 补齐 / 受击 / 被挑飞 / 被眩晕 | — |
| 施放（加攻） | 周期触发（首次有前置延迟） | 在场所有敌人攻击力 **+X%**，可叠加 | 永久（波内不过期） |
| 死亡（减攻） | 死亡瞬间 | 在场所有敌人攻击力 **−Y%** | 永久（波内不过期） |

**"在场"的准确定义**（实现必须逐条对齐）：

| 计入 | 不计入 |
|---|---|
| 已注册进 `EnemyManager` 且未死亡的全部敌人 | BOSS（`isBoss == true`） |
| 正在入场行进的单位（已注册） | 指挥官自己 |
| | 尚未生成的敌人（后续波次 / 后续入场） |

**叠加与净效果曲线**：`净效果(k) = k × X − Y`（k = 已施放次数），首版 X=10%、Y=25%、上限 5 层：

| k | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| 累计加攻 | 0% | +10% | +20% | +30% | +40% | +50% |
| 死亡减攻 | −25% | −25% | −25% | −25% | −25% | −25% |
| **净效果** | **−25%** | **−15%** | **−5%** | **+5%** | **+15%** | **+25%** |

**首版数值**：X=+10%、上限 5 层、Y=−25%（不叠加）、周期 4.0s、首次前置 2.5s、前摇 0.8s（举旗预警）。

**号令可被打断**：指挥官**没有霸体** → 任何直接伤害都能打断它的前摇。
打断来源：`BasicAttack` / `ActiveSkill` / `Ultimate` 打断；`Dot` / `Passive` / `Phantom` / `Item` / `Displacement` / `SpikeTrap` / `Collision` 不打断。
打断后：本次施放取消（不加攻、层数不涨）、回到 Idle、**下一次重置为完整周期 4.0s**。

### 7.2 它补的三层缺口

1. **优先级缺口**：现役 4 种"门"（1011 C技霸体 / 1021 盾卫 / 105 远程 / 109 冲锋）都是"打哪个都行"。
2. **敌方增益缺口**：场上所有增益都来自玩家侧，敌方没有任何"让局面变糟"的能力。
3. **"何时杀"的决策缺口**：把"先打谁"变成**时机成本**（号令层数）vs **时间成本**（去后排点它）。

**指挥官是"硬门"**：它活着 → 所在逻辑排永不清空 → 后排不前移 → 波次也无法结束 ⇒ 玩家必然要处理它。

### 7.3 临时形象方案（工程跑通用，正式形象见 §1–§5）

| 项 | 做法 |
|---|---|
| 形象 | 复用 `Enemy_104.prefab` 的 `BOSS_idle`（32×32）、`localScale=0.18`、`visualYOffset=1.035`（屏幕高度 5.76 单位 ≈ 1012 的 5.54） |
| 通用动作 | 复用 `Assets/Animations/Boss_104.controller`；建议复制为 `Animator_1013.controller` |
| 施法动作 | 复用放箭 QTE 三段：`QTE_TripleStab_Start`(0.50s) / `_Loop`(0.30s) / `_End`(0.30s)（`animator.Play(状态名)`，非 trigger） |
| 施法时序 | t=0 预警 0.3s → t=0.3 播 Start → **t=0.8 施放点**（施加加攻）播 Loop → t=1.1 播 End → t=1.4 回 Idle |

> **已核对**：这四个 clip 的 AnimationEvent 数均为 0 → 复用不会触发事件；箭矢由 `QTEController` 生成，1013 不挂它 → **不会放箭**。
> **两处已知缺口**：104 没有 `HitLeft` / `HitRight`（回落 HitFlash）、也没有 `Launched_Getup`（被挑飞后起身无动画，只报 Animator 警告）。

### 7.5 技术改动清单（M1–M9）

| # | 文件 | 改动 |
|---|---|---|
| M1 | `Enemy.cs`（Init 段） | 缓存 `_commander` 组件引用（与 `_cavalry` / `_shieldGuard` 同模式） |
| M2 | `Enemy.StateSwitch.cs` → `StartAttacking()` | 开头早退 `state = EnemyState.Idle; return;`（复用骑兵分支写法；**已核对**行军完成分支独立调用 `CompleteRushMoveOrder()` → 不会卡住补齐队列） |
| M3 | `EnemyManager.cs` → `OnEnemyAttackPlayer()` | 伤害 = `enemy.attackDamage × 出站攻击倍率`（近战唯一结算点） |
| M4 | `CavalryEnemy.cs` → `ChargeDamage` | 同乘出站倍率（**独立伤害源，不改则 109 完全不吃增益**） |
| M5 | `Enemy.Attack.cs` → `SpawnProjectile()` | 发射时快照一次出站倍率（与波次倍率快照口径一致） |
| M6 | `EnemyStatusRegistry.cs` | 新增状态 id 常量 |
| M7 | `EnemyHealthBar.cs` + `Enemy.Visuals.cs` + `EnemyOutline.OutlineFacts` | ① 血条第三根状态条（加攻）+ 层数文本；② 新增 `AtkBuffed` 描边事实位 |
| M8 | `Enemy.cs` + `Enemy.Combat.cs` | 新增 `OnDamagedWithSource`（带 `HitFeedbackSource`）→ 区分"谁能打断号令" |
| M9 | `EnemyCommander.cs` | 订阅 M8：前摇被打断 → 取消施放、重置完整周期、回 Idle |

**倍率存放（选 B）**：`EnemyStatusAtkMod : IStatusEffect` 挂在 `StatusHost`，自带层数，UI 走 `EnemyStatusRegistry` 查询；回池由**既有** `Enemy.Pool.cs:75` `_statusHost?.ClearAll()` 统一清理（无需新增清理代码）。
**公式**：`最终倍率 = (1 + 加攻层数 × X) × (1 − 减攻层数 × Y)`（减攻只有一层）。
⚠️ `Enemy.StatusHost` getter 每次访问会跑 `EnsureResidentStatusRegistered()`（只补登记"冻结"）→ 加攻 / 减攻必须**每次施放 / 结算时重新 Add**，不能指望被清空后自动回来。

**"在场"枚举写法**：

```csharp
var list = EnemyManager.Instance.GetAllAliveEnemies();   // ⚠️ 返回内部列表引用
for (int i = 0; i < list.Count; i++)
{
    var e = list[i];
    if (e == null || e == self || e.isBoss || e.state == EnemyState.Dead) continue;
    // 施加加攻
}
```

> **遍历期间不得修改该列表**；频率每 4s 一次、开销可忽略。
