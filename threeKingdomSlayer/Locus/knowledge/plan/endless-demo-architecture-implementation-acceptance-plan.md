### 步骤 A：记录并保护现场

1. 只读查看 Git 分支、HEAD、`git status --short`，必要时检查与本任务相关的既有 diff；明确哪些内容早已修改、哪些文件不得覆盖。不要 `reset`、`checkout`、`clean`、移动或删除已有内容。

3. 如状态与此前快照不同，以当前观察为准；不替用户恢复旧状态，也不假设 dirty 场景可以安全关闭。

### 步骤 B：只读核对关键引用与行为入口

围绕 P0 必要范围形成一份事实清单，至少包含：

| 范围 | 核对内容 |
|---|---|
| 成长与装备 | 当前角色槽位数、主动技能规则与默认发放设置、现有升级和装备数据的持有位置 |
| 奖励 | 经验、宝箱、候选池、波末选择的主要调用入口与 Inspector 引用 |
| 天赋与教学 | 当前天赋树引用、招式权限与教学读取入口；只记录依赖，不改节点 |
| 存档 | `SaveManager` 的存储 key、缓存、读写与迁移入口；与局内快照相关的字段 |
| 测试 | 测试包和现有测试的发现情况、可运行性前提；只记录已观察到的内容 |

资产与场景只读时区分 Editor 内存值和磁盘值；对无法确认的内容标记“未核实”。不为完成清单运行会写盘的菜单、驱动或测试。

### 步骤 C：确定安全测试隔离办法

1. 优先研究在**纯内存**中构造测试数据、序列化和反序列化的方法；这只能验证纯数据行为，不能代替真实存档读写或运行流程。
2. 如果某项以后必须验证真实读写或 Play Mode，先明确具体使用什么隔离环境，以及如何证明其不会访问或写入真实 `player_save` 和现有静态缓存。**仅复制一份工程目录或备份存档，不足以证明 PlayerPrefs 已隔离。**
3. 不修改正式 `SaveManager`、产品标识或项目设置来制造测试环境；也不在真实存档上执行 `SaveManager.Save`、`Delete`、清空或恢复操作。
4. 无法证明隔离安全时，把涉及写入的测试标为阻塞，说明需要何种独立环境或用户许可；不以冒险写入换取“验收通过”。
