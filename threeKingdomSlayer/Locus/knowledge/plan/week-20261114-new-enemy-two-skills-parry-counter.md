# 本周计划（2026-11-14）：新兵种 + 两个技能 + 防御后反击

> 任务来源：用户 2026-11-14 指令。
> 范围：① **新增 1 个兵种**（类型待定 ⇒ 见 §2 的候选与推荐）② **两个技能** ③ **优化防御后的反击**。
> 本文是**需求梳理 + 参考原型 + 方案 + 任务清单**；未经用户拍板不落地实现。
> 📌 **本轮已实施部分的交接与坑：`plan/session-handoff-20261114.md`（新对话先读那份）**；
> 架构欠账见 `plan/architecture-review-new-features-20261114.md`。

## 0. 一句话目标

**给战斗补三样东西**：① 一个新的敌人原型（补现有 6 原型的决策缺口）② 两个改变**目标选择**的技能（破盾 / 拉人）③ 把「防御 → 攻击」从"必须先松手收枪"改成**直接衔接**（纯代码、不依赖美术 ⇒ 最早能见效）。

## 1. 两个技能的参考原型（2026-11-14 联网核实，出处见括号）

### 1.1 技能1：抡斧劈砍 ← 影之刃零「**巨凶斧**」

| 原型事实 | 出处 |
|---|---|
| **破坏型**影之武装，评级 **A**；伤害 **309**、**破防能力 208**，卡牌标注「**高破盾能力**」 | 游民星空《影之刃零》全类型影之武装评级一览（2026-11） |
| 「破坏型影之武装是**击碎敌人护盾、破除防御**的关键」；**巨凶斧是前期最实用的破盾利器**；使用次数太少难堪大任 | 游侠网《影之刃零最强破坏型影之武装有哪些》（2026-11-04） |
| 三形态：强行蓄力 / 厚甲护身 / 疾行斧；铸魂后**蓄力速度 +30%** | 游民星空评级一览；`design/pbz-reference-analysis-20261109.md` §2 |
| 获取：**击败驿站 BOSS** 后获得（第一章前期唯一可获得的影之武装） | 游民星空《影之刃零前期破盾出血流配装说明》 |

**⇒ 我们的映射**：技能1 = 「从地上抡起一把大斧劈砍」
- **无视盾牌类减伤**（当前机制：`ShieldGuardEnemy.flatDamageReduction = 10`、`minDamage = 1`，正/盾侧格挡时固定减伤）⇒ 新增命中标记「**无视盾牌减伤**」。
- **高额破盾**（当前：盾牌有耐久与掉落 `shieldDropPrefab`，且 `heavyFromShieldSideBreaks = false`——按设计只有反侧重攻击破盾）⇒ 新增「**破盾值**」维度。
- **落地形态**：地面有一把斧 → 玩家走过去/触发 → 抡起 → 劈砍（**3D 模型后置**，先 2D 精灵或占位）。

### 1.2 技能2：追命锁链 ← 影之刃零「**猎人的追命锁镰**」

| 原型事实 | 出处 |
|---|---|
| **武学型**，评级 **B**；伤害 **247**、破防能力 213、**攻击范围覆盖中远距离**；铸魂后「**锁链的伤害与刀刃相同**」并造成流血 | 游民星空评级一览（2026-11） |
| 卡牌描述：「猎人的**追命锁镰**钩索可**勾住远处的锚点**」 | 同上 |
| 获取：**击败剧情 BOSS「追命」**（该 BOSS 的蓝光攻击需要格挡） | 游侠《影之刃零追命锁镰怎么获得》 |
| 另：巨凶斧「可击碎挡路的铁链」 | 游民星空评级一览 |

**⇒ 我们的映射**：技能2 = 「发射一个带铁链的镰刀」
- 原型的"钩索勾住远处锚点" ⇒ 改成 **把最远处、最弱的敌人拉到面前**。
- **设计意图不是伤害，是排序**：把躲在后排的脆皮/远程/阴兵**拽到前排**解决 ⇒ 直接打 §2 的缺口 **G4（目标优先级没有决策）/ G5（"一波打完了"不可信）**。
- ⚠ **与「追命」的关系**：本项目 PBZ 调研（`design/pbz-reference-analysis-20261109.md` §4.2）已把「**锁链型『追命』**」记为**敌人原型**（蓝光藏在连段中间）⇒ 技能2 天然是"反制那个 BOSS"的道具，可做联动。

## 3. 防御后的反击（本周最需要设计的部分）

### 3.1 现状（代码实测，非文档转述）

| 事实 | 位置 |
|---|---|
| 动作链：**招架 → 挥入（枪尖从下往上挑到 42°）→ 过冲/回弹/定格 → 防御位（角度同 42°、位置下沉 0.18）**；松手 → **收枪**（枪尖下沉到 -100° + 枪尾推出画面 → 出画才销毁） | `design/attack-interrupt-system.md` §4.7.1、`PlayerWeaponStance` |
| **防御态期间手势被吞、不能出招** | `AttackSystem.cs:424` → `if (playerState.IsDefendingActive) return false;` |
| 互斥口径（**2026-10-29 用户定**）：出招 ↔ 防御**互斥** | 同上 + `PlayerState.SetDefend` → `CanStartDefend()` |
| 武器底层准则：**任何武器动作必须入画/出画**，禁止原地出现/消失；**招式之间的交接必须在画面内连续、不得闪断** | `design/combo-move-state-machine.md` §19 |
| 姿态表达法：**不用手调欧拉角**，用「矛头指向 + 矛头落点」 | `design/attack-interrupt-system.md` §4.7.2 |
| 手势模型：点按 / 滑动 / 按住(蓄力门槛 0.3s)；**按下即出默认关闭** | `design/action-game-feel-and-input-buffering.md` |
| 缓冲机制已具备 | `PlayerMoveStateMachine.bufferLifetime 0.25` / `bufferCrossMove` / `hitCancelEnabled` |

### 3.2 目标（用户原话）

> 玩家防御时**若不在受击处理**，则可以**按点或滑动衔接 stab 和 slash**；
> 需要思考**长枪如何从防御态衔接到那两个抬手动作、如何旋转移动这杆长枪**，
> 以实现动作类游戏里**防御姿态直接转换为攻击**，而**不需要先完成防御收尾**。

### 3.3 设计方案（待拍板项用 ⚠ 标出）

**① 互斥规则改成单向**（⚠ 修改 2026-10-29 口径）
- 防御 → 攻击：**允许**（新）
- 攻击 → 防御：**仍禁止**（保留原口径）
- 落点：`AttackSystem.TryExecuteAttack` 的 `IsDefendingActive` 拦截改为「**仅当是防御态且要出招**时走新路径」，而非直接 `return false`。

**② 武器交接（核心，三选一）**

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| ★ **A：同一把枪连续运动** | 防御位的 3D 枪**不销毁**，直接插值到该招式的抬手姿态；命中帧由攻击的精灵帧/特效接管 | 无闪断、重量感连续、符合"武器是角色替身"的底层设定 | 需要在 §19 准则上开一个**有理由的例外**（同一把枪在画面内转向 ≠ 凭空出现）；攻击资产要支持"复用常驻枪" |
| **B：攻击视觉直接接管** | 防御位立即隐藏 3D 枪、同一帧切到攻击自带枪视觉 | 实现最省 | 交接点位置/角度必须严格对齐，否则闪断；读成"换了一把枪" |
| **C：转枪过渡** | 3D 枪播一段 0.12–0.18s 的"转枪"（防御位→抬手姿态），到位后交给攻击视觉 | 有过渡、风险低 | 多一段时长；且要保证转枪期间不出伤害 |

**③ 姿态插值（怎么"旋转移动这杆长枪"）**
- 防御位（枪尖 42°、位置下沉 0.18）→ 攻击抬手：
  - **枪突（stab）抬手**：枪尖指向目标列，杆身从斜举收到近水平（枪尾基本不动）——沿用「矛头指向 + 矛头落点」表达，不手调欧拉角。
  - **横斩（slash）抬手**：枪收到身侧/肩上（斜举位的反侧），准备横扫。
- 用现有 `MoveTo(..., absorbOffsets: true)`（把后坐/应变吸收进起点）⇒ 起点不跳变。
- 新参数落 `AttackSkillConfig`（真值写 `Zhangfei_Parry.asset`）+ `Tools ▸ 三国杀戮 ▸ 招架姿态调参` 滑条。

**④ 输入门：什么叫"不在受击处理"**
- 不在：破防硬直 / 格挡后摇（`parryWhiffDuration`）/ 受击硬直 / 动作锁中 / 输入门拦下 / 三选一弹窗。
- 处理方式：**不消费输入**（沿用现有缓冲：缓冲期内记下，等能出招的帧兑现）⇒ 与"按下即出"默认关的既有结论一致，不引入手势歧义。

**⑤ 攻击后的收尾**
- 攻击结束，若玩家**仍按住防御** ⇒ 直接接回防御位（反向复用现有"挥出途中按住→接住→回防御位"的规则）。
- ⚠ 需拍板：是否允许"边防御边输出"（破防值照常累积？）。

**⑥ 动作锁口径**
- 直接衔接时，攻击的动作锁**从转枪开始**计时（不是从收枪结束），否则会出现"两把枪同屏"的窗口（违反 §19 的交接连续性）。

> ### 4.2 ★ 机器人自测（2026-11-14）：改概率 → 机器人拿卡 → 战斗内验收
>
> 手法：① 运行时把两个新技能在 `ActiveSkillPoolConfig` 的权重临时拉高（rareWeight=1、common/legendary=0）→
> ② 运行时挂 `BattleAutoPlayer`（`autoStart` + `clickHubStartButton`，机器人**自己点「开始关卡」**）→
> ③ 三选一由机器人随机选卡 ⇒ **2.6 秒就拿到了「追命锁链」L1**（HUD 上能看到技能图标）→
> ④ 在真实战斗里触发技能 + `ScreenCapture` 截图（证据在 `Library/Locus/tmp/bot/`）。
>
> 过程中踩到并修掉的三个**实打实的 bug**（都是“看不见表现”的根因）：
> | 现象 | 根因 | 修法 |
> |---|---|---|
> | 链子完全不渲染 | `AddComponent` 会立刻触发 `Awake()` ⇒ **贴图还没赋值就初始化**（`_initialized=true`）⇒ 之后赋值无效 | `Awake` 不再初始化；改由 `Create()` 在赋值后触发 |
> | 链节小到看不见 | `Sprite.Create` 裁剪需要纹理 **Read/Write**，而 `chain.png` 没开 ⇒ **抛异常**、整条链的骨骼/渲染器全被跳过 | 不裁剪，直接用原图 + 放大（链环固定尺寸，不按节长拉伸，否则拉成黑杠） |
> | 锁镰/斧头被人群挡住 | 3D 模型在透视相机下靠**深度**排序，`sortingOrder` 压不过 2D 精灵 | 锁镰往相机方向挪 z；链身是 2D 精灵（sortingOrder 100）⇒ 稳压敌人 |
>
> ★ **另一个待用户确认的发现**：`ActiveSkillInventory.UsesActiveSkills` 在当前规则版本下是 **false**（V1 道具规则）
> ⇒ 机器人**拿得到技能但放不出来**（`TryActivate` 门禁）。若这不是预期的规则，需要把规则版本切到 V2_ActiveSkill。
>
> ⚠ **仍然偏弱**：链环偏小、链身偏短（读感像“几块碎片”而不是一条链）⇒ 要么继续调
> （`ChainLinkRig.linkScale / segmentLength / segmentCount`），要么等正式链节美术。
