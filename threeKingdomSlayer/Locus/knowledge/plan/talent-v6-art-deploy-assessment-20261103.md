## 3. 结论：**素材能进，但「拖进 Inspector 就生效」做不到**

美术的部署说明本身写得很准，我逐条对着代码核过，结论如下。

### 3.1 能直接接的（关掉两个程序化开关 + 拖引用即可）

| 槽位 | 图 | 备注 |
|---|---|---|
| `panelBackground` | A01 | 需 `useProceduralPanel = 0`；`Image.Type.Sliced`（代码里已经是） |
| `dimBackground` | A02 或现有白图 | 同受 `useProceduralPanel` 控制；A02 是全白不透明底，要靠 `Image.color` 染成半透明黑 |
| `nodeLocked/Available/Unlocked` | B01/B02/B03 | 需 `preferProceduralNodes = 0`；代码里是 Simple ✔ |
| `connector` | A09 | Simple，按长度缩放；线宽/接缝要在目标尺寸验 |
| `detailPlate` / `buttonNormal` / `dotOff` / `dotOn` / `coinIcon` | A05 / A06 / A07 / A08 / `panel_coin_icon` | 现有代码会给这些图**乘色**，深色新图可能过暗（文档已提醒） |

### 3.2 ⚠️ 三个硬阻塞（不解决就会「接了也不对」）

| # | 阻塞 | 事实 | 谁来解 |
|---|---|---|---|
| **1** | **A01 主底板会被非等比拉伸** | 面板是 `Stretch(…, 40)` → 目标 **1000×1840**；A01 只有 **512×512**。九宫格中间（460×460）被拉到 948×1788 → **横向 2.06×、纵向 3.89×**，而 26/25px 的边框保持 1:1 → **像素风中间会糊、纹理变形，且边框与中间的纹理比例对不上（有接缝）** | 建议：让美术按目标尺寸（或 2×）重出 A01；或 A01 只当边框装饰、底色仍用程序化 |
| **2** | **页签贴图字段存在但代码不读** | `TalentTreePanel.tabNormal/tabActive` 只有声明，`BuildTabs`/`RefreshTabs` 完全不引用 → 拖进去**不显示** | **对方**（`TalentTreePanel.cs` 是他那侧的文件） |
| **3** | **6 张新增候选没有槽位** | 标题牌 / 铜钱底板 / 旗饰 / 返回箭头 / 三色分支牌 / 选中角标：现有字段里没有对应 Image，且「分支标题牌」需要**分支视图**（现在只有 `treePosition` 平面布局，没有能显示分支牌的页面结构） | **对方**（要加字段 + 构建代码 + 分支视图） |

### 3.3 换图解决不了的（美术文档 §7 的 10 条，我核对后确认都成立）

跨页前置（分页算法与「方案 B：允许前置链跨页」冲突）、选中身份只记「分类＋页内序号」（多页会取错节点）、翻页不清空选中、横滑切分类沿用源分类页号、锁定节点现在不可交互（要拆成「可查看 / 可购买」）、连线只画同页直线、标签颜色重复赋值、图标解析优先级。

> 另外美术文档 §6.2 提到的「现有 `TalentCatalog_Main.asset` 三分类测试数据 5/3/6 各 1 页」——**属实**，它不是完整八分支内容，
> 所以「多页 / 跨页 / 购买」这些必须用临时测试数据单测，不能拿现有数据验。
