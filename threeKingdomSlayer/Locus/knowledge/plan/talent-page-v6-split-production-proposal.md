# 天赋页 V6 · 素材拆分与首批样品方案

> **状态：待用户审阅。** 本文是生产和接入提案，不代表素材清单、跨页提示或尺寸已获批准；本轮未切图、重绘、生图、修改代码或场景，也未进入 Play Mode。
>
> 视觉依据：`_art_process/Authoring/talent_ui/talent_page_ref_v6/talent_page_ref_v6.png`。接续入口：`plan/talent-page-next-session-handoff-20261103.md`。功能与原编号：`design/talent-page-art-brief-20261102.md`。本方案细化 `plan/talent-page-v6-modularization-plan-20261103.md`，不覆盖它。

## 1. 结论

**推荐先做 8 张基础样品，再决定是否生产其余素材：**

- A01 主面板外框 1 张。
- A03 / A04 分类页签常态、选中态 2 张。
- A05 详情卡外框 1 张。
- A06 购买按钮底板 1 张。
- B01 / B02 / B03 节点框三态 3 张。

它们是原清单中 14 个逐项标注 P0 的子集，**不是新增 P0，也不是将 P0 改成 8 项**。首批组合时，连线、页码点、分支标题、示意图标和文本先用临时程序化占位，只用来检查层级、比例和适配；不把占位当作正式美术交付。

样品经过静态组合审阅后，再考虑原 P0 的其余 6 张：A09 连线、D01–D03 招式图标、F01–F02 流派入口图标。是否以及何时开展下一批，仍待用户决定。

## 2. 为什么不能直接把整张图按矩形切开

V6 为 1024×1536、RGB 不透明概念图；背景、节点、连线、光晕和框互相遮挡。直接裁切会把背景一起带出来，且被遮住的边无法从原图还原。**应以原图确定外观，再将每个模块单独整理、补画或重绘；裁切只作为研究材料，不直接视为最终透明资产。**

原图是 2:3，目标设计画布是 1080×1920（9:16）。若原图等比放到 1080 宽，高只有 1620，还差 300 设计像素；若强行铺满则会拉变形或裁掉内容。因此必须重新排版，不把原图直接当最终整屏背景，也不把参考图上的裁切坐标当 Unity 最终坐标。

## 3. 组装后的视觉层级

```text
固定在屏幕上
├─ 遮罩：程序色及射线拦截，不一定需要图片
├─ A01 主面板：深色底 + 外轮廓、四角和可拉伸的边
├─ 顶栏：动态标题 / 返回 / 铜钱图标与数值
├─ 分类栏：A03/A04 共用页签底 + 动态分类文字
├─ 中部视口：固定边界与裁切，不是固定三列整图
├─ 当前分类页码：多页时显示，位置固定
└─ A05 详情卡：仅选中节点时显示
   ├─ 节点图标、名称、描述、前置、价格与状态：动态
   └─ A06 购买按钮底板 + 动态文字

中部视口内：随页一起滑动 / 裁切
└─ Page[分类, 页码]
   ├─ 可选的分支承托 + 分支标题 / 标识
   ├─ 根据真实前置关系生成的线和跨页提示
   └─ 节点：B 三态框 + 独立技能图标 + 名称 / 价格 + 独立选中提示
```

原图中的三列分支、马／水／火图形和路线仅是视觉示意，不能烘进 A01；真实分类有不同数量的分支，分支和节点会调整。顶部页签代表“基础数值 / 招式解锁 / 三选一解锁”，不等同于图中的火、水等分支图案。

### 节点组装示意

```text
一个节点
├─ B01 / B02 / B03：只负责节点外框及底
├─ 对应 D / E / F 技能图标：独立更换
├─ 名称、价格或“已解锁”：动态文字
└─ 选中提示：独立于锁定/可买/已解锁状态
```

**建议锁定节点仍显示技能图标**，以压暗、边框和状态文字表达锁定；若需要小锁，作为可独立控制的覆盖而非烘入 B01。选中提示建议先试与方形框协调的四角或方形描边，不继续默认使用当前的圆环；是否制作独立选中贴图，等样品组合后再定。

三态样品应一起设计和对齐，而不是分别从原图的金色、蓝色、红色节点截取：原图这些颜色主要表现不同分支，不能直接等同锁定／可买／已解锁。节点框中性不意味着整体画面必须灰色；分支色与状态色仍需在最终合成中共同验证。

## 7. 跨页提示：供讨论的具体建议，不是已确认交互

已确认的是：允许真实前置链跨页，并让玩家知道后面还有内容；**具体视觉方案未确认**。建议第一版不新增图片、不改变购买条件：

1. 右侧页码点提示当前分类还有其他页；必要时用简短文字提示可上下翻页。页码点只表示还有页面，不声称两页节点存在前置关系。
2. 只有真实前置边跨页时，才在对应节点附近以短线、箭头和文字提示，如源节点旁“续第 2 页”、目标节点旁“前置在第 1 页”。具体位置随真实布局避让，不能依赖被视口裁断的线。
3. 一对多或跨多个页时合并提示并显示数量/页码，选中节点的详情列出真实前置名称；不把多个节点合成一条看似不同的解锁关系。
4. 第一版建议提示**只用于说明，不作为跳页按钮**；是否需要点提示跳页由用户决定。锁定节点仍可查看详情，购买继续按完整前置、铜钱和有效载荷校验。

以上是便于评审的建议，未制作图，也未修改分页与购买逻辑。是否用页边提示、节点旁提示、详情提示及是否可点击，均待确认。

## 8. 尺寸、九宫格和透明：先解决的矛盾

需求文档既写“素材按 2× 出”，又给出 A01 512×512、A03/A04 320×96、A05 512×256、A06 256×96、B01–B03 256×256 等表格规格；这些值并不能无歧义地解释为当前所有控件实际尺寸的 2×。例如场景节点为 **132×132 设计单位**，严格 2× 是 264×264，而 B 表写 256×256。九宫格素材的源图大小又不等于最终铺满的控件大小。

**建议**：样品阶段先按原表规格制作或验证，记录实际设计尺寸、导出尺寸和九宫格边距；正式批量前由用户确认原表数值是否优先于严格 2×。不擅自把 B 组改为 264×264，也不把源图截图尺寸当导出尺寸。

- A01、A03/A04、A05、A06：预期按可拉伸件制作，九宫格边界应以最终清理后的实际图案检查；原表边距可作初始参考，不把它当未验证的最终边距。检查四角和边缘不能被拉变形、中心不能留下被放大的固定细节。
- B01–B03：现有节点使用 `Image.Type.Simple` 和保持比例；优先作为固定比例图验证。原表标了 B 组九宫格边距，是否真的使用须结合最终接入确认，不能因为表里有边距就强行九宫格。
- 技能图标：透明底、无文字数字，主体清晰；按原需求检查正方形画布与安全边距。面板和页签不强行套用正方形图标验收项。
- 所有图片检查透明边缘、残留背景、叠底后的黑白边；透明 PNG 的面板可以在内部是不透明底，但外部应按该部件轮廓透明。
- 在目标分辨率和较小预览下确认外观。当前代码将节点内图标设为节点宽高的 46%，132 设计单位节点内约 61 单位，若整体缩为一半约 30 像素；如辨识不足，应评估图标与文本排版，而非只增大源图分辨率。

## 9. 建议制作流程与验收

### 9.1 制作方法

1. **拆解参考**：只用 V6 自身研究轮廓、材质、颜色和遮挡；可制作不作为最终交付的局部参考。现有项目 UI、图标、角色、场景与特效只用于技术接线，不作画风、构图或配色参考。
2. **独立整理**：优先重建或补画空框与背景，明确透明区域；三态节点从同一底形衍生。不得将概念图整体裁片冒充透明成品。
3. **静态组合**：用 8 张样品和临时图形拼装一屏，并展示节点三态、长短文字及详情显示/隐藏；保留各层可调整，不把示意内容烘回素材。
4. **用户审阅后**：再决定是否调整样品、制作原清单其余部分，以及未编号候选是否立项。生图如被选用，调用前仍需完整中英文提示词、负面词、参考图职责、参数及用户明确批准；选择其他制作方式同样不意味着现在开始生产。

### 9.2 审阅重点

- 看单件：轮廓与 V6 是否同族；透明、边缘、金属细节是否干净；三态是否同形且易辨认。
- 看组合：外框、页签、节点和详情的比例与 V6 气质是否协调；无选中节点时详情隐藏；页面内容可变化，没有被烘死的三列。首批的分支牌和图标仍是占位，因此只能审查基础件与布局，不能据此宣称整套视觉已完成。
- 看适配：在 1080×1920 设计画布及较小预览尺寸下看文字、图标；九宫格四角不拉花，按钮文字可读。具体安全边距和移动端画面仍以最终布局测试为准。
- 看状态：锁定节点仍能表达是什么；已解锁、前置满足、选中与铜钱不足不互相混淆。
- 看工程可行性：所有动态文本、节点图标、连线和页面指示均是独立层；可在不改变原资产 GUID 的条件下接入。
