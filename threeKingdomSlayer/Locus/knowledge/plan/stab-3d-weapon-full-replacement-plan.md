## 推荐技术方向

Blender 负责骨骼、蒙皮和基础姿态；Unity 负责红缨实时次级运动。建议先实现轻量弹簧/Verlet 骨链，不优先给每节骨骼加 Rigidbody/Joint。

这把枪由程序化轨迹与 Tween 高频驱动，轻量骨链更容易约束高速挥动、瞬间生成、暂停、局部卡肉及销毁时的状态。模拟根据挂点平移和旋转自然产生惯性，包含重力、阻尼、段长与弯曲限制；必要时增加枪身的简单碰撞约束。参数和骨骼、材质引用应由 Inspector 显式配置。

红缨用软性骨链；枪杆与枪头保持刚性为主。枪杆需要的短暂弯曲、回弹、伸缩属于受控攻击表现，不应直接套用红缨柔软参数。

普通 Transform 骨链驱动不要求开启 Mesh Read/Write。只有确实需要 CPU 网格读取的方案才调整导入设置。

## 阶段 1：长枪骨骼与红缨动态原型

### 1A. 检查源模型与绑定

- 保护当前 Blender 未保存现场，确认实例身份后导入或恢复长枪。
- 核对枪尖、枪尾、红缨固定点、网格连通性、UV 和布片正反面；检查网格密度是否足以弯曲。不能在未看模型时固定骨骼数量。
- 定义武器根、枪尖/枪尾锚点、红缨挂点；刚性枪体与红缨权重明确分离，必要时留受控枪杆形变骨骼。
- 建红缨骨链、绑定权重，检查归一化、漏权重、根部固定和极端弯曲。
- 保存版本化 Blender 源文件，导出 FBX 并保留现有 Unity GUID/引用。
- 在 Unity 对照旧 Prefab 核实轴向、中心轴心、缩放、静止长度及 SkinnedMeshRenderer 包围盒，不依赖旧文档的坐标描述猜测朝向。

### 1B. Unity 实时红缨

- 先用现有 Stab 路径调通加速滞后、急停过冲、回收及左右转向。
- 模拟在武器主姿态更新后执行，明确与 LateUpdate、Tween 的顺序。
- 定义生成初始化、瞬移重置、暂停/慢动作、局部卡肉、退场和销毁规则；避免大时间步引起弹飞。
- 长度标定使用静止枪体或明确锚点，不能让甩开的红缨动态包围盒改变枪尖定位。
- 检查模型剔除包围盒，防止红缨甩出范围后消失。

验收：根部不脱离，静止能收敛，挥动后有自然滞后与回摆，无明显穿杆、无限抖动、停顿爆炸或出屏误剔除；枪尖定位不随红缨姿态漂移。

## 阶段 2：完整替换旧面片

先统一实际需要的武器视觉能力：基准姿态/尺寸、锚点、整体透明度、刚性部分与红缨引用、运动重置及必要的动态状态交接。避免发展成通用框架。

建议接入顺序：

1. Stab 基线：保留已有三连刺、蓄力和命中时序，接入带骨骼版本。
2. ChargeStabVisual：消除自动补 SpriteRenderer；修正缩放、测长和网格渐隐；处理蓄力保持到出枪的姿态与红缨连续性，避免重复可见武器。
3. Pierce：检查贯穿轴向旋转、既有视觉接管与进退场。
4. Slash / Sweep / Launch / Parry：逐项核对旋转轴、握持或旋转中心、路径、缩放与淡出；保留各招式语义，重写面片专用部分。
5. QTE：重建摄像机空间格挡尺寸与姿态；以真实三维运动替代换帧，支持渐隐与中断清理。
6. 回旋、折返、多路等升级分支与回退入口，补查试验场景及旧面片引用。

边界：保留伤害、命中、位移、招式触发和单把可见武器语义；旧资源保留用于追溯，完全替换不等于删除文件。

验收：所有预期路径使用 3D 武器，无旧面片重绘、尺寸突变、朝向错误、衔接闪现或残留；实际命中及卡肉也要验证，不能只看空挥。

## 阶段 3：速度表现、模糊与受控形变

- 优先试验局部、短寿命的方向残影/枪尖轨迹，按位移和角速度驱动，保持主体枪尖可读。
- 旧精灵 UV 多点采样不能简单移植到模型：UV 模糊无法可靠扩大三维轮廓，也不正确表达旋转路径。
- 残影先从刚性枪体或少量采样开始；若必须包含红缨，另行评估蒙皮快照成本，避免每帧无预算 BakeMesh。
- 在现有 Stab 形变上评估短时拉伸、枪杆轻弯和回弹，保持枪头体积及接触点；Slash/Sweep 的弧形速度感与 Stab 的直线速度感分别调节。
- 物理惯性与夸张形变分开采样/限幅，避免视觉拉伸造成红缨虚假爆发。
- 停顿、暂停、出场与对象复用时清空或重置历史采样，不留下拖尾。

验收：普通速度保持清晰，高速时方向明确；不变成多把实体枪，不遮挡目标或让视觉长度与命中时机明显错位。评估移动端绘制次数、透明叠加和 CPU 蒙皮成本。

## 阶段 4：贴图与 Shader 画风统一（最后优化）

功能阶段只先满足正确可见、透明度、深度/排序和红缨正反面要求；最终美术着色放在此阶段。

- 以 `design/art-style-guide.md` 的已验收 1011 Idle 与概念图为方向，在实际 Battle 摄像机、游戏尺寸和场景光照下对比。
- 区分色彩/纹理问题与光照问题：贴图控制冷钢、朱红、木杆、金绿件的大色块和材质分区；Shader 控制明暗层次、高光、法线细节强度与轮廓。
- 先尝试贴图简化与材质调整，再评估 BIRP 专用风格化 Shader；必要时两者配合。
- 不把统一画风等同于马赛克滤镜；也不预设单靠 Shader 可以修复造型或纹理结构。
- 复查阴影、透明排序、淡出、残影和皮肤蒙皮路径的兼容性。

验收：静止、挥动、蓄力、格挡在游戏内均与敌人和场景协调；金属与布料可辨，高光不过度写实，轮廓清楚且没有明显像素闪烁。最终观感由用户验收。

## 阶段 3 实施记录（一）：枪尖速度尾迹

用户选择先开始阶段 3。本条完成阶段 3 清单的第 1、2、5 项（方向残影/枪尖轨迹、不采样蒙皮、暂停/退出清理）。

实现：新增 `Assets/Scripts/Effects/MeshWeaponTrail.cs`，挂在 `Assets/Prefabs/FantasySpear3D.prefab` 上，`anchors` 指向 `WeaponTip`；材质 `Assets/Models/Weapons/FantasySpear/FantasySpear_Trail.mat`（`Sprites/Default`，靠顶点色 alpha，材质共享、不克隆）。因为组件在Prefab上，Stab/Slash/Pierce/Launch/Parry/QTE 自动全部生效。

关键设计：

- **只采样刚性锚点**：尾迹点只跟随 `WeaponTip` 这类刚性节点，**不读蒙皮、不 BakeMesh**，因此没有每帧网格拷贝成本；红缨不影响尾迹。
- **宽度用世界单位**：尾迹挂在自建 `MeshWeaponTrailHolder` 下，其 localScale 取性能抵消武器根缩放的倒数，使尾迹自身世界缩放为1，宽度不再受 Prefab 缩放影响。
- **速度驱动**：`intensity = InverseLerp(minSpeed, fullSpeed, 采样点世界速度)`；低于阈值不发射。
- **阈值来自实测**（`durationScale=1`）：Launch 枪尖峰值 147.5 / 均值 29.0，Stab 峰值 58.9 / 均值 12.1（单位/秒），故取 `minSpeed=12`、`fullSpeed=75`。
- **短寿命**：`trailSeconds=0.08`，头部宽为枪长的 4.5%（即 0.486 世界单位），尾部为头部的 8%。
- **不留残留**：`dt<=0`（暂停/卡肉）只停止发射不继续生长；`dt>0.1s` 视为卡顿，重置采样而不画出一条跨帧直线；`OnDisable`/`OnEnable` 清空。

验证（Play）：静止时 `emitting=false`、`positionCount=0`；Launch 1.13s 内发射79帧、峰值宽度0.486、最多13个采样点；Stab 1.20s 内发射62帧（只在快速刺出段）；动作结束后轨迹与 `MeshWeaponTrailHolder` 残留均为0；Console 0警告/错误；Battle dirty=false、根对象18。

未验证：**观感**（本会话无法看图）。尾迹只用单一枪尖采样，可能偏“细线”；如果读不出扫击弧线，下一步可加第二个沿杆采样点或改为加法混合（目前是普通 alpha 混合）。

## 阶段 3 实施记录（二）：方向闸门与街机加法表现

用户反馈：不够“街机爆发”；Slash 效果可以，但 **Stab 这种戳击在回收时看起来像拖尾**。

第一条（回收不发射）的关键认知：拖影不只是“还在发射”，更是“尾迹几何反向折返叠回”。仅停止发射不够，必须在反向时**丢弃已记录的点**。

改动：

- `MeshWeaponTrail` 新增 `retractSuppression`（默认 0.15）：当采样点速度与枪轴（枪尾→枪尖）的夹角大于约 99° 时，判定为回拉；此时停止发射**并 `Clear()` 丢弃带子**，避免折返。横扫是垂直于枪轴运动（沿轴比≈ 0），不受影响。
- 街机表现：新增 `Assets/Shaders/WeaponTrailAdditive.shader`（`Blend SrcAlpha One`，顶点色 × 共享 tint），新增横截面柔化贴图 `Assets/Models/Weapons/FantasySpear/Textures/FantasySpear_TrailSoft.png`（4×64 生成，中间亮、边缘柔），`FantasySpear_Trail.mat` 改用该 shader + 贴图 + 暖白 tint (1,0.96,0.88)；`headColor` alpha 降为 0.7，`tailColor` 为 0。原因：加法混合下纯色带会读成一块硬色块，带柔化横截面才能读成光刃。

实测时间线（Stab，单位/秒；沿轴比 = 速度与枪轴的点积归一化）：

| 时间 | 阶段 | 沿轴比 | 发射 | 点数 |
|---|---:|---|---:|
| 0.02–0.20 | 蓄势回拉 | -0.89 | False | 1–2 |
| 0.30–0.40 | **刺出** | **+0.98** | **True** | 10→21 |
| 0.50 | 回收开始 | -0.56 | False | 21→**2** |
| 0.60–1.10 | 回收 | -1.00 | False | **0** |

验证：Console 0警告/错误（自写 shader 编译正常）；材质 shader 与贴图接线回读正确；动作结束无残留；退出 Play 后 Battle dirty=false、根对象18、无临时对象。

待用户验收：加法亮度是否够“爆发”、以及 Launch 收势那一小段尾迹是否也需要消掉。

## 阶段 3 实施记录（三）：受控形变（拉伸与回弹）

先记一个硬约束：这杆枪的网格**没有枪杆骨**（只有刚性 `WeaponRoot` 与红缨骨链）。真正让枪杆**弯曲**只有两条路：回 Blender 给杆加 2~3 节骨并重新绑定，或写可弯曲的自定义 Shader（但对象是 `SkinnedMeshRenderer`，自定义 Shader 要自己接管 GPU 蒙皮，风险与工作量都大）。因此本轮先做**不需要重新绑定的那一半**：沿枪轴的短时拉伸与回弹。

实现（写在 `MeshSpearLaunchMotion` 里，因为 Launch 之前是纯刚体、没有任何形变）：

- 速度驱动：满速时枪杆沿轴拉长 `maxStretch = 0.10`；命中瞬间额外加入 `impactStretch = 0.06` 的拉伸冲量；两者经弹簧回弹（`stiffness 120` / `damping 16`），允许短暂压缩到 `1 - maxSquash = 0.97`。
- 驱动信号取枪尖速度（`stretchMinSpeed 15` / `stretchFullSpeed 60`）。阾值刻意高于“拉伸自身造成的回流速度”，避免自激。单帧超过 0.1s 视为卡顿、不注入速度。
- **保持手位与接触点**：缩放前记录枪尾世界位置，缩放后再测一次，反向补偿位移。因此枪尾始终钉在支点上，只有枪尖向前多伸。
- **与红缨隔离**：只改枪轴缩放，不驱动任何骨；红缨模拟每帧重算段长（已验证）因此能吸收缩放。
- **不与其他动作冲突**：实现在 Launch 专用控制器内。Stab 仍用 `_deformRoot` 它自己的缩放/滚转，Slash/Sweep 不动；没有在 Prefab 根上加通用缩放组件，因此不会与 Stab 的命中脉冲抢缩放。

验证（Play）：拉伸范围 **0.970 … 1.150**（正好落在设计的压缩下限与上限内）；**枪尾到支点误差 = 0**；枪长 10.80 → 12.42（= 10.8×1.15 一致）；红缨最大弯曲 **29.0°**（上限 38°，未出现虚假爆发）；支点无残留；Console 0警告/错误；Battle dirty=false、根对象18、无临时对象。

未验证：观感（本会话无法看图）。拉伸幅度是否明显、命中冲量是否正反馈，需用户判定。

**待决策（影响阶段 4 的材质计划）**：是否要做真正的“枪杆轻弯”。选项：
(a) 回 Blender 给杆加 2~3 节骨重新绑定（最自然，也最费工）；
(b) 写可弯曲 Shader，但需要自行处理 GPU 蒙皮（风险高）；
(c) 不做弯曲，只保留当前拉伸与回弹。

### 后续修正：弯曲在 Slash 中看不见，已定位并修正

用户反馈 Slash 左右挥击时武器完全没有形变。实测结论：

- 先排除了绑定问题：在 Unity 里手动把三节骨各转 20°，`BakeMesh` 显示 **2521 个顶点中 2086 个移动、最大位移 7.33**。绑定确实生效，但运行时只跑到 3.37°（上限 4.67°）。
- 瓶颈是驱动而非绑定：(a) 上限太小（整链 14°）；(b) 弹簧偏软，实测只掩到目标的 72%。Slash 时枪尖实测横向速度高达 338（对比 `fullLateralSpeed=45` 早已饱和），所以问题不在阀值。
- 修正：`maxTotalBendDegrees 14→30`、`fullLateralSpeed 45→30`、`stiffness 120→250`、`damping 16→22`。重测 Slash 单骨 **3.37° → 8.92°**（上限 10°），整链约 27°，枪尖相对轴线横向偏离约 3.3 世界单位。
- 本轮一个测量失误需记录：同时打印的 `maxMeshDisplacement=17.176` 不可信，因为基准点是“创建瞬间”的烘焙顶点，而武器本身在横扫中位移，所以它混入了整体移动。只有角度与静态 20° 手动弯曲那组数据可用。

另记一条绑定限制：`WeaponTasselDynamics` 的骨链是 `Tassel_00..05`（父节点已改为 `Shaft_02`），杆骨不在其控制范围内；杆弯曲与红缨模拟互不干扰，但红缨根会随 `Shaft_02` 一起被带动（这是希望的行为）。

### 后续修正二：权重太硬（“硬掰成三节”）

用户反馈：形变已可见，但偏硬，像把长枪硬生生掰成三节旋转，怀疑是绑定权重。判断正确。

根因（装配数据）：骨链跳变区间内，中间环（如 0.394）是 **100% Shaft_01**，只有关节环才是 50/50。于是每根骨覆盖的区间内杆身完全刚性，只在 2 个关节处折角 → 视觉就是三段直线。

修正（不改拓扑、不改层级，只改权重）：把“区间内 100% 单骨”改为**沿整条杆连续的高斯核混合**（核中心 S00=0.236 / S01=0.394 / S02=0.620，sigma=0.16），使每一环同时受 2~3 根骨影响；枪刃 z>0.763 仍**强制 100% 绑 Shaft_02** 以保住刚性。

修正后权重（关键环）：0.236=S00.725/S01.272、0.314=S00.494/S01.490、0.393=S00.251/S01.660/S02.089、0.472=S01.594/S02.320、0.551=S01.310/S02.673、枪刃=S02 1.0。权重和 0.9999–1.0（无异常顶点）；静止位移仍为 **0.0**。

弯曲平滑度证据：每骨均均 8° 时，相邻环段之间的折角为 **3.55° / 3.79° / 5.34°**（修正前是“区间内 0° + 关节处跳变”），即弯曲已摊成弧线。

产出：`StabWeaponArtSource/14_ShaftBendV02/FantasySpear_Rig_v03_smoothweights.blend` 与 `v03_rest_front.png` / `v03_bend24_front.png` / `v03_bend24_side.png`（前一份 3 骨刚硬权重版 FBX 已备份到 `Library/Locus/tmp/spear-shaft-v02/FantasySpear_Rigged_v02_3bone.fbx`）。
