## 3. 目标与不做事项

### 目标

1. 保持 06 的清晰、明亮和颜色稳定，让枪刃、红缨、木杆与装饰件分工明确。
2. 与敌人的硬朗边缘、块状折面、冷铁/朱红/暖棕关系协调，而非把武器整体压暗。
3. 随姿态变化仍有足够体积感，但不产生写实反射、全枪油亮或不断游走的宽高光。
4. 渐隐、幻影染色、蒙皮、骨弯、尾迹以及正常场景遮挡均维持原行为。
5. 以实际竖屏尺寸与连续动作验收；不靠像素统计或静态特写宣称完成。

### 本计划不改

- 模型造型、UV 布局、骨骼层级、权重、锚点和 1.35 倍尺寸。
- 普通 Launch 已验收的时长/姿态，C4 分流与原扫掠层，其他攻击的命中及伤害逻辑。
- 红缨回收模拟、枪杆弯曲方向/幅度；沿用用户暂缓边界。
- 已有尾迹 Shader/参数及三个试验场景旧枪迁移。
- 全项目色彩空间、场景光照、敌人材质或全屏后处理。
- 未授权的外部生成、付费请求、删除旧资源、Git 提交或推送。

## 4. 执行顺序与检查点

### A. 固定基线并保护现场

实施时重新读取 Git 状态、Prefab/材质/贴图引用及 Blender 实例身份，不用当前文档覆盖并行修改。

- 将 04/05/06 对照图、参数、来源和文件校验记录归档到 `StabWeaponArtSource/15_StyleUnlitV01/`；该目录已在后续实施中创建。
- 记录原贴图、正常/渐隐材质、Renderer 材质引用和 `fadeMaterial`，准备精确回退记录。
- 使用当前版本化 `.blend` 核对 UV 与材质区域；先备份 Blender 未保存现场。不修改模型或重导出 FBX。
- 准备相同相机/姿态的 A/B 捕获。03 等较早的静态预览不是优先验收证据。

**检查点 A：** 原始引用和现场可恢复，对照条件一致，没有夹带其他任务的场景保存。

### B. 先建立「生产可用的 06」

先不改 BaseColor。制作轻量 BIRP 保色 Shader 及正常/渐隐候选材质，使真实动作能获得 06 的外观。

- 初版直接使用贴图色彩；不启用实时镜面、环境反射、原 Normal 或额外分层光照。
- 支持 `_MainTex` 和 `_Color`；`_Color.rgb` 保留现有幻影/染色语义，`_Color.a` 支持现有渐隐控制。
- 不透明与渐隐材质使用同一套色彩逻辑，避免 alpha 开始降低时换色或明暗跳变。
- 沿用正常不透明深度与 Fade 透明深度行为作为初始配置，再检查精灵交错、红缨自遮挡和排序；不默认设置整枪永远置顶或全部关闭剔除。
- 使用 Unity 现有 SkinnedMeshRenderer 蒙皮路径；不实现自定义 GPU 蒙皮、不增加 BakeMesh 或逐帧材质实例。
- 新材质、贴图等均以 Inspector 显式引用接线，无 Resources.Load、字符串资产查找或隐藏运行时资源依赖。
- 候选优先放入独立目录；正式 `FantasySpear.mat` / `FantasySpear_Fade.mat` 及其 GUID 暂不覆盖。接线前明确候选 Prefab 与正式 Prefab 的影响范围。

候选目录已创建为 `Assets/Models/Weapons/FantasySpear/StyleCandidates/UnlitV01/`；Shader 为 `Assets/Shaders/WeaponColorUnlit.shader` 与 `Assets/Shaders/WeaponColorUnlitFade.shader`。

**检查点 B：** 同姿态 alpha=1 的候选与 06 保色表现一致；渐隐连续，幻影 alpha 不跳回 1，无粉色、漏材质或引用断裂。此时形成最小可回退版本，不把后续附加效果作为必做项。

### C. 在保色基线上局部修订贴图

使用现有 UV 和 1024 工作贴图。先导出 UV 线框/分区图，再按枪刃、装饰金件、木杆、红缨、绿色装饰建立可追溯选区；不直接生成一张与 UV 无关的新图集。

| 部位 | 保留 | 适度优化 |
|---|---|---|
| 枪刃 | 06 的银白亮面、冷灰暗面、中脊与刃口辨识 | 明确受光面与暗面，整理局部散碎反光，增强结构边缘；不把整刃变成暗铁 |
| 金件 | 华丽武器身份和暖金对比 | 收整连续亮条与碎小白点，增加稳定的中间色面；不统一改成脏旧、暗淡金属 |
| 木杆 | 暖红棕与沿杆方向 | 减轻贯穿式镜面亮带，以少量木纹、磨损与暗边表达材质；不加均匀噪声 |
| 红缨 | 06 的鲜明朱红和主要褶皱 | 合并过细渐变为清楚折面/色簇，收紧局部软边；不整体退饱和或硬压暗 |
| 绿色装饰 | 原造型身份、现有配色关系 | 控制细碎对比，让枪刃与红缨仍是主要焦点；不擅自删除或换色 |

- 先交付一版局部修订，不同时改造型、配色、光照和轮廓。
- 修订后的画法以体积与材质成立为目标，不对全图套马赛克或统一降低色数。
- 保留原图，另存候选 BaseColor。逐 UV 岛检查接缝、边缘填充和 mipmap 串色。
- Point/Bilinear、压缩和 mipmap 作为单独 A/B 变量：先在候选上测试，不全局照搬精灵导入参数。默认不关闭 mipmap，避免远处及高速旋转时闪烁；最终选择以实际动作证据为准。

**检查点 C：** 纯保色着色下，候选与 06 并排比较；材质区分更清楚、油亮和碎反光减少，同时保留用户选择的鲜明效果。用户确认后再进入可选附加着色。

### D. 只在确有缺口时增加 Shader 功能

这些是候选对照，不是默认全部实施：

1. **弱光照调制**：仅当某些角度体积难以辨认时加入，强度从 0 开始；保留暗部亮度底限。先试大体积调制，不回到 Standard PBR，也不再强叠第二套贴图阴影。
2. **材质限定高光**：仅在枪刃确实失去金属感时添加窄、低强度高光。使用区域遮罩区分钢、金件、木、布；木与布无镜面。初版纯保色无需额外遮罩贴图。
3. **薄深灰轮廓**：仅在天空/亮地面前轮廓不足时试验，保持可关闭；不默认粗黑描边或全屏轮廓处理。
4. **红缨反面**：先检查现有网格双面几何和实际漏面。只有确定存在可见缺口才处理，不无条件整枪 Cull Off。

**检查点 D：** 每次只新增一项，与「关闭该项」同姿态比较。没有明确收益就删除候选增强，保留纯保色版本；最终以用户对照选择为准。

### E. 动作兼容、正式接线与交付

美术候选确认后，沿现有 Renderer 与 `MeshWeaponVisual.fadeMaterial` 的显式引用接入正式武器。所有场景/Prefab 写入通过 Unity API，保留 GUID；修改前回读，落盘后在独立调用中复核。

只改画风有关引用与必要的 Shader 兼容，不借此重写动作或清理其他任务文件。用户验收前不把技术能播放写成最终美术通过。

| 范围 | 需要检查 | 通过标准 |

| 普通 Launch 与 C4 | 动作分流、近景、枪头红缨叠加 | 两种动作保持原行为；新材质不改变尺寸/轨迹 |

- 先用固定姿态对照定位贴图/着色差异，再跑连续动作，避免把模拟差异误认为画风变化。

- 移动端未实际运行时明确标记未验证，不能凭 Editor 画面宣称帧率/观感一致。
- 此矩阵是画风与视觉管线兼容回归；不替代尚未完成的实际手势、伤害、Boss QTE 成功判定等战斗验收。
- Play 验证完成后退出，核对场景 dirty、临时武器/支点/材质清理及 Git 差异；不保存测试现场。

### 渐隐修正与代价

直接采用透明单Pass时出现模型金件内层面显露，导致切换材质时明暗跳变；增加渐隐专用最近表面深度Pass后修正。正常1Pass、渐隐/幻影2Pass，不增加CPU蒙皮或逐帧材质实例。alpha=0丢弃深度，实际像素与无武器完全一致；0.9995→0.9985切换平均通道差约0.000279/255，没有大块内部面跳变。

限制：透明深度不能表示部分透明；在武器之后绘制、且位于其后方的透明特效/多幻影仍需实战交错验收。当前敌人排序0/1、武器2、尾迹3的基本路径已观察，不宣称任意透明排序都通过。

## 11. 历史方案：整杆纹理残影（已被第12节方向线路线取代）

状态：以下为此前围绕「动态模糊」提出的历史方案，未实施。用户随后澄清更倾向漫画方向线来描述挥动方向，当前推荐以第12节为准，不启动蒙皮快照/BakeMesh残影制作。V02主材质已验收，继续作为当前实体外观。

### 推荐方向

历史推荐曾以「保留V02纹理的整件武器短残影」为主体；用户澄清目标后不再采用此优先路线。下列取舍与参数保留作讨论记录，不是当前实施要求。

三条路线比较：

| 路线 | 能提供的效果 | 局限与建议 |
|---|---|---|
| 骨链驱动的连续扫掠面 | 廉价的整杆方向感，可沿杆颜色分区；不必BakeMesh | 主要仍是光带，不能单独重现实体纹理/红缨轮廓；作为后续街机增强 |
| 少量纹理蒙皮快照 | 覆盖整件武器，保留V02颜色、杆弯和当时的红缨姿态 | 有CPU蒙皮、透明叠加与多把枪读感风险；推荐先做有上限的原型 |
| 武器专用颜色/速度缓冲的屏幕空间模糊 | 更连续的轮廓模糊，可按像素运动方向处理 | BIRP需额外捕获/合成与深度遮挡处理，移动端带宽、边缘与近裁面更复杂；在原型明确不足后再评估 |

### 原型规模（调试起点，不是定稿参数或性能承诺）

- 单把主武器最多2–3层历史轮廓；寿命约35–60ms；发力高速段以16–25ms为目标采样间隔，每渲染帧最多一次真实蒙皮采样，不追帧补Bake。
- 单层alpha约0.08–0.16，累计权重约0.25–0.35内；沿时间快速衰减，合并速度与主武器alpha控制。保留原色，避免整杆强加法洗白。
- 用屏幕相对位移/角变化评估是否可见：将前后世界采样点投影到同一当前相机以排除纯镜头移动。枪刃离轴采样点须包含在内，才能识别Pierce纯轴向自转；只读枪尖/中心线会漏检。
- 历史轮廓间距上限以屏幕短边约3%–6%为初调范围，超出时丢弃过老样本，避免低帧率拉出整屏长影。低帧率若明显断层，应单独评估视觉姿态插值，不能靠增加真实时间滞留或单帧多次Bake伪造连续历史。
- 预分配并复用Mesh/数组/残影对象、共享材质；残影只带渲染数据，不复制整个Prefab、动态组件或Collider，不再次生成尾迹。主武器/幻影并发需全局可配预算；这是运行时实例预算，不是隐藏资产缓存。
- 当前模型2521顶点、1631三角面、13骨：3层几何上限为4893个额外三角面/主武器，若单Pass则最多3次额外绘制。CPU BakeMesh与竖屏透明覆盖成本仍需实测，不能据面数认定移动端廉价。

### 采样与渲染约束

- 每次采样读取该帧最终蒙皮姿态，显式安排在枪杆弯曲、Launch拉伸与 `WeaponTasselDynamics`（执行序1000）之后；当前固定局部TrailSample机制不适合作为整杆形变采样。
- BakeMesh使用明确的坐标/缩放语义，记录采样时Renderer到世界矩阵，实例交接或重挂父节点后仍保持原世界姿态；核对100倍模型子层与11.05倍武器缩放只应用一次。
- 新残影材质使用保色、透明、ZTest和不写场景深度的专用路径；不直接复用现有 `WeaponColorUnlitFade` 的深度预写，否则可能挡住其他残影/透明特效。内部重叠面显露仍须检查；若低alpha不能满足质量，再比较独立表面捕获合成的成本。
- 本体保持最清楚，历史轮廓位于运动后方。强度跟随各部位实际位移，而不是按枪尾到枪尖固定线性增强；握持/支点端通常弱，远端通常强，但Slash/Parry等动作支点不同。
- 仅红缨自然摆动不能触发整把枪强残影；用枪体运动作为主要开关，红缨随同一次姿态快照记录。

### 按动作开放

1. 左右Slash：首个验证目标，高速发力段开启；慢蓄势、末尾回摆及退场关闭。先对比当前枪尖尾迹、仅整杆残影、两者合用。
2. 普通Launch：在已验收的预转/蓄势后，于上挑发力段开启；顶点短停和缓沉收势立即收束。C4使用原动作的独立时间线，不复用普通Launch窗口。
3. Stab：仅刺出允许较弱且沿轴的短历史，回收清空；朝景深运动需考虑投影缩放，不能强制生成横向扇面。
4. Pierce：释放与飞行使用独立倍率，轴向自转由离轴轮廓采样识别；不得变成一串同等清晰的长枪。
5. Parry/QTE：快速抬枪/旋转可弱开启，判定保持段清楚；蓄力跟随默认关闭，以免手指移动就拖一屏武器。
6. 既有构筑幻影与C4扫掠层：倍率与主武器alpha相乘，限制再生残影数量，防止两层幻影产生多重残影链。

### 暂停与验收

`StabSweepEffect` / `SweepEffect` / `AttackWave` 的卡肉暂停Tween和红缨，使用 `WaitForSecondsRealtime`，不会保证 `Time.timeScale=0`；新效果必须显式接收局部暂停/恢复信号，暂停停止采样并快速收束旧影，恢复重置速度历史。全局暂停、反向回收、瞬移、重挂/实例交接、退场/销毁分别定义清理，不跨招式连成错误长线。

历史原型验收重点：正常速度连续播放读成一次整杆快速挥动，而非多把实体枪；停下后轮廓迅速清楚；枪尖、目标、UI和红缨仍可辨；30/60/120fps与实际命中卡肉时无拖影爆发。当前没有执行这些测试或制作残影原型。

## 12. 最新方向：漫画挥动方向线，而非武器残影

用户澄清：「但其实不是残影而是类似漫画里的方向线会更符合当前的画风设计？描述武器的挥动方向」。本节为当前推荐；仅完成思路修订，没有新增效果或改动运行状态。全局画风规范仍以 `design/art-style-guide.md` 为准，本节不修改Design文档。

### 视觉目标

主体长枪保持V02的清楚材质与剪影，以少量硬边、尖尾、断续的速度线描绘整杆的运动方向。覆盖整杆的含义是枪刃和可见枪杆分段都有运动提示，不是用发光实体或一整片扇面包住武器。

- 枪头附近2–3条较长的主方向线，可见枪杆中段另有2–3条短辅线；这是构图起点，最终数量根据画面密度调整。靠近支点通常更弱，以实际局部速度为准。
- 线条放在轮廓附近和运动后方，前端贴近当前移动部位，后端变细并尖收；不画箭头符号。颜色先试米白/浅金主线、极窄深暖灰边，避免在黄土地上失去对比；少量朱红作为外侧辅线候选。
- 边缘清楚、宽窄有节奏、局部断开，尽量避免大面积柔光、连续长飘带和均匀平行的激光线。金白只在高速主线前部少量加亮。
- 弧度由真实挥动路径产生，不给所有动作套同一种圆弧；沿杆不同部位有不同速度和路径，不能把所有线条都按枪轴方向拉长。
- 红缨保持自然运动，不为每个布褶生成线；必要时只加一笔顺势辅线，枪体运动决定整体开关。蓄力时红缨自身轻摆不触发效果。

### 各动作的方向语言

| 动作 | 线条走向与分布 |
|---|---|
| 左右Slash | 顺横向/斜向扫过路径的几组短弧线，靠枪头较长、杆中段较短；反向挥击时方向随实际运动翻转 |
| 普通Launch | 上挑发力时自下向上、略带弧度；蓄势预转和顶部停顿避免抢主发力的方向信息 |
| C4 | 根据原C4实际扫掠生成自己的弧线，不套普通Launch窗口和弧度 |
| Stab | 沿刺入纵深产生短直线和收束关系；透视投影允许长短/位置变化，不生成横向扇面；回收清空 |
| Pierce | 直线飞行用轴向方向提示，自转可在枪头周围加少量短弧；两种运动分开表达 |
| Parry/QTE | 快速抬枪、转枪阶段沿实际旋转出现短弧，判定保持段保持清楚 |

### 推荐实现

- 使用骨骼/显式锚点上的5–7处局部采样位置及短时间历史，覆盖枪头、杆身、支点附近；弯曲后读取实际骨骼姿态。采样点、线条材质/纹理与参数均从Inspector可追踪。
- 先在左右Slash原型中以约40–70ms历史生成几组窄曲线带，合并为一个复用的动态Mesh；用顶点宽度/透明度与尖尾纹理组织笔触。历史时长是调试起点，不是已验收参数。
- 方向依据采样点局部运动，不仅看根Transform，也不简单把枪轴作为挥动方向；检测剔除纯镜头移动，避免镜头震动生成伪线条。
- 主体采用普通透明混合、ZTest与ZWrite Off，必要时在极少主线前部增加加法强调。先保留场景遮挡，不让线条永远置顶；不复用武器渐隐的深度预写Shader。
- 不复制完整武器、不读取整件蒙皮顶点、不调用BakeMesh、不做全屏模糊；相较历史残影路线降低CPU蒙皮与多层武器覆盖负担，但透明排序/覆盖成本仍需实测。
- 稳定记录笔触身份和间距，避免每帧随机重新布局导致闪烁；以时间/距离约束采样和历史长度，低帧率不直接连成巨长光线。
- 明确动作发力窗口与局部卡肉信号，暂停/反向/瞬移/交接/退场清理历史。既有幻影降低倍率或禁用，防止特效倍增。

### 第一原型与验收

先左右Slash比较「当前枪尖光迹」「只有漫画方向线」「方向线+减弱枪尖光迹」。不预设两层全开一定最好；如果原枪尖光带抢方向，收弱或替换。

通过标准：正常速度下清楚看懂向左/向右挥动，枪杆与枪头属于同一次发力；线条随动作产生和消失，不像常驻飘带、激光或多把枪；停顿/回收不拖线，敌人和UI仍清楚。原型成立后再按动作分别适配Launch/C4、Stab/Pierce和格挡。
