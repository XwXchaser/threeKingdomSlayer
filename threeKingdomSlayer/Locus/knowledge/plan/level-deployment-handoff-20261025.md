## 1. 目标循环（用户 2026-10-25 定）

> 「让玩家能在 15min 内完成教学+第一关的重复游玩升级解锁，用合理的难度墙堵住玩家，
> 也让有一定操作水平的玩家可以提前通关。」

拆成三件事：

| 目标 | 落地形态 |
| --- | --- |
| 一次循环 ≤ 15 分钟 | 教学关 ~3min + 第一关 ~9~12min = 12~15min |
| 重复游玩 → 升级解锁 | 每轮结算给**局外铜钱** → 天赋树买**永久升级** → 下一轮更强 |
| 难度墙 | 第一关的 **Boss 波（104）** 血量定标：新手打不动、熟练玩家一轮过 |

### 1.1 难度墙的具体数字（为什么它成立）

Boss 波 104 血量 = `基础 500 × bossHealthMultiplier 11.5 ≈ 5750`（Excel「波次明细」页）。

| 玩家水平 | 到 Boss 波时的等级 / 预期 DPS | 打 5750 血需要 | 玩家能撑多久 | 结果 |
| --- | --- | --- | --- | --- |
| 新手（几乎不平A） | Lv12~18 / 45~57 DPS | 100~128s | 100 血 + 3 次复活 ≈ 30~40s（Boss 每 5s 一下 7 伤） | **过不去** → 墙成立 |
| 熟练玩家（会用蓄力重击/范围技/会躲） | Lv28 / 86 DPS | 67s | 只挨 9 下 ≈ 63 伤 | **一轮过** → 提前通关 |

所以墙是**数值墙**不是硬锁：跨过去的办法是「练操作 + 用天赋树的局外升级」，不是刷数值。

### 1.2 墙的旋钮（要调难度就拧这四个）

1. `bossHealthMultiplier`（Boss 波 104 的血量倍率；N2 7.5 / N3 11.5）
2. 每波 `healthMultiplier`（Excel「波次明细」页的建议 hp×，已按「DPS × 目标清场秒 ÷ 基础总HP」反推）
3. 经验曲线 `ExpCurve_30min`（实测 Lv1→2 = 200、之后每级 +4）
4. 复活次数（`HeroConfig.reviveCount` = 3）——直接决定新手能在 Boss 上试几次

### 1.3 还没闭合的一个缺口（必须你拍板）

按当前敌人经验值（1011 = 80/只），本关只能给到 **Lv28（约 28 次三选一）**，
设计目标（数值草案 §0.1）是 **Lv40 / 42 次**，差 **61%**。
三个补法在 Excel「玩家成长」页：**A 加波次**（推荐，每波仍 3~4 只、节奏约 50s 一波）、
**B 提敌人经验值**（但会三选一刷屏）、**C 启用 `StageConfig.killMilestones`**（现在全空）按里程碑补三选一。

## 2. 工具链：跑关 + 埋点 + 分析

### 2.1 跑关机器人

`Assets/Scripts/Utils/BattleAutoPlayer.cs`（挂在场景任意对象 → Play 即自动开打，或按 `P` 键）。

- 打法：只平A点最近目标（机械下限）；**遇盾兵(1021)自动改用上挑**（盾正面出手全被格挡）。
- 也会**点 UI**：升级三选一（`UpgradeChoiceManager.ConfirmChoice`）与路线选择（`RouteChoiceButton` 的 onClick）
  —— 不点的话游戏会暂停在原地（机器人会卡死，玩家也一样）。
- `useHeavyAttacks = true` 时混入蓄力重击（Sweep/Launch），用来对比不同操作水平的耗时。

### 2.2 埋点

`Assets/Scripts/Utils/LevelTelemetry.cs` → `Library/Locus/telemetry/run-*.jsonl`（机器本地，不入库）。
事件：`battle_begin` / `wave_begin` / `wave_end` / `battle_end`，字段含
波次序号、敌人构成（1011x2 这种）、该波用时、剩余敌人、玩家掉血、等级、已获升级数、死亡次数、铜钱。
波次边界接 `WaveSpawner.OnWaveStarted`（不要用存活数推断，会把一波切成好几段）。

### 2.3 分析

```bash
python Tools/analyze_level_telemetry.py                 # 摘要 + 对照目标（普通波 30~55s / Boss 波 45~90s）
python Tools/analyze_level_telemetry.py --csv out.csv   # 导出逐波明细
```

用途：**机器人给机械下限**（操作水平最低时的耗时），**真人试玩给上限**（同格式埋点）。
两者夹住设计目标 → 判定 hp× 偏高还是偏低。

### 2.4 已验证的用法（2026-10-25）

挂上机器人 → 落地页「开始关卡」→ 机器人自动清波、选三选一、推进节点。
实测：N1 首战 20s 清完 2 波、升到 Lv2、玩家掉 2 血；机器人把三选一和路线选择都点了（否则卡死）。

### 3.3 配对规则（写进关卡部署的硬规则）

- **盾兵掩护弓兵**：1021 在 row0 吃正面伤害，105 在 row2 输出（N2 第 4 波 / N3 第 5 波）。
- **骑兵做高潮**：每节点 109 ≤ 2 只，与 1011 混编。
- **弓兵只做后排**：105 的 row ≥ 该波排数/2（铁律十）。
- **Boss 必须在该波最后一排**（铁律九）。
- **不做大量对怪**：单波 3~5 只，压力靠机制与站位，不靠数量。
