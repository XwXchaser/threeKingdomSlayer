      - **开局免费发 3 次三选一**（起步 build）⇒ `UpgradeChoiceManager.GrantChoices(n)`（新公开 API）。
      - **控制器已放进 Battle.scene**（对象名 `EndlessRunController`）⇒ 所有数值参数在 Inspector 里可实时调。
      - 实测（机器人）：HP 全程 100、节点 1→2→3→4 正常推进、圈循环边可用。
- [x] **B6.14** **无限模式独占路线流程**（2026-11-16 实测“卡在节点不动”）
      - 现象：卡在第一个节点不动，调查发现**剧情路线也在跑**（落地页被点过「开始关卡」），
        两套流程争同一个 `RouteChoicePanel` ⇒ 路线弹面板时把无限模式的出口面板**销毁**了。
      - 修法：`FakeRouteRuntime.SuspendForEndless()` —— 停掉路线自身协程 + 封禁它弹面板/进节点；
        `PlayPostBattleSequence` 在挂起时**不隐藏面板**（那个面板是无限模式自己的）。
- [ ] **B6.12** ⚠ **圈结算必须给三选一**（2026-11-16 实测出的硬缺口）：
      实测 `ExpCurve_30min` 只有 **30 级**、合计 88,650 经验；而每圈约 **15,400 经验**（267+ 只敌人）⇒
      **每圈约 10 次经验三选一、整条经验线 3 圈用完** ⇒ **第 4 圈起玩家拿不到任何卡**。
      ⇒ 圈结算面板需要**固定给 N 次三选一**（建议 10 次，与经验段同量级），否则第 4 圈起玩家无 build 可加、只能挨打。
      详见 `design/in-run-build-design.md` §4.2.1。

**验收口径**：同一 seed 两次生成的波次序列完全一致；连跑 5 圈不卡死；死亡后重进从第 1 圈开始、最佳分保留。

### 7.1 无限模式怎么玩（用户验收路径）

1. 落地页 → 底部「选关」tab → **第一格「无尽关」**；
2. 自动开跑（每圈 = N1×k → E0 → J1 → 分支 → 回 N1；分支由种子自动选左/右）；
3. 每波清空 → 波结算飘字（+分）；每圈结束 → **圈结算面板**（本圈得分 / 当前总分 / 历史最佳 + 「继续」「退出」）；
4. 死亡 → 结束，**最佳分与最高圈数**写存档。

### 7.2 这一轮踩到并修掉的四个真 bug（都是"看着像数值问题、实际是规则/时序问题"）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 第 2 波卡死，敌人永远停在 1 排 | 生成器会产出「第 0 排为空」的波次；行前移只在"某排被打空"时触发 → 双方互相够不到 | 生成器加 `EnsureFrontRowOccupied()` + 校验项（**规则十一**）；删怪逻辑不再删第 0 排 |
| 2 | 无限模式跑到一半被正式关配置顶掉 | 剧情路线在落地页自举时也会进入战斗；两套流程并行，`StageController.stageConfig` 被抢 | `FakeRouteRuntime` 加**持久挂起标记** + `Begin`/`RunPrepared`/`EnterNode` 三处硬闸；无限模式启动时 `AbortRouteBattle()` |
| 3 | 玩家阵亡但无限模式不结束 | 阵亡时 `PlayerState` 先把自身置为 Defeat 再抛事件 → `StageRunFlow.OnPlayerDefeated` 的状态检查提前 return → `StageController.OnStageDefeat` 根本不广播 | 无限模式直接订 `PlayerState.OnPlayerDied`（路线模式靠 `FakeRouteRuntime.HandleStageDefeat` 兜底，无限模式不走路线运行时） |
| 4 | HUD 中文全是 □ | `TMP_Settings.defaultFontAsset` 是 LiberationSans（拉丁字体），中文无字形 | 新增 `UiFontUtility`：从场景里已在显示中文的 TMP 组件取字体（运行时安全、零新增引用） |

> 另外修掉三个 UI 排版问题（结算面板按钮顺序、详情文字跑出屏幕、节点序号出现 "5/4"），
> 以及一个事件顺序问题（`_waitingPlayerChoice` 必须在广播前置位，否则 HUD 会把刚弹出的面板又收起来）。
>
> **本轮（长关卡）又修掉两个真 bug**：
> ① **圈边界判错**：用“当前节点是起点”判一圈完成 → 循环边（N1→N1）会把圈立刻结算掉 ⇒ 改成“**走完回程边**才算一圈”；
> ② **内容源切换没生效**：一批编辑整体回滚导致运行时仍在走程序生成 ⇒ 补回「照抄手写配置」分支（并加了活体验证）。

**已修的一个真 bug**：`EndlessRandom.Range` 原来用 `NextUInt() % span`（取低位）——
xorshift32 的低位周期极短（bit0 周期 = 2），导致**每一排的敌人总落在同样几列、整波偏向一侧**。
已改为高位取模 `>> 16`。这类问题在"看起来只是排版不均匀"时很容易被当成数值问题放过，值得记一笔。

## 10. 工作纪律提醒（沿用项目规矩）

- 每批**只做一批**，不混批；每批做完**必须实测**再进下一批；
- 资产改动走 Unity API（`SerializedObject` + `AssetDatabase.SaveAssetIfDirty`），**不要**用文件工具改序列化资产；
- 改完 `.cs` 用 `unity_recompile`（本轮改动涉及 partial 类型字段布局变化，热重载不支持）；
- **不覆盖用户未提交的改动**（当前工作区有 1014 美术线与若干脚本的未提交修改）；
- 数值改动一律**先配一版跑起来**，再慢慢标定（用户口径）。
