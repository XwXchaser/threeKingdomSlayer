# Stab 三连击：参考视频驱动的素材与出招实现工作流

## 0. 目的与边界

本流程用于制作一段张飞 Stab 三连击参考视频，并以视频作为后续素材设计、动作时序和 Unity 接入的共同依据。

视频不是最终游戏动画，也不是直接可部署的透明 Sprite。它的作用是回答：

1. Jab1、Jab2、Jab3 各自应该怎样起手、刺出、穿入、回收；
2. 三段如何体现普通攻击串的段位递进、接续和终结；
3. 新素材需要哪些基础姿态、高速姿态和枪尖锚点；
4. 当前 `StabSweepEffect`、动作锁、接续窗口和 `attackWavePrefab` 能否实现视频中的手感；
5. 若不能，最小的代码、Prefab 或数据部署改动是什么。

本流程不允许在视频内容未讨论和用户确认前创建收费视频任务，也不允许先修改正式 Unity 资产。

## 0.1 认知更新（重要，优先于下文所有“素材”措辞）

关键图 / 参考视频的用途是**回答“这杆枪该怎么挥”**，属于动作参考；**不是**要导入游戏的美术素材。

- 招式动作全部由程序驱动同一杆枪：位移、绕轴旋转、沿长度/宽度形变、换帧、运动模糊强度、拖尾、淡出。
- 因此**几乎没有需要替换的素材**。枪的身份图只有 `stab.png` 一张；唯一可能的例外是“枪身高速拉伸”这类**形变帧**（已验收的 `stab_v13.png` 就是这种），是否需要更多形变帧由动作设计决定。
- 三段（以及后续招式）的区分不靠换图，靠**怎么驱动这杆枪**：轨迹（直线/弧线）、旋转相位、形变幅度、节奏（预备—加速—命中—惯性—复位）。
- 因此下文 §4 的“方案 A / B（每段一个 Prefab 并替换 Sprite）”仅在确认确实需要新形变帧时才适用；默认方向是 §4 的“方案 C：动作系统扩展”（先把这杆枪做成常驻、再动作参数化）。
- §5 的 Sprite 导入规则只在真的要新增形变帧时才用，不要拿它约束参考图。参考图允许带背景、辅助线与标注，不需要透明底、PPU 或 Pivot 对齐。

## 2. 当前系统基线

当前三段已经是三个独立 `AttackSkillConfig` 节点：

| 段 | actionDuration | stabVisualReachOffset | damage | 后继 |
|---|---:|---:|---:|---|
| Jab1 | 0.45s | 2.0 | 20 | Tap → Jab2 |
| Jab2 | 0.40s | 2.6 | 26 | Tap → Jab3 |
| Jab3 | 0.60s | 3.2 | 34 | 无，收招结束 |

三段当前接续窗口均为 `0.65–0.95`。当前 Stab 视觉序列为：

- 起手后撤：12%
- 刺出：28%
- 穿入：8%
- 回收：52%

当前三段仍指向同一个 `Assets/Prefabs/Stab.prefab`，并共享 `stab_v13.png` 高速帧。因此视频阶段必须同时区分：

- **动作设计差异**：速度、前伸、收招和接续节奏；
- **素材差异**：基础姿态、高速延展姿态、枪尖锚点；
- **运行时差异**：Prefab/Sprite 替换、动作取消、视觉重叠和命中时序。

禁止把三者混为“换三张图片即可”。

## 3. 工作阶段

### 阶段 A：建立视频目标，不生成

先输出一页动作分镜供用户讨论，至少包含：

- 镜头方向、画布比例、背景和目标物；
- Jab1 / Jab2 / Jab3 的动作描述；
- 三段相对时长和接续点；
- 每段枪体的延伸幅度、速度面和枪尖可读性；
- 命中卡顿、回收和第三段终结感；
- 是否展示角色、敌人、命中特效，或只展示武器轨迹。

推荐先采用“武器/角色局部动作参考”而非完整战斗电影镜头。镜头应固定，避免镜头运动、特效、敌群和背景叙事干扰动作判断。

### 阶段 B：准备参考素材

根据阶段 A 的决定准备上传副本，不覆盖正式资产：

- 身份参考：`stab.png`
- 速度参考：`stab_v13.png`
- 如需要完整出招姿态，再准备张飞当前战斗姿态或录制的游戏画面作为动作空间参考
- 所有参考图必须明确职责：身份、速度形变、动作空间不能混写

视频提示词必须明确：

- 这是游戏攻击动作参考，不是电影镜头；
- 同一把银灰枪尖、红穗、绿饰、红棕枪身贯穿三段；
- 枪尖保持可辨识；
- 高速面是武器本体形变，不是爆炸、光束或独立 VFX；
- 固定相机、固定画布和固定视觉锚点；
- 不要把普通三连击夸张成必杀技；
- 不要让模型一次生成多个独立概念帧并把它们当作最终 Sprite。

### 阶段 C：收费生成前确认

在创建 ReachAPI 任务前，必须向用户复述并确认：

- 模型：默认 `seedance-2-fast`
- 时长：由动作分镜决定，建议先 4–6 秒
- 分辨率和比例
- 是否生成音频：默认关闭
- 使用的参考图及其职责
- 输出路径
- 本次是生成动作参考视频，不是直接部署素材

未获得本次生成确认时，只能继续讨论分镜和提示词，不能调用创建接口。

### 阶段 D：创建、轮询、下载和技术校验

严格执行 `reachapi-seedance-video-generation-v2.md`：

1. 参考图逐张上传；只从环境变量读取 Key。
2. 使用新版 `input.content`，不得使用旧字段。
3. 保存 task id、提示词、参数和参考图路径；不保存 Key 或临时签名 URL。
4. 首次立即查询，之后间隔 5–10 秒；最多 12 次，总等待约 120 秒。
5. 成功后使用 `.part` 下载；保留断点和分段进度。
6. 校验 MP4 文件大小、`ftyp`、顶层 box 边界和可解码性。
7. 技术成功、视频已下载和动作美术验收分别报告。

下载失败不得自动重新创建收费任务；应优先使用同一 task 查询新 URL并续传。

### 阶段 E：视频动作验收

先看整段正常速度，再看慢放和抽帧。验收分为四层：

#### 1. 连招语义

- Jab1 是起手，不像终结技；
- Jab2 是承接，不像重新独立起招；
- Jab3 是最强的一击，并有明确收束；
- 三段仍属于普通攻击，不出现大招级别的全屏光束或爆炸。

#### 2. 武器身份

- 三段读起来是同一把枪；
- 枪尖始终可识别；
- 红穗、绿饰是局部速度结构，不铺成树枝或旗帜；
- 高速面围绕长枪身核心，不变成三角形、圣诞树或泛化光束。

#### 3. 运动连续性

- 起手、刺出、穿入、回收存在连续过渡；
- 第二段接入时不出现硬切、瞬移或整把枪重置；
- 第三段后有可读收招；
- 枪尖轨迹与攻击方向一致；
- 没有镜头推拉、跟随、旋转、抖动或重新构图掩盖问题。

#### 4. Unity 可实现性

逐帧记录：

- 每段起始姿态；
- 高速形变开始和结束；
- 枪尖位置；
- 武器有效长度和视觉前伸；
- 第二、三段接续时上一段是否已经消失；
- 命中和视觉冲击发生的相对时间。

视频中任何无法由当前系统表达的效果都必须标记为“视频目标，不是当前实现”。

## 4. 从视频反推素材方案

视频验收后，再决定以下方案之一：

### 方案 A：每段一个 Prefab，最小改动

- Jab1 继续使用 `Stab.prefab`；
- Jab2 / Jab3 各复制一个 Prefab；
- 每个 Prefab 只替换其基础 Sprite；
- 三段继续共享 `stab_v13.png` 高速帧。

适用于视频主要依靠基础姿态、视觉前伸和当前程序形变区分的情况。

### 方案 B：每段独立基础帧与高速帧

如果视频验收显示 Jab2、Jab3 的核心差异发生在刺出中段，而不是起始姿态，则需要评估把高速帧从 `AttackSystem` 的共享字段移到每招配置，并由 `StabSweepEffect` 按招式使用。

这是代码改动，必须单独确认，不得在素材任务中默认实施。

### 方案 C：动作系统扩展

如果视频要求真正的无缝取消、上一段视觉清理、逐段独立速度曲线或段间特殊命中时序，需先列出最小代码改动清单，再决定是否实现。不得为了复现视频直接修改伤害、冷却、接续窗口或攻击范围。

## 5. Sprite 制作与导入规则

正式素材必须满足：

- 透明 RGBA PNG；
- Point 过滤；
- 无 Mipmap；
- 无压缩；
- RGBA32；
- 枪尖视觉锚点一致；
- 画布尺寸可以不同，但通过透明留白、PPU 和 Pivot 对齐；
- 不按每帧独立包围框裁剪、居中或缩放；
- 不在运行时用 `sprite.bounds` 推算位移或缩放；
- 不修改 `Stab.prefab` 本体；
- 不复用 `stab_rotate1/2.png` 作为普通直刺素材。

视频不能直接证明 Alpha 正确。若从视频抽取或去背，必须单独检查透明通道、白边、半透明污染和枪身内部像素。

## 6. Unity 部署顺序

仅在视频目标和正式素材获得用户确认后执行：

1. 创建 Jab2 / Jab3 专用 Sprite 或 Prefab 副本；
2. 保留原 Prefab 的组件、碰撞体和 Transform 结构；
3. 只替换对应 `SpriteRenderer.sprite`；
4. 修改 `Jab2` / `Jab3` 的 `attackWavePrefab` 引用；
5. 不修改 `MoveTable_Zhangfei`；
6. 不修改伤害、时长、冷却、攻击范围、接续窗口和 `moveEdges`；
7. 重新读取三份招式资产，确认引用正确；
8. 在真正战斗节点 Play Mode 验证三连击；路由转场期间输入关闭，不能在那里验收。

## 7. 实机验收

至少验证：

- 点击触发 Jab1；
- 在第一段接续窗口内点击触发 Jab2；
- 在第二段接续窗口内点击触发 Jab3；
- 三段视觉不同且仍是同一把枪；
- 第二段没有提前到起手段；
- 第三段没有继续循环；
- 命中卡肉不会让窗口和动作视觉错位；
- 空挥、命中、多个目标和不同列位置都不出现枪尖跳位；
- 退出 Play Mode 后正式资产没有被运行时测试污染。

最终验收要分开记录：

1. 视频动作设计通过；
2. 视频文件技术校验通过；
3. Sprite 美术通过；
4. Unity 引用部署通过；
5. 实机手感通过。

任何一项未完成，都不能笼统报告为“三连击完成”。

## 8. 禁止事项

- 未确认收费规格前创建视频任务；
- 将参考视频直接当作透明 Sprite 或最终动画；
- 用视频成功或 MP4 校验通过代替动作验收；
- 先改代码或正式资产再根据视频找方向；
- 把三连击做成三次完全相同的 Stab；
- 把普通攻击做成全屏必杀技；
- 用生成模型对已验收高速帧做不可控的局部重绘并声称像素同源；
- 用矩形切片、错位、重叠制造枪身长度；
- 用运行时 bounds 补偿不同素材位置；
- 在没有单独授权的情况下修改 Stab 代码、动作时长、伤害、冷却或接续窗口。

## 9. 当前下一步

先讨论并确认“参考视频要表达的动作内容”，重点确定：

- 是否显示完整张飞和敌人，还是只显示武器/攻击轨迹；
- 三段的镜头时长和慢放方式；
- Jab1、Jab2、Jab3 的姿态差异；
- 第二段是否要求上一段视觉未完全回收就接入；
- 第三段是否需要明显命中停顿与收招硬直；
- 视频目标是偏真实游戏内效果，还是偏清晰的素材设计板。

这些内容确认后，才进入提示词、参考图准备和收费生成确认。
