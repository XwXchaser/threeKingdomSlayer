# Y 场景校验工具化方案（2026-10-24）

> 起因：表化 N1 路旁布景那天 ✅，**「逐件差异 0」骗了我一次** ❗ —— 逐件比对不查渲染器 enabled ✅，
> 又因为 `Object.DestroyImmediate(transform)` 只毁组件不毁物体 ✅，手摆组没删掉 ✅ → 场景里两份布景 ❗ → 画面多出一堆东西 ❗。
> 结论：**"画面没变"必须有一条独立于结构比对的硬口径** ✅。
>
> 上游：§五 自检规则 ✅（`plan/y-scene-rebuild-plan-20261023.md` ✅）里的规则 7 ✅ 需要细化 ✅；
> 背景与坑：§八 §九（`plan/scene-pipeline-handoff-20261023.md` ✅）。

**明确不做** ✅：不碰美术 ✅、不碰战斗 ✅、不改任何既有资产的内容 ✅（只加**检查** ✅）、不重构生成器 ✅。

## 二、改动清单（4 刀 ✅，按依赖顺序 ✅）

- **不查 color** ✅：表里没有颜色字段 ✅ → 查了也永远对不上 ❗ → 会变成新的噪音 ❗。
- 报错文案带路径 ✅ + 两边取值 ✅（和现有风格一致 ✅）。

> 为什么现在才有依据可查 ✅：摆放表直到 `6eee2a1` ✅ 才带 `rendererDisabled` ✅ —— 之前比对器无从判断 ✅。

### 2.2 刀二：自检降噪 —— 规则 7 只报**真叠放**（30 分钟 ✅）—— ✅ **已做（`44a2fd1` ✅）**

**原计划的判据是错的 ❗，已按实测改掉** ✅：

1. ~~给每条算世界足迹 ✅、判 AABB 重叠~~ ❗ → **实测不行** ✅：精灵的可见范围含大片透明 ✅
   （路牌那张 `bounds = 10.24 × 10.24` ✅）→ AABB 一判就和旁边所有东西"重叠" ✅ → 全量跑出 **52 条** ❗ 还是噪音 ❗。
2. **改用脚点距离** ✅（同组同父级 ✅ → 局部坐标可比 ✅）：
   - **< 0.1m** ✅ → 报「同层真叠放」✅（**真问题** ✅ —— 两件占同一格 ❗）。
   - **< 0.5m** ✅ → 进**可选清单** ✅（`Validate(spec, out clusterDetails)` ✅ / 菜单 ③ 只报数量 ✅）——
     实测这类共 **25~31 对** ✅，逐条看全是**故意**的叠放 ✅（路牌脚下的石头 ✅ / 墙脚的草 ✅ / 树边的灌木 ✅）。
3. 其余规则**一律不动** ✅：层级越界 ✅（组基准 + 最大 sortBias > 世界基准 ✅）、精灵/网格/材质引用为空 ✅ 照旧 ✅。

**实测依据** ✅：同 sortBias 的对子共 **18104 对** ✅，中位脚点距离 **26.4m** ✅；
脚点 < 0.1m 的 **0 对** ✅、< 0.2m 的 4 对 ✅、< 0.5m 的 25 对 ✅ —— 没有意外叠放 ✅。

**执行结果** ✅：全量自检 **56 条 → 0 条** ✅（21 个规格 ✅ 0 个有问题 ✅）｜可选清单 31 对 ✅
**反向用例** ✅：脚点几乎重合 → 报 ✅｜挤在一簇但不重合 → 不报 ✅（进清单 ✅）｜离得远 → 不报 ✅｜几乎重合但不同 sortBias → 不报 ✅。

> 结论值得记一笔 ✅：**这条规则在本项目里本来就没有信号** ✅ —— 同层叠放是**故意的** ✅（2.5D + Z 深度排序 ✅）→
> 计划文档 §五 规则 7 的**意图**（避免同 z 互相穿插 ✅）实际上被规则 6（层级越界 ✅）覆盖了 ✅。

### 2.3 刀三：三方漂移检查（表 ↔ 规格 ↔ 段 prefab）（1 小时 ✅）—— ✅ **已做（`9000593` ✅）**

新方法 `RunChainCheck(tablePath, specPath, prefabPath, out report)` ✅ + 菜单
`Tools/Y 场景规格/⑧ 全链路校验（表→规格→段 prefab 三方对齐 ✅）` ✅。

流程 ✅：
1. **表 → 规格**：用 `YScenePlacementImporter.Import` 把表导成 **specA** ✅（**临时新资产 ✅** —— `Import` 走 `GenerateUniqueAssetPath` ✅，**绝不能覆盖盘上的规格** ❗）。
2. **规格 A ↔ 规格 B**：盘上的规格 specB ✅ 与 specA 各生成一棵树 ✅ → `CompareTrees` ✅ → 差异数 = 表与规格是否同步 ✅。
3. **规格 → prefab**：specB 生成的树 vs 盘上的段 prefab ✅ → 差异数 = 规格与 prefab 是否同步 ✅。
4. 输出两行 ✅ + 结论 ✅。
5. **跑完删掉临时资产** ✅（否则 `Assets/RouteData/YSceneSpecs/` 会积灰 ✅ —— 实测 21 个规格 ✅ 无残留 ✅）。

> 为什么要有 ✅：`YSceneSpec` 加过字段 ✅（`rendererDisabled` ✅）→ 老规格反序列化**不报错、只静默变空** ✅（已知坑 ✅）→
> 没有这层检查，某天规格悄悄空了 ✅ 没人会发现 ❗。

**执行结果** ✅：正向 ✅ —— J1 中央路牌 ✅ / N1 路旁布景 ✅ / 左石板路 ✅ 三段「表→规格 0 ✅｜规格→prefab 0 ✅」
反向 ✅ —— 故意改坏一份表副本 ✅（挪 1.5m ✅）→ 表→规格 **2 条差异** ✅ 被抓到 ✅，规格→prefab 仍 0 ✅ ✅。

### 2.4 刀四：画面逐像素比对（1~1.5 小时 ✅）—— ✅ **已做（`9000593` ✅）**

新方法 `RunPixelCheck(GameObject source, tablePath, specPath, prefabPath, out report)` ✅ + 菜单
`Tools/Y 场景规格/⑨ 画面逐像素比对（现状 vs 由规格重建 ✅）` ✅。

流程 ✅：
1. 渲**现状** ✅：把现状**克隆**一份 ✅（不动用户的对象 ✅）→ 挪进临时场景 ✅ → 挪到检查层 ✅ → 渲 A ✅。
2. 由规格生成一份 ✅ → 渲 B ✅ → 关掉临时场景 ✅。
3. **C# 里逐像素比** ✅（`Texture2D.GetPixels32()` ✅）：输出「完全相同 ✅ / 差异像素数 ✅ / >4 级差异像素数 ✅」。
   - **不放 Python** ✅：编辑器工具不能依赖外部 Python ✅。
4. **机位自动定** ✅：按现状的**世界包围盒** ✅ → 眼高 1.7m ✅、FOV 60 ✅、aspect 0.5 ✅、俯角 10° ✅（沿用今天渲 N1 的那套 ✅）→ 两张图同机位 ✅。
5. **只渲检查层** ✅（layer 2 ✅）→ 当前场景的其它内容不会混进来 ✅。

**执行结果** ✅：正向 ✅ —— 同三段 → **完全不同的像素 0 / 1,573,538** ✅（与今天手工比的结果一致 ✅）
反向 ✅ —— 把一个物件挪 1.5m ✅ → **19,616 像素差异** ✅（最大通道差 252 ✅）被抓到 ✅；临时规格已删 ✅；原规格再跑仍 0 ✅ ✅。

**过程中修掉的两个坑** ✅（都是我自己写错 ✅，记下来别再踩 ✅）：
1. 渲 B 时**克隆还活着** ✅ → B 图叠着两份布景 ❗ → 比对必然有差异 ❌。**渲完 A 立刻销毁克隆** ✅。
2. Unity **不允许**在「有未保存的空场景已加载 ✅」时加性建场景 ✅（抛 "Cannot create a new scene additively with an untitled scene unsaved" ✅）
   → 工具改成**前置检查 + 明确报错** ✅（不抛异常 ✅）。

> 口径 ✅：**完全相同 = 差异 0 ✅** —— 今天实测 N1 表化前后就是 **0 / 1,573,538** ✅ → 说明这条口径可达 ✅；
> `>4 级` 单独列出来 ✅（容忍抗锯齿抖动 ✅）—— 超过 4 级的像素要逐个看 ✅。
