## 1. 最终规则（用户口径）

### 1.1 打断矩阵（`Enemy.Combat.cs`）

| 攻击者 | 前摇 | 出伤窗口 | 收招 |
|---|---|---|---|
| 轻攻击 | 打断（普通窗口；霸体期无效） | 打断 | 不可 |
| **重攻击**（`isHeavy`） | 打断（霸体期也能）→ 专职"拆前摇" | 打断 | 不可 |
| **招架** | **不断** | **格开**（取消攻击 → 出伤不结算）→ 专职"格出伤" | 不可 |

- **出伤窗口**：出伤瞬间前 `Enemy.parryStrikeWindow`（默认 **0.15s**）。出伤时刻 = 本次攻击前摇结束时刻（已按命中帧修正；远程=发射瞬间）。
  实现用攻击 tween 的已播比例换算（卡肉/冻结暂停时判定不错位）。
- **只有招架能在出伤窗口格开**；招架在前摇打不断。
- **削韧跟判定成功**：只有真的格开了一次才磨架势（旧行为是"对范围内每个敌人无条件磨"，已废除）。`Zhangfei_Parry.poiseDamage` = **30**（原 10）。
- 破防值满 → 破势眩晕 → 眩晕期间不可打断（`isAttackDrawPhase` 语义），破势把敌人打出 Stunned。
- 招架的"弹刀反馈"（`PlayClankEffect`）**至今未实现**（设计文档写了、代码里从来没有）——仍是缺口。

### 1.2 防御姿态（`PlayerGuard` + `PlayerWeaponStance`）

- 入口：**招架后按住**；预输入只是"提前按住"，**本质仍先播完 parry 再回防御位**（"挥入中一按住就切防御位"是 BUG，已修：挥入阶段只记住按住）。
- 防御期间**免伤**，只累积破防值；破防值**每帧固定速率回落**（真衰减条，无"停手 N 秒才开始降"）→ 阈值/速率 = 自然窗口（默认 120 / 30 每秒 ≈ 4 秒）。
- 破防值满 → 破防：`GameplayInputGate` 申请 `GuardBroken` → 不能行动 / 不能放技能 / 不能做手势输入，持续 `parryGuardBreakDuration`（1.5s）。
- 防御态期间**不允许出招**（手势被吞）；想攻击必须先松手收枪（与旧版"parry 时不能攻击"一致）。
- 破防条显示：`HeroHUD_Zhangfei.prefab` 的 `Health(Slider)` 上方新增 `GuardMeter`（Filled/Horizontal，复用 `zhangfei_HP_filler`）+ `HeroHUD.SetGuardMeter(ratio, visible)` + `BattleHUD` 每帧轮询。

### 1.3 武器动作准则（`combo-move-state-machine.md` §19，本轮立规）

- **除非特殊要求，武器必须"进入画面 / 离开画面"**：进入从屏外挥入，离开要挥出画面后才销毁；**不允许在画面里原地出现或原地消失**；招式交接点必须画面内连续。
- 理由：本作没有可见人物与手，武器是"手里有东西在动"的唯一证据；原地生灭会读成"凭空"。

## 2. 招架动作的最终参数（`Assets/Prefabs/UI/Skills/Zhangfei_Parry.asset`）

| 字段 | 值 | 含义 |
|---|---|---|
| `parryStanceTipDegrees` | 42 | 斜举角（= 防御位角度，防御位只用位置差） |
| `parryStanceHeadAnchor` | (2.121, 3.222, −2.5) | **矛头**落点 → 屏幕「右 104% / 上 62%」（枪尖滑出右上边缘） |
| `parryStanceEntryAngleDegrees` | 8 | 起手指向 |
| `parryStanceEntryRootOffset` | (−1.386, −2.769, 0) | 起手时枪尾（=手）沿枪轴**回退 2.2** + 落低 1.3 |
| `parryStanceExitAngleDegrees` | −100 | 收枪指向 |
| `parryStanceExitRootOffset` | (−1.2, −1.5, 0) | 收枪时枪尾推出画面 |
| `parryStanceSwingInSeconds` | 0.18 | 挥入 |
| `parryStanceOvershootDegrees` | 8 | 过冲 |
| `parryStanceSettleSeconds` | 0.08 | 回弹 |
| `parryStanceHoldSeconds` | 0.10 | 定格（格住的那一下） |
| `parryStanceExitFastSeconds` / `ExitNormalSeconds` | 0.12 / 0.54 | 收枪（**成功格挡加速 / 未格挡正常**，沿用旧版招架规则） |
| `parryStanceDefendAnchorDrop` | 0.18 | 防御位比斜举位低多少（**只用位置差** → 枪尖上扬角每次读得一样） |
| `parryStanceTasselDamping` / `MaxBend` | 26 / 14 | 持枪实例级红缨物理收敛（枪头附近抖动变小） |
| `actionDuration` / `parryWhiffDuration` | 0.48 / 0.9 | 动作锁必须覆盖"武器在画面上的全长"，否则玩家能在枪还没出画时出招（两把枪） |
| `poiseDamage` | 30 | 招架削韧（只在格开成功时） |

**动作链**：招架 → 挥入（枪尖从下往上挑，**整杆沿枪轴被推出**）→ 过冲 → 回弹 → 定格 → （按住）接防御位 → （松手）收枪**整杆出画后**销毁。

## 5. 本轮踩过的坑（别再踩）

1. **scale 不是可调项**：武器大小是**武器的属性**，slash/stab 一致 → 持枪必须用 prefab 原尺寸（`parryStanceScale` 已删）。slash/stab 的枪巨大是因为它**从镜头前扫过**（一次性特效、离相机 4.5 单位），持枪不能类比。
2. **整杆枪在任何前景深度都必然出画**：相机 aspect 0.5、可见半宽 `0.2887·(z+10)`，枪长 10.8 → 构图只能靠解算"矛头在哪、杆身从哪穿出"，不能靠截图目测。
3. **纯旋转会读成"绕一个点甩"**：手的位移在画面外 → 观众只看枪尖的净路径。第一人称双手持矛的正解是**手提 + 顺枪轴推出**（枪尖净位移近似直线，旋转只留 34°）。
4. **收枪必须整杆出画后再销毁**（准则），否则就是"原地消失"。
5. **一批多编辑里只要有一条"新旧内容相同"，整批不应用**（工具只提示那一条）→ 每次改完必须回读文件确认（曾因此漏掉 `_entryRoot`，表现成"武器凭空出现"）。
6. **资产值只在重进 Play Mode 时重读** → 改完必须退出 Play 再进，否则看到旧值。
7. 截图有秒级延迟，抓不到 0.18s 的动画中间帧 → 验收靠**慢速 + 数值采样**（手动 `Tick` 打印枪尖/枪尾轨迹）。

## 8. 实测：为什么"把矛头推出右上角"并没有露出杆身（2026-10-26 分析）

用户反馈：改动后（`8551efa`）实机仍"看到一大截枪尖、看不到枪身"。用真实相机把 prefab 网格逐顶点投影后测出根因。

### 8.1 实测几何（相机 Main Camera (0,3,-10) euler 18°、fov 60、aspect 0.5、1080×2160；玩家 (0,0,0)）

- 枪 = `FantasySpear3D`，根 scale 11.05，`weaponTip→weaponTail` = **10.8**；沿枪轴分段（mesh z，0=枪尾）：
  **木质杆身 z<5.0（约 5.4 长、0.4 粗）｜红缨 z 5.0–8.3（约 3.3 长、2.2 宽）｜金矛头 z≥8.3（约 2.5 长）**
- 当前资产：斜举角 42°、矛头锚点 (2.121, 3.222, −2.5) → 根节点（=枪身中点）落在 **(−1.892, −0.391, −2.5)**。
- 矛头深度处离相机 7.17 → 画面**可见半宽只有 2.07、半高 4.14（世界单位）**；而枪长 10.8、斜举 42° 时枪身中点已在 x=−1.89 ≈ **左边缘（ndc x=−0.91）**。
  → **后半身（枪尾那 5.4 单位）必然在画面外**，画面里能装下的只有"头部那一半"。

### 8.2 逐顶点覆盖实测（2521 顶点 × 真相机投影）

| 姿态 | 金矛头在屏 | 红缨在屏 | 木杆身在屏 | 杆身占可见武器 |
|---|---|---|---|---|
| 斜举位(IDLE) | 97.5%（ndc x 0.15–0.82, y 0.07–0.41） | 97.7% | **5.3%（30/561 顶点，全挤在左缘 ndc x −0.99~−0.91）** | 1.5% |
| 防御位 | 97.5% | 98.3% | 5.9% | 1.7% |
| 起手位(ENTRY 8°) | **100%** | 84.5% | **0%** | 0% |

**结论：招架动作的每一帧，屏幕上都是"矛头 + 红缨"，木杆身最多只在左边缘露一丝。**
用户截图（screenshot-20261026-035214）正是这个构图：金色矛头 + 大红缨 + 左下角一小截木杆。

### 8.3 为什么调参工具看不出来（两个盲点）

1. `ParryStanceTuningWindow` 把**矛头当成一个点**（根 + 方向×5.4）、枪尾也当成一个点 → 读数"矛头落在右 104%/上 62%"只说明**尖点**出画，真实网格的矛头有 2.5 长、红缨 3.3×2.2 → 头部总长约 5.8，**可见窗口几乎被头部塞满**。
2. "起手是否整杆出画"同样按点模型判断 → 现在读作"整杆出画 ✓"，但 ENTRY 帧实际上 **100% 矛头 + 84% 红缨在屏**（武器在画面右下角凭空出现）。

### 8.4 真正能让杆身占主体的三个杠杆（实测占比）

| 做法 | 杆身占可见武器 | 代价 |
|---|---|---|
| 现状（42°，锚点 x=2.12，z=−2.5） | 2% | — |
| 斜举角 42°→**60°**（贴近画幅对角线 63.4°，用画面高度而不是宽度装枪） | 17% | 与参考图《起源》42° 斜举的读感冲突 |
| 矛头锚点 x 2.12→**5.3**（矛头整根出画） | 45% | 失去"看枪尖上扬角"的读数锚点 |
| 深度 z −2.5→**+5.5**（把枪往后放，世界单位窗口变大） | 19% | 插进敌人阵位（z=+9）前后，且与排序 order=2 的遮挡语义打架 |

另外：**红缨在任何配置下都是最大元素**（3.3 长 × 2.2 宽，占可见顶点 70–90%）→ 想让画面读成"一根杆"，红缨本身也要处理（缩短 / 收幅 / 防御位藏起来）。

### 8.5 复现方式（无需进 Play Mode）

`LoadPrefabContents` 读 prefab → `SkinnedMeshRenderer.BakeMesh()` → 按 baked z 分类（杆/缨/头）→ 用 `Camera.main` 的投影把顶点投到 ndc → 统计在屏比例。本次脚本产物在 `Library/Locus/tmp/`：`stance_projection.csv`、`stance_map.png`（三姿态分色图）、`overlay_IDLE.png`（叠到用户截图上，红缨足迹与截图红缨完全重合）。

### 8.8 修：招架不再打断敌人的攻击前摇动画（2026-10-26）

**现象**：玩家反馈“parry 还是会打断敌人的攻击前摇动画”。

**根因（不是打断判定错，是表现链漏了门）**：`TakeDamage` 里招架**确实没有**取消敌人的攻击（那条按设计只在出伤窗口 `IsInStrikeWindow()` 内生效，前摇打不断）。但招架走的是普通受击表现链，会对敌人触发：
1. `HitFeedbackManager.Trigger(...)` → `enemy.ApplyHitStop(0.14s)`（Heavy 局部卡肉）→ **前摇动作顿一下**；
2. `allowHitReactionAnimation` → 闪白 + 受击缩放 + `PlayHitVisual` → **Hit 动画盖掉 Attack 状态** → 前摇动画真的被打断；
3. `AudioManager.PostEvent("Enemy_Hit")` → 范围内每个敌人都响受击音效。

**改法**（`Assets/Scripts/Enemy/Enemy.Combat.cs`）：加两个局部开关
- `bool parryDeflected` —— 在出伤窗口里真的格开了一次才为 true；
- `bool parryNoDeflect = isParryInterrupt && !parryDeflected` —— **招架没格开 = 对敌人零表现**：
  不卡肉（不调 `HitFeedbackManager.Trigger`）、不闪白/不播受击动画（`allowHitReactionAnimation` 门）、不播受击音效。
  格开成功时保留原表现（弹刀反馈 `PlayClankEffect` 仍未实现，暂用受击表现代替）。

**连带待定（未改）**：`AttackSystem.Types.cs` 的空放判定仍按“范围内有敌人在**前摇**”算 `blockedAttack` → 招架在前摇里也算“不空放”→ 走短后摇 0.48s 而不是空放后摇 0.9s（`parryWhiffDuration`），与“招架不能连续刷”的设计意图相悖。要改成“真的格开才算不空放”需用户点头（会明显变重）。

> 注：上面这条已被 §9 的 active-frame 重构顺带解决（新模型必须用“预测能否接上”决定后摇），不再待定。

## 9. 招架手感：active-frame 模型（2026-10-26，已实施 1+2）

**用户口径**：“parry 没有动作游戏（鬼泣/只狼）那样干脆利落；1011/1012 敌人的攻击很快、很难挡到”。先分析后实施，范围 = ①active frame ②窗口/预警对齐（弹刀反馈、输入改按钮、后摇时长未做）。

### 9.1 旧模型为什么接不住（实测数据）

- 玩家侧：输入 = 竖滑，识别延迟 **0.05~0.2s（可变）**；判定 = **输入那一瞬**的一次性检查（**没有 active frame**）；挥入 0.18s 后枪才到位 → 判定比视觉落点早 0.18s。
- 敌人侧（1011）：命中帧 `Enemy_1011_attack8` @2.000s（与声明 hitTime 一致，**视觉与逻辑没错位**）；慢速蓄力 0→1.8s（0.3s/帧）+ 快速挥击 1.9→2.8s（0.1s/帧）；预警 = 出伤前 0.3s。
- 旧窗口 = 0.15s（1011）→ **容错 0.15s < 人类反应+手势识别的 0.25~0.4s** → 只能背节奏，反应接不住；1012 的 0.4s 也只是勉强。

### 9.2 新模型

| 改动 | 位置 |
|---|---|
| 判定从“输入瞬间”移到**接触帧**（挥入结束、枪到位） | `AttackSystem.Types.cs`：`ExecuteParry` 只起手 + 预测，`_parryJudgeTimer`（unscaled）到点后 `ResolveParryContact` |
| 敌人新增 `TryDeflectByParry(window, poiseDamage)`：出伤落在 [现在, 现在+window] → 取消攻击（出伤不结算）+ 削韧 + 闪白 | `Enemy.Combat.cs` |
| `parryStrikeWindow` 语义改为**招架有效窗口**（接触帧之后持续多久）；默认 0.15→**0.3**；1011 prefab 0.15→**0.3**；1012 保持 0.4 | `Enemy.cs` / `Enemy_1011.prefab` |
| 预警时长 0.3→**0.5s**（要盖住玩家能反应的那一段） | `Enemy.Attack.cs` |
| 后摇：只有**预测能接上**才走短后摇 0.48s，否则空放 0.9s（旧的“有敌人在前摇就不算空放”已废） | `AttackSystem.Types.cs` |

**为什么判定计时用 unscaledDeltaTime**：教学的时停招架拍把 `Time.timeScale` 冻到 0（`TutorialStageDirector.Beats.cs`），冻结时游戏时间不走 → 接触帧永不到达 → 招架永远判不中 → 死锁。用 unscaled 计时 + 预测里的 `Time.timeScale > 0 ? tts - contactDelay : tts` 兼容冻结。

### 9.5 “发生段变慢”已实施（2026-10-26 上午，用户口径：把发生帧前那段砍下动作变慢，给玩家反应时间）

**判定要求（推导）**：提示必须出现在出伤前 **0.42~1.07s**（= 0.12 接触延迟 + 0.3~0.55 反应+手势）。
旧状态：预警在出伤前 0.5s（只够快手）、视觉“挥击开始”只在出伤前 0.1s（谁都来不及）。

| 对象 | 改前 | 改后 |
|---|---|---|
| `Enemy_1011_Attack.anim` | attack7@1.9 → **attack8@2.0**（砍下段 0.1s） | attack7@1.9 → **attack8@2.4**（砍下段 **0.5s**），其后 0.1s/帧不变，clip 2.933→**3.333s** |
| `Enemy_1011.prefab` hitTime | 2.0 | **2.4** |
| `Enemy_1012_Attack.anim` | attack5@1.5 → **attack6@1.8**（0.3s） | attack5@1.5 → **attack6@2.0**（**0.5s**），clip → **3.133s** |
| `Enemy_1012.prefab` hitTime | 1.8 | **2.0** |
| 预警时长 | 0.5s | **0.75s**（`Enemy.Attack.cs`） |

**预警与动画是同步的吗？——是（同一时钟）**：预警 = 攻击 tween 上的 `InsertCallback(telegraphStart)`（`telegraphStart = 出伤 − telegraphDuration`）；动画 = Animator 以 speed=1 播 clip（真实秒）；两者卡肉时一起暂停 → 始终同步。所以“把砍下段变慢”会把预警段一起往后推，预警自动盖到新节奏上。
**附带发现（死代码）**：`EnemySpriteController` 里“Parry 窗口停顿、显示 attack2 悬停姿态”没在跑——`_parryWindowStartTime` 全项目无赋值 → `IsParryWindowActive` 恒 false。只影响 102 这类简单精灵敌人（1011/1012 走 Animator 帧动画）。

改后时间轴：
- 1011：出伤 **2.40s**，W=0.40，预警 **[1.65, 2.40]**，可按区间 **[1.88, 2.28)**，挥击开始(视觉提示) 1.90s。
- 1012：出伤 **2.00s**，W=0.50，预警 **[1.25, 2.00]**，可按区间 **[1.38, 1.88)**，挥击开始(视觉提示) 1.50s。

**副作用（已按用户口径执行）**：降低难度是目的，**敌人循环变长是想要的**——
`attackSpeed` 只影响冷却（`1/attackSpeed` → 冷却 0.4×），**调高=出手更快=更难**，所以是**调低**：
- `Enemy_1011.prefab` `attackSpeed` 0.5 → **0.4**（冷却 0.8→1.0s，攻击循环 4.13→**4.33s**，原 3.73s）
- `Enemy_1012.prefab` `attackSpeed` 0.33 → **0.28**（冷却 1.21→1.43s，循环 4.35→**4.56s**，原 4.14s）

（波次配置的 `attackSpeedMultiplier` 仍会在初始化时乘上去（`Enemy.Init.cs`），难度倍率依然可调。）

### 8.7 红缨的可控性（回答"能不能控大小/隐藏"）

- **飘弹：可控**——`parryStanceTasselDamping`（现 26）/ `parryStanceTasselMaxBend`（现 14），只改弹簧链振幅。
- **大小：不是参数**——矛头+杆身+红缨是**同一个 SkinnedMeshRenderer、1 个 submesh、1 个材质**（`FantasySpear_UnlitV02` / `Custom/WeaponColorUnlit`），红缨尺寸（长 3.17、宽 2.13）烤在 mesh 里，不能单独调材质/关 Renderer。
- 唯一运行时手段：缩放红缨骨链 `bones[].localScale`。实测 1.0 → 宽 2.13；0.7 → 1.67；**0.5/0.3 不再变化（饱和）** → 不可靠，且只影响持枪实例。
- 真隐藏需改资产：改源 mesh（会影响 slash/stab 视觉）或改 shader 收缩红缨顶点。
- **但本轮把矛头推出画后，红缨已有 65% 在画外**，红色体量自然变小，不动它也改善明显。
