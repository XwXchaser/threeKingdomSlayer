### 压暗的开关点（拍的生命周期）

```
教学文本出现（PushBeatDialogue / 开场两段 / 技能拍台词 / 冻结台词）→ SetTeachingDim(true)
   ├─ 手势做完 → EndBeat → SetTeachingDim(false)
   ├─ 拍被打断 → StopHint → SetTeachingDim(false)
   ├─ 离开教学 → ReleaseGlobalTutorialState → SetTeachingDim(false)
   └─ 不教手势的波次 / 拍没开成 → 直接撤
```

### ⚠️ 为什么**不能**用全屏 UI 遮罩（用户 2026-11-06 当场纠正）

> 用户原话：「应该让**说话的头像、敌人和武器**都在遮罩上方（教学应该教的内容），你把这些都遮住怎么教？」

- 战场是**透视相机 + 世界物件**：长枪是 `MeshRenderer`、敌人是精灵 → **任何 Overlay 画布都必然盖在角色上面**（层级无解）。
- → 压暗只能用项目已有的 **`TutorialSceneDim`**：给**背景渲染器 + 天空盒**乘亮度系数（`dimBrightness`，默认 0.42），
  **角色与武器不碰**。台词气泡与说话头像都是 UI → 天然在上方。
- 另外修正了一个真 bug：**教学关没有路线场景时，`SetSceneDim` 直接 return → 一点都��暗**
  → 这就是「局内教学文本没有黑幕」的真正原因。现在改成**没场景也压天空盒**（`Rebind` + `Bind` 内部逻辑）。
- `TutorialSceneDim.Rebind()`：重绑时**保留当前压暗程度** → 避免“文本压一次、开拍又压一次”时的闪烁。

### 2.8 遮罩统一（2026-11-07 用户拍板：「本质应该只有一套，只是按不同规则遮挡 UI 物体」）

> 完整的**教程系统总览**（含教学链 R1~R10、六层架构、扩展指引、反模式清单）见
> **`design/tutorial-system.md`** —— 新增教学需求前先读那份。
> 之前的 8 套实现（见 §2.7）已**收成一套规则系统**。

#### 结构

```
MaskRule  ← 规则：谁要遮、遮多强、哪些 UI 豁免、要不要压背景、过渡时长
   ↓
MaskService（唯一入口，按 owner 管理）
   ├─ UI 侧 → UiMask（唯一的 UI 遮罩实现：不透明底图 + CanvasGroup.alpha）
   └─ 世界侧 → IMaskWorldDim 后端（教学：TutorialSceneDim）
```

| 规则字段 | 作用 |
|---|---|
| `Host` | 遮罩建在哪一层（它所在的 Canvas 决定实际层级） |
| `Alpha` | 压暗强度 0..1 |
| `BlockClicks` | 是否吃射线（挡住同层其它 UI 的点击） |
| `DimWorld` + `WorldBrightness` | 要不要同时压暗**世界背景**（走世界侧后端） |
| `Exempt` / `ExemptFilter` | 哪些 UI 要保持亮 + 保持可点（会被提到遮罩上层，关掉时放回原位） |
| `FadeSeconds` | 淡入淡出 |

#### 为什么必须分「UI 侧 / 世界侧」两个后端

战场是**透视相机 + 世界物件**（长枪是 MeshRenderer、敌人是精灵）→ **任何 Overlay 画布都必然盖在角色上面**，
层级无解 → 「背景压暗、敌人与武器保持亮」只能改背景渲染器的亮度（世界侧）。
**但**“遮哪些 UI”这件事统一由规则描述 → 对外只有**一个 API**。

#### 迁移前 → 迁移后

| 旧实现 | 现在 |
|---|---|
| `TutorialClickMask`（主菜单/天赋页聚光） | **已删** → `MaskService`（`Exempt` = 目标按钮） |
| `TutorialInputBlocker`（开场点击遮罩） | **已删** → `MaskService`（`BlockClicks=true`、`Alpha=0`） |
| `TutorialRouteBlackout` 的幕布 | 组件只管**时机**，渲染交给 `MaskService` |
| `TutorialSceneDim` | 保留为**世界侧唯一实现**（实现 `IMaskWorldDim`） |
| `DialogueDimOverlay` / `BattleDialogueView._clickBlocker` | **暂未迁移**（对话系统，不属教学线）；以后要收就按同一套规则做 |

#### 三条硬规矩（都来自实测）

1. **UI 遮罩底图一律不透明**，透明只由 `CanvasGroup.alpha` 控制 —— 半透明 Image 在本项目渲染不可靠。
2. **遮罩不能压在要教学的东西上面**：要么压背景（世界侧），要么把目标提到遮罩上层（`Exempt`）。
3. **豁免对象只在集合变化时重挂**（不能每帧重挂 → 会丢原始父节点，关掉时放不回原位）。

#### 实测（Play Mode + 射线命中顺序）

| 场景 | 结果 |
|---|---|
| 教学拍 | 背景压暗（天空盒 0.50→0.21）；**敌人亮度 1.00 / 武器 0.30 不变**；敌人中心射线命中 0 个 → 无 UI 遮挡 |
| 开场第一段 | `ActiveMaskCount=1`；点击遮罩 `raycastTarget=True`；继续按钮射线第一命中 = 按钮 ✓；气泡第一命中 = 遮罩（点气泡不推进 ✓）；暂停键第一命中 = PauseIcon（order 130 > 121 ✓ 仍可按） |
| 选路 | 幕布逐像素：天空 132→65、地面 94→45、旗帜 111→51（均匀 ≈0.48×）；路牌按钮第一命中 = Icon ✓（幕布 order 19 在路牌面板 21 之下） |
| 落地页聚光 | `ActiveMaskCount=1`，遮罩 alpha 0.45；**豁免目标**（开始关卡）第一命中 = 按钮 ✓；**非豁免**（天赋入口）第一命中 = 遮罩（被挡）✓ |
| 天赋页聚光 | `ActiveMaskCount=1`，遮罩宿主 = `TeachLayer`（canvas 41）alpha 0.45；**C2 节点**（教学目标）第一命中 = 节点本身 ✓（可点、在遮罩上层）；画面上只有教学文字板亮着，其余压暗 ✓ |

## 2.10 2026-11-07 晚：波末三选一「晚一波」的根因与修法（提交 `06689c3f`）

> 现象（用户实测）：教学关里**三选一应该出现在 E0 wave1 之后，实际却在 wave2** → 玩家拿到三选一时
> 「用技能打断」那一拍已经过去了 → 教学流程断。

**根因**：**击杀不给经验**。经验是「击杀 → 生成经验宝石 → 宝石飞到经验条 → 落地才结算」
（`EnemyManager.OnEnemyDied` 只负责生成宝石）。于是：

```
本波最后一只怪死 → 波末 flush（此刻宝石还在飞，队列是空的）→ 下一波开打
                → 宝石落地 → 升级事件发生 → 升级三选一被**顺延到下一波末**才弹
```

教学 E0 波0 正好踩中：那只 1011 的 `expMultiplier=3` → 240 经验，**刚好在波末**触发升级 → 弹窗晚一波。

**修法**：`StageRunFlow` 的波末 flush 改为**等经验宝石落地**（`ExpGemManager.IsCollecting`，超时 3s）再 flush
→ 升级事件已经入队 → 弹窗落在**同一波**末。实测（机器人跑正式 N1）：升级@波0 → 弹窗@波0 ✓。

> 📌 教学关经验账（实测资产）：曲线 200/204/207/211/215/219；
> 教学 N1 两波 `expMultiplier=0`（内容1 不升级）；教学 E0 波0 = 1×1011 ×3 = 240 经验 → **在 E0 波0 升级**。

## 2.12 2026-11-08：连招蓄力拍（stabC2 教学）的三处卡死（提交 `3a82e3b9`）

> 现象（用户）：「在 stabC2 教学中没有释放对应招式，游戏也无法继续」→ 整局卡死。
> 实测（机器人跑正式 N1，触发「招式解锁引导」的连招蓄力拍）定位到**三处叠加**：

| # | 根因 | 修法 | 实测 |
|---|---|---|---|
| ① | **闸门在「招式打出去」时就换成 ComboHold**（哪怕这一下**打空了**）→ 玩家再点第二下被自己的闸门拦掉 → 阶段永远停在 1 | **命中了才换闸门**（`OnBeatEnemyDamaged`） | 空挥后闸门仍是 Tap ✓ |
| ② | **阶段2 派生招式打空没有兜底** → 招式状态机已越过 Jab1（连段边没了）→ 玩家再也接不出蓄力 → 这一拍永远收不了（拍子期间游戏冻着） | 「接续窗口关了 + 状态机空闲」超 0.6s → 判为空挥 → 回阶段 1（状态机打回中立） | 正常路径不受影响（蓄力期间状态机一直 active → 兜底未误触发 ✓） |
| ③ | **这一拍默认按住全场敌人不让动** → 前排被打死后，正在补上来的敌人**被冻在半路**（行军进度 0）→ 玩家够不着任何目标 → 打不出东西 → 卡死 | 没有「够得着的目标」（第 0~1 排有活人）时**放开行军**，让它补上来 | hold=0 → 1013 从 r2 补到 r1 → 打得着 → 阶段1 命中 → 阶段2 → 这一拍收掉 ✓ 游戏继续 ✓ |

> 📌 通用教训：教学拍里「按住敌人」与「目标被打死」叠加会直接锁死整局；
> 凡是**需要玩家命中才推进**的拍，都要有「目标不可达 → 放开/换目标」的兜底。
