### 压暗的开关点（拍的生命周期）

```
教学文本出现（PushBeatDialogue / 开场两段 / 技能拍台词 / 冻结台词）→ SetTeachingDim(true)
   ├─ 手势做完 → EndBeat → SetTeachingDim(false)
   ├─ 拍被打断 → StopHint → SetTeachingDim(false)
   ├─ 离开教学 → ReleaseGlobalTutorialState → SetTeachingDim(false)
   └─ 不教手势的波次 / 拍没开成 → 直接撤
```

### ⚠️ 为什么**不能**用全屏 UI 遮罩（用户 2026-11-06 当场纠正）

> 用户原话：「应该让**说话的头像、敌人和武器**都在遮罩上方（教学应该教的内容），你把这些都遮住怎么教？」

- 战场是**透视相机 + 世界物件**：长枪是 `MeshRenderer`、敌人是精灵 → **任何 Overlay 画布都必然盖在角色上面**（层级无解）。
- → 压暗只能用项目已有的 **`TutorialSceneDim`**：给**背景渲染器 + 天空盒**乘亮度系数（`dimBrightness`，默认 0.42），
  **角色与武器不碰**。台词气泡与说话头像都是 UI → 天然在上方。
- 另外修正了一个真 bug：**教学关没有路线场景时，`SetSceneDim` 直接 return → 一点都��暗**
  → 这就是「局内教学文本没有黑幕」的真正原因。现在改成**没场景也压天空盒**（`Rebind` + `Bind` 内部逻辑）。
- `TutorialSceneDim.Rebind()`：重绑时**保留当前压暗程度** → 避免“文本压一次、开拍又压一次”时的闪烁。

### 2.7 教学遮罩审计（2026-11-07）

> 用户提问：「当前这个教学遮罩似乎不统一？需要你跑一下测试看看有无乱造轮子的现象」
> + 「按钮和文本被挡在遮罩下方？」
> → 新增两个工具：**`TutorialMaskAudit`**（跑测试、抓图、打印射线命中顺序）与
> **`TutorialMaskSetupTool`**（遮罩统一布线）。

#### 审计结果：项目里一共 8 套遮罩/压暗实现（确实不统一）

| # | 机制 | 实现手法 | 层级 | 渲染可靠 | 遮住教学内容？ |
|---|---|---|---|---|---|
| 1 | `TutorialSceneDim` 教学拍压暗 | 改背景渲染器/天空盒**亮度**（世界侧） | — | ✓ | ✓ 不遮（敌人/武器实测 1.00 不变） |
| 2 | `TutorialRouteBlackout` 选路黑幕 | UI 全屏遮罩 | **19** | ✓（本次修好） | ✓（路牌/文字在它上面） |
| 3 | `TutorialClickMask` 主菜单/天赋页聚光 | UI 全屏遮罩 + 目标提层 | 宿主层内 | ✓ | ✓（目标提到上层） |
| 4 | `TutorialInputBlocker` 开场点击遮罩 | 全屏**透明** Image，只吃射线 | 121 | ✓（透明） | ✓ 不遮 |
| 5 | `DialogueDimOverlay` 阻塞台词压暗 | UI 全屏遮罩（0.55 黑图 + CanvasGroup） | 20 | ✓ | ✓ 不遮（低于气泡/HUD） |
| 6 | `BattleDialogueView._clickBlocker` | 全屏透明 Image，只吃射线 | 120 | ✓ | ✓ 不遮 |
| 7 | `HubTutorialGuide` 主菜单引导 | 引导层（手 + 文字） | 60 | ✓ | ✓ |
| 8 | `TutorialGestureHint` 手势提示 | 手势提示层 | 200 | ✓ | ✓ |

**结论**：8 套实现、4 种“遮/挡”手法、3 种透明实现方式（材质亮度 / CanvasGroup+不透明图 / 半透明图），
层级散在 19/20/21/60/120/121/130/200，**没有单一真相源** → 这就是“乱造轮子”的实情。
另外发现两处**真缺陷**（已修）：
- **选路黑幕从来没显示过**：底图是**运行时新建的半透明 Image** → 本项目渲染不可靠；
  且透明度**乘了两次**（底图 0.55 × CanvasGroup 0.55 → 实际只有 0.30）。
- **选路黑幕层级高于路牌面板**（100 > 21）→ 一旦能渲染，路牌按钮与文字就会被压暗。

#### 修复（已落地）

| 项 | 改动 |
|---|---|

#### 实测（Play Mode + 逐像素比对）

| 检查项 | 结果 |
|---|---|
| 选路：幕布渲染 | ✓ 逐像素：天空 132→65、远山 153→73、地面 95→45、旗帜 108→51 → **均匀 ≈0.48×** |
| 选路：路牌按钮 + 箭头 + 文字 + HUD | ✓ 全部在幕布之上、清晰无遮挡；射线第一命中 = 按钮的 Icon → **可点** |
| 教学拍：敌人 | ✓ 精灵亮度 1.00；屏幕矩形在屏内；敌人中心射线只命中透明点击遮罩 → **无 UI 遮挡** |
| 教学拍：角色 + 长枪 | ✓ 未被压暗（材质亮度 0.30 不变） |
| 教学拍：台词气泡 / 说话头像 | ✓ 层级 120，在世界之上；射线命中顺序 遮罩→Text→Bubble |
| 教学拍：继续按钮 | ✓ 射线第一命中 = 按钮本身；位置在血条上方 ~27px |

#### 建议（**待拍板，未实施**）：把 8 套收成 3 种角色 × 各一个实现

1. **压背景**（世界侧）→ 只用 `TutorialSceneDim` → **角色永远保持亮**（本轮已统一）。
2. **压画面但不挡角色**（UI 侧）→ 一个**场景预置**的 CanvasGroup 遮罩，层级**低于**要教学的一切。
3. **聚光高亮**（UI 侧）→ 只用 `TutorialClickMask`（目标提到上层）。
4. **挡点击** → 只用 `GameplayInputGate` + HUD 的 CanvasGroup，**不要用图片挡**。
5. **铁律**：UI 遮罩底图**一律不透明**，透明只由 `CanvasGroup.alpha` 控制（半透明 Image 本项目渲染不可靠）。
6. 可合并项：`TutorialInputBlocker` 与 `BattleDialogueView._clickBlocker` 都是「透明全屏吃射线」；
   `DialogueDimOverlay` 与选路黑幕都是「全屏 UI 压暗」→ 以后各收成一个组件。
7. 用 `TutorialMaskAudit` 守住：每次教学改动跑一遍，看射线命中顺序 + 抓图。
