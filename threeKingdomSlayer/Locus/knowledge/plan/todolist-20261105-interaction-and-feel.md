## 2. P1（本工作流）：交互与手感

### 2.1 用户原话（2026-11-05，5 条）

| # | 原话 | 性质 |
|---|---|---|
| 1 | 需要动作游戏的**预输入** | 手感 |
| 2 | 教程**不应该点任意处都能继续** | 交互 / 教学 |
| 3 | 当前招式有点**不跟手**，有延迟感 | 手感 |
| 4 | 3选1 应该**长按选择**而不是双击 | 交互 |
| 5 | 三选一应该**波次结束时弹出**而不是升级立刻弹出，避免体验断档 | 节奏 |

### 2.2 第一批已实装（2026-11-05，编译通过，**待实机验收**）

| 反馈 | 实现 | 落点 | 新增开关 |
|---|---|---|---|
| ① 预输入 | 缓冲升级：有效期 0.25s、**跨招式兑现**、无匹配边的手势也记、蓄力不进缓冲、只留最近一条 | `PlayerMoveStateMachine` | `bufferLifetime` / `bufferCrossMove` |
| ③ 不跟手 | **命中取消**（打中后在伤害窗口结束处就能接下一招）；**卡肉对齐**（动作锁随卡肉冻结，修掉「枪没收完就能接下一招」） | 状态机 + `AttackSystem` | `hitCancelEnabled` |
| ⑤ 波末弹三选一 | 升级只入队，波末统一弹；**结算前先让玩家选完**（否则升级白送） | `UpgradeChoiceManager` / `StageRunFlow` | `deferChoicesToWaveEnd` |
| ④ 长按选择 | 按住 0.35s 确认，提前松手取消；进度用选中光圈由暗到亮（不新增美术）；教学提示改成「按住」 | `UpgradeCard` / `UpgradeChoicePopup` | `holdConfirmSeconds` |
| ② 不点任意处继续 | 删掉不查 UI 命中的裸 `Input.GetMouseButton*` 推进路径 → 改为点气泡 / 点「继续」；顺手打开了气泡与按钮的 `raycastTarget`（原本是 false，根本点不到） | `BattleDialogueView` | — |

> **「按下即出」默认关闭**（`InputManager.pressTapDelay = 0`）：本项目「按住」本身就是蓄力手势（门槛 0.3s），
> 任何小于该门槛的按下即出窗口都会把「按住一下再划」拆成「一记轻攻击 + 划动被丢弃」。
> 理由见 `design/action-game-feel-and-input-buffering.md` §3。

### 2.3 本轮新修的三个「卡死 / 输入出错」类 bug

| # | 现象 | 根因 | 状态 |
|---|---|---|---|
| A | **未解锁 C2（指向突刺）时仍然进入 C2 的蓄力**；还会出现**没有前置招式的蓄力**（站桩蓄力复活） | 三处「能不能蓄力」的判定口径不一致（`HasChargeContinuation` 不看天赋锁 / `comboChargeActive` 设得太宽 / 中立态 Hold 回落成穿刺） | **已修**（`a6490ca4`） |
| B | **教程需要出招的拍：防御键没提前锁** → 玩家的第一下点击错位 → 「点了没反应、这一拍过不去」 | 防御键静音是**开拍那一刻**才生效 → 前面「等条件 + 台词 + 等敌人收招」是**没静音的空窗**，玩家在这段里按了防御键 | **已修**（静音提前到「条件满足」那一刻 + 拍开不成/舞台结束时收回） |
| C | 同一拍里玩家点在防御键那一块 → **这一下被静音的按钮吞掉**（静音态仍然吃射线）→ 招式永远打不出来 | 静音态固定 `blocksRaycasts = true` | **已修**（静音新增「是否吃射线」：需要出招的拍**不吃**，三选一面板那段仍吃） |

> 另外补了**静默丢弃的日志**：`AttackSystem` 的「动作锁未结束」「戳击视觉门未过」两条拒绝路径以前一个字都不打
> → 「我点了它没动」在日志里查不到。现在会打印剩余时间。

### 2.4 剩余待办

| # | 事项 | 依赖 / 备注 |
|---|---|---|
| 1 | **实机验收 2.2 + 2.3 的全部改动** | 手感无法自动化；下面是验收清单（§2.5） |
| 2 | **难度表 / 铁律八重标** | 节奏变快了 → `Tools/analyze_level_telemetry.py` + `Tools/build_first_level_difficulty_table.py` + `design/stage-configuration.md` §5.6.1 |
| 3 | **缓冲的可见反馈**（"我按下的那一下被记住了"） | 需要一点美术；可复用现有指示器，不一定要新素材 |
| 4 | **把手感变成数**（埋点） | 承诺延迟 / 兑现延迟 / 丢弃率 / 提前量；复用 `LevelTelemetry` 的 JSONL 管线 |
| 5 | **空挥与命中的节奏统一** | 现在只有命中才设动作锁 → 打空无限快打；需要设计取舍 |
| 6 | 教程「连招蓄力」那一拍的**卡点复查** | 该拍依赖 C2 已解锁；未解锁时玩家过不去（**先确认是不是要保留这个前置**） |
| 7 | 场景里有 **2 个 EventSystem**（日志每次刷警告） | 与本次无关，但会淹没日志 → 建议清掉一个 |

### 2.5 实机验收清单（用户手按，逐条记结论）

| # | 动作 | 期望 |
|---|---|---|
| 1 | 连点三段枪突（点、点、点） | 能连上；不比以前快太多（快了要重标难度） |
| 2 | 点 → 按住蓄满 → 松手（指向突刺链，C2 已解锁） | 照常打出指向突刺 |
| 3 | **不锁 C2** 时按住 | 不出现蓄力表现（枪不停在蓄势位、指示器不出现）；松手是普通轻攻击 |
| 4 | 中立态长按 | 不打出穿刺 |
| 5 | 战斗中升级 | **不弹窗**；本波清空时才弹 |
| 6 | 三选一 | 按住 0.35s 才选中；提前松手取消；教学提示是"按住" |
| 7 | 教学台词 | 点敌人/战场**不**推进；点气泡或「继续」才推进 |
| 8 | 教学里需要出招的拍 | 防御键**从条件满足那刻起**就是灰的；点防御键那一块仍能出招；这一拍能收 |
| 9 | 招式解锁引导拍（正式关） | 同上，能收 |
| 10 | 关卡最后一波 | 三选一在结算**之前**给，选完才结算 |
