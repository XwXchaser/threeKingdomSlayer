# 场景美术从参考图到组装的可复用流程经验

来源：2026-10-09 E0 外围残门垣的完整实践（R1→v3 场景参考图 → A01/A02/A03/B01 单件生成与验收 → 独立场景组装）。本文只记录可复用规则，不复述单个节点的具体数值。

## 正确的生产顺序

```text
关卡/场景设计文档
→ 逐张推导场景参考图（母图 → 接近图 → 节点停留图 → 后续节点）并逐张验收
→ 按参考图建立资产拆分表、明确每件职责与边界
→ 逐件生成、逐件目视验收
→ 组装到独立预览场景，以 Game 画面检查
→ 正式接线 / 门内空间 / 战斗与 HUD 验收
```

**先部署后补参考图是错误顺序。** 直接试摆会产生“看起来能看”的假进展，掩盖拆分与形体问题，用户会要求回退重做。参考图未验收前不要进入批量素材与部署。

## 参考图分工与提示词

- 三类参考必须分开：**参考图**定构图/形体与空间关系、**已部署既有资产**定技术规格（PPU/Pivot/Filter/材质接线）、**新画风指南与已验收样本**定绘制语言。任何一类都不能替代另一类。
- 单件生成时，**目标局部决定剪影，材质小样只决定颜色/光照/笔触**。绝不把上一件整件成品作为下一件的形体主参考。
- 只写正向的“左边高、向右阶梯下降”等描述会直接指定重复剪影；负面词“不要复制”不能抵消它。**必须先在参考图上标出具体目标范围**，再写提示词。
- 目标局部可放大作为形体参考，但要声明它不是成品裁切；被前景遮挡的脚点必须补全为稳定基础，不照抄遮挡物。
- 透明单件：明确禁止把标注线、木桩、瓦砾、草、旗、天空烘进结果；生成后按浅/深/土色底各查一次边缘。

## 单件验收

- 先查**剪影是否对应参考图指定位置**，再查材质、Alpha、脚点和边缘。只凭“材质接近/Alpha有效/比例数值”通过会漏掉形体同质化。
- 逐件验收再组装；**单件通过不等于场景通过**，技术导入成功（HTTP 200 / RGBA / 导入）更不等于美术验收。
- 保留全部历史版本、请求与原始响应；失败候选标为未通过，不覆盖、不自动付费重试。

## 脚点与组装

- 部署前按**真实主体 Alpha 底边**设 Custom Pivot；远处低 Alpha 杂片不作为脚点。已按 Alpha 修过 Pivot 后**不得再用 Transform Y 抬升**，否则双重补偿导致悬空。
- 组装时**新建独立组**，旧布局整组隐藏但完整保留（对象、Transform、Sprite、材质、scenery 引用），便于切换对照；两组互斥，避免叠加。
- 保持等比缩放，只记录相对父组的 local 值；排序只用于覆盖关系。
- 一个阶段只保存目标场景，只做一类变更；保存后重载回读，并用 Game 画面检查静止与接近采样，关注中央通道净空。
- 预览用临时 progress 实验必须在结束前恢复（progress/right/camera/显隐），不写入基线。

## 常见坑

- 备用图变体可能并非 Sprite 类型（例如 `_grounded_v2` 为 Texture Default），`AssetDatabase` 取不到 Sprite，不能直接当插片；使用前先回读导入类型。
- 场景中已有的旧美术对象在近距离会暴露，替换前先回读，不自动删除用户布局。
- 远景（门垣轮廓）通过后，近中景过渡层是独立工作；不要用远景通过代替整段可读性验收，也不要用近景物件堵住战斗通道。
