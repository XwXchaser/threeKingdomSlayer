# Unity 编辑器里摆位/看图的三条硬教训（2026-11-15 抡斧接入踩出来的）

> 起因：抡斧劈砍的表现连改三版都被否。原因不是参数，是**自审方法错了**。
> 这三条对以后任何"在编辑器里摆模型、截对比图、判读姿态"的活都适用。

## 1. 编辑器脚本读不到游戏输入

`EditorApplication.update` 里调 `Input.GetKeyDown(...)` **不会触发**（编辑器不把键盘事件转发给运行中的游戏循环）。
⇒ 想在 Play 模式里用键盘调参，只能挂一个**运行时 MonoBehaviour**（走游戏的 Input），挂在场景对象上；编辑器脚本做不了。
⇒ 想让美术摆位，**就给一个场景让他在 Scene 视图里拖**，比键盘方案可靠得多。

## 2. RenderTexture 的 ReadPixels：第 0 行是图底

`ReadPixels` 读出来的行序是**自下而上**（第 0 行 = 图底）。把它写进 `Texture2D` 时**不要再翻 y**
（`SetPixel(x, H-1-y, ...)` 会得到一张倒图）。
⇒ 我在倒图上做了三轮目视自审，结论全错（把"斧头朝下"看成"斧头抡起来了"）。
⇒ **合成对照图后必须先验证方向**：画面上方应是天空/高处、下方应是地面。

## 3. 判读姿态要靠数值 + 参照物，不能靠目视

可用量的东西（2.5D 竖屏，相机 (0,3,-10) rot18 fov60，489×979）：

| 量 | 值 |
|---|---|
| 1 世界单位 ≈ 多少像素 | **≈96 px**（玩家深度可视高 10.16 单位） |
| 玩家精灵中心 | screen (245, 628) |
| 第一排敌人（rowIndex=0，最前排） | world (0, 0.14, −1.0)，胸口 screen (244, 427) |
| 敌人精灵高 | 1.9 单位（182 px） |
| 排位 z | `Enemies` 根节点 z=9，`zPos = 9 + (maxRows−1−row)×(−2.5)` ⇒ 排 0 在 z=−1、排 4 在 z=9 |

⇒ **先算尺寸预算再改参数**：目标间距 201 px 比一把大斧的屏上长度还短 ⇒ "玩家握着斧、刃口落在目标"
在几何上做不到，只能是"目标排上方的武器表现"；刃口宽度取敌人的 70~80% 才有"砸中了"的读感。
⇒ 对照图里必须画**参照物**（落点框、目标体块），并把**关键点的屏幕坐标打出来**，再逐帧看轨迹。

## 4. 什么时候别做

- 美术说"没那意思"时，先**算几何预算**再改参数，不要试参数看图。
- 别加用户用不上的脚手架（编辑器键盘调参器、场景生成器）——用户要的是"一个场景 + 能摆 + 能存"。
