# Y 场景（美术搭景 / 表驱动）· 使用文档

> **一句话** ✅ ✅：场景里的布景**全部由表生成** ✅ ✅ —— 改位置改**表** ✅ ✅，不改场景文件 ✅ ✅；
> 每次改动都有两道验收 ✅ ✅：**逐件比对** ✅ ✅（结构 ✅ ✅）+ **逐像素比对** ✅ ✅（画面 ✅ ✅✅ ✅）✅ ✅。
> **本文防的是** ✅ ✅：**手摆场景** ✅ ❗（改位置要改**表** ✅ ✅，不是改场景文件 ✅ ❗❗）与**只做结构比对就收工** ✅ ❗（结构对了画面也可能不同 ✅ ✅ —— 两道验收都要跑 ✅ ✅✅ ✅）✅ ✅。
> 纪律 ✅：本文只写「读代码得不到的东西」✅ ✅；**与代码不一致时以代码为准** ✅ ✅。

## 一、四个东西分层 ✅ ✅

| 层 | 在哪 | 谁生成 |
|---|---|---|
| **摆放表** ✅ | `Authoring/Placement/{name}.json` ✅ ✅ | 从场景/prefab **导出** ✅ ✅（真源 ✅ ✅）✅ ✅ |
| **规格资产** ✅ | `Assets/RouteData/YSceneSpecs/{name}.asset` ✅ ✅ | 从表**导入** ✅ ✅ ✅ |
| **段 prefab** ✅ | `Authoring/Segments/{name}.prefab` ✅ ✅ | 从规格**生成** ✅ ✅ ✅ |
| **节点 prefab** ✅ | `Authoring/Nodes/{name}.prefab` ✅ ✅ | 从规格**生成** ✅ ✅ ✅ |

**场景里** ✅ ✅：路线段表 = `YRouteSegments` ✅ ✅（**唯一真源** ✅ ✅ —— 规格里的 `segmentSpecs` ✅ ✅ 已删 ✅ ✅✅ ✅）；
常驻布景 = 场景里的 **prefab 实例** ✅ ✅（如 `Opening Roadside Props` ✅ ✅ / `N1 to E0 - Shoulder Detail v1` ✅ ✅ ✅）✅ ✅。

**现状** ✅ ✅：17 个段 ✅ ✅（14 个进路线段表 ✅ ✅ + 2 个常驻实例 ✅ ✅ + 1 个旧版退路 ✅ ✅）✅ ✅；场景里**已无手摆布景** ✅ ✅。

## 二、菜单（`Tools/Y 场景规格/` ✅ ✅）
| 菜单 | 干什么 |
|---|---|
| ① 导出切片为规格 | 场景里的一组 → 规格 ✅ ✅（含根组件 ✅ ✅）✅ ✅ |
| ② 从规格生成到当前场景 | 规格 → 场景对象 ✅ ✅（幂等 ✅ ✅，`userModified` ✅ ✅ 的不覆盖 ✅ ✅✅ ✅）✅ ✅ |
| ③ 校验规格 | 自检 ✅ ✅（**只有真问题才报** ✅ ✅ —— 同 sortBias 但屏幕不重叠 ✅ ✅ 不算 ✅ ✅✅ ✅）✅ ✅ |
| ④ 往返验证 | 场景组 → 导出 → 导入 → 生成 → **逐件比对** ✅ ✅✅ ✅ |
| ⑤ 摆放表往返验证 | prefab → 表 → 规格 → 生成 → 逐件比对 ✅ ✅✅ ✅ |
| ⑥ 节点 prefab 生产 | 节点组 → 表 → 规格 → 节点 prefab ✅ ✅ + 比对 ✅ ✅ |
| ⑦ 预览段 prefab | 把段摆进场景看一眼 ✅ ✅ |
| **⑧ 全链路校验** | **表 → 规格 → 段 prefab 三方对齐** ✅ ✅（防「规格静默变陈旧 ✅ ✅」✅ ✅）✅ ✅ |
| **⑨ 画面逐像素比对** | **现状 vs 由规格重建 ✅ ✅**（同机位渲两张 ✅ ✅ → 差异像素数 ✅ ✅✅ ✅）✅ ✅ |
| **⑩ 表化这个组** | **一条命令把场景里的一组接进流水线** ✅ ✅（导出表 ✅ → 规格 ✅ → prefab ✅ → 场景换实例 ✅ → 外部引用重指向 ✅ → 自动跑 ⑧⑨ ✅ ✅✅ ✅）✅ ✅ |

## 三、表格式里最容易搞错的规则 ✅ ✅
- **坐标空间** ✅ ✅：`space = "local"` ✅ ✅ —— **不做世界换算** ✅ ✅（世界换算会引入 ~1e-5 浮点误差 ✅ ✅ → 往返永远对不齐 ✅ ❗✅ ✅）✅ ✅。
- **精灵按名字取** ✅ ✅：多图集必须带 `spriteName` ✅ ✅（按路径取会取到第一个子精灵 ✅ ❗✅ ✅）✅ ✅。
- **嵌套 prefab 实例** ✅ ✅：容器**自己也要进表** ✅ ✅（真实位置在 prefab 内部 ✅ ✅）；**所有变换节点都进表** ✅ ✅ ✅。
- **组不写变换** ✅ ✅（组只是排序桶 ✅ ✅）—— 否则组与条目会写同一个 transform ✅ ❗（谁后写谁赢 ✅ ✅✅ ✅）✅ ✅。
- **作者态关掉的物件默认不搬** ✅ ✅（旧残留 ✅ ✅ —— 正式游戏不会激活 ✅ ✅ ✅）✅ ✅。

## 四、两种验收（都要 ✅ ✅）
- **逐件比对** ✅ ✅：结构级 ✅ ✅（位置 ✅ ✅ / 旋转 ✅ ✅ / 缩放 ✅ ✅ / 精灵 ✅ ✅ / 材质 ✅ ✅ / sortingOrder ✅ ✅ / 渲染器 enabled ✅ ✅ ✅）✅ ✅。
- **逐像素比对** ✅ ✅：画面级 ✅ ✅（**结构对了画面也可能不同** ✅ ✅ —— 绘制顺序 ✅ ✅ / 层级 ✅ ✅ / 透明混合 ✅ ✅ ✅）✅ ✅✅ ✅。
  → 口径：**完全相同 = 差异 0 像素** ✅ ✅（实测 N1 表化前后 = 0 / 1,573,538 ✅ ✅✅ ✅）✅ ✅。
  → 机位约定 ✅ ✅：眼高 1.7m ✅ ✅ / FOV 60 ✅ ✅ / aspect 0.5 ✅ ✅ / 俯角 10° ✅ ✅。

## 五、坑 ✅ ✅
1. **`DestroyImmediate(transform)` 毁的是组件不是物体** ✅ ❗ → 旧组没删掉 ✅ ✅ → 场景里两份布景 ✅ ❗❗。**要传 GameObject** ✅ ✅。
2. **规格会随类字段改动静默变陈旧** ✅ ❗（反序列化不报错 ✅ ✅）→ 每次改字段后跑 **⑧** ✅ ✅✅ ✅。
3. **自检曾经 100% 是噪音** ✅ ❗（21 个规格报 56 条 ✅ ✅ 全是「同 sortBias ✅ ✅」）→ 判据已改成「**屏幕上真会重叠** ✅ ✅」（脚点距离 ✅ ✅ <0.1m ✅ ✅）+ 簇清单 ✅ ✅ 进可选输出 ✅ ✅✅ ✅。
4. **比较树的根要对齐** ✅ ✅（规格里的 `applyRootTransform` ✅ ✅ 未必生效 ✅ ✅）→ 比对前把生成树的根**对齐到部署中的根** ✅ ✅✅ ✅。
5. **被表引用的素材不能搬出 Assets** ✅ ❗（我搬过程文件时踩过 ✅ ✅ —— 搬走后路径解析失败 ✅ ✅ → 重建时墙上没东西 ✅ ❗❗✅ ✅）→ 搬之前先查表引用 ✅ ✅✅ ✅。
