# 1012 美术替换管线 · 可复用经验（2026-11-04）

> 详细交接见 `Locus/knowledge/plan/enemy1012-art-replacement-handoff.md`。
> 本文只留**下次能直接复用**的结论。

## 1. 表情弧线：两阶段 + 时间线写法

**失败写法（v3）**：表情写成"保持图 1 的坏笑并让它活起来：坏笑缓慢加深" + 一串针对脸的"绝不"
（never lose the grin / never open his mouth wide / never bare his lower teeth / never droop his eyelids）
→ 表情**不动**（实测序列 18–39 无趋势、峰值在 f0）。负向词等于告诉模型"脸别动"。

**成功写法（v4）**，三条同时满足：
1. 表情写成**分段时间线**：第 1 秒闭嘴冷脸 → 第 2 秒嘴角起 → 中段坏笑露齿 → 第 3 秒后收回，末帧=首帧
2. 负向词**只留四条不可违反的**：嘴不张开 / 不露下齿 / 不变友善笑 / 不疲惫困倦
3. **把脸写成镜头里的主动作**，身体动作压到最低（idle 尤其；attack 身体是主体则改用"表情与节拍对齐"）

**流程**：E1 头部表情研究片（脸占画面最大，模型做表情可行性高；便宜、失败不污染工程）
→ E2 全身。E1 成片可当 E2 的参考视频（可选加强）。

## 2. attack 选帧：峰值对齐法

- 基准：`Enemy_1012_Attack.anim` = 3.1333s / 18 键；**t=0 与 t=3.1 同为 idle1**，t=0.3–1.5 = attack1..5，t=2.0–3.0 = attack6..16
- 旧片 attack1..16 ↔ 源片帧：f010 f019 f027 f035 f043 f050 f052 f053 f055 f061 f065 f068 f070 f074 f078 f082（严格递增）
- 节拍：前 5 帧稀疏（步长 8–9）＝举刀过顶；后 11 帧密集（步长 1–6）＝劈砍；attack16 回位
- 选帧算法 = **新片动作峰值帧 + 旧片各帧相对峰值的偏移**（在旧片回归 16/16 精确命中）。
  - 试过但**不可用**：幅度模板（平台期无唯一解，帧会挤在一起）；贪心最大最小差异（旧片回归 0/16，且丢整个上升段）
- 工具：`Tools/visual_brief/pick_attack_frames.py`（`--validate-on <旧片抠图目录>` 可复验）

## 3. 落位口径（实测反推）

| 组 | 缩放 | 偏移 | 备注 |
|---|---|---|---|
| idle | k=0.92366（605/源帧主体高） | 逐帧 x=521−缩放后中心x、y=897−**可见底行** | 脚底 897 六帧全同 |

## 4. 绿幕身份图规格

1024×1024，绿 **RGB(0,159,62)**，**主体高 696 / 脚底 895 / 中心 474.5**（与 v11 身份图同规格）。

## 5. 写精灵的硬规矩

- **必须保留 alpha**（曾用 `convert("RGB")` 落盘 → 透明区变黑底 → Unity 里是黑方块）
- **只覆盖 PNG 字节，保留 .meta**（GUID / 导入设置不变）
- **写完必须回读**核对（脚底、中心、高度）

## 6. 环境与工具的坑

- **`.meta` 里 guid 是 base64、引用处是 hex** → 本地无法反查映射；需要 Unity（AssetDatabase）才能解析。
  Editor 不可用时只能用旁证（轮廓匹配 + 源片对拍）反推落位与选帧。
- **不要自己启 Unity**：`locus.ensure_unity_editor` 会真的拉起 GUI。Editor 崩溃后由用户自己打开。
- **视频接口不返回 usage/cost**（历史 cost_spend 是记账值）。
- **一次动作只生成一次**（叠轮边缘锐度 3.71→3.33→3.14 逐轮下降）。
- 闸门在**全身 attack 上会假阳性**：头顶对齐锚点是"身体最高像素"，attack 里最高点是举起的刀 → 量到的是刀的移动。
  全身版闸门只能参考，**必须配目视六帧对照**。
- `Enemy1012ArtSource/*` 被 gitignore，只放行 `README.md` / `00_Index/` / `01_SourceVideos/` / `02_IdentityImages/`——新产物放这四处。

## 7. 动作母本：只能用验收的那支 take

- **不要拿"替换成片"（replacement video）当动作母本** —— 它可能来自另一支 take。
  实证（1012 attack）：真正验收的是 `sword_enemy_attack_front_v1.mp4`；替换成片 `dao_v11_attack_v1_4s_720p.mp4`
  的节拍源自 `sword_enemy_attack_front_v2.mp4`（中段带巨大白色回旋弧光）→ 照着它写词，
  生成结果与验收版的轨迹相关系数只有 **0.646**（验收版 vs 替换成片 = 0.980）。
- **母本应取「用户验收的那支」**（不一定是 `videos.csv` 记的那个名字）。1012 包里 attack 记的 `2b1888f6….mp4` 恰好与验收的 v1 同 take（相关 1.000），可用；但 1011 包里当时记的 `sword_enemy_attack_front_v2.mp4` **是错件**（另一支带大回旋弧光的 take），已于 2026-11-05 删除并替换为 v1。
- **怎么确认哪支才是验收的那支**：用绿幕**包围盒轨迹 + 中心轨迹的相关系数**两两比对，别信文件名记载。
  （attack 的 `videos.csv` note 原写"与 v2 同动作"，实测为错，已更正。）
- **更硬的判定（像素级）**：用 `Tools/visual_brief/compare_video_takes.py` —— 绿幕键出主体掩码 → 裁内容 bbox → 归一化同尺寸 → 算 **IoU**；再**扫全帧**（不只对记录的那一帧）以排除帧号漂移。
  实证（1011 attack）：已部署的 `Enemy_1011_attack1..16.png` 对 **v1** 的 IoU = 0.930/0.956/0.957，对 v2 最高仅 0.61 → **部署用的是 v1**，台账记的 v2 是错的。
- **部署产物 ≠ 记录来源**：即使台账/文件名写错，用 IoU 对拍仍能判定真实来源；反过来，“记录里写着的那支”往往只是当时被命名的那支。

## 8. attack 的表情设计：起手/收势对齐 idle，峰值对齐动作（2026-11-05 实证）

**方案 A（已采用）**：起手与收势 = **游戏内 idle 的实际表情**（半笑），峰值 = **动作峰值那一帧**（劈砍瞬间露齿）。
**不采用**「冷脸 → 坏笑 → 冷脸」：那会与实际部署的 idle 对不上 —— idle↔attack 与 attack→idle 两头都跳变。

| 阶段 | 动作 | 表情 |
|---|---|---|
| 举刀（游戏里占 1.7 s，是看得最久的一段） | 向上竖举 | 坏笑**渐深**，眼渐眯 |
| 举刀最高点停顿 0.5 s | 停住 | 笑意憋住、蓄势 |
| 劈砍（1.0 s） | 斜劈下压 + 前俯 | **峰值：露齿** |
| 收势 | 起身归位 | 笑意回落 → 回到起手 |

**铁律**：任何新动作的表情**起手态必须等于游戏内 idle 的实际长相**。先确认 idle 现在长什么样（裁头部特写目视），再写提示词。

## 9. 2026-11-05 新增工具与口径

| 工具 | 用途 | 关键说明 |
|---|---|---|
| `Tools/visual_brief/chroma_key.py` | 本地绿幕抠图 | T=79 + halo 去绿边(2 轮) + 孔填充 → alpha 严格二值；**回归验证**：与归档 SVL 产物逐帧 alpha 一致率 99.75%，绿味残留比归档更少 |
| `Tools/enemy1012_attack_land.py` | 攻击落位 + 写入 | **站姿帧配准**（新片 vs idle 掩码 IoU）→ 取固定偏移 → 全 16 帧共用；默认干跑，`--apply` 才写 |

**落位新口径（取代“全局常量偏移”）**：新片与 idle 用**同一张身份图 + 同一个模型**生成 → 站姿帧的像素构图本就一致 → 掩码配准得 dx/dy（实测 0/0, IoU 0.986）→ 落位直接用 idle 的 k 与偏移（k=0.92366, 脚底 897, 中心 521）。
好处：idle↔attack 体型与站位天然一致，且**脚不会漂**。

**选帧新口径**：旧文档的“峰值对齐”在**有定格段的片**上会把举刀段塔缩进静止区（实测 s03–s05 剪影差 0.000）。
改用：**举刀段手选 + 劈砍段 DP 最大化最小相邻差**（有序、含最小间隔约束、排除弧光帧）。

**诊断坑**：**bbox 中心不等于人体中心** —— 刀伸出画面时 bbox 会被拉偏（实测误报“角色漂移 +155 px”）。
测真实位移要用**靴子锚点**（最底若干行的不透明像素中位），实测角色脚位全程恒定，只有刀尖会低于脚。

**源片固有瑕疵（生成模型层面）**：刀形在片内会变（直刃 ↔ 环首弯刀）；动作段落常出现长定格段（f060–f072），16 键必然复用。

## 9.1b 带飘动布料的角色：idle 循环不能按固定周期取帧（2026-11-08 实测，1013 旗手）

- **问题**：像旗帜/披风这类**连续模拟的布料**，它的飘动**不是可重复的周期**。用「轮廓配对距离找周期 + 固定间隔等距取帧」得到的 6 帧，**接缝处旗形必跳**（1013 idle 首次取帧即此问题：f003→f016 与循环回绕 f003 的旗形明显不同）。
- **闸门也要改**：用**整幅剪影**算距离会被**不动的身体**淹没——指标显示「无缝」而实际在跳。应先算**运动区**（全片逐帧 XOR 的并集＝只有布料在动），只在运动区里度量。
- **正确取法**：① 运动区做闸门；② 在运动区里找**布料形状最接近的一对首尾帧**；③ 在这一对之间等距取 N 帧。实测 1013 idle：最佳对 f040↔f060（运动区差异 0.100，随机配对约 0.38），6 帧取 f040/044/048/052/056/060。

## 9.1 步态类（walk）动作的做法

**周期检测**：不要猜步态长度。用**剪影配对距离**找周期：对每帧做 bbox 归一化剪影，算 `1-IoU`，取所有 (i, i+P) 配对的最小值；使该值最小的 P 就是周期。
（1012 walk 实测 **P=16** 帧，配对距离 0.007；P=32/48 是其整数倍。）

**选帧**：取“配对距离最小”的那个相位 i 作为周期起点，再在周期内**等距取 N 帧**（偏移 = round(k·P/N)）。天然无缝，因为末帧与下一周期首帧同姿态。

**x 锚点**：用**躯干中心**（bbox 高度 30%–55% 带的 x 中点）的**中位数**，不要用 bbox 中心（刀伸出画面会把 bbox 拉偏）；摆动幅度与旧素材同量级就原样保留，不逐帧对齐。
（walk 实测躯干摆幅 38 px，旧 v11 43 px。）

**y 锚点（脚底线）**：**底行会被刀尖 / 腰带红布污染**（同一帧里“最低像素”可能在腰带上）。
可靠做法：靴子是深棕皮革，按颜色（b/g ≈ 0.6–0.7、r 90–215）取最低像素；或直接**目视放大脚部 + 画行标线**读数。
取**中位靴底行**作为地面线（walk 实测 838，与 idle 源片的 839 一致）→ 于是 walk 与 idle 共用同一 y 偏移。

## 9.2 「替换视频」的工作流定义（2026-11-05 定案，本轮踩坑后确立）

**完整定义与接口写法见 skill 文档：`Locus/knowledge/skill/reachapi-seedance-video-generation-v2.md` → 「## 替换视频工作流（角色换形象）」。**

**原始记录（三处）**：

**本轮教训（4 支全飘的共同根因）**：本轮一直用 **首尾帧工作流**（身份图当 first_frame/last_frame + 文字描述动作）去做「替换视频」，等于每次把动作**重新定义**一遍：

- hitHeavy v3：描述「下沉/举刀」，幅度放大 4.5 倍（头顶下沉 226px vs 母本 49px）、刀换到身体右侧、举到出画
→ **母本的量化参数（蹲多深/刀在哪侧/举多高）必须靠 reference_video 继承，不能靠形容词转述**。

**可行性已验证**：`file.reachapi.ai/file/uploads` 接受 mp4（HTTP 200 → 返回 cdn url，2.9 MiB 母本上传成功，不建任务不计费）。

**实测：母本的脸往往完全可见且表演很足**——1012 的 v11 受击母本里红布是**束带不是遮脸**，f041 咬牙瞪眼 / f051 张口惨叫 / f067–f090 低头龇牙 / f100 脸收回。
→ **表情随 reference_video 一起继承即可，不需要另发表情片**（我曾误判“脸被遮住所以要另做”，白白多花了一支）。
→ 表情研究片（E1'）只在两种情况下需要：① 母本的脸真的不可见（背影/远景/面甲）② 本轮要**改**母本的表情设计。

## 11. 道具类型直接决定素材成本：贴身 vs 外挂（2026-11-08 实证）

选新敌人的道具时，先问一句「这东西贴在身上还是挂在外面」——它直接决定这支 enemy 要花多少生成量：

| 道具类型 | 例子 | 成本 |
|---|---|---|
| **贴身** | 腰鼓、背篓、背后大盾、刀鞘 | 每支动作（idle / walk / hit / hitHeavy / dead / 击飞三支）都要重做；模型几乎必然出现道具与身体穿插 → **全量新生成** |
| **外挂** | 长杆 + 旗、灯、标枪、长矛 | 杆与布可做成独立 sprite 挂在手部锚点 → 母本帧**直接复用**，只需新生成身份图 + 一支基准帧 + 新动作（**1013 实测后改为「整张一起动」，见下方修正**） |

实例（**已按 2026-11-08 用户定案修正**）：1013 旗手最终采用「旗杆与旗面跟人物整张一起动」而非外挂 sprite → **剩余 8 支动作（Walk / HitFlash / HitLeft / HitRight / Dead / Launched 三支）每支都要整张新生成**，母本只作动作语义与节奏参考，母本帧**不能直接复用**。若做成鼓手（贴身腰鼓），同样是 8 支全部重做——**外挂省下来的成本在 1013 上并没有兑现**。

推论：**新敌人选道具时优先挑外挂型的**；确实需要贴身道具时，把它设计成「独立可拆件」（如鼓 + 鼓架而非腰鼓），以便后期改成外挂。

**2026-11-09 修正（用户定案 + 实测）**：上表「外挂 → 母本帧直接复用」的收益**在 1013 上不成立**——用户选择旗杆/旗面与人物整张一起动（一致性、无接缝、无遮挡穿模优先），且 2026-11-08 明确**不用视频替换流**。代价：杆与布每支动作都要重画，**剩余 8 支动作 = 8 支完整新生成**。**成本估算按「每支动作一次完整生成」计，不要按「外挂可复用母本」估。**

**2026-11-08 实测（1013 旗手 idle 基准）**：带高道具的角色出片时，**画幅比例是硬约束，不是风格选择**。旗手杆顶到脚底＝人物身高的 1.51×，在 720p **1:1** 里人物身只能留到 ≈447 px（旗顶要贴边），到游戏里要放大 1.35 倍，像素发糊；换 **3:4（接口实际给 834×1112）** 后人物身 642 px，游戏放大 0.94×，与 1012 同级锐度。附带：`seedance-2-fast` 的 `aspect_ratio` 支持 `21:9/16:9/4:3/1:1/3:4/9:16/adaptive`，`Tools/visual_brief/submit_seedance.py` 已加 `--resolution/--aspect`（默认 720p/1:1 不变）。另：把「旗杆顶≈1.5×人物身、旗布尺寸不变」写进提示词可有效防止模型擅自缩短长杆。

另：**不要指望模型把「剑」变成「旗杆」**。母本持剑而新角色持杆时，"剑变杆"在替换视频里不可靠 → 先出一支新角色的持杆基准帧做手部像素替换，其余动作仍走母本复用。

## 12. 参考图比例与并排研究图（2026-11-08 实测修订）

1013 旗手的早期双参考图融合曾生成约 **4 头身**，用户判定比例不正确；之后单图 1011 + 2.6 得到用户认为观感尚可的候选，但另一组双图比例修正又被否决。请求提示词、模型和输入图同时变化，因此不能把结果归因成“多图必坏”或“单图必好”。详见 `plan/enemy-commander-buff-unit-plan.md` §2.11–§2.15。

- `input_tokens_details.image_tokens = 0` 不能证明参考图没被接收；`input_fidelity=high` 也不能保证几何比例继承。
- 对单角色请求，头身相对量、头肩关系和等高目视对照仍需写进提示词与验收；孤立的“2.5–3 头身”数字不能单独承担比例锁定。
- **并排比例研究图已验证为有用的讨论工具**：四人同排、正面、脚底大体同基线；图 1 只管共同体型 / 画风，其他图只管职业身份。用户反馈本次返图效果不错，但成图仍只是参考图，不能直接裁切部署。完整复用经验见 `Locus/knowledge/memory/enemy-proportion-lineup-reference.md`。
- 旗杆仍可能被模型自发加矛尖；需要明确写“平的素木杆顶”。
- **2026-11-08 1013 Cast 实测（v2→v5）的通用结论**：
  1. **模型只服从“位置类”约束，不服从“模糊幅度词”**。v3 写“杆顶与画面 1 完全同高同位” → 逐帧 y 恒定；v4 写“只小幅摆动、只微微倾斜” → 幅度发飞、17 帧出画。**幅度必须写成可事后量出来的图像相对量**（如“横向移动不超过他自己一个头宽”“始终停在画面 1 里杆顶所在的那一小块区域”）。
  2. **动作语义要写“他做什么”**。写“风吹旗布”→ 人像雕像、只布在动；写“他自己挥旗两下”→ 才是要的摇旗动作。
  3. **给动作留行程要先把人物在画幅里缩小**：方形画幅里长杆角色占满时杆一动就出框（1440² 实测）；人物降到画幅 43% 后才有 ±一个头宽的摆动空间。
  4. **表情要写成与动作同拍的弧线**（顶点张口喝令），负向词只留四条；写太多“绝不……”等于告诉模型脸别动（1012 v3 的失败模式）。
  5. 圆画幅里**杆顶离画面边缘的距离**直接决定动作能不能做；算清楚再定人物占比。
- `Tools/visual_brief/compose_identity_greenscreen.py` 继续负责已验收单角色的抠图 / 落位 / 量测；不要把并排研究图当作身份图加工。

## 12. 通用动作帧管线的新增教训（2026-11-08 · 1051 弓手）

做 1051 的 idle / walk / attack 三套动作时又踩了几类坑，与具体角色无关，可复用到下一个敌人：

### 12.1 落位：**固定 k + 统一偏移**，不要逐帧归一化

- 逐帧把「本体高」归一化到 605，会把**模型动画里的上下浮动翻译成整体缩放** → 动画看着像角色在缩放（1051 idle 初版就是这样）。
- 走路更不能逐帧对位：会抹掉角色自身的水平摆动（1012 的做法是「躯干中心的中位数」「靴子中位底行」）。
- **统一做法**：固定 k（取各帧 body_h 的中位数）+ 贴图偏移取各帧中位数（x=身体中心、y=可见底行），逐帧只做缩放不做对位。

### 12.2 选帧：按**动作相位**抽，不要按时间等距

- 等距抽会全落在同一相位（1051 walk 初版六帧里五个都在「并腿」相位，循环像原地蹭）。
- 正确做法：先出**相位尺**（逐帧裁出动作部位的带编号图），目视定位关键相位（走=contact/pass/swing；射=抽箭/搭箭/引弓/满弓/放箭/收势），再按经典相位序列抽，并让**首尾同相位**保证循环接缝顺。

### 12.3 选帧前必须**整片分段看**，生成片可能混进闪回帧

1051 的 walk 成片在 **t≈1.0s 有一次步态倒退/重放**，其后还退化成同一条腿反复抬起。单看相邻帧发现不了，选帧跨过去就把闪回带进动画了。
→ 规矩：**先整片扫一遍找闪回/退化段，选帧只在干净段里取**。

### 12.4 生成路线：用文字描述动作 = 让模型重新定义动作

- 「用文字描述新动作」的路线实测会把**持物侧/瞄准方向**改掉（1051 attack v1 箭指到画面右侧，用户否决）。
- 稳妥做法：**把旧角色的动作帧做成与身份图同构图的姿势参考图 → 生图模型只换人 → 母片/首尾帧驱动视频**。
- 但**母片只能给两三个关键姿势**：给两帧（1051 walk v1 用了旧 105 的两帧走姿）模型就在两个姿势之间跳帧；宁可让模型自己走，再用硬约束压住（躯干正对镜头、原地踏步不靠近镜头、尺寸逐帧不变）。
- 提示词里**别写「朝镜头走来」**（模型会真的走过来，脚底线漂 100px、身体变大）；要写「原地踏步、尺寸逐帧不变」。

### 12.5 姿势参考图的构图口径必须与身份图一致

旧角色动作帧要先用同一套落位口径（本体高/脚底/中心）合成到身份图规格，否则模型要同时猜「换人」和「改构图」。
另：**道具会遮挡/改写手部位置** —— 替换目标若带杆/旗/剑，模型常把道具换不掉（1013 的旗、1051 的箭都出过问题）；带外部道具的替换目标，要单独出「持道具的基准帧」再像素替换手部。
