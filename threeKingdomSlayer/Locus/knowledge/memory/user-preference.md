## 交互偏好

- **先分析后实现**：若用户未在对话中明确提及「实现」「开始做」「动手」等指令，仅做分析、方案设计和调查，不直接修改代码或场景。只有在用户明确说「开始实现」「按这个方案做」之后才进入工程改动。
- **「分析」= 仅分析，禁止实现**：当用户说「分析」时，严格只做分析、讨论方案、梳理逻辑，不允许直接动手改代码。明确说「开始实施」「实现」「做吧」等指令后才可修改代码。
- **计划/文档任务的交付边界**：当任务被限定为「计划、制作或修订文档」时，交付物仅为文档本身（写完后回读验证）；文档中的待办项是给用户的，不自动实施，也不把实施动作排进本次会话（不使用「我建议下一步开始做…」这类自我派工的口吻）。
- **任务闭环与回复保证**：每次任务必须以一条明确的用户可见回复结束，说明已完成的工作、验证结果、未完成项或阻塞原因，以及下一步需要用户做什么。即使工具调用失败、子程序异常、超时、返回空结果或任务被中断，也不得静默结束；必须主动报告当前状态。调用子程序后不能把等待子程序作为最终状态，必须在收到结果后继续处理并回复；若子程序无结果或失败，须说明失败并改用直接工具或给出明确的人工排查步骤。
- **图片/视频生成前置审批**：任何准备调用图片或视频生成接口前，必须先提交完整的中文提示词和英文提示词，连同负面提示词、参考图职责、尺寸/质量/透明度/时长等关键参数，以及生成目标和验收重点，等待用户明确验收或批准。未获得明确批准前，不得调用 `image_gen`、GPT Image、视频生成接口或其他收费/远程生成服务；“继续分析”“收到”或仅查看方案不等于批准。若生成前提示词、参考图职责或关键参数发生实质变化，必须重新提交中英文版本并等待批准。
- **GPT Image 质量档位**：所有 GPT Image 生图、编辑、融合与去背请求统一使用 `quality=max`；编辑类请求仍可同时设置独立参数 `input_fidelity=high`。未经用户明确要求，不降档使用 `high` 或更低质量。
- **角色动画部署与验收边界（2026-10-11 用户明确要求）**：今后部署只做到将角色接入第一关并配置对应动画；完成后通知用户，由用户自行开游戏检查和验收。除非用户在对话中明确要求自检动画部署情况，否则不得自动进入 Play Mode、执行运行自检、驱动动画采样或对象池测试，也不自动追加画面自检。常规部署收尾以资产导入、引用接线与保存完成为界，不因 Skill、旧交接或通用检查清单要求运行验收而扩大范围。
- **素材交付路径**：图片、视频、帧序列、预览等本地素材交付时，回复必须优先给出可直接粘贴到 Windows 资源管理器的绝对磁盘路径；同时明确“最终候选素材目录”和“仅供预览/追溯的文件或目录”，不能只给工作区相对路径或无法跳转的 Markdown 引用。若文件较多，列出目录、分组子目录和完整文件名范围。
- **角色视频绿幕流程（2026-10-13）**：用户将1021 HitRight v2采用浅灰制作底而非绿幕明确指出为严重流程问题。此类角色视频不要自行沿用静态定妆/姿态图的浅灰底；生成前先准备统一绿幕上传副本并供审阅，明确色值，常用已验收色为RGB(0,177,64)。收到生成授权不等于允许跳过绿幕准备。对已验收灰底成片，优先保留原片、先选有效帧验收，再本地分离背景/换绿/抠图；换绿仍依赖准确蒙版，不能全局删灰而伤及金属高光，不自动重生成或批量收费。
- **分工对话的任务边界（2026-10-16 设定，2026-10-17 两次更正，以本次为准）**：在 1021 持盾死亡这类分工协作中，多个侧各自承担不同环节。被指定为**素材侧**的对话：**不写生成词**（生图词与视频词由另一方负责）；但**要承担选帧与抠图**；**对齐、补边、Clip 创建与 Unity 接入不由本侧做**，由接入侧负责。图片与视频验收由用户自己做；本侧不验收画面、不自行重发收费任务。交付到透明素材就结束，不以“下一步建议”的口吻替另一侧派活，也不自动开工。
