## Stab 高速穿刺素材生成经验

### 成功版本
- 成功参考图：`C:/Users/steam/Pictures/gptGen/stab_recognizable_tip_speedbody_v13.png`
- 项目最终素材：`Assets/Sprites/zhangfei/stab_v13.png`，由用户完成透明清理和长度处理，已接入并验收。
- 生成方式：以项目原始 `Assets/Sprites/zhangfei/stab.png` 作为武器身份与配色参考，以用户提供的街机动作截图作为运动构图参考；不再把之前失败的生成图作为参考。
- 结果特征：远端保留可识别的银灰枪尖；枪尖后连接红穗、绿色装饰和连续的红棕枪身核心；两侧为长距离、近似平行的白色高速面；近端可延伸出画面；整体仍是同一武器的高速变形，而不是独立爆炸特效或泛化枪尖。
- 最适合的定位：v13 是普通 Stab 的中间加速/中间形变帧，不是极限速度帧，也不应直接被继续放大成终极攻击造型。

### 成功的提示词与参考策略
- 先明确“这是武器本体高速变形，不是独立特效图”。
- 原始武器图负责颜色、枪尖、枪杆和装饰身份；动作截图只负责透视、冲击方向和速度语言。
- 方向确定后只生成单张姿态，避免多帧概念图分散结构约束。
- 保留枪尖作为远端识别锚点：它可以变小，但不能删除或模糊到无法识别。
- 主体描述为“长枪身核心 + 长距离近似平行的白色高速面”，而不是“完整三角楔形”。
- 红穗和绿饰只作为局部、不连续的速度结构，不要铺满两侧。
- 使用原始项目图与真实动作参考图；不要继续把失败生成图作为参考输入。

### 失败生成的共性原因
- 反复强调“近端宽、远端窄、远端小点”，会诱导模型生成等腰三角形、圣诞树或旗帜形轮廓。
- 要求红绿装饰铺满两侧，会形成树枝状边缘，破坏武器主体比例。
- 把枪尖描述成“几乎消失”会丢失武器识别锚点；参考动作仍需要可见的枪尖元素。
- 同时生成多帧概念图会降低单帧结构遵循度，并导致三帧彼此不像同一物体。
- 把完整武器重绘、运动残影、碰撞闪光和独立 VFX 混在同一个 prompt 中，会导致角色、爆炸、光束或泛化长枪。
- 过度夸张“极限速度、巨大穿刺、全屏通道”等语义，会把普通 Stab 推成必杀技规模，失去当前项目的战斗尺度。
- 对 v13 使用生图模型做所谓“局部编辑”时，模型仍会重绘整张图，改变构图、方向或枪身比例；局部编辑提示词不能保证像素级同源。
- 对 v13 做矩形分段缩放、错位和重叠的程序加工，会造成明显横向接缝，像拼接图而不是连续动画形变。
- 直接绘制新的几何色块虽然能消除完整枪杆，却会丢失原始像素纹理，使结果变成规则几何块、硬质长条或装饰贴片。
- 因此，当前工具链不适合可靠地产出 v13 的极限速度同源帧；继续生成或自动加工的收益低于风险。

### Unity 接入教训
- 动画换帧应保持职责单一：运行时只修改 `SpriteRenderer.sprite`，不要同时根据新旧 Sprite bounds 改 `localPosition` 或 `localScale`。
- 原始 Stab 含大量透明边缘，整张 `sprite.bounds` 不能代表有效武器轮廓；使用它计算换帧缩放会把新帧放大数倍并推到画面顶部。
- 不同画布尺寸应在素材侧通过透明留白、PPU 和 Pivot 对齐；运行时代码只负责时间点。
- DOTween 换帧回调应在刺出 Tween 建立后，以明确的 `windupDuration + thrustDuration * ratio` 插入，避免误入起始/蓄力阶段。
- 最终采用“原始 Stab 起始 → v13 刺出中段 → 恢复原始 Stab”，用户已验收效果不错。
