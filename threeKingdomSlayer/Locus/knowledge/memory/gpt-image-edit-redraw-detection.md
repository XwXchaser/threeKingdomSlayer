# GPT Image 编辑"是否只删除、还是有重绘"的量化判定

来源：2026-10-16 109 S1「从 f107 删除倒地骑手与长枪」的一次编辑（`plan/enemy109-rider-fall-mount-escape-handoff-20261015.md` §0.6.9）。结论与既有经验一致（`memory/stab-vfx-generation.md`「局部编辑仍会重绘整图」；`skill/workflows/image-asset-generation.md`「`input_fidelity` 不能锁死局部重绘」）。本文只补**可复用的测量方法**，不重复已有结论。

## 问题

`input_fidelity=high` + `quality=max` 下，模型会把"只删除 A 物体"理解成"重画整幅图"。肉眼很容易被"看起来还是那匹马"骗过——身份、配色、鞍具都在，只是**每个像素都被重画并整体放大位移**。文案层的"保持像素不变"完全无法约束它。

## 判定方法：源主体实心像素的保留率

不看包围框、不看风格相似度，直接问：**源图里那些确定性属于保留主体的像素，在输出里还是原来的颜色吗？**

1. 取源图 alpha > 200 的像素作为"实心主体"。
2. 排除掉**将被删除物体**所占区域，以及**两者相接**的窄带（保守排除，宁可少算）。剩下的就是"必须原样保留"的核心像素集。
3. 对核心集逐像素算 `|dR|+|dG|+|dB|`，统计落在 ±10 / ±30 内的比例。

判据（本次实测）：

| 指标 | 实测值 | 含义 |
|---|---|---|
| 核心像素保留率（±10） | **0.65%** | 几乎全被重画 |
| 核心像素保留率（±30） | 5.54% | 同上 |
| 核心区平均 RGB 绝对差 | 154.4 | 逐像素换了颜色 |
| 头颈子区保留率 | 78.4% | 该子区恰好人马不重叠、且有部分保留，**不能单独作判据** |

结论：**保留率是个位数百分比 → 全量重绘**。这个方法不依赖"把相接的人马切开"是否准确，比包围框比值更硬。

## 同时要做的几何对照

- **输出主体包围框 ÷ 源主体单独包围框**：本次 ×1.34 宽 / ×1.25 高 → 整体放大。
- **最低行（隐形地面行）**：本次前蹄带由 y=816 → y=844 → 地面关系变了。
- **头颈裁剪并排对照**：吻部/张口形状、鬃毛分块、面甲渲染都会变。

只报"包围框差多少"不够，因为物体相接时包围框要靠切分，只能算估算值；**保留率是主判据，几何是辅证**。

## 成功与失败部分要分开记

同一次输出里，"删除"和"保真"是两个独立结论：本次**删除步骤通过**（骑手与长枪干净消失、空区纯绿、无替身/阴影/残件、四边 ≥64px），**保真步骤不通过**。返工时应**保留删除措辞，只改保真条款**——否则会把已经成功的删除一起推翻。

## 提示词层面：文字约束不了它

已在词里写了"visible horse pixels stay as in the source / no redraw / no rescale / no recentering / keep the reference canvas coordinates and drawing scale"，仍然全量重绘。因此：

- 不要靠继续堆"禁止重绘"的同义词来修；这类负面词是无效的。
- 可行的方向是**把几何钉成数值**（给出预期包围框与地面行）并配合**换时间/换路由重试**（参见 `skill/workflows/image-asset-generation.md` 关于路由与重绘抖动的记录）。
- 当"只删除一个前景物体"是硬需求时，评估**自绘遮罩+按轮廓重映射原像素**这类确定性路径，不要默认生成模型能保住像素。
