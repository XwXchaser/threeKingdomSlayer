# 教学手势引导（暂停 + 做对才继续）开发坑点与经验

来源：2026-10-19 教学关「手势引导」从零到跑通的一整轮对话。这次连续多次「改完没效果」，
根因不在业务逻辑，而在**构建与验证链路**。以后做教学/引导类功能前先读这一页。

## 一、最致命的三个坑（按出现频率）

### 1. 程序集陈旧：`unity_recompile` 说 compiled，游戏里还是旧代码

- 现象：源码已改，游戏行为不变，新加的日志一条都不出现。
- 判定：比对 `Library/ScriptAssemblies/Assembly-CSharp.dll` 与 `.cs` 源的 **mtime**。DLL 比源码旧就是没编译。
- 处理顺序：改完 → touch 源文件 → `unity_recompile` → **再比对一次 mtime** → 才算改完。
- 本次教训：连续 4 次「已修复」汇报都是假的，全部因为 DLL 停在旧时间。

### 2. 文件写入不落盘 / 被回退：工具说「已编辑」，文件里没有

- 实际遇到过：`dimOverlay.gameObject.SetActive(true)` 这行**从没进过文件**；`choiceDialogue` 字段被回退；
  日志行被换成旧版。
- 处理：**每次改完立刻用 grep 回读源码**确认目标文本存在，再看 mtime，再编译。不要相信编辑工具的「成功」回执。

### 3. 编译错误会让 Unity 拒绝进入 Play

- 现象：玩家说「开不了游戏」；Play 按钮无反应或超时。
- 判定：看 Console 的 error，或 `unity_recompile` 的 detail。
- 注意：Console 里的报错可能是**上一轮**的，源码修好后仍需一次成功编译才会消失。
  用「DLL mtime > 源码 mtime」作为编译真的成功的唯一判据。

## 二、引导门槛本身的坑

| 坑 | 现象 | 正确做法 |
|---|---|---|
| 示范循环把自己取消 | 刚暂停又立即恢复，只剩手在闪 | 播放示范用 `StopRoutine()`；`Cancel()` 只给外部打断用 |
| 对话系统顶掉暂停 | 引导暂停后一秒又自己跑起来 | `DialogueManager.Finish()` 无条件 `timeScale=1`；门槛期间每帧压住 `timeScale=0` |
| 收尾动画误关全屏 UI | 遮罩闪一下就没了 | 遮罩只在 通过/取消 时关；示范动画的收尾**不能**碰全屏层 |
| 通过后提示不消失 | 手/光圈黏在屏幕上 | 通过时 `StopAllCoroutines()` + 隐藏所有图层 |
| 通过后“什么都不发生” | 教学没有意义 | 通过后必须把玩家做的手势**重放**给输入系统 |
| 重放被动作锁挡 | 重放结果 false，敌人不掉血 | `timeScale=0` 时动作锁不走时；重放用 `cancelCurrentMove: true` |
| 重放戳歪列 | 点第 2 列，打出左边一列 | 别用屏幕坐标反算列；直接用**目标敌人的 columnIndex** |
| 引导出现在空场 | 敌人在后排入场途中就弹手势 | 等目标敌人 `rowIndex==0` 且 `state != Moving` 再引导，带超时兜底 |

## 三、时间轴约束（教学的先后顺序）

```
波次开始（敌人从后方入场，此时不能暂停，否则敌人不动）
→ 等目标敌人站定
→ 推台词（此时暂停，台词与手势同时可见）
→ 手势门槛（暂停 + 遮罩 + 示范）
→ 玩家做对 → 重放该手势 → 放完剩余台词 → 恢复 timeScale=1
```

台词**不能**在波次开始就推：会立刻 `timeScale=0`，敌人永远走不到前排。

## 四、验证方法（比截图可靠）

- `unity_run_states` 可以跨帧取值：`gating`、`Time.timeScale`、`dimOverlay.activeSelf`、敌人 `hp` 前后差值、
  `AttackSystem.LastMoveConfig`。这次就是靠它一次拿到「遮罩=True / hp 100→80」，才结束反复猜。
- 需要确认“屏幕上到底有没有变暗”时：抓 `game` 视图截图，用 Python/PIL 算**平均亮度**对比（有遮罩会明显变暗），
  不要凭肉眼或描述判断。
- `Logs/Editor.log` 会被逐帧诊断日志刷屏：先记行数，再 `grep` 新增区段，别用 `tail` 找业务日志。

## 五、给下一次的检查清单

1. 改完 → grep 回读源码，确认目标文本在文件里。
2. 编译 → 比对 DLL 与源码 mtime，DLL 更新才算成功。
3. 运行时 → 用 `unity_run_states` 取数值，不靠肉眼。
4. 只报**有数据支撑**的结论；没验证就说“未验证”。
5. 教学/引导类功能，先把“谁在暂停、暂停期间谁会被动改 timeScale”列清楚，再动手。
