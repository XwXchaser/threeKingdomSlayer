# 角色动作全流程入口清单

> **用途**：给某个角色制作「一套新动作并接入 Unity」时，从这一页开始。它不定义任何规则，只负责按执行顺序指向正确的文档、工具和门禁，避免规则已存在却检索不到。
> **维护**：本页只放**阶段顺序、去向、门禁**。规则细节写在各专项文档；实测数值、任务 id、文件与费用写进 `memory/video-generation-case-log.md`，都不要写进本页。

---

## 跨阶段三条铁律

1. **未经用户验收，不进入下一阶段。** 每个阶段的产物（姿态、帧序、透明结果、游戏表现）分别验收，不能用上一阶段的验收代替下一阶段。
2. **付费/远程生成前必须先审批**：完整中英文提示词、负面词、参考图职责、尺寸/时长/质量参数全部呈现并获批后，才允许调用。
3. **代理不自动进入 Play Mode、不采样动画、不运行画面自检。** 部署做到「接入 + 配置 + 静态核验」为止，游戏表现由用户开游戏验收。

## 可标记 N/A 的阶段

阶段 3–5 与阶段 7 的部分子项不是每套动作都需要。允许跳过，但**必须在核验记录里写明理由**，而不是静默略过：

- 素材不是视频来源 → 阶段 3 标 N/A（说明：来自关键图/单帧）。
- 素材本来就是透明 PNG → 阶段 4 标 N/A（说明：源已透明）。
- 新动作尺寸与参照一致 → 阶段 5 只做锚点归一（说明：缩放取值 = 1）。
- 动作不涉及装备/物件脱离 → `action-to-unity-deployment.md` 的接管子段标 N/A。
- 该状态不由代码计时切换 → 时长契约项标 N/A（说明：由转场 exit time 驱动）。

## 检索约定

- **规则在专项文档，数据在台账。** 本页与两个接入专项文档保持短小、稳定；`memory/video-generation-case-log.md` 可以很长，按需查。
- 发现某个规则「已经写过但没被查到」时，优先**在本页补一条去向**，而不是在专项文档里重写一遍。
- 不同角色的部署需求不同：遇到与本页阶段划分不符的情况，先记录差异，再决定是补决策表还是新增阶段，不要为了对齐流程而扭曲实际做法。
