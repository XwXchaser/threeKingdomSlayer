# 动作接入 Unity 工作流（透明帧 → Clip → Controller → 脱离物件接管 → 静态核验）

> **用途**：把已验收的透明帧变成**可运行的动作资产**：Clip、与显示同步的事件、Controller 接线、装备/物件脱离后的独立对象、以及代码侧生命周期与静态核验。
> **为什么需要它**：抠图手册只负责「帧变成透明精灵并入库」，入库后的精灵是孤立的；Clip/事件/Controller/接管此前没有任何规范，每次都要重新推导。
> **不写死原则**：本文**不记录具体数值**。所有需要取值的地方都是**参数槽**，取值写在本批的 `job/config.json` 与核验记录里。遇到本文没有覆盖的新情况，**补决策表，不要把个例写成定值**。

## 1. 参数槽与本批取值记录

开工前把这些取值**显式写下来**（建议 `Library/Locus/tmp/<任务>/job.json` 或核验记录，而不是本文件）：

- 角色/单位标识、目标精灵目录、精灵命名模板

- 目标状态名、驱动的代码入口、控制时长的字段名

- 是否涉及「物件脱离」；若涉及，事件名与事件时刻

- 脱离物件的接管模式与运动参数
- **保护文件清单**（接入前后必须哈希一致的路径集合）

## 2. 阶段 A：素材就绪与尺寸/锚点归一

- 素材必须来自**已验收**的帧序；文件名与清单 JSON 对应，逐帧哈希可回溯。
- **只允许一个全局缩放**（同一批所有帧同一个值），禁止逐帧 fit 包围框。逐帧缩峰会抹掉姿态本身（例如「受击变矮」）。
- **只钉脚底锚点**；横向按源画布居中补边，**不做横向重锚定**（脚心未必在源画布中心）。
- 若该动作还要与独立物件分开，人物层与物件层必须使用**同一变换**，以便分开后仍能复原相对位置。
- 与参照比对时放在**相同中性底**上，并记录比对用的 ROI 与证据强度；弱相关（例如局部配准得分很低）必须写明，不能当成精确标定。

> 尺寸不一致时的取值走 §11 决策表 1；不要在本文件里记住某个具体缩放倍数。

## 3. 阶段 B：精灵入库与导入设置镜像

- **不改全项目导入设置**；新精灵的导入设置**逐项镜像**同角色已部署精灵（PPU、pivot、filter、compression、mipmap、alphaIsTransparency、mesh 类型等）。
- 替换素材时**只覆盖 PNG 字节、保留 `.meta`**，GUID、pivot、PPU 与现有引用不变。
- 入库工具默认干跑：先看「逐帧所需偏移及跨度」，跨度异常说明该组做过额外裁切/重排，需要逐帧对齐或单独处理。
- 入库完成后立刻建**保护文件哈希基线**（§9 会用到）。

## 4. 阶段 C：帧 → Clip

- **时长契约**：若该状态的结束由代码计时或字段控制，Clip 长度必须与该字段一致；字段值变化时同步改 Clip（或反之）。
- 键位时间：按帧序给出各帧键位时间；**末帧是否需要保持键**取决于该状态结束后是否立刻被别的状态接管。
- **旧分离层清空键**：若该单位历史上存在由 clip 驱动的子渲染器（装备/武器层），必须在新 clip 里给它打显式清空键，否则会残留或双显。
- 非循环/循环按状态语义设定，不要为了「看起来更顺」把一次性动作设成循环。
- 采样帧率取一个能让**所有所需键位都落在采样点上**的值；键位与帧率不匹配时，Unity 会对曲线做插值，读到的姿态可能不是你要的那一帧。

## 5. 阶段 D：与显示同步的接管事件

**判据（何时必须用事件而不是墙钟计时）**：只要满足任一条，就该用 AnimationEvent——

- 动画可能被**卡肉**暂停（本项目命中卡肉会临时 `Animator.enabled = false`）；
- 动画可能暂停（`Time.timeScale` 为 0 的暂停/三选一）；
- 动画播放速率可能被外部调制（例如按移动速度调 `Animator.speed`）；
- 接管时刻必须**精确落在某一帧姿态**上（装备脱手、物件消失、状态切换）。

事件放置规则：

- 事件时刻必须**与「本体已不含该物件」的那一帧一致**。早一帧会看到物件跳位，晚一帧会看到双份。
- 事件方法名必须**真实存在于被引用的组件上**（Unity 按名字在 Animator 所在对象上解析）；改名或删除字段/方法前要检查所有 AnimationEvent 绑定。
- 当动画不可用（缺 clip / 被禁用）时需要**兜底**：兜底同样应受卡肉与暂停约束，不能让暂停期间流程继续推进。
- 必须区分「已存在可用动画」与「没有动画」两条路径，避免在没有动画时永不结束、或有动画时被兜底提前结束。

## 6. 阶段 E：Controller 状态与转场契约

- **只替换 motion**，不重排既有转场。已有 Exit Time / duration 是本单位的既有契约。
- 由代码 `Play` 驱动的表现状态（例如瞬时反应、一次性表现）**不要接入边**；加了边会被其它 Trigger 抢走表现。
- 新增状态时，从**复制同一单位的既有状态**出发，避免引入其它单位的参数与权重差异。
- 改 Controller 后要核对：其它状态的 motion 未被顺带替换、状态名未被改名（代码按名 `Play`）。

## 7. 阶段 F：脱离物件的独立对象接管

> **仅当动作涉及装备/物件脱离时执行**；不涉及则整段标 N/A 并写明理由。

先按 §11 决策表 2 选定表现方案。选定后要落实的点：

- **生成时机**：由阶段 D 的事件触发，且必须**只生成一次**（重复触发、打断后重入都要防）。
- **坐标系归属**：独立对象应在脱离瞬间**读取敌人的姿态一次**，之后**不跟随**敌人的移动、补齐、形变、旋转或死亡动画；否则会出现「物件跟着人漂」。
- **层级与层序**：先核对本单位的层序规则（本项目敌人本体靠世界 Z 排序，固定 `sortingOrder` 的子渲染器会跨排压过其它敌人）。独立对象应继承本体的层序与透明度来源，不要写死一个绝对值。
- **可见性来源**：本体的透明度可能来自材质实例（按排淡化、命中闪白）。独立对象要**继承同一透明度来源**，否则会出现「人淡了物件还全亮」。
- **生命周期**：明确何时销毁/回收；自然结束才销毁，不要在外部清理时重入销毁。
- **打断**：抢走表现的状态（死亡、击飞、眩晕等）必须**显式处理未完成的接管流程**：未到脱离点的取消、已脱离的让世界对象自行完成，两者不能混淆。
- **池复位**：复用敌人实例时必须把旧子渲染器的 sprite 与 transform、以及接管流程的进行中标记**全部复位**，否则会出现「新实例带着上一个的残件」。

## 8. 阶段 G：代码侧生命周期挂点

新增/修改代码时，至少确认这些挂点存在且语义正确：

- 接管事件的入口（由动画事件调用）与幂等保护；
- 结束回调（由动画事件调用）与**兜底路径**；
- 打断入口（被死亡/击飞/眩晕调用）；
- 对象池复位（`ResetEnemy` / `ResetShieldGuard` 一类）与实例禁用路径。

改动应**只影响目标单位**：新增字段而不是重命名既有字段；如必须改共享代码（例如通用的表现路由），用「该组件是否存在/当前形态」这类条件把影响限制在目标单位，并说明对其它单位的影响。

## 9. 阶段 H：静态核验（不进入 Play）

接入前：对**保护文件清单**记录哈希。
接入后，逐项确认：

- 目标文件引用完整（Clip ↔ Controller ↔ 精灵 ↔ 独立对象 Prefab ↔ 代码字段）；
- 事件方法名可在被引用组件上解析到；
- Clip 长度符合时长契约；键位与帧序一致；
- 旧分离层已清空（sprite 为空、transform 已复位）；
- 场景与关卡配置**未被顺带修改**（若该单位已在关卡里，不重复添加；不改 dirty 场景）；
- **非目标文件哈希不变**；
- 编译与域重载完成，Console 无新增 error。

**明确不成立**的等价关系：编译通过 ≠ 动作合格；导入成功 ≠ 引用完整；方法返回成功 ≠ 表现正确；Inspector 数值正确 ≠ 运行时行为正确。

## 10. 不变量总表（跨角色、跨动作都必须为真）

1. 一个动作只用**一个全局缩放**，没有逐帧缩放/逐帧 trim。
2. 对齐只钉**脚底**，横向不重锚定。
3. 新精灵的导入设置与同角色已部署精灵**逐项一致**；不改全项目设置。
4. 替换素材只覆盖 PNG 字节，保留 `.meta`。
5. 由代码计时切换的状态：**Clip 长度 == 玩法时长字段**。
6. 需要与显示同步的接管**必须**挂在「本体已无该物件」的那一帧。
7. 事件方法名必须真实存在；改名/删除前检查所有 AnimationEvent 绑定。
8. 会被接管的旧子渲染器必须有**显式清空键**，且池复位要复位它。
9. 独立物件**只生成一次**，脱离后不跟随敌人的移动与形变。
10. 打断路径要么「未到点取消」要么「已脱手由世界对象完成」，二选一明确。
11. 接入改动**只落在目标文件**；非目标文件哈希不变。
12. 未经用户验收，不标记为通过。

## 11. 决策表

### 表 1：新动作与已部署参照尺寸不一致怎么办

| 选项 | 适用条件 | 代价 / 风险 |
|---|---|---|
| A. 把**一个全局缩放**烘焙进该动作的像素 | 现有单位新增动作；改单位 scale 会破坏其它已验收动作 | 该动作像素密度与其它动作不同，必须与参照在**同中性底**上比对；后续若要再加动作，沿用同一取值 |
| B. 调**单位 scale** | **新单位**，尚无其它已验收动作 | 影响该单位全部动作与碰撞盒/血条，需要按基准单位反算 |
| C. 重做/重选素材 | 缩放后仍明显失真（部件被压扁、细节丢失） | 成本最高；不得用「看起来差不多」掩盖 |

> 表 1 的取值(a) 不写进规范；每个动作/批次把取值与证据写进核验记录。

### 表 2：脱离物件的表现方案

| 选项 | 做法 | 代价 |
|---|---|---|
| A. 物件画在本体帧内 + 引擎生成独立对象 | 脱离前不需要额外的层；脱离由事件触发 | 每个持物件的动作都要把物件画进帧；接管与生命周期必须验证 |
| B. 分离层子物体（由 clip 驱动） | 不需要在帧里画物件 | 每个 clip 都要给物件打 sprite 键与位置曲线；固定层序会跨排压层；池复位债务 |
| C. 只在 clip 内做位置曲线，不建对象 | 最省事 | 无法做物理感/自毁；被外部打断时容易残留 |

### 表 3：结束时机用事件还是计时

| 条件 | 选择 |
|---|---|
| 动画可能被卡肉/暂停/变速，或接管必须精确落帧 | **事件** |
| 无对应 clip，或纯代码表现 | 计时**兜底**（同样受暂停约束） |

## 12. 已知行为与陷阱（含对策）

| 现象 | 原因 | 对策 |
|---|---|---|
| Clip 长度比设定值多出一帧 | Unity 按最后一个键的时间 + 一个采样间隔自动延长 PPtr clip | 把末帧保持键放在 `目标时长 − 1/采样率`，创建后回读实际长度 |
| 结束回调提前/滞后触发 | 用墙钟计时，但动画被卡肉暂停或变速 | 改用动画事件（§5） |
| 物件跟着敌人漂 / 人淡物件不淡 | 独立对象挂在敌人子层级，或没继承透明度来源 | 脱离瞬间读取姿态一次并脱离层级；透明度取本体同一来源 |
| 新实例带着上一个动作的残件 | 池复位没清空旧子渲染器 | 在复位路径显式清 sprite 与 transform |
| 打断后出现双物件或空转 | 打断路径与正常路径都生成了物件，或流程没有终止条件 | 幂等保护 + 两条路径明确二选一 |
| 读 `.anim/.controller/.prefab` 报错 | 这些资产禁止直接读文本 | 用 Unity API / Property Tree 读取 |
| 写核验报告时序列化异常 | 直接序列化 Unity 结构类型（如 Vector3）会因自引用属性失败 | 报告只输出原生数值/字符串，或用 JsonUtility |

## 13. 交接与验收边界

- 收尾只做「接入 + 配置 + 静态核验」；**通知用户开游戏验收**，不自动进入 Play、不采样动画、不追加画面自检。
- 交付回复必须写清：改了哪些目标文件、哪些是保护文件、核验了什么、**哪些没有验证**（尤其是只能游戏内判断的手感、尺寸观感、时序衔接）。
- 未进行游戏验收时，状态只能写「已接入待验收」，不得写「已完成/已通过」。
