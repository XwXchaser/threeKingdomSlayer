# 本地绿幕抠图工作流（非 GPT 路线）

> **用途**：源素材是绿幕（chroma green）视频帧，且 GPT 语义抠图路由不可用（或需要免费/批量/离线）时的**权威配方与验收口径**。
> **来源**：2026-10-04「1011 持剑敌军攻击帧」抠图 13 次失败的完整复盘，并与已验收的 `Enemy_1011_idle1.png`（GPT 语义抠图产物）、`Enemy_1011_hit1..5.png`（本地键控产物）以及成功案例 `matted_final/attack_fXXX_final.png` 逐像素比对得出。
> **维护方式**：新对话如需完善本流程，只改本文件；改动必须附"实测数值 + 已验收参照物对照"，不接受只凭描述的结论。
>
> **路线优先级（2026-10-04 用户定调，先读这条）**：**当前 GPT 语义去背依然是最可靠的抠图路线**（本项目已验收的 `Enemy_1011_idle1.png` 与 Walk 6 帧均出自它）。本流程是**免费/离线**路线，适用于**静止或慢动作的锐利绿幕源**（过渡带/实体 ≈0.07 量级），并作为对照基线；对**快速动作源**直接走 `skill/workflows/image-asset-generation.md` 的 GPT 语义去背分支。

## 0. 适用与不适用

适用：

- 源素材背景是**纯色绿幕**（实测背景绿优势 d_bg 稳定，如 d≈96、边框 std ≤ 2）。
- GPT 语义抠图路由落在 B 类后端（`background=transparent` 被忽略）时的兜底路线。
- 需要与既有"本地键控风格"素材保持一致的批量处理。

不适用（改用 GPT 语义抠图）：

- 源素材是灰底/复杂底（如本项目 idle 视频的 (44,43,48) 灰底）。
- 需要语义理解（背景与主体同色、半透明物体）的场合。
- **快速动作源（跑动、甩动等）：实测边更软、描边偏绿，本流程再怎么调参数都到不了已验收基线**——2026-10-04 Walk v4 实测：过渡带(d 20–80)/实体 = **0.104–0.118** vs dead 0.073 / attack 0.077 / idle 锚点 0.016；边缘相邻实体环 gEx **−30** vs idle −54 / attack −66.6；而同 d 的 alpha 映射曲线与参照**一致（甚至更紧）** → 差异来自源而不是参数。此时只有“噪声底抬高”有效（清压缩幽灵残影，v4 可见像素 274k→146k）；外扩环半径自适应反而更灰、α<12 归零≈无效果，继续拧只会落到 §4 记录的“硬边+弱须”。

## 1. 开工顺序（先判定路线，再抠图）

1. 发 **1 次** GPT 语义去背探针（`background=transparent` + `output_format=png`），并读回指纹：
   - G 类（`cdn.jd23kjs.work` / `img.zxai.us`，或完全无回显）→ **原生 RGBA**（主体 alpha 多为 251–254，几乎没有 255）→ 批量走 GPT，本流程仅作对照；
   - B 类（`r2.52image.xyz`，回显无 `background`，usage 明显偏大）→ **RGB 无 alpha**（主体 alpha=255 为主）→ 立即停手，转本地路线。
2. 每张图都要**读 PNG 实际的 Color Type 与 alpha 直方图**，不能只看 HTTP 200。
3. 判定为本地路线后，先取"定标素材"：同角色的**已验收**素材（本项目：`Assets/Sprites/Enemy/Enemy1_1/Enemy_1011_idle1.png`、`Enemy_1011_hit3.png`），本篇所有阈值都以它们为基线。

## 2. 三条支柱（缺任何一条都会产生"绿边 / 淡边"）

### 支柱 1：alpha = 覆盖率的连续映射，**禁止硬化**

- 逐帧实测两个端点：背景绿优势 `d_bg`（取画布边框环中位数）与角色本体绿优势 `d_char`。
  本项目实测：`d_bg ≈ 96`、`d_char ≈ −46`（角色美术 0% 偏绿）。
- **权威实现（2026-10-04 修正）**：不要再自行推导公式，直接用成功案例的脚本：
  `Library/Locus/tmp/matting_green_screen_v2_CANONICAL.py`（副本；原文件在 attack 任务目录 `matting_from_raw_v2.py`，按需只改输入/输出路径与帧表）。它已包含下列 6 步，**缺任何一步都会得到“金属半透明 / 淡边”**：

  1. **软切 + 噪声底**：`d_cut = d_bg − max(6, 6%·d_bg)`，使被压缩的底噪恰好落在 α = 0（避免整幅画布留一层 3% 的雾）；
  2. **双模型反混合**：分别假设前景是“暖色”与“中性（白 / 亮部）”，取反混合后不溢出 [0,255] 的那个（平局取更小的 α）；
  3. **enclosed-hole fill（本次我漏掉的关键一步）**：被实心剪影包住的浅色 / 高光区域（= **金属、甲片高光**）**强制置为不透明**；否则这些区域一直是半透明，肉眼就是“**金属色丢失**”；
  4. 反混合去污染 `C' = (C − (1−α)·B)/α`；
  5. 2px 环颜色替换（把边界环颜色向外传播，并给 2px 外扩区上色）；
  6. 硬绿保证 `g ≤ max(r,b)` + 2px 外扩之外的全透明像素 RGB 清零。

- 若仍要手写 alpha，最低限度是“覆盖率 + 软切 + 噪声底”：

```python
d_cut = d_bg - max(6.0, 0.06 * d_bg)                 # 噪声底：底噪落在 α=0，而不是留一层 3% 的雾
d_art = median(d[core])                              # 深层内部 d 的中位数（实测值）
cov   = clip((d_cut - d) / (d_cut - d_art), 0, 1)    # d = g - max(r, b)
```

- **50% 覆盖率点必须落在 d 的中点**（本项目 d≈25）。把中点放到 47（第一版）或 65（V6–V9）会把整圈"背景与角色混合"的像素都判成半透明 → 得到"实心边 + 一圈淡须"，肉眼读作淡绿/灰绿描边。
- 验收形状（**从实心核向外逐环的 alpha 均值**）：

| 环 | 合格（成功案例） | 不合格（本次失败版） |
|---|---|---|
| 实心核（α=255） | 98,989 px（源覆盖 ≥0.9） | 151,145 px（核太大） |
| 外 1px | **224** | **79** |
| 外 2px | **207** | 57 |
| 外 3px | **157** | **2**（须边消失） |
| 外 4px | 127 | 1 |
| 外 5px | 87 | 0 |

- 结论：合格边是"平滑羽化 5–6px"，不合格边是"硬边 + 1–2px 弱须"。后者必被读成淡色绿边。

### 支柱 2：去绿**仅限边界环**，**禁止** `g = max(r,b)`，**禁止对角色内部做颜色替换**

- **禁用写法**：`g = max(r, b)`。对暖色描边（r>g）它把绿通道抬到红的高度：(80,39,45) → (80,**80**,45) 橄榄绿；而且这类像素的绿优势**恰好 = 0**，用"绿优势 > 5"的阈值永远测不出来（本次 V9 有 6,131 个这样的像素，指标却报 0）。
- **禁用写法 2（2026-10-04 dead 案例新增）**：把"非绿主导（gex > 2）"当脏像素判据，再对整个可见区域做颜色替换。这会把**金属 / 中性白 / 亮部**误判为脏：干净像素只剩最亮的那些，颜色从它们向内部泛滥，**角色内部整体被冲淡**（实测内部 RGB (111,71,75) → (147,95,94)，**ΔRGB ≈ 22–26**，用户描述为"金属色严重丢失"）。金属像素的 gex 在 **+20 左右仍属正常**（冷灰、蓝灰），不能用 gex ≤ 2 当干净线。
- 正确做法：**只处理边界环**（内侧 ~2px + 外侧整条半透明带），内部一律保留反混合后的原色：

```python
# (a) 反混合去污染：用支柱 1 的真实 alpha
C1 = clip((C - (1 - alpha) * BG) / max(alpha, 0.05), 0, 255)

# (b) 外侧带取"边界环自身的颜色"（= 角色那圈深色描边色），向外传播直到覆盖整条外侧带
inner2 = (alpha >= 0.99) & ~erode(alpha >= 0.99, 2)    # 角色自身边界环
outer  = (alpha > 0) & (alpha < 0.99)                  # 外侧半透明带（可能宽达 6px，必须传播满）
for it in range(10):                                   # 传播到不再变化，或上限 10px
    ... 从 inner2 向外填色到 outer ...

# (c) 整条边界环内"确实偏绿"的像素才压绿，并留 -3 余量（避免产生"绿优势恰好 0"的橄榄色）
ring = shift_or(shift_or(alpha >= 0.99)) & ~erode(alpha >= 0.99, 2)
col[...,1] = where(ring & (gex(col) > 0), max(r, b) - 3, g)

# (d) 内部（距边界 ≥4px 的实心像素）不做任何替换/压绿
```

- 关键：边界环上的金属像素 gex ≈ −10 ~ −15（冷色），**不会被 (c) 命中**，所以金属与描边的完整性都能保住。实测（2026-10-04 dead 6 帧）：内部 ΔRGB = **0.0**、金属 ΔRGB = **0.0**、边界环合成偏绿像素 = **0**。

- 目标量级（相对同一源帧）：

| 指标 | 合格（成功案例） | 本次失败版 |
|---|---|---|
| 被污染带（源 gEx≈+81）处理后 | **≤ −60** | −15（仍接近中性） |
| 全帧可见像素 Δ(R,G,B) | **+17.6 / −12.3 / +8.6** | +2.3 / −2.3 / +0.2（几乎没处理） |
| 描边 gEx | −66.6 | −48.8（=源值，未处理） |

- 自检：**不得存在成片的"绿优势恰好 0"像素**（尤其沿描边一圈）。

### 支柱 3：全透明区必须清零

- 反混合在 α→0 时会把背景噪声放大 `1/0.05 = 20` 倍（±3 噪声 → (40,60,20) 暗绿）。**所有 alpha=0 的像素 RGB 必须置 0**。
- 可选保留 **2px 外扩色**（供过滤与描边 Shader 采样），其余全透明像素置黑。
- 自检：透明区"绿优势 > 5"的像素数必须为 **0**。

## 3. 验收清单（每次抠图逐项过，缺一项不得交付）

| # | 指标 | 合格线 | 测量方式 |
|---|---|---|---|
| 1 | 可见像素合成白底后绿优势 > 0 | **= 0** | `comp = C*α + 255*(1−α)`；`(comp_g − max(comp_r,comp_b)) > 0` 计数 |
| 2 | 可见像素合成白底后绿优势 > −5（读作灰绿/橄榄） | ≤ 已验收参照同量级（idle1 26,603 / hit3 5,264） | 同上，阈值改 −5 |
| 3 | 描边（实心且 lum<100）颜色 | 与源帧同源：gEx 差值 ≤ ~15；"绿优势恰好 0"占比 ≤ 3% | 与源帧同坐标逐像素比 |
| 4 | 透明区 | 绿 RGB 像素 **= 0**，RGB 全 0（或仅 2px 外扩） | 直接扫 alpha==0 的 RGB |
| 5 | 羽化剖面 | 符合支柱 1 的"合格形状" | 从实心核向外逐环统计 alpha 均值 |
| **3c** | **不透明核占比＋浅色区不透明度（2026-10-04 新增）** | 与已验收同源素材同量级（本项目 attack/dead 素材 ≈ **0.53–0.57**、idle ≈ 0.83）；**金属/高光区必须 α≈1** | 统计 α≥0.99 占 visible 比例；再单独看浅色/低彩度子集（lum 120–215、chroma<45）的 α 均值 |
| 6 | 几何 | 脚底行与源帧一致（本项目非特效帧 = **777**）；**禁止横向重锚定** | 与原源帧 bbox/脚底比对 |
| 7 | 人眼定标 | 用户对"1 帧 × 边缘 8× 放大 + 已验收素材同框"的对照图给出部位级结论 | 必经，禁止用指标代替 |

## 4. 失败模式速查（2026-10-04 攻击帧 13 次失败复盘）

| 错误做法 | 指纹（实测） | 为什么指标测不到 | 修正 |
|---|---|---|---|
| 硬化 matte（cov ≥ 0.5 视为实心） | 羽化 255/79/57/2 | 均值/"绿优势"阈值看不出"边太硬+须太弱" | 支柱 1：alpha = 覆盖率 |
| `g = max(r,b)` 中和 | 橄榄像素成片（g == max(r,b)），绿优势**恰好 0** | 用 ">5" 阈值 → 永远 0 | 支柱 2：干净色替换 / 反混合 |
| 透明区不处理 | 放大 20 倍的绿噪声，1,578–12,491 px/帧 | 只看"可见像素"的指标漏掉 | 支柱 3：透明区清零 |
| 只修暗部像素（lum<120） | 亮甲片边、白弧边仍残留绿 | 污染判定不能只看亮度 | clean/非 clean 全量处理 |
| 反复换参数（T1/T2、hard_level、ring 半径） | 每版一个新目录，共 11 个 `keyed_*` | 验收对象错位，问题从 1 处变多处 | 先定标、单版本、旧版明确作废 |
| 单点指标（均值、">5"）当验收 | 与肉眼结论长期冲突 | 缺陷落在阈值盲区 | 三件套：合成白底的可见像素 + 透明区 + 羽化剖面 |

**一句话总结**：失败版把三处都选在了错的一侧——**硬化 alpha、保留源色、透明区不管**；成功案例是**覆盖率连续 alpha、强力去绿、透明区清零**。

## 5. 协作协议（必须遵守）

1. **定标先行**：抠图前先做 1 帧、边缘 8× 放大、与已验收素材同框的对照图，让用户指出"哪一帧、哪个部位、什么方向"，再动手。
2. **单一候选**：同一时刻只保留一个候选目录（带版本号）；产生新版本时必须明确宣告旧版本作废，并建议删除旧目录。
3. **结论只认量化项与路径**："已修好"必须给出本清单各项实测值与完整文件路径，不接受"应该没问题"。
4. **以磁盘为准**：工具回执不可信时，用 `exists / size / mtime` 三查核对产物，再报告。
