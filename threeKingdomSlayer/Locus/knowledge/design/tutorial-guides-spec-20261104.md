# 引导（教学）规格 · 全量梳理（2026-11-04）

> **这份文档是所有引导的唯一口径。** 改引导前先看这里；实现与本文冲突时，以本文为准（并同步改本文）。
> 起因：2026-11-04 之前，交接文档 §3.2 把「Tap 教学用 `TutorialGestureHint.Gate`」当成事实，
> 实际**教学拍根本不用 Gate** → 照着做出来的解锁引导与教学拍不一致，反复返工两轮。

---

## 0. 术语

| 词 | 含义 |
|---|---|
| **教学拍（beat）** | 一段「教玩家做某个操作」的演出：**等目标到位 → 冻结 → 示范循环 → 玩家做对 → 收拍**。由 `TutorialStageDirector` 驱动。 |
| **招式教学** | 教学拍的一种：教玩家做出某个招式的手势（点戳 / 连点三下 / 横划…）。 |
| **门槛（Gate）** | `TutorialGestureHint.Gate(...)`：暂停整个游戏 + 拦输入 + 原始输入自判的**旧机制**，**当前全工程无人使用**，不是教学机制。 |
| **常驻引导** | `AttackTapIndicator`：敌人身上的手+光圈，提示「可以点这里攻击」，常驻。 |

## 1. 五条原则（2026-11-04 用户定）

| # | 原则 | 落地要求 |
|---|---|---|
| **P1** | 引导只出现在**玩家能停下来看**的时刻 | 不在战斗进行中插教学；教学拍期间敌人被冻结、场景压暗 |
| **P2** | 引导**不能被玩家的顺手操作**误完成 | 完成判据 = 玩家做了**指定手势**且**招式真的打中敌人**（空挥不算） |
| **P3** | 只教一次；「教过」的判据 = 玩家真的做到了 | 做不到就**不写存档**，下次进关再教 |
| **P4** | 教学关专属的行为**必须自己判路线** | 教学导演是常驻组件（挂在 Battle.scene，切场景会重建）→ 不能靠「一次性标志位」 |
| **P5** | **只有一种教学形式**：所有招式教学都是教学拍 | 解锁引导 = 教学拍，不另起表现 |

## 2. 教学拍的标准形态（所有招式教学统一）

```
① 等目标到位      目标敌人走到前排、站定（FindTargetEnemy + hintWaitForEnemySeconds）
② 冻结            敌人冻结（SetEnemiesHold）+ 场景压暗（SetSceneDim）+ 手势闸门只认这一招
③ 示范循环        PlayGestureAt(kind, from, to) 循环播（TapCombo 用 PlayTapLoop）
④ 玩家做对        手势闸门放行 → 招式打出去 → **打中敌人**（敌人受击事件确认；空挥不算）
⑤ 收拍            手势提示层收掉 → 该招式转为「已教」（白名单放开）→ 补播收尾台词
```

- 完成判据：**`OnTutorialAttackExecuted`（招式打出去）+ 敌人受击（真的打中）**，两者都满足才算「攻击成功」。
- 招架拍例外：成功判据是「真的格到了」（`LastParryBlocked`），不打伤害。
- 防御拍 / 技能拍不是招式教学：判据分别是「进入防御姿态」和「敌人的霸体招被打断」。

### 3.1 招式解锁引导（#2）细则

- **触发**：天赋节点配了 `moveGuideGesture` + 招式已解锁 + 存档里没教过 → 由 `MoveGuideService.CollectPending` 收集。
- **时机**：**开波那一刻**（`OnWaveStarted`），排在教学关自己的拍**前面**；正式关同样适用。
- **形式**：完全等同教学拍（§2）——等敌人到位、冻结、示范循环、玩家划出横扫**并打中敌人**才收拍。
- **收尾**：收拍后补播该天赋节点自己的台词（`guide_move_slash`：「手指横着划过去 —— 横扫一排敌人！」），台词为**教学类**（自动推进，不把游戏暂停等点击）。
- **「已教过」**：**只有招式真的打中敌人**才写 `SaveData.taughtMoveGuides`；没打中 → 下次进关再教。
- **正式关**：解锁引导**要教**（这是玩家第一次用这招）；但**三选1 教学不教**（见 3.2）。

### 3.2 三选1 教学（#3）细则

- **只在教学路线上教**（`IsOnTutorialRoute()` 判断，不靠一次性标志位）。
- 正式关升级弹三选1 时：**不念台词、不指卡片、也不「只让玩家选推荐的那张」**——那是教学关的规则。
  （2026-11-04 用户定：「你见过教两次同样操作的教学吗？」）

### 3.3 常驻引导（#6）与教学手势的互斥

- 教学手势提示在屏上时，常驻引导整体收起（`AttackTapIndicator.Update` 里 `hint.IsShowing` 判定）。
- 反向：常驻引导在教学关也会出现（敌人到前排就有）→ 教学拍期间靠上面的互斥收起。

### 3.4 台词的硬规则

- **一行文字必须和手势示范**同时出现**（不是收拍后补播）。
  - 教学关的「波次台词」通道（`n1Dialogues` / `e0Dialogues`）= **拍前**台词（敌人站定后、开拍前推）。
  - 「招式解锁引导」的一行文字 → 走**新增的 `TutorialGestureStep.beforeDialogue`**（同样是拍前）。
  - `afterDialogue` 只给「补充说明」用（例如连点三下后的「多次攻击可以打断」）。
  - **冻结拍（教学把游戏冻住的那一拍）用 `TutorialGestureStep.freezeDialogue`**：
    「用技能打断」这一拍是**冻结时**才需要告诉玩家「点下面的技能图标」→ 台词必须和冻结时出现的
    手势示范同时上屏。
    ❗**不要拿 `afterDialogue` 干这件事**：那一拍是「靠放技能收拍」的，而 `afterDialogue`
    只在「靠出招收拍」的路径上播（`RegisterBeatHit`）→ 挂上去也**永远不会出现**。
    （2026-11-05 实测：那句「用技能打断它」从来没上过屏。）
  - ❗ 同一句话**不能同时**挂在波次台词通道和 `afterDialogue` → 会**播两遍**
    （2026-11-04 实测：`tutorial_t0_wave1` / `tutorial_t0_wave3` 各被挂了两处 → 已清掉 afterDialogue 那两处）。
- **教学关所有台词都是 `nonBlocking=1`（不阻塞 → 不暂停游戏）**。
  引导台词 `guide_move_slash` **也必须是 `nonBlocking=1`**（2026-11-04 实测：`nonBlocking=0` 会让
  `DialogueManager` 把 `Time.timeScale` 压成 0 直到自动推进结束（~5 秒）→ 正式关里表现为「莫名其妙暂停」）。
- 台词类型：`eventType=Tutorial` → 自动推进（不用点掉）；`Conversation` → 要玩家点击。

### 3.5 手势示范的硬规则

- **示范的滑动方向必须和这一拍要求的手势一致**（横划拍 → 示范必须横着划）。
  - ❗2026-11-04 实测踩过：引导拍没设 `from01/to01` → 用了类默认值 `(0.5,0.5)→(0.5,0.72)` = **向上挑**，
    而闸门要求横划 → 示范教上挑、判定要横划 → 玩家照着做根本过不了。
  - → **已加运行时自检**：`AssertDemoDirectionMatches`（对**所有**拍生效）→ 方向不一致直接 `Debug.LogError`。
  - 横划轨迹：`(0.2,0.5)→(0.8,0.5)`（同一 y）；竖划：`(0.5,0.25)→(0.5,0.75)`（同一 x）。
- 示范位置**每轮重新取活着的目标敌人**（敌人被打死后光圈不能停在尸体上）；没有活目标就收掉提示层。

| 问题 | 根因 | 处理 |

| 正式关 N1 弹三选1 教学 | `OnChoicesReady` 没有路线门槛；教学导演常驻 + 切场景重建 → 标志位复位 | 加 `IsOnTutorialRoute()` 门槛 |
| 敌人攻击播 QTE UI 音；启用防御播招架音 | `_enemyAttackTelegraphClip` 指到 `QTE_block1`；`SetDefend` 里 `PostEvent("Player_Parry")` | 敌人攻击音 → **待办**（要一个「挥武器」音效，见交接文档 T7）；启用防御不播招架音 → 见 T7 |

> ① **TMP 文字必须有带中文字形的字体**：`TMP_Settings.defaultFontAsset` 是 `LiberationSans SDF`（**没有中文字形** → 中文全是空白）→ 必须用「方正粗黑宋简体 SDF」。

> ③ **`localScale` 是倍率不是尺寸** → 尺寸和缩放别同时乘。

### 4.3 长枪冻结（问题 6）

- 现象：玩家打出点戳后，**枪还在空中没收回来**（敌人被冻住了，枪没有）→ 蓄力姿势对不上。
- 机制：枪停在回收段中途等蓄力，是游戏自己的「**连段蓄力保持**」（`AttackSystem.BeginComboChargeHold` → 枪体换蓄力素材帧）；但它平时跟着「**手指按住**」走 → 玩家还没按住时枪就自己收回去了。
- 修：这一拍期间 ① `PlayerState.freezeWeaponStance` → **持枪姿态的推进停住**；② 阶段 2 **每帧重新声明一次** `BeginComboChargeHold()` → 枪一直举在蓄势位；玩家中途松手（没蓄满）也还是举着 → 可以再蓄一次（收拍时才 `EndComboChargeHold()`）。

### 4.4 引导的落点与「只教一次」（2026-11-04 第三轮）

| 问题 | 根因 | 修 |
|---|---|---|
| 主菜单指引**不在按钮正中心** | ① 锚点用的是 `rectTransform.position` = **pivot** 的位置（很多 UI 的 pivot 在角上：「开始关卡」按钮的 pivot 在**顶边中点** → 实测偏 **129px**）② 按压动画绕**掌心**旋转 → **指尖被甩离目标**（实测偏 44,-68px） | ① 锚点改用**视觉中心** `TransformPoint(rect.center)` ② 手的位置**每帧反算**（抵消当前旋转+缩放）→ 指尖始终钉在目标上 |
| 天赋页解锁后**没人教怎么回主菜单** | 天赋教学只有两步（节点 → 确认），解锁完就结束 | 加**第 3 步**：指面板左上角「返回」；点返回 = 教学完成（写标记） |
| 「点开始关卡」引导**反复出现** | 没有「这段教程已完成」的标记 | 新增存档标记 `taughtStartStage`；**只在落地页（路线 Ready）** 引导，玩家一进战斗就写标记 → 同一教程里不再出现 |

> **两条可复用的经验**：
> ① 引导的锚点要用 `rect.center`（视觉中心），**不要用 `rectTransform.position`**（那是 pivot，很多 UI 的 pivot 在角上）。
> ② 带旋转/缩放动画的手，位置必须**每帧反算**，否则指尖会随动画甩离目标。
