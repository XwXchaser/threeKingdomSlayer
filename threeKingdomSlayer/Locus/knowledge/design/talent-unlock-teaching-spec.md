# 天赋解锁教学 · 指向突刺（stabC2）硬性教学 —— 需求与方案（2026-11-04）

> **本文只做「需求梳理 + 方案」，不改代码。** 实施前请先确认 §5 的三个未决点。
> 配套：`design/tutorial-guides-spec-20261104.md`（教学拍标准形态）· `design/stage-configuration.md`（关卡数值约束）

---

## 0. 一句话结论

要教的东西是**两段式输入**（点戳 → 在接续窗口里按住蓄力满 → 松手 = 派生招式「指向突刺」），
它**超出现有教学拍的能力边界**（教学拍只会教「单个手势」），
而且**当前配置下这个输入窗口极窄**（按下的时机要在点戳后 0.15s 内、蓄力要 0.3s、接续窗口总共 0.2s）——
**所以第一件要做的事不是写教学，是先把「派生招式到底打不打得出来」这件事定死。**

### 1.2 天赋面板的交互现状（**没有任何教学**）

```
点节点 → OnNodeClicked（选中，详情卡展开）
      → 点确认按钮 → OnBuyClicked → TalentTreeState.TryUnlock(tree, node)
      → 反馈文字：已解锁：X / 已经解锁过了 / 前置节点还没解锁 / 铜钱不足：需要 N，当前 M / 这个节点还没有配好解锁内容
```
（`TalentTreePanel.cs:1086 / 1099`）

- **面板第一次打开时没有任何引导**：玩家不知道「节点要花铜钱」「前置要先点」「确认按钮在哪」。
- 存档里**没有「已看过天赋教学」的标记**（`SaveData` 只有 `unlockedTalents` / `claimedSupplyIds` / `unlockedManuals` / `taughtMoveGuides`）。
- 面板在 **TalentTree.scene（overlay 场景）**里 → **战斗场景的 `TutorialGestureHint` 提示层用不了**（场景切换即销毁）→ 面板内教学必须**面板自己画**。

### 1.4 派生招式到底怎么打出来（**这是本次需求的技术核心**）

`Zhangfei_Jab1.moveEdges`（`Assets/ScriptableObjects/Moves/Zhangfei/Zhangfei_Jab1.asset`）：

| 边 | 手势 | 蓄力要求 | 窗口 | 后继 |
|---|---|---|---|---|
| 1 | `Tap`(0) | 0 | 默认（Stab 0.48–0.95） | Jab2（连点三下） |
| 2 | **`Hold`(1)** | **1（蓄力满）** | **override 0.55–1.0** | **Zhangfei_StabR2（指向突刺）** |

⇒ **指向突刺 = 点戳（Jab1）→ 在接续窗口内按住到蓄力满 → 松手。**（`PlayerMoveStateMachine.cs:302-347` 的连段边匹配；天赋锁 `IsMoveLocked` 在 `PlayerMoveStateMachine.cs:328/354`）

**接续窗口的实测宽度**（窗口是招式动画进度的比例，`NormalizedTime = _elapsed / _duration`）：

| 量 | 值 | 出处 |
|---|---|---|
| Jab1 动作时长 | **0.45s** | `Zhangfei_Jab1.actionDuration` |
| Hold 边的窗口 | 0.55–1.0 → **0.2475s ~ 0.45s**（宽 **0.2s**） | 同上 |
| 一级蓄力所需按住时长 | **0.3s**（`chargeLevelTimes = {0.3, 0.6, 1.0}`，按 `Time.time` 计） | `InputManager.cs:53/68` |
| ⇒ 可行性 | 玩家必须在**点戳后 0.15s 内按下**，按住 0.3s，**在 0.45s 前松手** | 算术 |

**中立态拿不到指向突刺**：`MoveTable_Zhangfei.roots` 只有 Tap→Jab1、Hold→Slash、Hold+蓄力→（另一个）、斜划→Slash —— **StabR2 只能靠连招拿到** ✓（与需求一致）。

## 2. 需求

### R1 · 天赋页硬性教学（教「如何解锁天赋」）

| 项 | 需求 |
|---|---|
| 触发 | 玩家**第一次打开天赋页**（教学关结算后的第一个落地页） |
| 教什么 | ① 天赋页是什么 ② 节点要花**铜钱** ③ **前置节点要先点** ④ 选中节点后要点**确认按钮**才解锁 |
| 形式 | 面板内**自绘**的硬性引导：压暗 + 一只指向目标的手 + 一行文字 + 玩家必须按提示操作 |
| 完成判据 | 玩家**真的解锁了第一个节点**（`TryUnlock` 返回 Success）才算教完 |
| 教完 | 写存档标记 → 以后不再出现 |
| 失败/放弃 | 关闭面板 = 放弃本次教学（不写标记，下次再教）；不阻塞玩家离开 |

### R2 · 招式硬性教学（教「连招中释放蓄力技打出派生招式」）

| 项 | 需求 |
|---|---|
| 触发 | **解锁「指向突刺」之后的第一场战斗**（沿用 `moveGuideGesture` 机制：解锁后首次进关触发一次） |
| 教什么 | ① 先**点一下**（点戳）② **立刻按住不放**（蓄力到满，看枪身蓄力视觉）③ **松手** → 打出派生招式「指向突刺」 |
| 形式 | **两段式教学拍**（新拍型）：第一段示范点戳 → 第二段示范按住蓄力 → 玩家完成「点戳 + 蓄力松手」 |
| 完成判据 | **派生招式（StabR2）真的打出来并打中敌人**（不是普通点戳） |
| 教完 | 写 `taughtMoveGuides`（现有机制即可） |
| 依赖 | **§5.1 的窗口问题必须先解决**（现在的窗口对新手不成立） |

### R3 · 「硬性」的含义

- 阻塞式：教学没完成前，相关操作被拦住（面板里不给解锁别的节点 / 战斗里手势闸门只认这一招）。
- 必须玩家完成：不做完不写「教过」。
- 只教一次：靠存档标记。

### R4 · 不在本次范围

- 天赋页的**三维/美术改版**、天赋页的新交互（当前是二维分页）。
- 其余招式节点（`talent_move_stabc4` 枪突收尾 / `talent_move_slashc2` 斩击C2 / 招架）的教学 —— 本次只做 stabC2，但**机制要能复用到它们**。
- 正式关数值（见 §6）。

## 3. 目标流程（时序）

```
① 教学关结算（250 铜钱）
        ↓
② 落地页 → 玩家点「天赋」→ TalentTree.scene（overlay）
        ↓
③ 【R1 硬性教学】面板自绘：讲天赋页/铜钱/前置/确认按钮
        ↓
④ 玩家按指引解锁「指向突刺」（花 1 铜钱）→ R1 完成，写标记
        ↓
⑤ 玩家回到落地页 → 进正式关（第一场战斗）
        ↓
⑥ 【R2 硬性教学】战斗内两段式教学拍：
   示范「点一下」→ 示范「按住蓄力」→ 玩家做对（派生招式打中敌人）→ 收拍 → 一行文字
        ↓
⑦ 写 taughtMoveGuides → 以后不再教
```

**为什么 R1 放在面板内、R2 放在战斗内**：解锁动作发生在面板（那里才有铜钱/前置/确认按钮）；
招式的手感只能在战斗里教（要有敌人、要有枪身蓄力视觉、要有命中反馈）。

## 4. 方案

### P0 · 数据与文案前置（不改玩法数值）

| 做什么 | 为什么 |
|---|---|
| 写 `talent_move_stabc2` 的正式 `description`（现在还是「（测试节点）」） | 天赋详情卡直接显示它 |
| 新建两条台词资产：R1 的天赋页说明、R2 的「点一下→按住蓄力→松手」提示 | 复用现成 `DialogueEventData`（教学类 + `nonBlocking=1`，见教学规格 §3.4） |
| `moveGuideGesture` 填什么 | 见 §5.2（现有枚举表达不了两段输入） |

### P1 · 存档标记

- `SaveData` 加一个「已看过天赋页教学」标记（新增分片，沿用 `SaveSections` 模式）。
- 复用 `taughtMoveGuides` 记 R2（节点 id 即可）✓ 现有机制。

### P2 · 面板内教学（R1）

- **在 `TalentTreePanel` 里自绘**（不用战斗的提示层 —— overlay 场景里它不存在）。
- 需要的最小能力：压暗 + 一只指向的手 + 一行文字 + 「玩家必须点到这个节点/这个按钮」的引导状态。
  → 面板已经是程序化生成的，**加一层 overlay + 一个高亮框**即可，不新建场景。
- 引导状态机：指向节点 → 玩家点了别的 → 回到指向；指向确认按钮 → 等 `TryUnlock` 成功 → 教学完成。
- 关闭面板 = 放弃（不写标记）。

### P3 · 两段式教学拍（R2）

- 新增拍型 `GestureHintKind.ComboCharge`（或等价的「两阶段」拍）：
  - 阶段 1：示范「点一下」→ 等玩家点（第一段招式真的打出去 = Jab1）。
  - 阶段 2：示范「按住蓄力」（光圈收缩 + 枪身蓄力视觉）→ 等玩家按住到蓄力满并松手 → 派生招式打出去。
  - 判据：**打出的是 StabR2**（不是普通 Stab）→ 需要在拍里区分「这一下是派生招式」。
- 完成判据沿用现有的「打出去 **且** 打中敌人」。
- 天赋锁：未解锁时 `IsMoveLocked` 会让输入不成立 → **教学必须在解锁之后才排得上**（现有 `CollectPending` 已经按「已解锁」过滤 ✓）。

### P4 · 验收

| 项 | 怎么验 |
|---|---|
| R1 | 机器人/脚本：打开天赋页 → 教学出现 → 按指引解锁 → 标记写入；再打开 → 不再出现 |
| R2 | 机器人：解锁后进关 → 教学拍出现 → 注入「点戳 + 蓄力松手」→ 派生招式打中 → `taughtMoveGuides` 写入 |
| 回归 | 教学关全流程（`TutorialFlowDriver`）、正式关编队与数值不动 |

## 5. 风险与未决（**动手前必须定**）

> ✅ 2026-11-04 用户已裁决三条：
> **① 窗口问题走 A**（教学期冻结时间 + 教学期蓄力按 unscaled 计）· **② 新增 `ComboCharge` 拍型** · **③ 数值崩坏 = 敌人血量远超原教学关设定**（见 §6）。

### 5.1 派生招式的窗口对新手不成立（**已定：方案 A，但冻结的对象改了**）

- 现状：点戳（Jab1，动作 0.45s）→ 按住蓄满（0.3s）→ 松手 → 指向突刺（StabR2）。
  接续窗口 = Jab1 动作进度的 0.55~1.0 → **只有 0.2s 宽**。
- ⚠️ **我上一轮算错了一点**：状态机本来就有「**时钟推进到接续窗口起点就停住**」的驻留机制
  （`PlayerMoveStateMachine.IsWaitingForHold`）→ 玩家**只要点完继续按住**，机器就会停在窗口起点等它
  → 真人**是可做到的**（不用抢 0.15s）。
- ✅ **最终方案（已实现并验证）**：教学拍把**招式状态机的时钟**冻住（`PlayerMoveStateMachine.Frozen` / `SetFrozen`）
  → 接续窗口**一直开着** → 玩家从容地「再按住 → 蓄满 → 松手」。
  - ⚠️ **不能用全局 `timeScale=0` 冻结**：`InputManager.IsPointerDown` 要求 `timeScale > 0`
    → 一冻结指针就判为未按下 → **连招蓄力直接断**（实测代码得出）。
  - ⚠️ 因此**不需要**改蓄力的时间基准（蓄力本来就是真实时间算的）→ 上一轮定的「蓄力改 unscaled」**作废**。
- 教学拍的两段（用户指定）：
  1. **阶段 1**：像点戳教学那样，玩家**点一下**打出第一记戳（真的打出去并打中敌人）。
  2. **阶段 2**：**接续窗口打开时冻结** → 闸门换成 `ComboHold` → 玩家**按住蓄满 → 松手** → 打出指向突刺。
- ⚠️ **阶段 2 的闸门不能用 `BlockAll`**：教学闸门在手势路径的**第 1 道**（`InputManager.ProcessTutorialGate`），
  排在「连招释放」那道**前面** → `BlockAll` 会把连招的松手一起 drop 掉 → 单独开了 `TutorialGestureTarget.ComboHold`
  （只放行「蓄满后的按住松手」，其余拦掉）。

### 5.2 `moveGuideGesture` 表达不了两段输入（**已定并已实现：新增 `ComboCharge`**）

- 现有枚举：`None / SwipeHorizontal / SwipeVertical / Hold / Tap` —— 只能表达单手势。
- **已定并已实现**：新增 `MoveGuideGesture.ComboCharge` + `GestureHintKind.ComboCharge` + `TutorialGestureTarget.ComboHold`；
  新增 `TutorialGestureStep.comboPhase2Dialogue`（阶段 2 的台词）；节点新增 `TalentNodeConfig.moveGuidePhase2Dialogue`。
- 拍内判定靠**阶段**而不是招式类型：阶段 2 的闸门是 `ComboHold` → 那一拍里玩家除了「按住松手」什么都做不了
  → **阶段 2 的命中必然来自派生招式**（不需要区分招式资产）。
- ⚠️ 待查：连段窗口没赶上时（第一记戳打得太晚）→ 教学拍会**回到阶段 1 让玩家再点一记**（已实现）。

### 5.3 面板内教学的自绘工作量

- 面板是程序化生成的 → 加 overlay + 高亮 + 指向手，**不需要新场景、不需要美术**（用现成的 `TutorialGestureStyle` 素材口径）。
- 但**面板在 overlay 场景**，得确认素材（手/光圈）在 `TalentTree.scene` 里有 —— 否则要复制一份（注意：不要 `Resources.Load`，按项目的反幽灵引用规范）。

### 5.5 面板内教学（R1）与存档标记（P1）—— ✅ 已实现并实测（2026-11-04）

| 项 | 实现 |
|---|---|
| 存档标记 | `SaveData.taughtTalentPanel`（bool）+ `TalentSaveSection.IsTalentPanelTaught / MarkTalentPanelTaught` |
| 教学形态 | 面板**自绘**（不用战斗的 `TutorialGestureHint` —— 面板在 overlay 场景，那个会被销毁）：压暗层（不拦点击）+ 一只手（指尖落在目标上）+ 一个光圈 + 一行文字 |
| 贴图 | 复用战斗场景同一套素材：`tutorial_gesture_finger_ui` / `tutorial_gesture_hold_ring_ui`（已在 `TalentTree.scene` 的面板组件上配好） |
| 步骤 | 0 = 指向一个「**现在就能解锁**」的节点（前置已满足 + 铜钱够）；1 = 指向详情卡的【解锁】按钮 |
| 教学目标选取 | **优先「招式解锁」分类**（这条教学链就是「解锁一个招式」）→ 当前分类 → 其余 |
| 完成判据 | **真的解锁了一个节点**（`TryUnlock` 返回 Success）→ 写标记 → 以后不再教 |
| 放弃 | 关闭面板 = 放弃（**不写标记** → 下次打开还教） |

## 6. 另一条线：正式关数值（**用户已指明：敌人血量远超原教学关设定**）

### 6.1 已实测的事实（2026-11-04）

| 项 | 数值 | 结论 |
|---|---|---|
| 教学关 1011 的血量 | **100**（`Tutorial_N1_Battle` 倍率 = 1） | 教学关的基准 |
| 正式关 1011 的血量 | **470 ~ 610**（N1 5.8 / E0 5.9·6.1·5.0 / N2 4.5·2.9·3.5 / N3 4.7·5.6·4.4·4.7·3.7） | **是教学关的 4.7~6.1 倍** ⚠️ |
| 正式关 N1 第一波清场（**刚打完教学关的真实状态**：无天赋节点） | **30.9s** | ✔ 铁律八（普通波 30–55s）**合规** |
| 铁律八 | 普通波 30–55s | ✔ 合规（但只看**波次时长**，不约束**单只敌人的 toughness**） |
| 「没 C2 就卡死在 E0 的 1012」 | **已过时**：本次实测机器人（无天赋）**清过了 E0** 一路打到 N3 | 设计文档该条要更新 |
| 各波 `waveId` | N3 五波、E0/N2 三波**全是 0** | ⚠️ 数据不卫生（运行时按**列表下标**走 → 暂时不影响战斗） |

### 6.2 问题的实质

**约束表（铁律八）管的是「波次时长」，没管「单只敌人的 toughness」**。
于是：波次时长合规（30.9s ✔）**且** 单只敌人的血量是教学关的 **4.7~6.1 倍** —— 两者可以同时成立，这就是「数值崩坏」的来源：
**玩家在教学关学的是「1011 几下能杀」，进正式关立刻变成 4.7~6.1 倍的硬度** → 手感断层。

### 6.3 建议的修法（**保持铁律八不变的前提下**）

| 方案 | 做法 | 影响 |
|---|---|---|
| **D（推荐）** | **波次总血量不变（时长不变），把血量从「集中在 1~3 只」摊到「更多只」** → 单只硬度回到教学关量级 | 编队要改（敌人数量↑），倍率↓；铁律八自动保持 ✔ |
| E | 教学关敌人血量也抬到正式关水平 | 教学节奏变长（教学失去「一下一下很快」的手感）✘ |
| F | 正式关倍率下调，接受波次时长 < 30s | **违反铁律八** ✘ |

⇒ 走 **D** 时要一并回答：**波次里塞多少只、倍率取多少**（要按「玩家实际 DPS 模型」反推，而不是沿用 2026-11-03 那份按「中期玩家」算的倍率）。

### 6.4 与教学流程的耦合（**重要**）

- 正式关 E0 波 2 含 **1012（霸体）** → 设计文档说「没 C2 会被卡住」；**本次实测已不复现**（机器人无天赋也清过了）→ **「C2 是通关必需」这个前提现在不成立** → R2 硬性教学的定位是**设计选择**（教一个玩家主动解锁的招式），不是**通关门槛**。
- 但**教学的血量口径必须和正式关一致**（§6.2）→ **数值那条线要先出结论，R2 的验收标准才能定**（教学里「打中敌人」这一条判据的松紧度取决于血量）。
