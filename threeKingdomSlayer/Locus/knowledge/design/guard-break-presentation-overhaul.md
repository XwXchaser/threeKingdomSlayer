# 格挡 / 破防表现改造（方案 A）· 设计与认知

> 状态：**已实施（2026-11-13），待用户实机验收**（A1/A2/A3 三批全部落地；实施清单与实测数据见
> `plan/bugs-and-requests.md` REQ-006 与 `plan/guard-break-handoff-20261112.md` §7）。
> ★ 实施时按用户拍板：**破防不打断攻击者的攻击表现**（不切受击动画）⇒ 「被打方受击表现」那一层未做，
>   只做「冻结 → 慢放 → 回 1」。
> ★ **2026-11-13 晚第二轮（用户反馈「没有慢放感 / 武器生硬」）**：又改了节奏 ——
>   ① 慢放窗口从「后坐那一小段」改成**盖住整段脱手旋转**（后坐 = 冲击 1×，脱手 = 重量 0.35×）；
>   ② 旋转曲线从「前慢后快」改成「**先快后慢**」（`1-(1-k)²` = 甩出去后失速）；
>   ③ 新增**起手余震**（3°，衰减抖动 ⇒「被顶了一下」）；
>   ④ 敌人的慢放改为**每帧重申**（敌人状态机有 6 处写 `animator.speed` 会踩掉它）。
>   详见 `plan/guard-break-handoff-20261112.md` §8。
> 配套交接：`plan/guard-break-handoff-20261112.md`（逐条现状与复跑配方）。
> 上游：`design/guard-break-feedback-20261109.md` §5.3、`design/combat-hit-feedback-direction.md`、`memory/hit-feedback-system.md`。

## 0. 一句话

破防那一拍"完全没有时停感"，根因不是幅度不够，而是**顿帧落错了对象**（落在自己的枪上 ⇒ 读成"我的动作卡了一下"）＋**没有命中确认**（无闪白、无火花 ⇒ 画面上没有任何东西在说"打中了"）＋**慢放作用在枪上而不是时间上**（0.35× 只作用于持枪姿态 ⇒ 读成"枪变慢了"）。

本方案按《影之刃零》「完美格挡 / 完美闪避」的**演出语法**重建这一拍：判定点 → 顿帧 → 闪白 → 音效 → 镜头 → 奖励，取我们有的载体落地。

## 1. 认知

### 1.1 PBZ 的机制层〔来源：本地 `design/pbz-reference-analysis-20261109.md`，2026-11-09 调研〕

| | 完美格挡（精防） | 完美闪避 |
|---|---|---|
| 判定 | **在被击中的瞬间点按防御键**（不是按住；连按不生效、一直按住也不触发） | 闪避有**独立时间窗口**（饰品"浑源经脉仪"可把**完美防御/完美闪避的窗口 +15%**） |
| 成功代价 | 免伤 + 不耗己方杀气 | — |
| 成功收益 | **削对方杀气 + 回自己杀气 + 自动触发「鬼步」接近敌人** | 特殊演出（把敌人扔的炸药丢回去）或直接触发鬼步贴身 |
| 后续 build | 反击护腕（完美格挡后 2s 伤害 +20%）、影魅面具（完美格挡触发鬼步后生成 3 个面具自动攻击） | 读招信号：蓝光=可精防、红光=只能闪避、黑光=精防但代价大 |

**关键语义**：PBZ 的完美格挡/闪避是**成功事件**，时停是"你做到了"的**奖励信号**。
⚠ **我们的"破防"是失败事件** —— 用子弹时间会读成"我赢了"，语义不合（详见 §4）。

### 1.2 PBZ 的演出层〔来源：Wikipedia 开发章节 + 行业通行语法〕

- 〔Wiki〕制作人 Liang 原话：战斗"以极快的速度进行……**突然的电影化终结技会动态切换镜头到远景或近景**"⇒
  **成功瞬间会"切镜头"**，不只是抖屏 —— 这是演出级介入。
- 〔通行〕"成功瞬间"的 6 层语法（缺一层就读不出来）：

| 层 | 做法 |
|---|---|
| ① 判定点 | 帧精确的那一帧（交击的那一下） |
| ② 顿帧 | 交击处**局部**定格 2~6 帧；PBZ 的完美闪避升级为**子弹时间**（整幅画面慢下来 + 高对比/去色 + 镜头推近 + 敌人悬停） |
| ③ 闪白 | 接触点爆出高对比白光（把那一小块画面打亮） |
| ④ 音效 | 极短金属交击（高频瞬态）+ 一记低频"闷"（胸腔感） |
| ⑤ 镜头 | 极短**推近**（不是抖），或切近景 |
| ⑥ 奖励 | 削敌/回气/触发追击 ⇒ 让"完美"值得追求 |

### 1.3 本项目的结构性约束（全部已实测，不是推断）

| 约束 | 证据 | 对方案的影响 |
|---|---|---|
| **玩家没有可见身体** | Battle 场景 `Player` 对象 = `Transform + PlayerHitFeedback + ThornArmorEffect + ChargeStabVisual + PierceAimIndicator + PlayerMoveStateMachine`，**无 SpriteRenderer / 无 Animator** | 玩家侧只有「**枪**」一个载体；"玩家被弹开"这类第三人称表演无法对标，只能对标**语法**不能对标**载体** |
| 远景天空是**钉在屏幕上的 clip 空间四边形** | `Assets/Experiments/CurvedScroll/Shaders/YSkyBackground.shader` 手写 `clipXY`、不过投影矩阵 | 相机一动它不动 ⇒ 震动时必须让它**跟滚转**、**不跟平移**（跟平移会与远景错位 ⇒ "背景和场景不同步"，2026-11-12 已犯过一次） |
| **材质染色无法提亮** | 敌人 `Custom/EnemyOutline`、武器 `Custom/WeaponColorUnlit` 都是**乘法混合**，`_Color` 是染色乘数 ⇒ white 只能去染色 | 真闪白必须**新增 `_FlashStrength` 通道**（`lerp(c.rgb, white, s)` 后 `*= c.a`），并用 `MaterialPropertyBlock` 驱动（敌人 `EnemyOutline._PierceHighlightStrength` 是现成范式） |
| 敌人的"停"是**冻结**不是慢放 | `Enemy.PushSuspend` → `_animator.enabled = false` | "停"与"慢"是两种读法：冻结=卡住，慢放=被打飞。**破防该用慢放** |
| 相机的 component 必须**落盘** | 2026-11-12 实测：`CameraFeedbackController` 曾是未落盘 + `enabled=false` ⇒ 域重载保留 managed 状态 ⇒ 改 C# 默认值对它无效，**Inspector 调参也无效** | 任何改到该组件参数的需求，都必须**同时写进场景资产** |
| 所有张飞招式反馈强度都是 **Standard** | `Zhangfei_*.asset` 的 `stabFirstHitStrength / slashFeedbackStrength = 2` | 配合 `heavyOnlyCameraShake=true` ⇒ **普通命中本来就不震镜头**；会震的只有格挡/破防/玩家受伤/Heavy 命中（Launch/Displacement/Ultimate） |
| 相机震动要挂在 **Tween** 上，不能挂 `LateUpdate` | 震动本体是 DOTween 驱动（与组件 enabled 无关） | 任何"跟着震动走"的表现（背景跟随）都必须挂在震动 Tween 的 `OnUpdate` |

### 1.4 已试过并被否掉的方向（**不要重走**）

| 试过的做法 | 结果 | 教训 |
|---|---|---|
| 全局 `Time.timeScale` 时停（1→0.02 保持 0.1s 再回正） | **用户反馈"完全没有时停感"** | 顿感来自**对比**（被打的定住、其它还在动）；全局齐停 ⇒ 没有对比 ⇒ 读成掉帧；且与 `memory/hit-feedback-system.md`「局部表现暂停，不修改全局 Time.timeScale」冲突 |
| 顿帧期间把镜头改成 scaled + 背景跟随相机平移 | 制造"背景和场景不同步" | 背景是**无穷远层**：平移时它本就不该动；只有**滚转**必须跟 |
| 大幅镜头震动（旋转 = 强度×80°，vibrato 14 ≈ 127Hz） | **用户反馈"像地震"** | 竖屏第一人称下，整屏旋转甩出 ~2% 屏宽 + 127Hz 高频抖动 = 地震。已改为 20°/单位 + 4 次 + 总幅度 ×0.35（≈4.4 像素 / 0.64°） |
| 只在枪上做慢放（0.35× / 0.15s） | 读成"枪变慢了" | 慢放要落在**对方**（被打的）身上，或落在**时间**上（子弹时间） |

## 2. 对照与根因

### 2.1 六层对照（破防这一拍）

| 层 | PBZ 完美格挡 | 我们现在 | 缺口 |
|---|---|---|---|
| ① 判定点 | 命中瞬间点按（窗口判定） | 破防值满（累积判定） | 语义不同（失败 vs 成功） |
| ② 顿帧 | 交击处**局部**定格 2~6 帧 | 4 帧，但定格在**自己的枪**上 | **定格落错对象** |
| 被打方反应 | 对方武器被弹开 / 被钉住 | 攻击者 Animator 被**冻结**（`enabled=false`） | 冻结 ≠ 慢放；无"受击"表现 |
| ③ 闪白 | 接触点高对比白光 | **无** | 缺"命中确认" |
| 火花 | 有 | **无**（玩家打敌人时才有） | 缺 |
| ④ 音效 | 金属交击 + 低频闷响 | 复用 `Guard_Block`（=普通格挡音） | 缺专属音 |
| ⑤ 镜头 | 极短推近 / 切近景 | 4.4 像素位移 + 0.64° 倾斜 | 缺"推近"这种**时间感**演出 |
| ⑥ 奖励 | 削敌/回气/鬼步 | 无 | 玩法层（§4 方案 C） |

### 2.2 四条根因（为什么"还是没有时停感"）

1. **定格没落在"被打中的东西"上** —— 玩家防御时可见形象只有枪 ⇒ 定格枪 = "我的动作停了"。
2. **没有命中确认** —— 没有闪白、没有火花 ⇒ 画面上没有任何东西说"打中了"。
3. **慢放作用在枪上而不是时间上** —— 0.35× 只作用于持枪姿态。
4. **定格没有被强调** —— 4 帧（66ms）孤零零静止，旁边什么都没有 ⇒ 只是"微卡"，不是"顿住了一瞬"。

## 3. 方案 A：局部演出包（推荐，本轮要做的）

### 3.1 目标时序（破防那一拍，60fps 帧号）

```
f0     命中帧：攻击者开始被"顶住" + 接触点爆出火花 + 枪闪白 + 红边框闪 + 专属音 + 枪被顶开
f0-3   定格 4 帧：世界几乎静止，但火花/闪白/边框在动      ← 这才是"顿"
f4     攻击者转入 0.25× 慢放 + 镜头开始极短推近（0.08s 进）
f4-18  慢放 ~0.35s：枪的脱手旋转、对方的被顶开，一起放慢
f19+   全部回正常速度（0.2s 内），破防硬直开始
```

**关键**：定格期间**必须有东西在动**（火花/闪白/边框），否则 4 帧静止就是"卡了一下"而不是"顿住了一瞬"。

### 3.2 六层逐层规格

| 层 | 落点（文件 · 接口） | 做法 | 参数（建议起点） | 风险 |
|---|---|---|---|---|
| **被打方慢放** | `Assets/Scripts/Enemy/Enemy.Combat.cs`（`PushSuspend`）/ `EnemyHitFeedback.cs` | 破防时不再只"冻结"，改为：冻结 0.25s 之后以 `Animator.speed = 0.25` 慢放 0.35s，再回 1 | 冻结 0.25s / 慢放 0.25× / 0.35s | 与既有 `SuspendSource` 挂起叠加要做成"可叠加、可单独解除"；慢放结束必须还原 `speed = 1`（对象池复用会带脏值） |
| **被打方受击表现** | 敌人现成的 `PlayHitVisual()`（`HitFlash`/`HitLeft`/`HitRight` 状态） | 破防时让**攻击者**播一个"被顶开"的受击动画（现在它只是被冻住） | 复用 `HitFlash` | 敌人正在攻击 ⇒ 受击动画会打断攻击表现 ⇒ 需确认是否接受（PBZ 里成功格挡确实会让对方武器被弹开） |
| **闪白（枪）** | `Assets/Shaders/WeaponColorUnlit.shader` 新增 `_FlashStrength`；`Assets/Scripts/Effects/MeshWeaponVisual.cs` 用 `MaterialPropertyBlock` 驱动 | `c.rgb = lerp(c.rgb, white, _Flash)` 后 `c.rgb *= c.a` | 强度 1 → 0 用 0.12s | MPB 要在对象回收/销毁时清；不能实例化材质（会 GC） |
| **火花（命中点）** | `Assets/Scripts/Core/PixelHitEffectManager.cs` `RequestHit(context)` | context.enemy = 攻击者、worldPosition = **接触点**；强度取 Heavy | 复用现成通路 | **需要拿到接触点坐标**（现在 `TryAbsorbDamage` 只拿得到 `source` 敌人 ⇒ 要取敌人的受击点/武器位置） |
| **屏幕红边框** | `Assets/Scripts/Player/Combat/PlayerHitFeedback.cs` 新增公开方法；复用 `Assets/Sprites/BattleHUD/hitted.png` | 破防时闪一次红边框（比普通受击更短更红） | 0.25s 停留 + 0.1s 淡出 | `hittedImage` 目前是**普通受击**用的 ⇒ 两套频率不要打架 |
| **专属音效** | `Assets/Scripts/Services/AudioManager.cs` | 加 `Guard_Break` 事件 + `PostEvent(name, pitch, volume)` 重载（现有没有 pitch/音量参数）；素材先用 `_guardBlockClips` 降调 + `_heavyHitClips` 叠一层低频 | pitch 0.75 / volume 1.4 | 需要**加 API**；素材最终版待补 |
| **镜头推近** | `Assets/Scripts/Core/CameraFeedbackController.cs` 新增 `RequestGuardBreakPush()` | FOV 60 → 58 脉冲（0.08s 进 / 0.25s 出）；**不是抖** | FOV 幅度 ≤2° | ⚠ **FOV 会动构图**（用户对构图敏感）⇒ 必须小幅度 + 可一键关闭 |

### 3.3 参数落点

- 全部进 `AttackSkillConfig`（真值写进 `Assets/Prefabs/UI/Skills/Zhangfei_Parry.asset`），沿用 `Tools ▸ 三国杀戮 ▸ 招架姿态调参` 窗口的滑条惯例。
- 建议新增字段（名称待实现时定稿）：
  `parryGuardBreakHitStopFrames` / `parryGuardBreakEnemySlowScale` / `parryGuardBreakEnemySlowSeconds` /
  `parryGuardBreakWeaponFlashSeconds` / `parryGuardBreakScreenFlashSeconds` / `parryGuardBreakPushDegrees`。
- ⚠ **改完必须写进资产并 `AssetDatabase.SaveAssets()`**（域重载会保留 managed 状态；2026-11-12 踩过：代码改了 0.02、运行时仍是 0.1）。

### 3.4 实施顺序（分 3 批，每批可独立验收）

| 批 | 内容 | 验收 |
|---|---|---|
| **A1** | 被打方慢放 + 受击动画（敌人侧） | 破防时能看到"对方被顶住/被打慢"，而不是"我的动作停了" |
| **A2** | 闪白（枪）+ 火花（命中点）+ 红边框 | 破防那一帧画面上出现明确的"命中确认" |
| **A3** | 专属音效 + 镜头推近 | 声音与镜头把这一拍"钉"住；FOV 可关 |

### 3.5 明确不做（本轮边界）

- ❌ 不做全局 `Time.timeScale` 时停/子弹时间（§1.4）。
- ❌ 不改相机的震动幅度体系（已解决"地震感"，别再动）。
- ❌ 不改格挡/破防的**判定与数值**（破防阈值 120、衰减 30/秒、硬直 1.5s、防御锁 3s 全部不动）。
- ❌ 不引入"完美格挡"的新输入判定（那是方案 C）。

## 4. 方案 B / C（另开）

### 4.1 方案 B：子弹时间（PBZ 完美闪避观感）——**建议不做**

要成立必须**同时**满足，否则就是掉帧：
1. 明确的进入曲线（0.05s 压到 0.2）+ 明确的退出曲线（0.25s 回 1）；
2. 画面高对比 / 去色（后期或全屏 shader）；
3. 白闪 + 专属音 + 镜头推近；
4. **只在"成功"事件上用**。

⇒ 破防是**失败**事件，子弹时间会读成"我赢了"。这套应该留给方案 C 的"完美格挡"。

### 4.2 方案 C：把 PBZ 的"完美格挡"搬过来（玩法层，需用户拍板）

- 现在"防御"只有**按住**，没有"点按的时机判定" ⇒ 玩家永远拿不到"完美"这个状态。
- 若引入**精准格挡**（敌人命中帧前后 ±X 帧内按防御键 ⇒ 判为完美）：免伤 + 削敌 + 缩短破防值 + **成功向**的时停演出（方案 A 的那套，但语义是成功）。
- 代价：新的输入判定（点按 vs 按住冲突 —— 按住即防御是现有基础）、判定窗口、UI 提示、教学要改。**范围大**，但这是 PBZ 结构的核心。

## 5. 风险与回归清单

| 风险 | 影响 | 对策 |
|---|---|---|
| 特效叠太多糊成一团 | 破防那一帧最多 3 层动态（火花/闪白/边框） | 分批实施，每批单独验收；层数上限写死 |
| 敌人受击动画打断攻击表现 | 攻击者的攻击被"被顶开"取代，玩家可能觉得"我的格挡生效了但对方没事" | 先在 A1 单独看，确认可接受再往下做 |
| FOV 推近动构图 | 用户对构图敏感 | 幅度 ≤2° + 一键关闭 + 单独验收 |
| 慢放期间敌人攻击判定继续跑 | 敌人可能"慢着打"、出伤时机被拉长 | 慢放只改 Animator 的 `speed`，**不改攻击判定时钟**（判定走 `Time.deltaTime` 仍是正常速 ⇒ 会出现"动作慢但判定正常"的错拍 ⇒ 需要一起想清楚） |
| 命中点坐标缺失 | 火花不知道往哪儿放 | 从攻击者的受击点/武器位置取；取不到就退回枪尖位置 |
| 旧场景实例吃不到新参数 | 改了不生效 | 参数写进资产 + 运行时兜底（照 2026-11-12 的做法） |

## 6. 验收方式

- **脚本驱动**：真实 player loop 协程逐帧采样（配方见 `plan/guard-break-handoff-20261112.md` §2.1）。
  ⚠ `unity_execute` 片段的 `await` 循环**不执行 MonoBehaviour 的 Update** ⇒ 采样必须走协程；姿态要用 **scaled** `Time.deltaTime` 驱动，否则与 timeScale 脱钩。
- **实机**：破防那一拍的"爽不爽"只能由用户在真实战斗里判断（脚本测不出）。
