## 0. ⚠️ 本文的素材参考边界（**最重要的一节**）

### 0.1 **不提供任何现有项目美术资源作为参考**

**当前项目里已有的图标、UI 素材、角色、场景、特效，绝大部分是凑数 / 临时的。**
→ 它们**只能**作为技术接线参考（资产路径、挂点），**不能**作为画风参考、构图参考或配色参考。

**本文因此不包含任何现有素材的图片、截图或「照着这个画」的指引。**

### 0.2 唯一允许的画风依据

| 允许 | 内容 | 说明 |
|---|---|---|
| ✅ **画风权威** | `design/art-style-guide.md` | 完整画风规范（笔刷 / 金属 / 色彩关系 / 图标原则 / 特效原则） |
| ✅ **概念图（用户提供）** | 战场概念图 + 战斗界面概念图（路径见 `art-style-guide.md` §2.1） | 这两张图**已包含 UI、HUD、图标、特效的方向** |
| ✅ **已验收的角色样本** | 1011 六帧 Idle（路径见 `art-style-guide.md` §2.2） | 仅用于确定「可部署角色的具体标准」——**形体 / 材质 / 比例** |
| ❌ **禁止** | `Assets/Sprites/**` 下的一切图标、UI、角色、场景、特效 | 旧美术 / 临时素材，**不得引用为参考** |

> `art-style-guide.md` 原文已写明这条边界：「其他既有角色、场景、图标和 UI 素材均属于旧美术，只可作为技术接线参考，**不能反向定义本风格**」。本文与之一致。

### 0.3 **菜单 / 天赋页这类尚未在概念图中展示的页面**

`art-style-guide.md` §7 已给出可继承的语言：

> 菜单、奖励卡、对话面板和科技树等尚未在这两张概念图中展示的页面，可**继承笔刷、金属和高可读信息的语言**；这些属于后续设计推导，**不能称为已经验收的具体界面**。

→ **天赋页属于这一类**：风格从概念图的 UI 语言**推导**，不是在照抄任何现成界面。

### 0.4 交付方式：**按编号交付，不按功能名**

```
TT_Icon_Vitality.png      ← 生存向「铁血」节点图标
TT_Branch_Charge.png      ← 蓄力流 分支标识
```

功能会改、节点会增删、分支会重划 —— **编号与语义稳定，画面可以随时改**。

> **文件名沿用 `TT_` 前缀**（TalentTree 命名空间）→ 工程师只需在 Inspector 换引用，**代码零改动**。
> ⚠️ 交付时**建议用新文件名**（如 `TT_Icon_Vitality_new.png`），由工程师替换旧资产 —— 避免同名覆盖导致 GUID 变化、场景引用丢失。

### 0.5 ⚠️ 功能可能会更改 —— 抗变更约定

| # | 约定 | 为什么 |
|---|---|---|
| 1 | **素材 ID 按「功能语义」命名，不按「画面描述」命名** | 功能改名 → 素材不用重做（例：`TT_Icon_SlotActive` 表达「主动槽」这个概念，不表达「+1」） |
| 2 | **图标只表达「类别 / 机制」，不表达「具体数值 / 关卡 / 等级」** | 数值会变、等级会变、关卡会变；图标不该跟着变 |
| 3 | **节点标题用文字，不用素材** | 改名零成本 |
| 4 | **分支标识可缺省**（标题文字兜底） | 分支增减 / 重划不阻塞面板实现 |
| 5 | **节点三态底图全局共用一套** | 新增节点类型不需要新底图 |
| 6 | **秘籍图标按「技巧类别」而非按每个秘籍** | 新增秘籍不需要新图 |
| 7 | **一切素材标 P0 / P1 / P2** | P2 可整体延期；功能没定的先不做 |

### 0.6 变更影响矩阵（**功能改了先查这里**）

| 若这项功能变更 | 受影响的素材编号 | 影响程度 |
|---|---|---|
| 天赋节点增删 | 对应 `TT_Icon_*` | 小 |
| 分支重划 / 合并 / 拆分 | `TT_Branch_*` | 小（可缺省） |
| 大页面增删 | `TT_Tab_*` | 小（文字为主） |
| 节点改名 | **无**（ID 不变） | 无 |
| 节点语义微调（如「巧思」从 +1 改成 +2 槽） | `TT_Icon_SlotActive` 类别不变 | 小 |
| 技能重做（数值大改） | 技能节点图标**语义不变** | 无 |
| 秘籍种类变化 | `TT_Manual_Icon_*` 按类别 | 中 |
| 面板版式改版（滚动 ↔ 分页） | `TT_Panel` / `TT_Node_*` 尺寸可能要调 | 中 |
| 战斗 UI 改版 | `TT_*` 需重新对色 | 中 |

### 0.7 反馈渠道

- 素材**按编号**交付 → 策划 / 工程按编号填进 Inspector
- 功能变更时**先改本文的编号清单**，再改实现 → 避免美术白做
- 本文带**变更记录**（§11），每次改动追加一行

## 1. 玩家实际看到的三段体感

| 阶段 | 玩家看到 | 玩家感受到 |
|---|---|---|
| **选路线** | 顶栏三个页（能力 / 招式 / 技能），每页下面若干条**分支**，每条分支是一条从起点往下走的链 | "这一局我想走哪条路" |
| **看内容** | 分支上挂着节点图标 + 名字 + 价格；前置关系用**连线**表达；锁定 / 可买 / 已解锁三种状态 | "还差哪一步" |
| **拿到东西** | 点一下就解锁；局内三选一里开始出现对应技能；秘籍则是在局内**打怪 / 打破坏物**掉落 | "我变强了" |

**关键认知**：玩家**不应该**在天赋页上看到大段数值说明。天赋页只回答「能拿到什么 / 还差什么 / 要花多少」，细节说明放节点详情。

## 3. 通用规格

### 3.1 图标类（A / B / D02–D05）

| 项 | 值 |
|---|---|
| 画布 | **正方形**，主体居中，四周留 **12%** 安全边距 |
| 透明 | 透明背景 Alpha，**不要**白底 / 棋盘格 / 背景场景 |
| 表现 | 小尺寸可识别**符号**，不是完整小插画（`art-style-guide.md` §7.3） |
| 焦点 | 单一视觉焦点，轮廓优先 |
| 禁忌 | 无多余文字、无无关边框、无柔光 / 厚涂 / AI 插画感 |
| 导入 | 与工程侧约定一致（PPU、Filter Mode、Compression、Alpha Is Transparency） |

**尺寸**

| 用途 | 建议画布 | 面板实际显示 |
|---|---|---|
| 节点图标（A 组） | 256 × 256 | 160 × 160 设计像素，`preserveAspect = true` → **正方形画布 + 居中留边即可** |
| 分支标识（B 组） | 128 × 128 | 小尺寸 |
| 秘籍类别图标（D02–D05） | 96 × 96 | 随卡片 |

### 3.2 UI 框架类（C 组 / D06 / E01）

| 项 | 值 |
|---|---|
| 气质 | 墨色 / 黑色**破边笔刷块**作为信息承托；金属、黄铜、金色作为边框与外圈；红色留给危险与重要数值（`art-style-guide.md` §7.1） |
| 构图 | 竖屏优先；关键操作适配安全区；**不堆叠成厚重面板**，避免遮挡（§7.2） |
| 可拉伸 | 面板底板 / 详情栏底板 / 提示条 → **九宫格（9-slice）**，横向拉伸不糊 |
| 交付 | 源文件 + 切图规格（**九宫格边距需在交付说明里写明**） |

### 3.3 连线（C09）

| 项 | 值 |
|---|---|
| 用途 | 表达「前置 → 后继」 |
| 形态 | 一条可**任意角度旋转**的直线段（工程侧按两节点坐标旋转摆放）→ 素材本身应**居中对称**、两端干净，旋转后不出头 |
| 交付 | 一张可拉伸长条（建议 512 × 64 或 1024 × 128），**中段可平铺** |
| 亮度 | 工程侧会整体染色（锁定 / 已点亮两态）→ **素材本身建议中性灰白**，或交付两态各一张 |

| 态 | 差异 | 工程侧会叠的色 |
|---|---|---|
| 锁定 | 去饱和 / 压暗 / 内部符号变灰 | `lockedColor` (0.32, 0.30, 0.28) |
| 可买 | 正常色 | `availableColor` (0.86, 0.70, 0.36，金) |
| 已解锁 | 提亮 / 描边高光 | `unlockedColor` (0.93, 0.90, 0.82) |

→ **三张底图必须是同一形状家族**，靠亮度与描边区分，**不要用完全不同的形状**（工程侧会叠色，形状不同会割裂）。
→ 底图本身**不要自带强色调**，否则叠完会脏。

## 10. 禁止项

- ❌ **不要把项目里现有的任何图标 / UI / 角色 / 场景 / 特效当作参考**（§0.1）

- ❌ **不要柔光 / 厚涂 / 写实 / AI 插画感**
- ❌ 不要在图标里画**人物立绘**（技能图标是「效果符号」，不是角色）
- ❌ **不要白底 / 棋盘格 / 背景场景**
- ❌ 不要**自建平行的素材目录**（统一 `Assets/Sprites/UI/Talent/`）
- ❌ 不要**逐帧改 Sprite Editor 锚点**去对齐（沿用 `design/visual-yoffset-system.md` 的偏移思路）
