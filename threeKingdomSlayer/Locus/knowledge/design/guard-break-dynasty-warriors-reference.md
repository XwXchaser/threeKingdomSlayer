# 破防表现的「无双口径」研究（2026-11-13）

> 起因：用户反馈「完全没有学到破防表现的精髓」，要求先学真·三国无双玩家破防时到底会发生什么。
> ⚠ **取材说明**：初次写作时本机网络被拦（fandom Cloudflare / 维基超时），只能靠既有认知；
> **2026-11-13 晚拿到代理后重查**，下面标「✔ 已核实」的条目都有一手出处（见 §0）。

---

## 0. 已核实的一手事实（2026-11-13 联网后）

| 事实 | 出处 | 对我们的意义 |
|---|---|---|
| 古典无双的**ガード**是「**按键时机**」机制，不是防御值槽：按住防御接下攻击的瞬间再按攻击键 ⇒ **反击并把敌人打倒**（ガードnirai = 闪到侧面绕后打） | ✔ JP 维基《真・三國無双》条目「操作方法→ガード」 | 无双的防御重心从来不在「把防御值打空」，而在**时机**；我们没有「点按完美防御」，所以只能用**破防条**这一版（项目已有口径） |
| **乱舞（Musou）进入子弹时间**：普通敌兵**慢速**，敌方将**不受影响**，玩家**正常** | ✔ EN 维基《Samurai Warriors》“Differences from Dynasty Warriors series” | ★ **这就是无双的慢放语法：慢的是「别人」，清晰且正常速度的是「自己」** |
| 格斗游戏里的 **guard crush** 机制：体力条下有**防御崩溃槽**，格挡会消耗它；**耗尽 ⇒ 防御崩溃 ⇒ 一段时间无防备** | ✔ JP 维基《CAPCOM VS. SNK 2》《対戦型格闘ゲーム》条目 | 破防的**语义是惩罚与窗口**（我们已有：硬直 + 防御锁） |
| 无双与 Samurai Warriors 的**武器不会因破防而脱手** | 系列内无「破防掉武器」这一状态（武器被打碎是另一套系统） | ⚠ 与我们「枪被打脱手飞出去」不同（用户拍板保留我们的做法） |
| ★ 用户本人（玩过无双）的第一手观察：**无双里玩家破防也会「慢放 + 模糊」** | 用户 2026-11-13 口述 | ⇒ **慢放 + 模糊就是要做的那一拍**，而不是可有可无的调味 |

> ⇒ 结论（写在最前面）：**无双的子弹时间语法 = 世界慢下来、拖成流线；我方清晰、照常速度。**
> 我们前几轮把慢放全堆在「自己的枪」上 ⇒ 既没有对比，也没有模糊 ⇒ 读不出来。

## 一、真·三国无双里，玩家破防时发生什么

### 1.1 机制层

| 事实 | 说明 | 把握度 |
|---|---|---|
| 防御有**耐久/防御槽** | 连打之下防御值归零 ⇒ 防御崩解（Guard Break / 防御崩し） | 高 |
| 崩解后**角色被击退 + 踉跄**，有一小段**不能行动** | 姿态失控、重心失衡（よろけ） | 高 |
| **武器留在手里** | 崩解不是「武器被打飞」；无双里没有这个状态（武器被打碎是另一套系统） | 高 |
| 崩解**给攻击方收益**：攻击方**继续压上**，形成追击窗口 | 破防是「惩罚」，不是「演出」 | 高 |
| 破防后防御**短暂不可用**，玩家要花代价脱离 | 逼玩家用移动/闪避解围 | 高 |
| 节奏要**快** | 无双的压迫感来自**速度差与连续压制**，不是慢放 | 高 |

### 1.2 演出层（冲击的三个载体）

| 层 | 无双怎么做 | 我们能不能抄 |
|---|---|---|
| ① **受击者的姿态垮掉** | 身体/持械姿态被压垮、重心失衡、被顶开一步 | 能（我们没有身体 ⇒ 用**持枪姿态垮掉**代替） |
| ② **攻击者的命中确认** | 敌人武器的打击特效 + 火花 + 撞击音 | 能（已有火花/闪白，但**对象错了**） |
| ③ **镜头一下** | 短促震动 / 极短拉近 | 能（已有震动 + FOV 推近） |
| ④ **音效** | 防御崩解的专属音（玻璃碎裂感）+ 打击音 | 能（现在是降调拼的，缺专属音） |

⚠ **无双的子弹时间语法（已核实）是：慢的是「别人」，清晰的是「自己」**。
   「破防该用慢放还是快节奏」取决于这一拍要表达什么；本次按用户口径 =
   **破防那一拍做「时停 + 慢放 + 模糊」**（见 §3.6）。

### 1.3 新作（SW:DW / 无双：起源）额外的一层：Guard Crush 演出

⚠ 把握度中：新作把「防御被击溃」做成了**明确的一拍演出**——镜头切近/压向角色、
画面边缘出现**碎裂/裂纹**特效、防御槽碎裂、角色踉跄，随后**敌人获得追击**。
⇒ 对我们最有价值的一点：**破防这一拍要给「防御崩解」一个专属的、独占的视觉事件**，
而不是用通用受击特效拼。

## 二、跟我们现做法的差距（2026-11-13 实现版）

| 维度 | 无双 | 我们现在 | 结论 |
|---|---|---|---|
| **武器** | 留在手里，**姿态垮掉** | **旋转 150° 飞出画面** | ✗ **载体错了**：玩家只看到"我的枪跑了"，看不到"我被打崩" |
| **攻击者** | **继续压上**（破防是他的收益） | 被**冻结 0.12s + 慢放 1.1s** | ✗ **方向反了**：破防让敌人变弱了 |
| **节奏** | 快；冲击 2~4 帧 + 踉跄 0.5~0.8s | 1.3s 慢放演出 + **硬直 1.5s** + **防御锁 3s** | ✗ 变成"被罚站"，不是"被压制" |
| **命中确认** | 敌人武器的打击特效 + 火花 + 碎裂 | 闪白打在**玩家自己的枪**上 + 红边框 | △ 有形但**对象错**：无双闪的是"对方打到你"的证据 |
| **慢放** | 不用于破防 | 当作破防的主要语言 | ✗ 用错了工具 |
| **防御锁** | 短暂失效，逼你解围 | 3s | ✗ 太长 |

> ★ 另有一条**我们违背了用户原意**的地方：用户 2026-11-13 拍板的是
> 「破防时**不要打断攻击者的攻击表现**」——"不打断"本来就该意味着**攻击者继续打**，
> 而我们实现成了「攻击者被冻住 + 慢放」。这是理解偏差，不是实现取舍。

## 三、改造方案（建议，待用户拍板后落地）

### 3.1 破防本体：把「枪被打飞」换成「枪被压垮」

- 破防时**枪不脱手、不飞出画面**；改成专属姿态 **BrokenCrouch**：
  从防御位过渡到「**枪尖被压到屏幕左下** + 枪身**下沉** + 略微**前倾**」，并带**被压的余震**（轻微颤）。
- 破防硬直期间保持这个垮掉的姿态；硬直结束后**收回防御位**（而不是重建枪）。
- ⇒ 玩家一眼看到的是「**我被打崩了、枪被压下去了**」，这才是无双的破防语义。

### 3.2 攻击者：从「冻结/慢放」改成「继续压制」

- 破防**不再冻结攻击者**（也不慢放）；他**把这一招打完**，并**追加一下追击**（若该敌人有追击手段）。
- 命中确认挂在**攻击者**身上（敌人武器的打击特效 / 敌人闪白），而不是玩家的枪。

### 3.3 节奏收紧

| 参数 | 现在 | 建议 | 理由 |
|---|---|---|---|
| 破防硬直 `parryGuardBreakDuration` | 1.5s | **0.8s** | 无双踉跄 0.5~0.8s；要让"被压制"而不是"被罚站" |
| 防御锁 `DefenseLockSeconds` | 3s | **1.2s** | 逼玩家快速解围，而不是站着等 UI 变亮 |
| 武器定格 `parryGuardBreakHitStopSeconds` | 0.033s | **0.05s**（3 帧） | 冲击靠"顿"，不靠慢 |
| 慢放 | 0.25× / 1.15s | **只保留 0.15~0.2s 的顿** 或**完全去掉** | 无双不用慢放演破防 |

### 3.4 「防御崩解」专属视觉事件（抄新作的 Guard Crush 那一拍）

- **屏幕边缘碎裂/裂纹**（全屏 overlay，0.25s 淡出）——这是"防御碎了"的独占符号；
- **镜头压近**（FOV 2~3°，0.1s 进 / 0.35s 出）+ 短促震动；
- **防御槽碎裂**（若 HUD 有破防条 ⇒ 破防瞬间整条碎掉，而不是平滑见底）。

### 3.5 保留我们已有的（无双里也成立的部分）

- 三层冲击的骨架：受击者垮 / 攻击者命中确认 / 镜头一下；
- 防御值累积与回落（无双的防御槽也是「打一下涨一点、不打就回落」）；
- 破防后防御短暂不可用（无双同款）。

### 3.6 ★ 本轮已实施：「破防那一拍 = 时停 + 慢放 + 径向模糊」（用户 2026-11-13 拍板）

> 依据：无双的子弹时间语法（§0 已核实）+ 用户口径「破防也会慢放 + 模糊」。
> 实现：`Assets/Scripts/Core/GuardBreakTimeFx.cs` + `Assets/Shaders/GuardBreakRadialBlur.shader`
> （组件已落在 Battle 场景 Main Camera 上，shader 走 Inspector 引用，符合 `design/anti-ghost-reference.md`）。

| 要素 | 做法 |
|---|---|
| **世界定格 / 慢放** | 全局 `Time.timeScale` 压到 **0.25**（**绝不用 0**：教学冻结/对话/三选一/暂停菜单都用 `timeScale <= 0` 判暂停），持续 **0.6s 真实时间** ⇒ 世界实际只走 0.15 秒游戏时间（约 9 帧）⇒ 读作**慢放**而不是卡帧；再回正 |
| **径向模糊** | 以**玩家**为焦点向外的 6 段采样拖影，半分辨率两趟（移动端可控）；强度 0.6、拖影 12px，0.04s 冲起 → 跟到慢放结束 → 0.35s 淡出；★ 复合阶段**再去饱和 + 压暗** ⇒ 读作「时间凝住」而不是彩色拖影（暖色背景会被抹成彩虹） |
| **我方清晰且正常速度** | 破防窗口内持枪姿态改用 **unscaled** 时间驱动 ⇒ 枪照常速度飞、不被模糊；**世界（敌人/特效）被压住并拖成流线** |
| **攻击者** | 敌人不再被二次减速（本地慢放等全局定格结束后才上），窗口里它是「凝住」⇒ 就是无双的「对方被顶住」 |
| **HUD** | Overlay UI 在 OnRenderImage 之后绘制 ⇒ **界面永远清晰**（与无双一致：糊的是战场，不是 UI） |

## 四、需要用户拍板的三点

1. **武器**：破防时**留在手里被压垮**（无双口径），还是**继续脱手飞出**（我们现在的做法）？
2. **攻击者**：破防后**继续压上**（无双口径），还是保持现在的冻结/慢放？
3. **节奏**：硬直 1.5s→0.8s、防御锁 3s→1.2s 这类收紧要不要做（无双是快的）？

> 拍板后按 3.1→3.4 的顺序改造，每步可独立验收；本轮先改**破防本体（3.1）**与**攻击者（3.2）**，
> 因为这两条决定"像不像破防"，其余是打磨。
