# 冰系元素联动（首个元素切片 · 规则权威版）

> 本文整合外部草案 `ice-element-spec-v1` 与 2026-10-17 的规则补充，作为冰系唯一规则依据。
> 与草案的差异集中在第 9 节；草案里错的资产映射、确定性冻结、推动与碰撞的互斥问题都已在此修正。
> 数值一律【开放】，实现时必须做成可配置字段，不得硬编码。

## 0. 定位

- 六槽位归属：**压制 + 爆发**（敌人失去行动 + 积累后一次打大数字）。
- 冰系是七元素通用容器的**首个切片与模板**：技能施加状态 → 玩家获得一次性 BUFF → 合规重攻击消费。
- 后续元素只替换"状态 + 反应规则"，容器结构不变。

## 1. 术语

| 术语 | 含义 |
|---|---|
| `columnMode` | 重攻击派生的横向覆盖标签：单列 / 多列。元素反应只判这个，永不动态变化 |
| `hitRows` | 纵向排数，只用于伤害覆盖，可被技能改写 |
| `isHeavy` | 显式"重攻击派生"标记，用于元素反应判定 |
| 冰伤害 | 由冰系来源造成的伤害，`DamageType.Ice` |
| 冻结概率 | 每名敌人独立持有的百分制概率值 `freezeChance`，达到掷骰条件即可能进入冻结 |
| 冻结 | 敌人状态 `Frozen`：暂停而非取消一切行动 |
| 破冰预备 | 玩家身上的一次性 BUFF，无时限，挂到被消费为止 |
| 破冰推动 | 破冰时对冻结目标施加的**一次最大档击退**，逐排推进直到被阻挡 |
| 碰撞伤害 | 破冰推动被阻挡时，推动者与阻挡者各承受一次的固定值伤害 |

## 2. 冰雾（施加方）

- **实现方式**：复用现有扇形喷流特效 `Assets/Scripts/Effect/ShootFireEffect.cs` 的扇扫分支 `PlaySweep`，把火焰精灵替换为冰系精灵（美术素材后续替换）。
  - 现成参数：`sweepAngle = 35°`、`sweepDuration = 0.9s`、`sweepProjectileDuration = 0.45s`、`sweepHitRadius = 0.8`
  - **同一敌人可重复命中**：`sweepHitInterval = 0.2s`，一次施放会对同一目标结算多次冰伤害 → 天然提供"多次叠加冻结概率"的节奏
- **数据模型**：复用 `TimedAoeLevelConfig`（`rangeRows` 射程排数 / `damage` 每跳伤害 / `columns` 影响列），并新增冰系专属字段 `iceFreezeChancePerHit`。这符合 `design/active-skill-v2-rules.md`「可以复用底层效果执行代码、Prefab、图标和通用数值结构」。
- **触发**：玩家主动技能槽，走 `ActiveSkillRunner`，新增效果类型 `IceMist`。
- **即时效果**：
  1. 向玩家前方喷射扇形冰流，命中的敌人每次冰伤害结算一次冻结概率；
  2. 玩家获得一次性 BUFF【破冰预备】。
- **零伤害还是带伤害**：带伤害——冻结概率只由"受到冰伤害"驱动，无伤害就没有叠加入口。

## 3. 冻结概率模型（替代草案的确定性冻结）

每名敌人各持一个 `freezeChance`（0–1）。规则：

| 事件 | 效果 |
|---|---|
| 受到 1 次冰伤害 | `freezeChance += 冰雾当级 iceFreezeChancePerHit` |
| 受冰伤害时**处于攻击前摇播放中** | 增量 **×2** |
| 每次受冰伤害 | 重置"衰退起点"（连续喷冰期间概率不掉） |
| 距最后一次冰伤害超过 `freezeChanceDecayDelay` | 开始按 `freezeChanceDecayPerSecond` 随时间下降，下限 0 |
| 每次冰伤害**命中时** | 先叠加，再**按当前累计概率立即投掷** `rand < effective`；命中则进入冻结，并把 `freezeChance` 归零 |
| `freezeChance` 上限 | clamp 到 `freezeChanceMax`（默认 0.75），防必冻 |
| `freezeResist` | **减算**：`effective = max(0, freezeChance - freezeResist)`；`effective <= 0` 视为免疫，不投掷 |
| 已处于冻结中 | **不累加、不掷骰**（已冻结无需叠加；避免解冻即再冻的死循环） |
| 可见性 | **暂不可见**：不做进度条、不做描边指示 |

**前摇判定口径**（与 Parry 打断同源，见 `Enemy.TryInterruptAttackByParry`）：
`state == EnemyState.Attacking && isAttackAnimating && !isAttackDrawPhase`
→ 收招段（AttackDraw）**不算前摇**，不享受翻倍。

**参数归属**（施加量归技能，承载量归敌人）：

| 参数 | 归属 | 默认建议 |
|---|---|---|
| `iceFreezeChancePerHit` | 冰雾等级配置 | 0.12 |
| `freezeChanceMax` | 敌人预制体 | 0.75 |
| `freezeChanceDecayDelay` | 敌人预制体 | 0.6s |
| `freezeChanceDecayPerSecond` | 敌人预制体 | 0.5/s |
| `freezeWindupChanceMultiplier` | 敌人预制体 | 2.0 |
| `freezeDuration` | 敌人预制体 | 4s（一次重攻击 + 收招的窗口，2026-10-17 从 1.5s 上调） |
| `freezeResist` | 敌人预制体 | 0（减算到概率；≥ `freezeChanceMax` 等效免疫） |
| `iceBreakAnimDuration` | 敌人预制体 | 0.4s（美术素材到位后再调） |
| `breakIceReturnDelay` | 敌人预制体 | 1.2s（从破冰动画结束起算；可调） |

## 4. 冻结（状态语义）

### 4.1 暂停，不是取消

被暂停的内容：冷却计时、前摇、攻击判定、收招、位移、冲锋。

- **在途补齐移动**：先把剩余位移落位（走完整完成分支，含补齐链回调），再进入冻结。
- **骑兵冲锋**：停在当前所在位置，不落位、不落马；解冻后**进入返航**（不续播冲锋），骑乘状态不变。

### 4.2 冻结中受击

- 普通攻击命中冻结敌人：不解冻、不播 hitted。
- **不取消被暂停的动作**：敌人保持暂停，直到自然解冻、破冰解冻或死亡；受击只是"打在静止目标上"。
- 保留：形变、震动、卡肉、伤害跳字、命中音效。
- 例外：本次命中触发破冰 → 走破冰流程（第 6 节）。

### 4.3 状态矩阵

| 冻结落点 | 结果 |
|---|---|
| Idle / Moving / Attacking（前摇·命中帧·收招） | 可冻结 |
| Stunned | 可冻结，眩晕计时随冻结暂停 |
| Launched（空中） | 不可冻结 |
| GettingUp | 不可冻结 |
| QTEAttacking | 不可冻结（系统演出） |
| `isPhaseTransitioning`（BOSS 阶段切换） | 不可冻结（系统演出） |
| Dead | 不可冻结；**冻结中被击杀 → 直接播放死亡**（不播受击、无解冻过程） |
| BOSS 血量跨阶段阈值 | **解除冰冻**并进入阶段演出（转阶段优先，演出不可被暂停） |

### 4.4 打断层级

```
冻结 > 收招（AttackDraw）
冻结 < QTE 演出
冻结 < BOSS 阶段切换演出
```

冻结是全游戏**唯一能暂停收招**的机制，但不得打断任何系统演出。

### 4.5 重复冻结

- 冻结中再次被冻结：**重置时长到满值，不叠加**。
- 收招/前摇被暂停的进度**保留**，不因再次冻结重置。
- 冻结抗性为减算（第 3 节），抗性达到上限时等效免疫。

### 4.6 解冻只有两条路

| 方式 | 行为 |
|---|---|
| 自然解冻（计时归零） | 从暂停处**续播**原动作：冷却继续、前摇照常落下、收招续播 |
| 破冰解冻 | 播放**破冰动画**；动画播完才真正解除冻结，随后取消原动作、回到正常状态机调度 |

普通受击不解冻。

**破冰动画期间（`IceBreaking`）**：仍算"冻结中"——位置静止、不可再次冻结、不叠冻结概率、可正常承受伤害；但**hitted 与破冰动画同步播放**（这是唯一允许在冰态下播受击动画的时刻，用来表达"冰碎了"）。动画时长 `iceBreakAnimDuration`（可配）。

## 5. 破冰推动（= 一次最大档击退 + 撞停结算）

### 5.1 定义

破冰时对被命中的冻结目标施加一次**最大档击退**：逐排向后推进，直到以下任一条件：

1. 推满 `breakIcePushRows` 排（2026-10-18 定为 **4**，从第 0 排出发可顶到最后一排）；
2. 下一排被**阻挡**（非本次命中的敌人 / 骑乘骑兵预留位 / BOSS 墙）。

- 条件 1 结束：正常推进，无碰撞。
- 条件 2 结束：**停在阻挡者前一排**，推动者与阻挡者**各结算一次碰撞伤害**。
- 若第一排就被阻挡：推动者原地不动，同样结算碰撞伤害。

这与普通击退"被阻挡则整列击退失败"不同，是**效果自带的明确规则**（`design/push-back-compaction.md` §2 允许"除非效果另有明确规则"）。

### 5.2 与普通击退的差异

| 项 | 普通击退 | 破冰推动 |
|---|---|---|
| 被阻挡 | 整列失败，全部原地 | 停在阻挡者前一排 |
| 碰撞伤害 | 无 | 双方各一次固定值 |
| 回原槽 | 停顿后回精确原槽（`pushReturnDelay = 0.35s`） | 同样回精确原槽，但延迟拉长到 `breakIceReturnDelay`（默认 1.2s），**从破冰动画结束起算** |
| 触发源 | 招式 `pushBackRows` / 海浪等 | 仅破冰 |

### 5.3 工程先例

同样是"逐排步进 → 遇阻挡停在阻挡者前 → 结算打击"的结构已经存在：`Assets/Scripts/Enemy/CavalryEnemy.cs` 的 `CavalryPhase.Charging` 循环（`CHARGE_CONTACT_ENEMY` → `StrikeRoutine(blocker)`）。方向相反（冲锋向前、破冰向后）、载体不同（骑兵用单位位移，破冰用排坐标），**不能直接复用代码，但语义与判定顺序完全一致**，可作为实现范式。

### 5.4 跳过推动与碰撞的情况

| 情况（作为**被破冰的冻结目标**） | 处理 |
|---|---|
| BOSS | 跳过 ①推动 与 ②碰撞，只走 ③双倍 ④解冻 ⑤消费（BOSS 免疫击退 + BOSS 墙） |
| 骑乘骑兵（109） | 跳过推动与碰撞，破冰不产生位移、骑乘状态不变 |
| `freezePushImmune = true` | 跳过推动；无位移即无碰撞 |

**BOSS / 骑乘骑兵 / 骑兵预留位作为"阻挡者"时**（挡在别的冻结目标的推动路径上）：视为阻挡，双方各结算一次 collisionDamage。BOSS 未进入战斗（`bossState != InCombat`）时它自身不吃伤害（`TakeDamage` 内置早退），被推者照常结算。

### 5.5 回位的技术前提（方案 A：延迟回位）

击退回位是带 owner + generation 的交易（`ColumnManager.PushReturnTransaction`）。破冰复用同一条通道，只改三处：

1. **照常登记交易**（不取消）：原槽 = 命中前的真实槽位，新槽 = 推动后的槽位；
2. `returnDueTime` 改为**破冰动画结束时 + `breakIceReturnDelay`**，避免回位行军与破冰动画抢 transform；
3. 若目标身上已有未完成的回位交易，走现有 `RegisterPushReturn` 的重注册路径（原槽取最早那次，与普通击退一致）。

因此"原槽回位例外"实际只体现为"回位时间更长"，位移系统不需要为冰系开新语义。

### 5.6 被推之后怎么回到战线（工程实测 + 待决策）

实测结论：**普通敌人不会自主前进。** 位置变化的合法来源只有四种——补齐/行军订单（`ColumnManager`）、击退回位、SpawnEntry、BOSS 推进；`Enemy.StartMoving(isRush: false)` 对非 BOSS 直接 return，`RowBasedFillUp` 与 `CompactAllColumns` 均已停用。

当前前排推进来自"逻辑排重排"（`RequestLogicalLayoutReflow`），触发条件是**某个逻辑排没有存活成员（即发生死亡）**；重排会把"当前排比逻辑目标排更靠后"的敌人一路拉回，可一次跨多排，带回位交易的敌人会被跳过。

因此"被推后排"的实际表现是：**停在后排，直到下一次整排清空才被拉回**；这期间它既不攻击也够不到。由此需要两条硬规则：

1. **推动上限**：`rowIndex + 推动排数 ≤ maxVisibleRows - 1`。`Enemy.GetRowZ` 的公式是 `(maxRow - row) * -spacing`，超出可见排的敌人 z 会变正，直接落到画面外。

**已定（方案 A：延迟回位）**：破冰不需要"战线安全阀"——被推的敌人会在 `breakIceReturnDelay`（默认 1.2s，从破冰动画结束起算）后自行回到原槽，阵型不会永久流失，也不会出现"全员被推出可攻击排导致整波停摆"。

### 5.7 同列多个冻结目标同时破冰

沿用现有"单列多个击退"的处理方式（`ColumnManager.ExecutePush` 的做法）：

- **从后往前**逐个处理（row 大的先推），避免互相占位。
- 阻塞判定只看**非本次命中**的敌人；本次命中的其他冻结目标不算阻塞，可以互相顶替位置。
- 某个目标被阻挡停住后，排在它前面的目标不能越过它，也不能把它顶开。
- 每个目标的移动、碰撞伤害、解冻各自独立结算，位置不共享、不传递。

## 6. 破冰结算顺序（严格按序）

触发条件（全部满足）：

1. 是重攻击派生（`isHeavy`）；
2. 满足当前【破冰预备】的作用域（单列版：`columnMode == SingleColumn`；解锁版：任意）；
3. **实际命中**了冻结目标（空挥不触发、不消耗）。

结算：

```
① 破冰推动：推到最远合法排；被阻挡则停在阻挡者前一排
② 碰撞伤害：仅当被阻挡时，推动者与阻挡者各承受一次 collisionDamage（BOSS 未进战斗时它自己不吃），**跳字在碰撞发生瞬间**
③ 原始命中双倍：本次命中的伤害 ×2（只作用于原始命中，不含碰撞伤害），**跳字在命中瞬间**
④ 破冰动画：播放破冰表现并**同步播放 hitted**；**动画播完才解除冻结**，动画结束时登记延迟回位（方案 A）
⑤ 消费 BUFF：满足条件的破冰预备全部消费
```

多条目标命中时：每个冻结目标各自走 ①–④，全部双倍、全部解冻；每个目标的碰撞伤害独立结算；⑤ 只消费一次。

时间竞争：冻结自然解冻与破冰同帧成立 → **破冰优先**。

**推动优先级**：若本次命中触发破冰，则该目标**跳过招式自带的普通击退**（`pushBackRows`）。破冰推动与普通击退**不叠加**；未触发破冰的命中照常走原本的击退规则。

## 7. 攻击级会话

因为 ③ 允许多目标双倍而 ⑤ 只消费一次，需要一个攻击级作用域：

- 招式开始时创建会话；
- **首次实际命中**时校验作用域 → 消费全部匹配 BUFF → 会话进入"本次攻击有效"；
- 招式结束时关闭会话。

结果：多列重攻击在单列版 BUFF 下**不触发、不消耗、冻结保留**；空挥不影响 BUFF。

## 8. 与既有硬约束的关系

遵守的部分（不得为冰系开例外）：

1. 段位推进按输入；伤害/能量/被动/BUFF 消费按**首次实际命中**结算。
2. 所有位移走 `ColumnManager` 既有通道，遵守不重叠、未受位移者不动。
3. 方向判定与 `columnMode` 无关，`hitReactionDirection` 不改。
4. 冻结、冻结概率、破冰预备、碰撞均为**战斗内状态**，战斗结束/节点切换必须清空。
5. 非战斗阶段（旅行、出口确认、等待奖励）不得保留冻结与概率。

唯一的例外（需在位移系统显式放行）：

- **破冰推动的回位延时更长**（`breakIceReturnDelay`，默认 1.2s，从破冰动画结束起算），且只对"被破冰推动的冻结目标"生效；其余击退保持 `pushReturnDelay = 0.35s`。

新增的独立入口：

- 碰撞伤害是全新数值通道（`StageConfig.collisionDamage` + `DamageType.Collision` + `HitFeedbackSource.Collision`），与骑兵冲锋伤害、`coinReward` 完全隔离。
- 碰撞伤害**计入连击数与伤害统计**，但**不推进大招能量与被动计数**（后两者是攻击级"首次实际命中"结算）。被撞者不因碰撞解冻，也不算作"被这次攻击命中"。

## 9. 与外部草案 v1 的差异（更新理解）

| 项 | 草案 v1 | 现规则 | 原因 |
|---|---|---|---|
| 冻结触发 | 冰雾命中即冻结 | **概率冻结**：冰伤害累积概率 + 前摇翻倍 + 时间衰退 | 2026-10-17 补充 |
| 冰雾形态 | 抽象"扇形冰雾" | 复用 `ShootFireEffect.PlaySweep` 扇扫，换冰系精灵 | 2026-10-17 补充；同一敌人 0.2s 可重复命中，正好驱动概率叠加 |
| Sweep / Launch 的 `columnMode` | 单列 | **多列**（代码实测 `GetAllEnemiesInRange`） | 草案资产映射错误 |
| 单列重攻击的实际集合 | 含 Sweep/Launch | **Pierce + C2 指向突刺**（C2 在 2026-10-18 被定为本重攻击；终结技/Sweep/Launch 均为多列） | 同上；初始版 BUFF 的消费方 |
| 推动与碰撞 | 先推到终点，再撞到的敌人受伤 | **撞停**：逐排推进，被阻挡即停并结算碰撞 | 现有 `CanPushColumn` 下"能推=目标排空"，二者不可能同时发生 |
| 推动排数 | 未定 | 一次**最大档**击退，排数可配 | 2026-10-17 补充 |
| BOSS 破冰 | 可冻结，未说明推动 | 跳过推动与碰撞，只双倍+解冻 | BOSS 免疫击退 + BOSS 墙 |
| 回原槽例外 | 冻结+推动整体不回原槽 | 缩窄为"破冰推动、仅冻结目标" | 例外越窄越可审计 |
| 一次性 BUFF 容器 | 抽象描述 | 独立于 `BuffManager`（后者只承载 `StatModifier`） | 不污染同 id 叠加语义 |
