# 技能与道具图标美术制作规范

> 适用范围：局内三选一奖励、Buff 栏、道具栏、技能冷却图标，以及后续同一视觉体系的图标资产。
>
> 当前观察样本：`Assets/Sprites/31Reward/icon/` 中的箭雨、定时喷火、地刺、旋风、海浪、幻影武器、护甲与冲击波图标。

---

## 1. 核心视觉目标

图标在小尺寸 UI 中承担“玩家一眼识别技能类别和效果”的职责。优先级依次为：

1. **轮廓可读**：不看文字也能分辨箭、火、旋风、海浪、护甲、机关、武器。
2. **效果方向明确**：从构图就能看出前冲、喷射、下落、爆发、环绕或防御。
3. **三国机关感统一**：武器、甲胄、机关使用青铜、深木、金属细节；不做现代枪械或科幻材质。
4. **元素分色一致**：不同流派可通过主色和特效色快速识别。
5. **小图清晰**：即使缩放到 Buff 槽位大小，主体仍完整、醒目、无关键信息丢失。

图标不承担“完整插画”职责。避免复杂背景、多个平级主体、长文本、过度写实的细碎纹理。

## 2. 现有画风拆解

### 2.1 像素街机线条与渲染

- 采用 **三国像素街机风格**：低分辨率像素画感、硬边轮廓、有限色阶；不是平滑赛璐璐插画，也不是厚涂写实。
- 主体使用偏深的棕黑、深蓝黑或墨色**像素描边**；关键外轮廓必须比内部细节更清楚。
- 上色使用高对比、清晰分阶的像素块面：暗部明确、边缘高光清晰；避免平滑渐变、空气笔刷、柔焦和细密写实纹理。
- 可使用少量像素化火星、速度线、冲击星芒、飞溅碎屑增强动势；不可让它们压过主体。
- 透明区域边缘应干净，避免发灰、白边、半透明杂点和背景残留。

### 2.2 构图规律

- 主体占画面约 **60%–80%**，四周保留约 **10%–18%** 安全边距。
- 默认以中心主体 + 单侧/单向特效构图；允许轻微越界的火焰、浪花、箭矢来制造动势，但不能贴边截断核心。
- 斜向构图优先使用左下 → 右上，或上方 → 下方；与现有武器、箭雨、冲击线方向保持一致。
- 主体应具有单一视觉焦点：如炮口、箭簇、旋风中心、浪头、护甲胸甲、武器锋刃。
- 不绘制 UI 外框、等级数字、名称、按钮、背景面板；由游戏 UI 的 `31_ReFrame_*` / `31_ReFrame_skill` 统一承载。

### 2.3 背景与透明度

- 正式导入目标为 **PNG + 透明背景 Alpha**。
- 不要白底、方形彩色底、场景背景、渐变色卡或外框。
- 如需提升主体分离度，只能在主体附近加入轻量的元素辉光、速度线、冲击线或淡色能量团。
- 图标交给生图模型时明确要求：`transparent background / isolated game skill icon / no frame / no text`；生成结果若无 Alpha，需后处理抠图后再导入。

## 3. 色彩与流派编码

### 3.1 通用材质色

| 内容 | 主色方向 | 辅色/高光 | 禁忌 |
|---|---|---|---|
| 青铜机关 | 旧金、黄铜、赭金、深棕 | 金黄反光、橙红火星 | 塑料黄、现代工业灰、未来科技蓝光 |
| 冷兵器 | 钢蓝、银灰、深墨 | 冷白锋刃、金色护手 | 平淡纯灰、模糊刀刃 |
| 甲胄/防御 | 深青铜、黑金、暗棕 | 金色铆钉、橙黄冲击高光 | 轻飘飘的布料质感 |
| 木制机关 | 深木棕、铜金 | 火星、金属铆钉 | 现代枪械结构 |

### 3.2 技能类别与元素色

| 类别/流派 | 主视觉色 | 现有参考 | 表达重点 |

| 连击位移/风 | 青蓝、冰���、少量深蓝 | `icon_31_cyclone.png` | 旋转中心、运动轨迹、吸附/卷起 |

同一图标中不应同时竞争三种以上高饱和主色。主体材质色 + 一种元素色 + 白色高光，通常足够。

## 4. 各类图标构图模板

### 4.1 机关类（火蛇、地刺、弩炮等）

- **主体**：青铜/木制机关必须是画面最大信息；齿轮、铆钉、炮口、折叠臂只保留能帮助识别的细节。
- **特效**：从机关明确的出口发出，火焰/箭矢不能看起来无来源。
- **方向**：机关通常朝右上或正上偏右；发射物与炮口方向一致。
- **火蛇机关建议**：三国青铜喷火机关，短粗炮管或兽首喷口，橙红火焰扇形扫出；强调“机关喷射”，而非独立火球。

### 4.2 箭矢与箭雨类

- 主体可以是 3–8 支清晰箭矢形成箭簇，或从远处压下的密集箭雨。
- 箭头、尾羽至少有一个能在小尺寸辨认；不能全部化为抽象蓝色线条。
- 使用下坠斜线、冲击星芒或地面爆点暗示落点；不要画人物。
- 万箭齐发优先使用“多方向密集箭簇 + 蓝白风压/落点冲击”，避免和普通三连箭完全相同。

### 4.3 武器、幻影与连击类

- 真实武器是视觉主体，幻影以半透明残像、重复轮廓或蓝色轨迹表现。
- 残像不应多于 2–3 层，避免武器轮廓难读。
- 武器护手和锋刃可保留金色/冷白高光，能强化三国兵器辨识。

### 4.4 防御与蓄力类

- 以护甲、盾、包覆的金属结构、尖刺或冲击波为主体。
- 保持对称或近对称构图，表达稳定、厚重、可靠。
- 蓄力可用外围同心冲击线、暗红能量、金色闪点表现；不能变成轻盈魔法盾。

### 4.5 元素范围类（旋风、海浪、火焰）

- 必须有清晰的起点/中心和推进方向。
- 旋风：中心涡旋最亮、外缘呈深蓝线条，整体可略向一侧倾斜。
- 海浪：浪头应向目标方向卷起，白色泡沫只作为边缘高光。
- 火焰：橙红主体、黄色核心、深红边缘；火焰流向不能模糊成静止火团。

## 5. 技术规格与 Unity 导入要求

### 5.1 原始交付

| 项目 | 规范 |
|---|---|
| 推荐出图尺寸 | 1024 × 1024 px |
| 画面比例 | 1:1 |
| 文件格式 | PNG（必须保留 Alpha） |
| 色彩空间 | sRGB |
| 文件命名 | `icon_31_<effectName>.png`；道具可用 `icon_31item_<effectName>.png` |
| 文字 | 禁止；中文/英文名称、数字、稀有度、等级均不进入图标 |
| UI 框 | 禁止；由现有 UI 框架统一添加 |

高分辨率原图保留在外部美术源目录；导入 Unity 的图标使用统一裁切、命名和透明边距。不要直接把带白底的生成图放进 `Assets`。

### 5.2 Unity 导入建议

- Texture Type：`Sprite (2D and UI)`。
- Sprite Mode：`Single`。
- Alpha Is Transparency：开启。
- Mip Maps：关闭（UI 小图不需要）。
- Wrap Mode：`Clamp`。
- Filter Mode：`Point (no filter)`，保持像素边缘清晰；禁止 Bilinear/Trilinear 将像素画模糊。
- Compression：优先保证像素描边、有限色阶和透明 Alpha 干净；避免造成色阶抖动、边缘发灰或像素糊化。
- Pivot：中心（除非图标后续要用作世界空间特效，不适用于本规范）。

### 5.3 UI 适配检查

��标会进入三选一 `UpgradePopup`、左侧/底部 Buff/道具槽位，必须检查：

1. 64–128 px 预览时主体是否可读。
2. 套入现有技能框后，主体是否被边框遮挡。
3. 冷却遮罩覆盖后，轮廓是否仍能识别。
4. 右上角等级/数量数字是否压住主体焦点；若会冲突，主体焦点需往左下或中央偏移。
5. 透明边缘是否出现白边、黑边或脏色。

```text
no text, no letters, no numbers, no UI frame, no border, no character portrait, no scenery, no smooth gradients, no painterly rendering
```

中文版本：

```text
三国像素街机风格手游技能图标，1:1 方形构图，透明背景，主体居中并保留安全边距，
低分辨率像素画、硬边像素轮廓、有限色阶、深色像素描边、清晰剪影、高对比像素分阶明暗，
青铜/木制机关与冷兵器质感，[技能主体与效果描述]，少量像素速度线或粒子加强动势，
不要文字、不要数字、不要 UI 外框、不要按钮、不要角色头像、不要场景背景、不要白底、不要平滑渐变、不要赛璐璐插画或厚涂
```

### 6.2 图生图/风格参考工作流

- 以 3–6 张现有 Icon 为参考输入，选择至少一张机关、元素、武器、护甲样本。
- `input_fidelity` 取 `low`：需要新技能结构而只继承画风时。
- `input_fidelity` 取 `high`：只需替换小元素、维持既有构图时。
- 生成前明确主体优先级、颜色类别、动作方向和禁止项。
- 生成后不直接入库；先检查透明底、可读性、是否混入文字/边框/现代物件。

## 7. 评审与验收清单

每张新图标入库前逐项确认：

- [ ] 透明背景，无白底/棋盘格/背景场景。
- [ ] 无文字、数字、外框、稀有度角标和水印。
- [ ] 主体在缩略图尺寸仍可一眼识别。
- [ ] 技能语义准确：动作方向、机关出口、元素流向、武器类别不矛盾。
- [ ] 与现有 `31Reward` 图标在描边粗细、明暗对比、金属/元素风格上不突兀。
- [ ] 不出现现代枪械、科幻能量枪、欧美魔幻盔甲等题材漂移。
- [ ] 与同流派图标的颜色编码一致，但不会和已有图标难以区分。
- [ ] 导入 Unity 后在三选一卡片、Buff 槽、道具槽及冷却遮罩下均清晰。
- [ ] 文件名、Sprite Import Settings 与项目约定一致。

## 9. 维护原则

- 本规范是当前项目已存在图标风格的提炼，新增图标应优先服从它，而非单张图追求独立风格。
- 当 UI 框、尺寸、图标显示逻辑或总体美术方向发生变化时，应更新本规范并重新检查示例提示词。
- 新素材正式替换前应保留原图标引用，完成 UI 与实机验证后再清理占位图。
