# 敌人变体设计：藤甲兵与自爆兵（草案）

> **状态：两个变体方向已确认，数值与表现未定。**
> 本文记录已确认的敌人变体机制，以及尚未拍板的候选池。
> 通用原则：一个威胁 + 一个对策；优先复用已有系统；每类敌人至少保留两种解法。

## 1. 藤甲兵（101 剑士 / 102 盾兵 的变体）

**定位**：火系构筑的专属靶子。

| 项 | 规则 |
|---|---|
| 核心 | **全场霸体**（轻攻击打不断前摇）+ **灼烧易伤** + **灼烧不退** |
| 对策一 | 火系影之武装（火龙舌 / 烈焰喷射 / 蛇形喷射） |
| 对策二 | 重攻击拆前摇、削韧破势（必须保留，否则没抽到火就卡死） |
| 视觉 | 暂用原形象 + 渲染（霸体描边色可复用），后续替换 |

### 1.1 三个技术落点（已核对代码）

1. **霸体**：`isSuperArmor` 目前只有 BOSS 有赋值路径（来自 `BossPhaseData`），普通敌人恒为 false
   ⇒ 敌人预制体需要新增一个开关，并接入 `inArmorWindow` 判定。
2. **灼烧易伤**：没有 `DamageType.Fire`，火就是灼烧状态；且灼烧每跳走 `ignoreDamageModifiers: true`
   ⇒ 通用增伤对它无效，倍率必须加在 `EnemyStatusBurn.Tick` 内部（敌人侧的新字段）。
3. **灼烧不退**：`_ticksRemaining` 归零即结束 ⇒ 需要"永久"标记。

### 1.2 三条边界

- **霸体不等于免疫位移**：击退/击飞是另一套字段，要不要一起免疫需单独定。
- **"永久灼烧"容易过强**：现有规则是重复施加重置跳数、单跳伤害取较大值。
  建议永久保留但**单跳伤害低**，靠反复施加提升，避免"点一次烧到死"。
- **不能被火唯一化**：火系来自影之武装，没抽到就不能解，所以重击/削韧两条路必须有效。

## 2. 自爆兵（101 剑士 的变体）

**定位**：会走动的定时炸弹——处理得早，它就是你的工具；处理得晚，它炸你。

### 2.1 机制链

```text
自爆兵随「补齐」推进到前排（row 0）
  → 引信开始（可见倒计时/染色脉冲）
  → 到点自爆：伤害玩家
或者在引信到点之前被击杀（含到达前排之前）
  → 立即爆炸，**只伤害敌人**：自身所在排 + 前后两排
或者用带「火」标记的攻击**提前引爆**（不等它到前排）
  → 点燃后延迟一小段并播放对应动画再爆炸，同样只伤害敌人
```

### 2.2 它怎么到前排：补齐就是玩法

按不可变约束第 7 条，**敌人不得自行移动**；敌人前移只有"整排清空后的补齐"一个来源。
⇒ 玩家通过"清不清这一排"决定它什么时候到前排，**这是设计意图，不是漏洞**（用户确认）。

- 不清排：它一直待在后排，但也不会自爆伤你；
- 清排：把它推到前排，引信开始；
- 不等它到前排：可以用**火系攻击提前引爆**。

⇒ 不需要额外加"必须被处理"的压力机制；是否再给它普通近战攻击属于可选的强度调节，不是必需。

### 2.3 爆炸规则需要定的四件事

| 项 | 建议 | 理由 |
|---|---|---|
| 范围 | 自身排 + 前后各一排；列范围限自身列 ±1 | 全列 3 排会变成白送的清场 |
| 对敌伤害 | 按目标最大生命百分比；精英减半、Boss 大幅递减 | 无尽关也能保持价值，又不会被当成主要输出 |
| **到点自爆也伤敌人** | **是**（用户定） | 它在 row 0 引爆，会同时波及前排敌人 |
| 对玩家伤害 | 固定高伤，**不可防御**；后续"防御强化"类效果可以挡任意伤害，但仍扣格挡值 | 默认没有安全解，必须提前处理 |
| **火系引爆** | 带「火」标记的攻击或灼烧状态均可引爆；点燃后**延迟一小段 + 播放动画**再爆 | 需要先定义「火」tag 的载体 |
| 连锁 | **允许**；被炸死的另一个自爆兵**自己播放引爆演出** | 不做特殊上限，靠延迟控制节奏 |

### 2.4 与其他系统的交互

- **DoT 击杀算"提前击杀"**：火/疾病把它烧死也会触发友军爆炸（合理，且强化火系）。
- **爆炸原点按击退后的当前位置**（用户定），不是逻辑槽。
  ⚠ 现有 `pushReturnDelay = 0.35s`（`DisplacementMover.cs` 私有常量），回位太快，
  实机上几乎抓不到"在击退位置引爆"的窗口 ⇒ 需要把回位延迟参数化并加长。
- **冻结暂停引信**（用户定）；眩晕是否同样暂停待定。
- **免疫击飞**（用户定）：直接不做击飞动画，省一套素材。
- **引信期间不建议霸体**：否则玩家无法打断，只能跑。
- **友军伤害击杀算玩家击杀**，照常给经验与铜钱（用户定）。

### 2.5 表现要求（决定这个敌人是否可读）

- 引信期间必须**一眼看出**：染色脉冲 + 轻微放大 + 音效。
- 两种爆炸要能区分：提前击杀＝"闷"的内部炸开（只伤敌）；到点自爆＝"亮"的冲击波（伤玩家）。

### 2.6 「火」的统一 tag

火不是一个独立的伤害类型（现有 `DamageType` 里没有 Fire），而是一个**来源标记**：

- 带火标记的招式（`AttackSkillConfig`）、影之武装（`ActiveSkillDefinition`）、
  被动喷火类（`UpgradeDefinition`）都算「火」；
- 处于**灼烧状态**也算「火」（哪怕灼烧来源本身没打标记）。

⇒ 藤甲兵的"火易伤"与自爆兵的"火引爆"**必须复用同一个 tag**，避免两套判定。
⇒ 灼烧每跳走 `ignoreDamageModifiers: true`，所以火系倍率要加在 `EnemyStatusBurn.Tick` 内部。

## 5. 待定

1. 藤甲兵的霸体是否同时免疫位移；灼烧永久后的单跳数值与重复施加规则。
2. 自爆兵的引信时长、延迟引爆时长、爆炸范围与对敌/对玩家的伤害口径。
3. 自爆兵是否眩晕暂停引信（冻结已定暂停）。
4. 自爆兵是否算精英（是否掉宝箱）。
5. 「火」tag 的载体与字段名；藤甲兵的火易伤是否复用同一 tag（建议复用）。
6. 击退回位延迟参数化后的具体值（当前 0.35s）。
7. 火系的获取节奏：用户定"后期才能拿到、普通灼烧伤害一般"，具体解锁位置与数值待设计。
