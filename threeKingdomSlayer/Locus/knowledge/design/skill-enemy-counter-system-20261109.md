# 技能组 × 敌人对策体系（设计提案）

> 来源：用户玩《影之刃零》后提出，参考其「影之武装 ↔ 敌人交互」与「饰品 ↔ 武器/影之武装联动」的 build 体验。
> 约束（用户明确）：**我们是小游戏方向，按键与操作维度不能高**；**没有闪避**（只有防御，红光=重攻击或防御），闪避不表达；**暂不做更多武器**（武器=我们的招式层，固定）。
> ⇒ 所以"影之武装"这一层落在我们的**主动技能组**上，"武器特色"暂不展开，"饰品联动"落在**被动**上。

---

## 1. 现状盘点：我们其实已经有"对策雏形"，但没体系化

### 1.1 现有主动技能与其对策对象（从资产描述读出）

| 技能 | 现有机制 | **已有的对策/联动** |
|---|---|---|
| 火焰喷射（蛇形喷射） | N 列区域伤害 | 施加**灼烧** |
| 火龙舌 | 前方直线伤害 | **对灼烧目标暴击 200%** ← 已经是"特攻" |
| 冰雾 | 扇形冰流 + 冻结概率 | **对"攻击前摇中"的敌人冻结概率翻倍** ← 已经是"特攻" |
| 旋风 | 吹飞 N 排；未眩晕 Boss 削韧%架势 + 打断 | 打断/削韧 |
| 海浪 | 推进 + 击退前方 N 排；未眩晕 Boss 削韧 + 打断 | 打断/削韧 |
| 染病 | 下次戳击染病，4 秒 DoT，**目标死亡时传播** | 传播 ← 已经是很"答案库"的思路 |
| 箭雨 | 前方 1 排 N 波箭 | —— |
| 地刺 | 尖刺陷阱 | —— |
| 冲击波 | 点击得 1 层，蓄力攻击释放（**当前不在池**） | 与蓄力招式联动 |
| 幻影武器 / 回旋波 / 连锁弹射 / 暴击齐射 | 被动攻击型 | —— |

### 1.2 现有被动（26 个定义，在池 13 项）

- **数值型（13）**：疾风(攻速)、拔苗助长(戳击射程)、波长(横扫射程)、神通(伤害倍率)、专注(冷却缩减)、铁壁(蓄力减伤)、反伤、聚拢波、汇聚波、策略(道具伤害)、捞漏(掉落)、敛财(击杀触发)、智慧(经验)、延长、连刺(攻击触发)、震荡(蓄力命中触发)
- **被动攻击型（4）**：幻影武器、连锁弹射、回旋波、暴击齐射

### 1.3 现有敌人机制（→ trait 的原料）

| 敌人 | 机制 |
|---|---|
| 101/1011/1012 | 基础近战 |
| 102 | 常态减伤 50% + 与相邻同族**共享血池** |
| 103 | C 技前摇 **霸体** |
| 105 / 106 | 远程（落点随机 / 固定） |
| 109 | 骑兵冲锋（骑乘期免疫眩晕与位移） |
| 1013 | 督战**号令**增益 |
| 1021 | 正面/盾侧**格挡**，反侧+蓄力破盾 → 胆怯 |
| 104/107/108 | Boss：霸体阶段、多阶段、QTE |

### 1.4 缺口（对照 PBZ）

| | 我们 | PBZ |
|---|---|---|
| 技能↔敌人的关系 | **隐式、零散**（写在描述文案里，没有数据层的关系） | **显式**：影之武装声明自己是什么定位、对什么敌人特攻 |
| 敌人特性 | 没有标签 | 每种机制自带"对策身份"（盾/自爆/犬群/远程/人偶） |
| 被动↔机制联动 | **几乎没有**：被动多为通用数值/通用触发 | 62 件饰品大半是"机制开关"（对破防敌人加伤、扩大完美防御窗口、按持法分档） |
| 波的难度感 | 靠数量和数值 | 靠 **trait 组合**（盾+远 = 不好打；簇+冲 = 不好打） |

## 2. 提案 A：敌人特性标签（trait）

> **不新增任何敌人行为**，只给现有机制打标签，让技能/被动能引用。

| 标签 | 含义 | 现有敌人 | 我们现有的对策（=玩家手上的牌） |
|---|---|---|---|
| **盾** | 正面被格挡/免伤 | 1021 | 反侧 + 蓄力破盾（⚠️ 目前是**概率**，见 `design/gameplay-pillars.md` §4.2） |
| **韧** | 常态减伤 / 难破防 | 102（减伤 50%） | 削韧、破防、破甲 |
| **霸** | 起手霸体、不可被打断 | 103、Boss 阶段 | 蓄力打断、削韧 |
| **簇** | 数量压制、成群 | 1012 山贼 / 小兵成排 | 范围技能（横扫、箭雨、蛇形喷射、旋风） |
| **远** | 在我方射程外输出 | 105 / 106 | 拉近（海浪、挑飞）或远程（箭雨） |
| **冲** | 主动贴脸冲击 | 109 骑兵 | 蓄力打断、击退（海浪、冲击波） |
| **令** | 给同伴增益（优先级目标） | 1013 督战 | 集火点杀 |

**规模判断**：7 个标签对小游戏是偏多的。备选压到 **5 个核心**（盾/韧/霸/簇/远）+ 把"冲/令"当变体（冲≈霸的变体、令≈韧的变体）。

---

## 3. 提案 B：技能带"对策声明"（技能组 = 答案库）

每个主动技能加两个数据字段：
- `counterTags`：它能处理哪些 trait（玩家看到技能就知道"这个克那个"）
- `specialVs`：对特定 trait 的额外效果（**加伤** or **改机制**）

| 技能 | 建议 counterTags | 建议 specialVs |
|---|---|---|
| **火龙舌** | 簇 / 韧 | 对**灼烧**目标暴击（已有）；对**韧**（高减伤）目标：灼烧改为**无视部分减伤**（把"高防"变成可打） |
| **火焰喷射** | 簇 | 范围上**灼烧**；灼烧目标被击杀时**小范围爆开**（引燃连锁） |
| **冰雾** | 霸 / 簇 | 对**攻击前摇中**的敌人冻结概率翻倍（已有）；追加：冻结期间目标**受到伤害 +15%** |
| **旋风** | 簇 / 霸 | 对**霸**（霸体前摇）目标：削韧按最大架势的**更高比例**（现在只对未眩晕 Boss 生效） |
| **海浪** | 冲 / 簇 | 对**冲**（骑兵）：**中断冲锋**并把它推离玩家；这是"勾爪"的我们的版本 |
| **染病** | 簇 / 韧 | DoT **无视"韧"的减伤**；死亡传播对**簇**多传 1 个目标 |
| **箭雨** | 远 | 对**远**目标：箭雨**波数 +1**（覆盖更远的排） |
| **地刺** | 冲 / 簇 | 对**冲**：在冲锋路径上**定身**（打断冲锋） |
| **冲击波**（当前不在池） | 韧 / 霸 | 蓄力释放时对**霸**目标额外削韧；对**韧**目标破防 |

> ⚠️ **"改机制型"特攻**（拉近、引燃、无视减伤）比"加伤型"贵得多，但更接近 PBZ 的手感（"它们解决的不是『打得疼』，而是『够不着』和『人多』"）。**这一层要不要做，是本次最大的分岔。**

## 4. 提案 C：被动池引入"机制开关"型（PBZ 饰品层）

> 现有被动几乎全是通用数值/通用触发；这一层要补的是**改手感、不改数字**的被动。

| 候选被动 | 效果 | 对应 PBZ 的哪件 |
|---|---|---|
| **破阵** | 对**盾**目标伤害 +40%；破盾后 5 秒内再 +40% | 破盾符（对盾牌耐久削减 +50%） |
| **焚** | 目标处于**灼烧**时受到伤害 +25% | 瑞狮火球（点燃扩散） |
| **霜** | 对**处于攻击前摇**的敌人伤害 +30% | 浑源经脉仪（完美防御窗口 +15%） |
| **猎骑** | 对**冲**（骑兵类）伤害 +30% | 斩骑符（对骑兵 +25%） |
| **群猎** | 同列 3 只以上时伤害 +20%；击杀时对同列溅射 | 瑞狮火球（火焰伤害 +20%、点燃扩散） |
| **破韧** | 削韧效率 +30% | 追命符（对破防状态敌人 +7%） |
| **引** | 技能命中**远**目标时把它拉近 1 排 | 玉双环（远程收残血）——"够不着"的对策 |
| **专精·X** | 某一类技能消耗 +1，但伤害 +50% | 力士神像（"破坏"类多耗 1 暗源、伤害 +75%） |

**联动示例**（PBZ 式的"饰品 × 影之武装"）：
- 「焚」× 火龙舌 = 灼烧流的核心
- 「破阵」× 破盾手段 = 盾墙流的核心
- 「引」× 箭雨 = "用远程处理远程"的双技能联动

## 5. 提案 D：用 trait 组合倒推敌人编排

> 关卡节奏仍由用户调整（2026-11-09 定），这里只给**编队原则**。

| 原则 | 说明 |
|---|---|
| 每波 **1 个"需要对策"的敌人** + 若干杂兵 | 波次不该同质（现在 N2 wave0 是清一色 1011/1012） |
| **一波最多 2 种 trait** | 超过 2 种玩家就没有选择余地，答案库用不上 |
| **trait 组合 = 难度感** | 盾+远 = 不好打（要既能破盾又够得到）；簇+冲 = 不好打（要能清场又要打断）；盾+簇 = 好打（一个破盾手段 + 一个范围手段就够） |
| **同一 trait 反复出现要有升级** | 第一次只给"盾"（教会玩家它需要破盾），后面给"盾+霸"（需要两套手段） |
| BOSS = **多 trait 汇总 + 一条独有机制** | Boss 波应检验玩家 build 的完整性（对应 PBZ 七星剑阵：六条独立血条 + 自损续命 + 合击） |

**"好打 / 不好打"的判定表**（给编队用）：

| build | 擅长 | 不擅长 |
|---|---|---|
| 火系（灼烧流） | 簇、韧（DoT/灼烧无视减伤） | 盾（打不穿）、远（够不着） |
| 位移流（海浪/旋风） | 冲、霸（打断/削韧）、簇 | 韧（打不动）、令（优先级不对） |
| 远程流（箭雨） | 远、簇 | 盾、霸（够不到/打不断） |
| 破防流（重攻击） | 盾、霸、韧 | 簇、令 |

## 6. 需要用户拍板的点

1. **trait 标签的数量**：7 个（盾/韧/霸/簇/远/冲/令）还是压到 5 个核心 + 2 个变体？标签越多，敌人配置与技能声明的维护成本越高。
2. **特攻做成"加伤"还是"改机制"**（拉近/引燃/无视减伤/打断冲锋）？后者更 PBZ、更有策略味，但每个都要新代码与新表现。
3. **被动池要不要新增 trait 联动型被动**（提案 C 的 8 个），还是先改造现有被动（比如给"震荡"加"对霸目标削韧翻倍"）？前者扩池、后者不加内容但联动弱。
4. **技能要不要真的带 `counterTags` 数据字段**（进 `ActiveSkillDefinition` 资产）并**在 UI 上显示"克什么"**（让玩家看得见答案库）？还是只在内部生效、靠描述文案暗示？
5. **"引"这类"把敌人拉过来"的机制**是否允许（会改变敌人位置，可能与"不可重叠/不可越位"的硬约束冲突）。
