# 无限模式（无尽关）：循环拓扑 · 波次生成 · 分数

> **本文是短线主设计文档。** 讨论于 2026-11-16，结论已与用户对齐；**【暂定】** 表示用户外出期间按推荐先定、可随时推翻。
> 配套：`design/weapon-system-design.md`（武器与经济）、`design/pbz-reference-analysis-20261109.md`（对标）、
> 执行清单 `plan/weapon-endless-mode-plan-20261116.md`。

---

## 0. 一句话

**独立于长坂坡剧情关的第二种模式**：卷轴**无限前进**（神殿逃亡式，内容按圈复用、玩家**不回头**）、节点序列循环、波次程序生成，局结束时结算总分。

> **圈不是玩家可见概念**（2026-11-24 用户定：“不存在圈数这个概念”）：圈只是内部的难度与内容复用单位，不进 HUD、不进分数、不进结算面板。
它是**长期留存内容**，也是**武器获取的主引擎**（Boss 掉武器）。

---

## 1. 模式定位与复用边界（用户已定）

| 项 | 结论 |
|---|---|
| 与长坂坡卷轴关的关系 | **独立新模式**，不替换剧情关 |
| 滚动几何 | **无限前进 + 素材复用**（2026-11-21 用户澄清）：玩家**永不回头**，没有环路；"回到 N1" = 同一批内容再铺一遍。详见 §2.2 |
| 首版范围 | **生成器 + 分数先行**，闭环几何并行推进（几何最吃美术） |

### 1.1 复用 / 不复用

| 复用 | 不复用（另起一条 Flow） |
|---|---|
| 战斗内核、`StageConfig`/`WaveConfig` 数据模型、ColumnManager 补齐、WaveSpawner、三选一、表现层滚动 | `FakeRouteRuntime` 的存档点 / 禁止回访 / 有限节点列表（它是**有限路线**的运行时） |
| 主菜单入口模式（`RouteCatalog` / 选关页） | 剧情关的"抵达→出口确认→旅行→提交"流程（无限模式是自动推进的圈） |

### 1.2 存档语义

- **局内进度不存**：退出即清零（roguelite 惯例，"这局死了就没了"是核心动力）；
- 只存：**最佳分 / 最高圈数**；
- 剧情关**保持原样**（单局成长不变），只有无限模式用循环模型。

## 2. 循环拓扑

### 2.1 圈结构（现状：已按路线纪律跑通）

```
圈（lap）=  N1  →  E0  →  J1  →┬ 左：村口 EV → N3  →（出村）回 N1 ┐
                             └ 右：官道 N2   →（折返）回 N1 ─────┴→ 圈结算
```

- **J1 的左右由玩家在出口面板上点**（左路：村庄石路 / 右路：官道）——与剧情关同一套出口 UI；
- **右路资产早就存在**（`Choice_J1_N2` + `Travel_J1_N2`，距离 76.1），只是**没挂进 `Node_J1.outgoingChoices`**
  （实测：`Node_J1.outgoingChoices` 只有 `j1_to_ev` 一条 ⇒ N2 是不可达孤儿）。
  ⇒ **不动剧情关的节点资产**（那样会多出一个出口，而 N2 没出口 = 死路），改挂在路线的 `extraChoices` 上，**无限模式自己读它**；
- **回程边**（N3→N1 / N2→N1）= 沿路**继续往前走**到"下一圈的 N1"（`PlayNodeTravel` + `wrapTravelSeconds`，
  `MoveTo` 的 `end` 可以 > 1 ⇒ progress 继续增长、**不会倒着滚回去**）；
  既不是锚点跳转，也不是几何闭环（闭环已作废，见 §2.2）；
- 左路 `EV → N3` 已有接线（`Choice_EV_N3`）。

### 2.2 ⚠️ 已作废：**不做几何闭环**（2026-11-21 用户澄清）

> **用户原话**：「我不想转回去，我们是一个像神殿逃亡那样**无限前进**的，这个"回到之前节点"是**素材复用**而已。」
> ⇒ 原 §2.2 的"真闭环 / 环路图 / 主干+两支线+合流点 / 转回主干方向"**全部作废**，不得再按它施工；
> 据此推出的方案（例如把 `Evaluate` 改成环路图、加合流点）一律不采纳。

**正确模型（神殿逃亡式，2026-11-19 已按此实现）**

- 路径是一条**无限延伸的开路径**：`EvaluateLap` 的尾段沿切线方向**不设上限**，位置是沿路距离的连续函数
  （`YScrollSample.EvaluateLap` 注释原话：「不再取模、不再平移 —— 尾段沿原方向无限延伸」）。
- 内容按**一圈长度**重复摆设：第 k 圈 = 第 0 圈内容套本圈**刚体帧**（`GetLapFrame`：位置 + 朝向）。
- 玩家**永不回头**；"回到 N1"指同一批内容在第 k 圈**重新出现**，不是路径闭合。
- ⇒ 因此**没有合流点、没有"转回主干"、没有环路图**。

**唯一残留的接缝**：内容从「地图末尾」切回「地图开头」的那一瞬间。要求只有一条 ——
**看上去是连续的正常路面**（靠内容密度 + 材质收尾，不靠几何闭合）。

| 原 §2.2 条目 | 现状 |
|---|---|
| ① 路径模型升级为**环路图** | ❌ **作废，不要做**。尾段无限延伸已经解决"推进不回头" |
| ② `_YSViewDistance` 从单程路长改成周长；`_YSPose` 带支线状态 | ✅ 已由"一圈长度"接管；"支线状态"随左右路方案一起定（见 §7-2 / §7-4） |
| ③ 锚点周期映射（节点 → 圈内偏移 + k×周长） | ✅ **已实现**（`TryGetNodeProgress` 取"当前距离之后最近的第一次出现"） |
| ④ 战斗坐标与滚动坐标解耦 | ⚠ 与闭环无关；跳接缝时若战斗区错位，仍按此排查 |

> ⚠️ **教训（2026-11-21）**：本文 §1 / §2.2 曾要求"真闭环"，而代码在 11-19 已转向"无限前进"，两者冲突。
> 按旧口径推出来的方案（环路图）是错的。**改设计前先确认口径是最新的。**

### 2.3 流式装载（已有能力）

`YRouteSegments` 按沿路米数预载 / 卸载段 prefab（dwell 预载 + 每帧预算限流）——
**无限流式地形需要的机制已经有了**；按圈复用后，段的区间按 **`startDistance + k × 一圈长度`** 展开（已实现）。

### 2.4 地面与路面连续性（2026-11-24 用户已验收）

> 实现：`Assets/Experiments/CurvedScroll/Shaders/YGroundJ1Branches.shader` + `YLapFollower` 复制模式。
> 取证/未覆盖项见 `plan/endless-ground-continuity-repair-plan-20261123.md` §13–14 与
> `plan/endless-ground-road-uv-handoff-20261124.md` §10。**观感口径以用户实机验收为准。**

**① 谁画哪一段：相邻副本共享同一个平面**

- 地面走**复制模式**（`YLapFollower.copyInsteadOfMove = true`），每圈一份 mesh，按 `GetLapFrame(k)` 摆放；
  原件只当模板、不参与渲染。
- 归属用**副本自身地图空间**的互补半空间：
  - 起点：`_YSLapIndex > 0 && map.y < 0` ⇒ 丢弃（第 0 份不裁下界，保住开局脚下与身后）；
  - 终点：`dot(map − lapEnd(本圈支路), lapForward(本圈支路)) >= 0` ⇒ 丢弃。
- 因为 `F_(k+1) = F_k ∘ S(branch_k)`，第 k 份的终点平面与第 k+1 份的起点平面在世界上是**同一个平面**
  ⇒ 严格互补：不重叠、不露洞。**无缝来自这里，不是靠贴图颜色接近。**
- `copyLapRadius` 必须 ≥ 1（相邻两份各负责一侧）；**不要改回 0**。

**② 纹理坐标：路外固定、路心跟路**

| 区域 | UV | 理由 |
|---|---|---|
| 路外（路肩外 1.5 m 过渡带以外） | `i.map / 4`（本圈地图坐标） | 全图沿路坐标在弯道内侧会**折叠**、路肩会**拉伸**（两次历史失败） |
| 道路走廊（\|横向\| ≤ 路宽+路肩+1.5 m） | 沿路坐标：横向有符号距离 + 沿路米数 | 让土纹**顺着路**，不再相对道路斜铺 |

- 走廊按横向距离 `smoothstep` 与路外混合，过渡带 1.5 m。
- **每圈相位** `phase = fmod(k × fmod(cycleLength, 4), 4)`：按 4 m（贴图周期）约束，不用无界的 `k×L`。
  相位**只**作用于走廊采样与圈界局部；路外必须保持 `i.map/4`，否则圈长不是 4 的整数倍时路外纹理每圈平移。
- 圈界前 20 m 保留一次两套坐标的局部衔接（`seamMix`），且只作用于路外（`× (1 − corridorWeight)`）——
  路心不再叠两套土纹（叠两套会产生重影/颗粒游动）。

**③ 石板（左路村庄）**

- 收尾区间按**本圈 flat z** 反算：`cycleEndZ − (路宽+路肩) − _StoneExitFade`。不能用沿路米数直接填 ——
  分叉后每 1 m 沿路只推进 `cos(45°) ≈ 0.707 m` flat z（旧值 350/26 就是按沿路 380 填的，结果什么都没修到）。
  当前材质真值：`_StoneExitStart = 350`（只对剧情关外路径生效）、`_StoneExitFade = 26`。
- 石板在**圈界之前**淡回土路 ⇒ 圈界两侧都是土路，不会「整屏石→土」。
- 剧情关（`_YSCycleLength = 0`）走原 `_StoneExitStart` 分支，公式与改动前逐字相同 ⇒ 逐像素不变。

**④ 不要做的事**

- ❌ 把沿路 UV 推广到整张地面（拉伸/折叠）。
- ❌ 改回世界 XZ 或整图沿路 UV（纹理相对道路旋转）。
- ❌ 用黑幕、整屏渐隐、移动相机、取消村庄石板来遮接缝。
- ❌ 用「同一像素被画两次」直接判定共面闪烁：远处下沉地面（`0.009·d²`，无上限）会**投影回折**到近景屏幕像素，
  必须用限制近处距离（`_YSGroundMaxZ`）的隔离实验或最终深度归属来区分。

**⑤ 已知遗留（不属于本修复范围）**

- `YLapFollower` 的副本只 `SetActive(false)` 不销毁：每圈 +1 GameObject（mesh 共享），10 圈后字典留存 12 份。
- 远端地面回折投影本身未处理（当前靠深度测试 + 近景裁剪兜住）。

**验收记录（2026-11-24）**：用户在真实无尽入口按正常速度观察 N1 → J1 → 左右支路 → 圈界后确认「已验收」。
定量侧：剧情关右支/左村定点逐像素 0 差；左右混圈 LR/RL 经自然旅行到第三圈入口；两次圈界近景逐像素单份覆盖。
**未覆盖**：Android 真机性能、宝箱/掉落与完整布景生命周期、玩家手动打完战斗的全程。

## 3. 波次生成器（替代手写编队）

### 3.1 为什么以前配得很烂（自我诊断）

1. **把难度等同于 HP 倍率**：`stage-configuration.md` §5.6.1 白纸黑字写着"已落倍率 = 脚本推导值"。
   但玩家等级与装备在波次之间持续增长 → 前磨后秒。倍率只买到"这一波打 30 秒"，没买到"这一波有威胁结构"。
2. **编队是"列清单"不是"场景"**：一波 10 排里只有 3–5 排有敌人，空排占位符吃掉行预算，视觉上是"点状"不是"阵型感"。
3. **教学契约靠天赋节点兜底，是事故**：实测"机器人没有 C2 就卡死在 E0 的 1012"；
   1012 在任何正式关里一次都没出现过（实测）；105/106 随机/固定远程混用没区分；1021 破盾只有 ~1/3 概率也没当成关卡设计问题。
4. **难度曲线没跨节点标定**：各节点各自调倍率，没有贯穿整线的"时间—威胁—成长"曲线。

### 3.2 四层规则（生成器 = 规则，不是手写行）

**输入（参数化，不含随机）**：`phase`（教学/中段/后期/BOSS）、`budget`（本波威胁预算）、
`archetype`（波次原型）、`circle`（圈数）。

**第 1 层 · 威胁配对表（教学契约，硬约束，不随机）**

| 敌种 | 威胁 | 强制对策 | 我们手上的对策 |
|---|---|---|---|
| 1011 | 推进压迫 | 任意攻击 | 基础戳击 |
| 1012 | C 技霸体前摇 | 重攻击打断 / 招架格开 | 蓄力重攻击、招架 |
| 109 骑兵 | 冲锋 | 蓄力攻击打断（招架无效） | 蓄力重攻击 |
| 1021 盾卫 | 盾侧格挡 | 反侧 + 重攻击破盾 | ⚠ **目前只有 ~1/3 概率**（重攻击方向 Random） |
| 105/106 远程 | 远程消耗 | 招架弹反 / 位移打断 | 招架、位移流主动 |
| 1051 | 固定落点远程 | 同上 + 预判列 | 同上 |
| 1014 投壶兵 | 毒 + 远程 | 打落投射物 / 走位 | 挥枪打落（已实现） |
| 104/107/108 | 阶段霸体 + QTE | 招架削韧破势 | 招架 |

⇒ **对策不在玩家能力表里 ⇒ 该敌种不出场**（这是对"教学顺序与关卡实际配置不符"的根治办法）。

> ⚠ **暴露的缺口**：1021 的破盾概率化（`hitReactionDirection = Random` × `isHeavy`）意味着
> "破盾"**不能**作为关卡的强制教学点，除非先做跟手精确攻击。
> ⇒ 暂定：无限模式里 1021 只作"混合威胁"，不作"考核点"。

**第 2 层 · 编队语法（行模板库）**

| 模板 | 形态 | 用途 |
|---|---|---|
| 压迫排 | 3 杂兵同排 | 推进压迫感、基础手感 |
| 护卫+远程 | 近战前排、远程在后 50%（规则十） | 混合压力 |
| 侧翼包夹 | 两侧近战 + 中间空槽 | 给玩家走位/位移空间 |
| 冲阵 | 骑兵单排突前 | 逼玩家用蓄力打断（同波需有可打断手段） |
| 盾阵 | 盾卫排 + 后排杂兵 | 盾侧/反侧教学（需先修破盾） |
| 精英 | 单只高威胁单位 | 波次收尾 |
| 节奏门排（999） | 整排门 | 分隔"前段小怪 → 后段大阵" |

**第 3 层 · 难度 = 威胁结构，不是数值**

用**威胁点数**记账：`threatPoints = Σ(敌种基础威胁 × 数量 × 阶段系数)`，与阶段目标曲线比对 → 多退少补，
**补的必须是配对敌种或模板结构，不是血量**。血量倍率只在最后作收尾成本微调（≤±20%）。

> 对应 PBZ："高难度不是加血加攻，是敌人行为变难"（我们的对标文档 §4.3 已记）。

**第 4 层 · 合规校验器（自动）**

把 `stage-configuration.md` §4 的硬规则做成生成器自检：
规则七（每波 ≥1 次升级）/ 规则八（30–55 秒）/ 规则九（Boss 最后排）/ 规则十（远程后 50%）/
列长 ≤5 / 999 位置 / 每波有唯一可解威胁。
工具可复用：`FakeRouteGraphValidator`（拓扑自检先例）、`Tools/analyze_level_telemetry.py`、`CombatDataTableWindow`、跑关机器人 `BattleAutoPlayer`。

### 3.3 随机性的边界（"有规律"的操作化定义）

| 随机 | **不**随机 |
|---|---|
| 选哪个模板、列位偏移、同一敌种的列分布、插入次要威胁 | 是否首次引入某敌种、是否与对策配对、难度档位、Boss 时机、波数 |

⇒ **随机只作用于"布局与配比"，不作用于"教学契约与难度曲线"。**

### 3.4 种子

**建议做**：生成器是纯函数 `Generate(seed, circle, phase) → WaveConfig[]` ⇒ 同种子同关卡。
无尽模式没有种子就无法复现 bug、无法分享、无法做"今日一局"。【暂定：做】

### 3.5 难度曲线的两条铁律

1. **敌人等级按圈数显式给，不跟随玩家**（PBZ 口径：遭遇等级由区域/敌群配置决定，不跟随玩家等级）。
   ⇒ 玩家堆数值不会自动抵消难度；否则内容被架空。
2. **清场时间护栏**：生成器校验器加一条"目标清场 ≥ 8 秒"。
   玩家堆到 30 秒秒杀时，这条规则强制生成器改用"更多波 / 更多排"，而不是"更高血量"。

> **圈数 → 敌人等级的曲线本身是数值工作**，用户定"慢慢打磨"；工程侧先配一版（见执行计划 Batch 1 的"占位曲线"）。

### 3.6 ★ 长关卡的难度口径：**照抄手写配置 + 按圈数改倍率**（2026-11-16 用户定）

> 用户口径：“**照抄我的关卡配置，适当改波次敌人倍率，试着配个长关卡**”
> （背景：“你之前配的关卡都很烂不如我配的” ⇒ **内容基底用玩家/策划手写的关卡，程序生成器降为备用**。）

**内容基底（实测）**：

| 关卡资产 | 波数 | 每波行数 / 敌人数 | 备注 |
|---|---|---|---|
| `Formal_N1_Battle`（N1·当阳乱军） | 1 | 10 行 / 7 只 | 1011×3 + 1013 + 1012×3 |
| `Formal_E0_Battle`（E0·盾阵残门） | 5 | 10 行 / 10,6,9,14,10 只 | 大量 1012（霸体）+ 1051 + 109 |
| `Formal_N2_Battle`（N2·官道断后） | 3 | 2~3 行 / 4 只 | 含 104（两阶段）；原资产自带 hp×4.5/2.9/3.5 |
| `Formal_N3_Battle`（N3·村落搜救） | 5 | 10/10/15/6/1 行 / 17,12,30,8,1 只 | 末波 = 107 BOSS |

**圈数缩放（只写在**深拷贝**上，绝不污染原资产）**：

| 项 | 公式 | 圈 1 → 2 → 3 → 4 → 5 → 6 |
|---|---|---|
| 杂兵 HP | `×1.6^(圈-1)` | 1 → 1.60 → 2.56 → 4.10 → 6.55 → 10.49 |
| BOSS HP | `×1.25^(圈-1)`（上限 ×4） | 1 → 1.25 → 1.56 → 1.95 → 2.44 → 3.05 |
| 攻速 | `×1.06^(圈-1)`（上限 ×1.5） | 1 → 1.06 → 1.12 → 1.19 → 1.26 → 1.34 |
| 伤害 | `×1.04^(圈-1)`（上限 ×2） | 1 → 1.04 → 1.08 → 1.12 → 1.17 → 1.22 |

设计意图：**血量成长快于玩家成长**（否则圈数一多就秒清），**伤害/攻速成长慢**（否则直接死亡螺旋）。系数均为 Inspector 可调字段（占位值，等实机标定）。

**长关卡的圈拓扑**（用户给的形状，循环边用**循环边 + 次数上限**表达）：

```
N1（可循环，上限 = n1NodesPerCircle=2）
 → E0（5 波）
 → J1  ★玩家在这里选：左路 EV / 右路 N2
     ├ 左：EV → N3（可循环，上限 3）→（回程边）→ N1
     └ 右：N2（可循环，上限 3）→（回程边）→ N1
```

⇒ 一圈约 **25+ 波**（N1×2 + E0×5 + J1 + EV + N3×3×5 …）= 真正的长关卡。

### 3.7 ⚠ 规则十一：**波次的第 0 排必须有敌人**（2026-11-16 实测踩到，已写进生成器）

现象：生成器偶尔产出「第 0 排是空排占位符」的波次 → 敌人**永远停在 1 排**，玩家打不到 → 双方互相够不到 = **永久卡死**（实测卡在 row 1/5/9）。

根因：
- 敌人在「逻辑目标排后方两排」生成，再靠**行前移**进场；
- 行前移的触发条件是「**某排被打空**」——空排占位符**不会自己往前挪**；
- 现有关卡资产每一波的第 0 排都有敌人（N1/E0/N3 全部如此）——这是隐含约定，之前没写进规范。

⇒ 生成器已加 `EnsureFrontRowOccupied()` + `ValidateWave` 校验项；清场护栏的删怪逻辑也**不再删第 0 排**。

## 4. 分数与结算

### 4.1 计分规则：**只按击杀**（2026-11-24 用户定）

| 来源 | 取数 | 时机 |
|---|---|---|
| 击杀分 | `EndlessEnemyThreat.score`（杂兵 10 / 15 / 20 / 25；Boss 220 / 260 / 300） | **击杀当场累加**，HUD 数字立即跳 |

> **一个敌人值多少分是固定的**，不随层数放大（旧版 `1 + (层-1)/2` 已删）。
> **没有波次奖励分**：旧版那套「基础 100 + 快枪 + 残血 + 连击 + 无伤 + 无破防」是代码里自行设计的占位规则，
> 用户表示不了解也不需要 ⇒ 已整体删除（`EndlessScoreLedger` 只剩 `AddKill` / `Reset`）。
> **没有圈里程碑分**。总分 = 击杀分之和。
> 以后要加新计分规则（连击、破防、探索等），**先写进本节再实现**。

### 4.2 只有一层结算：局结束

| 层 | 时机 | 内容 | 是否打断 |
|---|---|---|---|
| 局结束结算 | 阵亡 / 玩家提前退出（暂停菜单） | **只显示本局总分 + 历史最高分**；淡入 0.28 s，确认后回落地页 | 重，是玩家唯一的结算面板 |

> 圈结算 2026-11-19 被否定（“除非玩家死亡、结束本局，你出这个结算干嘛？”），
> 2026-11-24 进一步取消圈概念本身，并取消波次结分 ⇒ 中途没有任何结算画面、没有飘字积分。
> 阵亡与提前退出共用同一个面板。

### 4.3 分数的用途

1. 即时反馈（数字滚动）——最便宜；
2. 存档最佳分（无尽模式天然需要"我上次多少分"）；
3. **换局外成长材料**（铜钱 / 武器材料）——与长线交汇，价值最大。

## 5. 武器掉落节奏（用户定：不断打 Boss 获得新武器）

| 来源 | 性质 | 去向 |
|---|---|---|
| **无限关每圈的 Boss** | **永久武器** | 进武器台（永久收藏）→ 主留存钩子 |
| 局内宝箱 / 精英掉落 | **临时武器**（当局有效，用完即失效） | 应急解法（手头武器打不过时） |

两条约束（缺一不可，否则循环空转）：
1. **武器获取必须挂在无限关上**（不是剧情关）⇒ 打到第 N 圈才拿到第 N 把武器 ⇒ 无限关成为**内容解锁的主引擎**；
2. **首把武器要早给**（前 10 分钟内）⇒ 新玩家还没建立"换装"钩子就流失了。
