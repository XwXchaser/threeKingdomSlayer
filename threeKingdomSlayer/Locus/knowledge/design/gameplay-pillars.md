# 玩法五大支柱：轻重攻击 / 连招 / 技能组合 / 敌人机制 / 路线分支与节点奖励

> 本文只写**玩法**：玩家在每个支柱上做什么决策、系统如何回应、现在缺什么。
> 系统实现全貌（UI、技术架构、资产地图、实现状态清单、已知问题）见 `design/game-mechanics.md`。
> 所有数值与"字段是否存在/是否被消费"均来自工程实测（资产 + 代码引用检查），已实现/未实现严格区分。

## 0. 五个支柱的位置与成熟度

| # | 支柱 | 玩家的核心决策 | 成熟度 | 主要落点 |
|---|---|---|---|---|
| 1 | **轻重攻击** | 什么时候快速轻击、什么时候按住蓄力出重招 | 🟡 机制在，分工未成立（数值倒挂、蓄力分级无收益） | `InputManager`、`AttackSystem`、`AttackSkillConfig` |
| 2 | **连招** | 用哪条链、什么时候接续、拿什么收尾 | 🟡 状态机 + 2 条链已完成，内容/上下文态未做 | `PlayerMoveStateMachine`、`Moves/Zhangfei/*` |
| 3 | **技能组合** | 三选一怎么搭配成流派 | 🟡 系统完备、池被调试权重污染、组合大多靠"共用触发键"隐式成立 | `ActiveSkillPoolConfig`、`UpgradeDefinition`、`ActiveSkillRunner` |
| 4 | **敌人机制** | 识别威胁 → 用正确对策 | 🟡 6 类机制已实现且各有反制，但关卡没按教学顺序摆、1021 破盾是概率 | `Enemies/*.cs`、`EnemyPrefabs` |
| 5 | **路线分支与节点奖励** | 走哪条路、得到什么 | ⛔ **半成品**：节点奖励未实现、分支之间无差异 | `RouteFake/*`、`RouteData/ChangbanpoScroll/**` |

结论先说：**1–4 是"机制在、内容不在"，5 是"框架在、玩法不在"**。讨论新机制前，五根支柱里最值得先补的是支柱 5（分支与节点奖励目前没有任何决策价值）。

## 1. 支柱一：轻重攻击

### 1.1 现状：轻/重由**输入门槛**划分

| | 轻攻击 | 重攻击 |
|---|---|---|
| 输入 | 点击（松手且未滑动）；未蓄力的横滑/斜滑 | 按住 ≥1 级蓄力（0.3s）后：松手 / 横滑 / 竖滑 |
| 招式 | 戳击 Stab、斩击 Slash | 穿刺 Pierce、横扫 Sweep、挑飞 Launch |
| 排数 | 1 | 3（Launch 为 1） |
| 架势伤害 | 0 | Launch 50、Parry 10 |
| 大招能量 | 10 / 10 | 15 / 12 / 8 |
| 动作时长 | 0.45 / 0.50 | 0.50 / 0.55 / 0.60 |
| 系统级"重"标记 | — | `interruptsCavalryCharge = true` |

**关键事实：`interruptsCavalryCharge` 就是当前唯一的"重攻击"语义**。它被两个机制消费：

1. 能否打断 **109 骑兵**的冲锋；
2. 能否**破 1021 盾卫的盾**（见支柱四）。

即：目前"重"的真实战术含义 = "能处理骑兵与盾牌"，不是"伤害更高"。

### 1.2 蓄力分级目前只决定"出哪种招"，没有伤害收益

- 蓄力门槛 `0.3 / 0.6 / 1.0` 秒对应 1/2/3 级；等级门槛 ≥1 才允许出重招。
- `AttackSkillConfig.chargeLevelDamageMultipliers`（按级缩放伤害的表）**在所有 11 个招式资产上都是空的** → 蓄到 1 级、2 级、3 级打出的 Pierce 伤害完全相同。
- 唯一与"蓄得久"有关的收益是生存类：铁壁（蓄力减伤）、蓄力期间获得的一次性护盾。

### 1.3 当前轻/重的实际平衡（讨论时必须面对的真实数字）

| 招式 | 伤害 | 排数 | 备注 |
|---|---|---|---|
| Stab（轻） | **20** | 1 | 0.3s 冷却口径，主力 |
| Slash（轻） | **8** | 1 | 比 Stab 弱 60% |
| Pierce（重） | **20** | 3 | 与 Stab 同伤害，但覆盖 3 排 |
| Sweep（重） | **5** | 3 | 伤害最低 |
| Launch（重） | **2** | 1 | 价值全在削韧+浮空 |

→ **伤害与"轻重"完全脱钩**：轻的 Stab 是全场最高单体输出之一，重的 Sweep/Launch 几乎是纯功能招。这是内容量不足时期的遗留值，不是设计结论。

### 1.4 已有的两条冷却哲学（都已实现，可切换）

- **动作锁模式（当前运行）**：攻击动画期间锁住全部输入，不查每招独立 CD。手感接近无双连打。
- **独立 CD 模式**：每招各算冷却，可交替连打。设计上保留给"移除动作硬直"这类奖励效果。
- 攻速提升会同时压缩动作时长与视觉序列（连招窗口按百分比自动跟随）。

### 1.5 支柱一可讨论的空间（接口已就位）

- **分工维度**：伤害 / 排数 / 削韧 / 打断能力（重标记）/ 位移（击退排数、击飞）/ 大招能量 / 命中反馈强度（Light-Standard-Heavy 卡肉已分级）。
- **蓄力等级收益**：`chargeLevelDamageMultipliers` 表已预留，填表即可让"蓄更久"有回报。
- **轻攻击节奏**：动作锁 vs 独立 CD 的双模式开关已实现，可直接对比试玩。

## 2. 支柱二：连招

### 2.1 模型：招式转移图

```
节点 = 一个招式资产（AttackSkillConfig：表现/判定/位移/时长全在一个资产里）
边   = (手势 + 接续窗口 + 最小蓄力等级) → 后继招式资产
窗口 = 同一条视觉序列的百分比区间（默认 0.65~1.0，最小绝对 0.06s）
无匹配边 = 不响应（当前招式收尾回中立，不回落出中立招式）
```

- 输入在窗口内提前到达会进**输入缓冲**；窗口外丢弃。
- 按住不放时节点会**驻留**在最早窗口起点（上限 1.2s），以便"按住蓄力再滑出"的收尾招能成立。
- 卡肉会冻结阶段时钟，因此窗口与视觉始终对齐。

### 2.2 已实装的两条链

| 链 | 输入 | 段位与数值 | 落点/位移 | 受击方向 |
|---|---|---|---|---|
| **张飞·枪突链** | 点 → 点 → 点 →（按住蓄力）上划 | 枪突-1 `20`/0.45s → 枪突-2 `26`/0.40s → 枪突-3 `34`/0.60s → **终结技 `60`**/0.60s、3 排、架势 80 | 前 3 段单列；终结技全列 3 排 + 挑飞 | 正面 → 盾侧 → 反侧 → 随机 |
| **张飞·指向突刺链** | 点一下 → 按住（可横向改目标列，枪身朝所指列偏摆 60°）→ 松手 | `35`/0.66s，2 排，击退 1 排 | 松手所指列的前 2 排 | 随机 |

值得注意的是：**枪突链三段刻意给了三种受击方向**（Front / Left / Right）。这在 1021 盾卫身上会变成设计张力——第 2 段打在盾侧（被格挡）、第 3 段打在反侧（全额伤害）。

### 2.3 连招与"结算"的分离（不可破坏的契约）

- 段位推进**按输入**（空挥也推进，否则面向空列永远连不上）。
- 冷却、大招能量、被动计数**按首次实际命中**结算（空挥不刷能量、不触发被动）。
- 位移与击退必须走 `ColumnManager` 既有通道，不能绕开。

### 2.4 未完成的部分（新机制讨论的真实边界）

| 项 | 状态 |
|---|---|
| 招架成功态 + 专属连招（P3） | ⛔ 需要 `OnParrySuccess` 事件与状态替换解析表 |
| 局外解锁"边/节点"（P4） | ⛔ 依赖尚未实现的天赋树 |
| 三段枪突的**视觉区分** | 🟡 三段目前共用同一套素材，只有参数不同 |
| 斩·二连 / 挑·二连 / 三连等分支 | ⛔ 边未配 |
| 空中连段、跳跃攻击、无双槽 | ⛔ 明确排除在近期范围外 |

### 2.5 扩展协议（加新连招必须走）

资产 `Assets/ScriptableObjects/Moves/Zhangfei/<武将>_<动作><段号>.asset`；`id` 区间：1–9 直通招式、11–19 枪突链、21–29 指向突刺链、30 起每条新链一个十位段；后继一律用 `moveEdges` 直接引用（禁止字符串查找）；登记到 `design/combo-registry.md`。

## 3. 支柱三：技能组合（局内 Build）

### 3.1 组合的容器

| 项 | 值 |
|---|---|
| 被动上限 | 6（硬编码） |
| 主动槽 | 4（`HeroConfig.itemSlotCount`） |
| 池条目 | 14 个（Common 6 / Rare 5 / Legendary 3） |
| 稀有度权重 | Common 0.60 / Rare 0.35 / Legendary 0.05 |
| BOSS 掉落 | 只抽 Rare + Legendary 的**主动技能** |
| 升级次数 | 每级一次三选一；经验曲线 60 级（Lv1 需 200 经验） |

### 3.2 "组合"从哪来：现有机制只通过**共用触发键**产生耦合

| 触发键 | 挂在上面的技能 | 组合含义 |
|---|---|---|
| **蓄力攻击** | 铁壁（蓄力减伤）、主动冲击波（点击充能 → 下次蓄力逐层释放）、震荡（蓄力命中附带冲击波，蓄力期间每受击 +15~25% 波伤害） | 蓄力流：一个键驱动攻防两路 |
| **戳击命中** | 染病（"下一次戳击"使目标染病，可叠层） | 疾病流必须保留戳击/枪突链；与纯蓄力流互斥 |
| **灼烧状态** | 蛇形喷射（定时喷火挂灼烧 DoT）→ **火龙舌 Lv3 起对灼烧目标 200% 暴击**（代码已验证：`critIfBurning = level >= 3`，命中时查 `IsBurning`） | 火系协同：跨主动/被动的真实联动，且**有 Lv3 门槛** |
| **主动 CD** | 专注（主动 CD 累计 −52%）→ 海浪 / 旋风 / 箭雨 / 冲击波 / 火龙舌 循环加快 | 位移流：靠减 CD 实现"控制技能高频循环" |
| **攻击范围** | 拔苗助长（+1/+2 排，代价是这些范围伤害 −30%/−25%） | 与伤害流冲突，是"范围换伤害"的取舍 |
| **连击数** | 20 连击 → 伤害 +10%（独立系统，不占技能槽） | 与高频轻攻击/多目标技能协同 |

### 3.3 现状可辨识的三条路线（不是设计愿景，是当前池能凑出来的）

- **蓄力流**：铁壁 + 主动冲击波 + 震荡，全部挂在蓄力攻击上，靠生存换蓄力时间。
- **位移流**：专注 + 海浪（零伤害击退）+ 旋风（零伤害浮空）+ 疾风（攻速），对未眩晕 BOSS 改为按最大架势百分比削韧。
- **火系协同**：蛇形喷射（挂灼烧）+ 火龙舌（Lv3 起暴击），跨主动/被动，不绑定流派。

### 3.4 支柱三的现存阻碍（讨论前最好先清掉）

1. **池内调试权重**：染病 300、蛇形喷射 100000（会碾压其他候选）。
2. **稀有度与资产字段不一致**：火龙舌在 Common 池、疾风与蛇形喷射在 Rare 池，但设计稿是反过来的。
3. **前置条件系统已实现但零使用**：所有条目 `prerequisites` 为空——"组合解锁"这条玩法线还没启用。
4. **主动技能零伤害的两个（海浪/旋风）**：纯控场，必须与输出类组合，否则打不死人；这是有意设计还是缺口需要在讨论中定。
5. **图标缺口**：专注缺图、拔苗助长复用疾风、染病复用主动冲击波、主动冲击波复用被动冲击波图标。
6. 未入池但存在：主动烈焰喷射（与被动蛇形喷射重复）、虚幻武器、回旋波、连锁弹射、箭矢齐射等——是否回收或改造未决。

### 3.5 可讨论空间

跨技能"改写规则"型效果（把属性挂到某条边上、放宽接续窗口、替换节点）、双 DoT（灼烧 + 疾病）交互、主动/被动同键共振（例如"每次蓄力释放都刷新某主动的 CD"）、技能与连招段位的绑定（"第 3 段附带火"）。

## 4. 支柱四：敌人机制（威胁识别与反制）

### 4.1 反制表（这是玩法本体）

| 敌人 | 威胁 | 正确对策 | 错误对策的代价 |
|---|---|---|---|
| **101 / 1011** 杂兵 | 推进压迫、成排推进 | 任意攻击打断 | — |
| **103** 长枪兵 | C 技前摇 3s，期间**霸体**（红描边） | **招架 / 任何重攻击** 打断；重攻击还削韧，削满可破势眩晕 | 用普通攻击打：弹刀反馈，攻击照常落下 |
| **105** 弓箭手 | 远程落点随机散布（±1.2） | Parry 弹反飞行物 / 先手位移打断 | 被持续消耗 |
| **106** 固定弓 | 远程落点按列固定（可预判） | 同上，且可提前走位/预判列 | 同上 |
| **109** 骑兵 | 冲锋循环（可从任意排发起），伤害 = 8 ×(发起排+1)× 波次倍率 | **蓄力攻击**（`interruptsCavalryCharge`）打断，本次不结算伤害 | 骑乘期免疫眩晕与位移，Parry 无效；打不断就被撞 |
| **1021** 盾卫 | 盾侧/正面格挡（伤害固定 −10，下限 1） | 从**反侧**打（受击方向 Right）；反侧 + 重攻击 = **破盾** → 掉盾 → 胆怯（受伤 ×1.5、不再攻击） | 从盾侧/正面打重攻击也只是格挡（`heavyFromShieldSideBreaks = false`） |
| **102** 盾兵 | 常态减伤 50%，且与相邻同族**共享血池** | 集中输出共享血池；整组同时死亡 | 分散打、逐个点杀效率极低 |
| **104 / 107 / 108** BOSS | 霸体阶段、多阶段切换、QTE 必杀 | **招架立即打断；重攻击也能打断并削韧**，削满 → 破势眩晕（安全输出窗） | 霸体期硬拼、QTE 失误（受 15–20 伤害） |

### 4.2 ⚠️ 1021 破盾目前是**概率**，且与"轻重攻击"耦合

- 破盾条件（代码实测）：`反侧（Right）` **且** `isHeavy`；其中 `isHeavy` 传入的是 `interruptsCavalryCharge`，即**蓄力攻击**。
- 但所有重攻击（Pierce / Sweep / Launch / 终结技）的 `hitReactionDirection` 都是 **Random**（命中时 `Random.Range` 掷向 Front/Left/Right）。
- 结果：**蓄力攻击砸盾卫只有约 1/3 概率摸到反侧并破盾**，其余情况是普通伤害或格挡。
- 设计文档已记录要引入独立的 `breaksGuard` / `isPreciseAim` 字段与"跟手精确攻击"（松手所指列打反侧），尚未实现。这是支柱一 × 支柱四最直接的耦合缺口。

### 4.3 敌人攻击的窗口与打断（所有反制的时间基础）

```
冷却 → AttackSpawn 前摇（可打断）→ 造成伤害 → AttackDraw 收招（不可打断）→ 冷却
```
BOSS 差异：CFrame（C 技）/ SuperArmor（阶段霸体）窗口**只有招架与重攻击**能打断（重攻击同时削韧，削满 → 破势眩晕）；收招一律不可打断；QTE 期间不可打断（独立系统）。

### 4.4 BOSS 作为"机制毕业考试"

- 推进仪式感：后排待机 → 前两排全清 → 进 1 秒无敌缓冲 → 开战；期间作为**墙壁**不允许敌人被击退到身后（该保护仍有已知缺陷）。
- 架势/眩晕：削韧来源 = **招架 + 任何重攻击**（重攻击 = 招式资产 `isHeavy`），但**只在霸体窗口内生效**（破势是破霸体的手段，不是通用输出窗）；架势不自动恢复，**眩晕结束后重置满值**；另有“招架命中 + 血量低于阈值”直接眩晕的第二条路径。
- 阶段：104 为 3 阶段（100% / 70% / 30%，后两阶段带霸体），107 单阶段，108 两阶段。
- QTE：TripleStab（3 次点击防反，`fixedQteDuration 4.5s`，7 箭/波）与 Sweep（180° 滑动格挡）；Strict 输入规则会在 QTE 期间吞掉战斗输入、提前输入判失败。

### 4.5 教学顺序与关卡实际配置不符（现状问题）

设计意图是 `101 → 103（霸体）→ 106（固定弓）→ 105（随机弓）→ BOSS`。
但当前部署的卷轴预览关 N1 首排就是 `[1021, 0, 1011, 0, 109]`——**玩家第一波就同时遇到盾卫与骑兵**，而这两种"需要正确对策"的敌人是玩家还没学会 Parry/蓄力打断的时候。新机制讨论时若涉及教学曲线，这是需要一并解决的。

### 4.6 可讨论空间

新敌人的"教学点"必须**唯一且可反制**（一个威胁 + 一个正确对策）；方向/部位判定（盾已开先例）；群体连携（共享血量已开先例）；精英化（同时叠加两个需对策的窗口）。

## 5. 支柱五：路线分支与节点奖励

### 5.1 运行模型

```
抵达节点 → 播放节点内容（对话/演出）→ 执行 BattleEntry（每次进入最多 1 个未完成条目）
 → 内容完成后显示出口 → 玩家点击出口（单出口也必须点击）→ 播放该边旅行演出
 → 提交目标节点（此时才写存档点快照）→ 下一节点
终点节点：无出口 → 终点演出 → 整关结算
```

### 5.2 字段 → 是否真的生效（这是本支柱的关键表）

| 节点配置字段 | 语义 | 运行时是否消费 |
|---|---|---|
| `battleEntries[]` | 该节点的战斗序列（每次进入最多打一个未完成条目） | ✅ 生效 |
| `outgoingChoices[]` | 出口列表（0/1/多个） | ✅ 生效 |
| `isFinalNode` | 终点节点 | ✅ 生效 |
| `savePoint` | 抵达即写快照 | ✅ 生效 |
| `entryDialogue` / `postBattleDialogue` / `postBattlePresentation` | 进节点台词、战后台词与演出 | ✅ 生效 |
| `dialogues[]` | 节点台词列表 | ❌ 未被运行时读取 |
| **`rewards[]`** | 节点奖励（`KillRewardEntry`：铜钱/回血） | ❌ **字段存在，运行时完全未读取 → 节点奖励未实现** |
| `completionPolicy` | 完成策略枚举（4 种） | ❌ **全项目无任何消费点** |
| `terminalPolicy` | 终点策略枚举 | 🟡 仅路线校验器使用 |
| `visualProfile` | 节点视觉档 | 🟡 供卷轴表现层使用 |

整关级：`FakeRouteStageConfig.clearCoinReward` **生效**（终点结算时发放），但当前卷轴路线配的是 **0**。

### 5.3 奖励目前只有两个层级在跑

| 层级 | 现状 |
|---|---|
| **战斗内** | 敌人 `coinReward = 10`/只、`expReward`（101 为 80、103 为 50、104 为 400 等）、击杀里程碑（`Stage_1` 配了 5/20/50 → 30/50/100 铜钱；卷轴预览关与 `Stage_Trial` 均**未配**） |
| **节点级** | ⛔ 未实现（见 5.2） |
| **整关级** | ✅ 生效但当前为 0 |

### 5.4 当前分支**没有**任何玩法差异

- 拓扑：`N1 → E0 → J1 →{ 左：EV → N3 ｜ 右：N2 }`。
- 左支（EV，无战斗）最终打 N3、右支直达 N2，但 **N2 与 N3 引用的是同一份战斗配置**（`SmallBattle`），奖励、敌人、时长完全一致。
- 选择面板只显示 `displayName` 与按钮布局，**没有任何风险/奖励/预览信息**（`FakeRouteChoiceConfig` 字段只有 choiceId / displayName / targetNode / presentation / layout）。

→ 也就是说：**支柱五目前只有"流程"没有"选择"**。这是本轮最值得先补的玩法缺口。

### 5.5 做分支玩法时必须先定的三件事

1. **差异来源**：分支之间差什么？（战斗配方：敌人组合/波次倍率/Boss 有无；奖励：节点奖励/整关奖励/局内成长加速；风险：血量惩罚/额外波次/更难的敌人机制教学）。可选做法都已具备载体——`battleEntries` 可挂不同 `StageConfig`，`killMilestones` 是按战斗配置配的，`rewards` 字段已存在只差消费。
2. **信息呈现**：选择界面是否展示"预期收益/风险预览"（现在连字段都没有，需要新增预览数据）。
3. **规则边界**：已完成 BattleEntry 不重复挑战；存档点在节点入口；跳过的条目不算永久完成；单出口也要玩家确认；不得自动前进、不得按节点瞬时切换整套场景视觉。

### 5.6 结构约束（分支/节点机制不能破坏的东西）

- 节点是逻辑资产，不是 Unity 场景；节点切换不加载/卸载场景。
- 旅行是连续的距离推进（3 秒/段、节点间距 80 单位），战斗坐标不随卷轴移动。
- 非战斗阶段（旅行、出口确认、等待奖励）必须**清空战斗运行态**：主动技能与计时被动显示为就绪、无被动触发、禁止出招，直到下一场战斗正式开始。

## 6. 支柱之间的耦合（改一根会动到另一根）

| 耦合 | 说明 |
|---|---|
| 轻重攻击 × 敌人机制 | `interruptsCavalryCharge` 同时定义"能否打断骑兵"与"能否破盾"；重攻击方向是 Random → 破盾概率化 |
| 连招 × 敌人机制 | 枪突链三段故意给了 正面/盾侧/反侧 三种受击方向 → 与 1021 的方向判定直接互动 |
| 连招 × 轻重攻击 | 终结技本质是"链内的重攻击"（Launch 类型 + poise 80 + 重标记）；轻攻击负责推进段位 |
| 技能组合 × 轻重攻击 | 蓄力键同时被铁壁/冲击波/震荡/铁壁减伤消费；蓄力等级本身仍无收益 |
| 技能组合 × 连招 | 染病挂在"戳击命中"上 → 枪突链每段都是戳击，是疾病的天然载体 |
| 分支 × 节点奖励 | 没有奖励差异就没有分支意义（当前状态） |
| 分支 × 战斗规则 | 节点内战斗必须遵守同一套补齐/位移/打断约束，分支不能引入新的移动语义 |

## 7. 讨论新机制时的检查清单

1. 它属于五根支柱的哪一根？是加强现有决策，还是新增一层决策？
2. 它挂在哪个**触发键**上（蓄力 / 戳击命中 / 灼烧 / 主动 CD / 连击 / 击杀 / 节点）？没有触发键就无法与既有技能组合。
3. 它会改变哪个"重攻击"语义（打断骑兵 / 破盾 / 削韧 / 击退），还是需要新增一个被系统消费的标记？
4. 位移是否只走 `ColumnManager` 通道？是否满足不重叠、未受位移者不动、原槽回位？
5. 打断/受击方向是否逐段透传（`canInterruptCFrame` / `interruptsCavalryCharge` / `poiseDamage` / `hitReactionDirection`）？
6. 数值是否与当前量级一致（101 HP 200、Stab 20、Pierce 20/3 排、BOSS 500）？
7. 是否需要玩家在**正确时机**做**唯一正确的事**？若"什么时候做都行"，它就不是敌人机制而是数值。
8. 是否要求玩家在分支上做取舍？如果需要，节点奖励与选择预览数据目前**还不存在**，要先建。
9. 是否依赖未实现系统（天赋树、条件系统、剧情选项、节点奖励、`RandomUpgrade`）？若是，须同时给出降级方案。
10. 是否破坏第 5 节与 `design/immutable-constraints.md` 的约束？
