```
┌──────────────────────────────────────────┐
│  天  赋                          [铜钱] 🪙 │  ← 标题 + 铜钱（已有）
├──────────────────────────────────────────┤
│  [能力]  [招式]  [技能]                    │  ← 顶栏：大页面（新增）
├──────────────────────────────────────────┤
│  ┌ 战斗向 ─┐ ┌ 生存向 ─┐ ┌ 经济向 ─┐      │  ← 页内：分支（新增）
│  │  ●破阵   │ │  ●铁血   │ │  ●聚财   │      │
│  │   │      │ │   │     │ │   │     │      │
│  │  ●追击   │ │  ●连击精通│ │  ●巧思   │      │
│  │   │      │ │   │     │ │   │     │      │
│  │  ●运筹   │ │  ●不屈   │ │  ●博学   │      │
│  └──────────┘ └──────────┘ └──────────┘      │
├──────────────────────────────────────────┤
│  节点说明栏（点击节点后显示）                  │  ← 已有
│                                    [返回] │  ← 已有
└──────────────────────────────────────────┘
```

**两级导航**

| 级别 | 内容 | 数量 | 来源 |
|---|---|---|---|
| 大页面 Tab | 能力 / 招式 / 技能 | 3 | `TalentNodeConfig.pageId` |
| 页内分支 | 见 `talent-tree-architecture.md` §2.1 | 3 + 2 + 3 | `TalentNodeConfig.branchId` + `TalentTreeConfig.branches[]` |
| 节点 | 可购买项 | 20 | `TalentNodeConfig` |

**设计意图**：顶栏让玩家一眼看到「有哪几条路」；分支分组让玩家看到「这条路上要走几步」；节点是具体可买项。

## 3. 节点三态

面板已有三态刷新（`TalentTreePanel.Refresh()`）：

| 态 | 判定 | 图标 | 底色 | 文字 | 按钮 |
|---|---|---|---|---|---|
| **锁定** | 自己没解锁 **且** 有前置未解锁 | `nodeLocked` | `lockedColor` (0.32,0.30,0.28) | 灰 (0.62,0.60,0.56) | 不可点 |
| **可买** | 全部前置已解锁 **且** 铜钱够 | `nodeAvailable` | `availableColor` (0.86,0.70,0.36) | 深 (0.12,0.10,0.08) | 可点 |
| **已解锁** | 存档里有该 nodeId | `nodeUnlocked` | `unlockedColor` (0.93,0.90,0.82) | 深 (0.15,0.12,0.10) | 可点（点了看说明） |

**价格文字**（已有三色）

| 情况 | 文字 | 颜色 |
|---|---|---|
| 已解锁 | `已解锁` | 绿 (0.55,0.85,0.55) |
| 买得起 | 数字 | 金 (0.95,0.82,0.42) |
| 买不起 | 数字 | 红 (0.85,0.45,0.42) |

### 3.1 需要补充的一态：**不可购买（无载荷）**

`TryUnlock` 对 `HasValidUnlockPayload == false` 的节点返回 `Invalid`，面板会显示「这个节点还没有配好解锁内容」。

→ **这是数据错误，不该出现在玩家面前**。校验器应在上线前拦下（见 `talent-tree-architecture.md` §10）。
若仍发生，面板建议**直接隐藏该节点**而不是给一个报错文案。

### 3.2 需要补充的一态：**秘籍已获得**

秘籍类节点（`重击解冻` 等）不是用铜钱买的，而是掉落获得。

| 态 | 表现 |
|---|---|
| 未获得 | 节点显示为**锁定**，但**不显示价格**，而是显示「秘籍 · 局内掉落」 |
| 已获得 | 与「已解锁」同态，价格位置显示「已获得」 |

> 建议用**不同图标**（例如带锁/卷轴角标）区分「铜钱买」与「秘籍掉」，让玩家一眼看出这两条获取路径。

## 4. 分支呈现

### 4.1 分支容器

每个分支一个容器，带：

| 元素 | 说明 |
|---|---|
| 分支标题 | `TalentBranchConfig.displayName`（战斗向 / 生存向 / 经济向 / 蓄力流…） |
| 分支图标 | `TalentBranchConfig.icon`（可空 → 用文字标题） |
| 分支说明 | `TalentBranchConfig.description`（可空） |

### 4.2 分支内排位

**建议：枝内按拓扑序自动纵向排位**，而不是手摆坐标。

理由：手摆坐标的痛点已经出现过——加一个节点就要重排全树坐标，且已经发生过 `talent_unlock_c2` 与 `talent_ice_thaw` **坐标完全重叠**。

```
分支容器（内高 = 节点数 × (节点高 + 间距)）
 └─ 节点（按拓扑序从上到下）
     └─ 同层节点横向排开（宽度不够则换行）
```

`treePosition` 降级为「**可选的手动微调**」：默认由算法算，留空/为 0 时用自动值。

> 若另一侧坚持全部手摆，则必须加**坐标重叠校验**（见架构文档 §10）。

## 5. 连线语义

### 5.1 现有实现

`BuildNodes()` 第 204-219 行**按「边」画**：遍历每个节点 → 它的每个前置 → 生成一条 `Link_{from}_{to}` 连线。

| 规则 | 现状 |
|---|---|
| 点亮判定 | **目标节点已解锁**即点亮（`Refresh()` 第 313-319 行） |
| 画法 | 从 `from` 到 `to` 的旋转矩形（`PlaceConnector`） |
| 隐藏节点 | **完全不画连线**（第 213 行 `if (from.hidden || to.hidden) continue;`） |

### 5.2 需要补的规则

| 场景 | 现状 | 建议 |
|---|---|---|
| **前置未解锁** | 目标节点未解锁 → 线是暗色 | ✅ 够用 |
| **前置已解锁、目标未解锁** | 线也是暗色 | 建议**半亮**（表示"路已通"），与"前置未解锁"区分开 |
| **跨页 / 跨分支前置** | 无处理 | 画不了跨页连线 → **用文字徽标**（见 §5.3） |
| **隐藏节点** | 完全不画 | 见 §6 |

### 5.3 跨页前置的文字徽标

节点卡片上追加一行小字：

```
┌─────────────┐
│   ⚔ 震荡    │   ← 节点
│    160      │
│  需要：巧思  │   ← 跨页前置徽标（新）
└─────────────┘
```

- 只在**存在不属于当前页/当前分支的前置**时显示
- 列出前置节点的 `displayName`，用 ` / ` 分隔
- 前置已解锁 → 徽标转绿 / 隐藏；未解锁 → 灰字
- 点前置名 → 可跳转（若做得到）；做不到就纯文字

## 6. 隐藏节点

`hidden` 字段（`d278593` 引入）的用途：招式暂时不开放时，用一个隐藏节点当「天赋门」。

**当前实现的问题**

| 问题 | 后果 |
|---|---|
| 隐藏节点**完全不画连线** | 用隐藏节点当门时，玩家看到的是一个**孤立的、没有连线的节点**，不知道它从哪来、为什么在那 |
| 隐藏节点仍然 `SetActive(false)` 建对象 | ✅ 这部分是对的（保证 `_nodeImages` / `_nodeButtons` 与 `tree.nodes` 下标一一对应） |

**建议**（三选一，按另一侧的实现成本定）

| 方案 | 做法 | 成本 |
|---|---|---|
| **A（推荐）** | 隐藏节点**仍然画连线**，但用暗色/虚线；节点本身不显示 | 改 1 行（去掉 `from.hidden` 判断，保留 `to.hidden`） |
| **B** | 不再用隐藏节点做门——把「天赋门」的效果并到真实节点上（例如直接给 C2 节点加 `moveConfig`，不做门） | 改数据 |
| **C** | 隐藏节点作为「未开放的分支」占位，显示一个锁住的分支标题 | 改 UI 结构 |

> 本周 R2 已经把 C2 从「直接开放」改回「天赋解锁」，所以**门节点的需求本身可能消失**。先与另一侧确认是否还需要隐藏节点。

## 7. 版式与滚动

### 7.1 坐标系

| 项 | 值 |
|---|---|
| 设计分辨率 | 1080 × 1920（竖屏） |
| 节点坐标原点 | **面板中心**（`_nodeRoot` 的 anchor 是 0.5/0.5，`anchoredPosition = (0, -40)`） |
| `treePosition` 单位 | 设计像素，+Y 向上 |
| 节点尺寸 | `nodeSize` 默认 160 × 160 |
| 连线粗细 | `connectorThickness` 默认 10 —— ⚠️ **当前从未被使用**（见 §9.1） |

### 7.2 滚动容器（硬前置）

**`Assets/Scenes/TalentTree.scene` 没有 ScrollRect 组件**（无 `!u!225`）。面板是全屏 `Stretch` 的静态层，节点直接挂在 `_nodeRoot` 上。

当前 8 个节点挤在 x ∈ [-56, 56]、y ∈ [-480, 360]（一条斜线），勉强塞进 1080×1920。

→ **换成 20 个节点的多分支后必然溢出屏幕，节点做出来是看不到的。**

**必须先解决的方案**

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A（推荐）** | `ScrollRect` + `ContentSizeFitter` + `RectMask2D`，`_nodeRoot` 放进 Content | 节点数无上限；分支多时体验一致 | 需要处理 Canvas 层级与手势冲突（战斗输入） |
| **B** | 分页（顶栏页内再分页） | 实现简单 | 页数随分支增长，且玩家难感知"还有几页" |
| **C** | 分支容器 + 各容器独立滚动 | 每枝内部独立 | 多个滚动区域手势打架 |

> 竖屏 + 战斗场景 + 可能同时有战斗输入 → **方案 A 要确认输入不冲突**（`GameplayInputGate` 已有输入门控机制可用）。

## 9. 已知面板缺陷（本周需修或需另一侧修）

### 9.1 🔴 连线根本没画出来

```csharp
// TalentTreePanel.cs:402-412
private static void PlaceConnector(RectTransform rect, Vector2 from, Vector2 to)
{
    rect.sizeDelta = new Vector2(length, 0f);   // ← 高度被设成 0
    ...
}
```

`connectorThickness`（默认 10f）**全文件只出现在第 34 行的声明处，从未被使用**。场景里 `connector` 精灵已配（guid `12ae361e6cdd27244be09cb399e502f9`），但 RectTransform 高度为 0 → 精灵被压成零高 → **运行时看不到任何连线**。

→ 天赋页现在实际呈现的是**一堆孤立圆点**，根本没有「树」的结构。这也解释了为什么 8 个节点能被塞成一条斜线。

**修法**：`rect.sizeDelta = new Vector2(length, connectorThickness);`，或改用 `Image.type = Sliced` + 九宫格精灵。

> 建议实机截图复核一次（本文只做了代码级确认）。

### 9.2 🟠 隐藏节点不画连线 → 孤立节点

见 §6。

### 9.3 🟠 没有二次确认 / 撤销

`OnNodeClicked` 点一下即买、扣钱即生效。局外花 100–400 铜钱（现总 1750，调整后约 2850）不可撤销。

**建议**（可作为后续优化）：首次购买该节点时弹一次确认；已解锁节点点击只展示说明，不重复扣钱（现状已正确：`TryUnlock` 返回 `AlreadyUnlocked` 不扣钱）。

### 9.4 🟡 说明栏位置固定在底部

`_descText` 固定在面板底部（`offsetMin (80, 40)` / `offsetMax (-80, 240)`），点击节点才显示内容。多分支下建议改为**跟随选中节点**或保持底部但加高。
