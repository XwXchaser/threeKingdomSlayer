# 破防蓄值的表现设计（已实现 T1）

> 起因：用户提出「如何让破防蓄值表现出来（格挡值上涨时格挡动作会怎样、快破防时会怎样、长枪会怎样反馈变化）」。
> 用户定调：**「不要（HUD 条）。可以考虑（脱手飞出）。我不想显示具体剩余的值，想用别的表现方式」**
> ⇒ 方案从「连续插值 + 数值」改为「**定性三档 + 枪上的定性表现**」。

## 1. 现状（实测）

> ⚠️ **参数真源是 `Assets/Prefabs/UI/Skills/Zhangfei_Parry.asset`**（`heroConfig.GetSkillConfig(AttackType.Parry)` 拿的是它）。
> `Assets/ScriptableObjects/Moves/Zhangfei/Zhangfei_Jab1.asset` 里也有一份同样的字段，但**那份不生效**（容易看错）。

| 事实 | 值（Zhangfei_Parry） |
|---|---|
| **破防条完全没有表现** | `PlayerGuard.MeterRatio` / `MeterVisible` **零消费者** → 玩家看不到自己在逼近破防 |
| **每次格挡表现完全相同** | 后座 + `Guard_Block` 音 + 敌人卡肉 0.12s + 镜头重击级震动 |
| 破防阈值 | `parryGuardBreakThreshold` = **120** |
| 回落速率 | `parryGuardDecayPerSecond` = **30/秒**（实测：每 0.1 秒掉 3.00 点 ✓） |
| 破防硬直 | `parryGuardBreakDuration` = **1.5s** |
| 格挡后座 | `parryGuardRecoilDistance` = **0.5**，`parryGuardRecoilSeconds` = **0.18** |
| 防御位下沉 | `parryStanceDefendAnchorDrop` = **0.18**（玩家基本看不出“防御位更低”） |
| 斜举位角度 | `parryStanceTipDegrees` = **42**（防御位**同角度**，只靠位置下沉表达差异） |
| 红缨 | `parryStanceTasselDamping` = **26**，`parryStanceTasselMaxBend` = **14** |
| 死字段 | `parryGuardDecayDelay` = **3** —— **代码里没有任何地方消费**（`Tick` 只用 perSecond） |

**武器呈现方式**：`PlayerWeaponStance` 把武器**独立实例化**在场景里，每帧 `ApplyPose` 写 `position` + `rotation`；根节点 = 矛头锚点 − 斜举方向×半枪长，**旋转支点在枪尾**；`_recoilOffset` 是逐帧叠加的 z 轴后退量。

## 2. 设计原则

1. **表达要长在"枪"上**，不是屏幕角落的条 —— 移动端玩家注意力在角色与武器上；HUD 条只作辅助。
2. **单调递增**：所有反馈强度都随破防条上升，不能忽大忽小。
3. **连续量 + 分档附加信号**：位置/角度/抖幅用连续插值（平滑），"进入临界"用一次性告警（好认）。
4. **不影响读招**：防御位是"按住"的持续状态，不涉及来招轨迹 → **压角度/下沉不会干扰读敌人招式**（招架的"角度一致"设计只针对挥入/格挡那一瞬，不受影响）。
5. **让"什么时候松手防御"变成一个决策**：破防条是玩家唯一的"还剩多少"线索 → 反馈要让人**知道自己快撑不住了、该换手段了**（松手输出 / 重攻击打断 / 放技能）。

## 3. 三问三答（具体到参数）

### ① 格挡值上涨时，格挡动作会怎样？——**枪被一点点压退**

| 通道 | 现状 | 提案（随 `MeterRatio` 线性） |
|---|---|---|
| **每次格挡的后退量** | 0.5 固定 | `0.5 → 0.95`（r=0→0.75）→ `1.25`（r→1） |
| **每次格挡的后退时长** | 0.18s | `0.18 → 0.26`（越吃力，顶回来越慢） |
| **防御位整体下沉** | -0.25 固定 | `-0.25 → -0.62`（r=0→1）→ **整杆枪在屏幕上逐渐被压低** |

> 实现要点：防御位是**入场时定死**的目标点（`EnterDefend` → `MoveTo`），要让下沉跟随条子，必须像 `_recoilOffset` 那样**在 `ApplyPose` 里逐帧叠加**，不能烤进 MoveTo 目标。

### ② 快破防时会怎样？——**加"告警层"**

临界段（`r ≥ 0.75`）在①的基础上叠四件事，让玩家明确知道"临界了"：

| 通道 | 提案 |
|---|---|
| **枪身持续微抖** | 幅度 `0 → 0.8°`、频率 ~14Hz，叠加在位置上（`_recoilOffset` 同层叠加） |
| **枪尖额外下垂** | 防御位角度 `42° → 38°`（压低 = "枪被压弯"） |
| **红缨甩得更开** | `SetSettle(damping, maxBend)` 的 maxBend `26° → 40°` → 枪尾红缨狂甩 = "手要滑了"（**现成接口，零成本**） |
| **格挡音变闷** | 同一个 `Guard_Block` clip 降 pitch（~0.85）→ 越吃力越"闷" |

可选（T2）：屏幕边缘泛红 / 玩家描边转红 / 心跳低频音。

### ③ 长枪会怎样反馈变化？——**四个通道 + 破防瞬间脱手**

| 通道 | 作用 |
|---|---|
| **位置** | 被压退：后退量↑ + 防御位下沉（①） |
| **角度** | 枪尖下垂（②） |
| **抖动** | 持续微颤（②） |
| **红缨** | 摆幅上限放大（②，`SetSettle` 一行） |
| **破防瞬间** | 现在是 `BeginExit(0.12f)`（沿原路收枪出画）→ 提案改成**"被打飞/脱手"**：枪脱手、翻转、飞出画面；配合强音效 + 屏幕红闪 + 相机猛震 |

> ⚠️ 脱手需要新增"武器不再被 `ApplyPose` 驱动"的一段自由落体（简单：加一个 `Released` 阶段，位置交给重力积分 + 旋转）。

## 5.1 已实现（T1）· 落点与实测

**实现位置**
- `Assets/Scripts/Player/Combat/PlayerGuard.cs`：新增 **定性档位** `StrainLevel { Steady, Strained, Critical }` + `Strain` 属性 + 阈值（吃力 0.45 / 临界 0.8）。
  **玩家看不到任何数字**（没有 HUD 条）；档位只给表现层用。
- `Assets/Scripts/Player/Combat/PlayerWeaponStance.cs`：
  - `ApplyStrain(ref root, ref pose)` —— **逐帧叠加**（不能烤进 `MoveTo` 目标，否则防御位只在入场时定死）：
    ① 防御位额外下沉 `0.45 × 比例`；② 枪尖下垂 `4° × 比例`（防御态重算 `PoseForAngle`）；
    ③ **持续微抖**（仅临界档）：角度 ±0.8°、位移 ±0.05、14Hz。
  - `UpdateTasselSettle()` —— 红缨摆幅上限倍率 稳 1 / 吃力 1.35 / 临界 1.6（`WeaponTasselDynamics.SetSettle`）。
  - `Recoil(cfg)` —— 格挡后退量与时长倍率 稳 1 / 吃力 1.3 / 临界 1.6。

**实测（Editor Play，N1 战斗，逐档推破防值采样枪的变换）**

| 破防条比例 | 档位 | 位置偏移 | 角度偏移 | 枪世界 Y |
|---|---|---|---|---|
| 0.23 | 稳 | **0.000** | **0.00°** | 1.71 |
| 0.43 | 稳 | **0.000** | **0.00°** | 1.71 |
| 0.62 | 吃力 | 0.485 | 2.50° | **1.25** |
| 0.78 | 吃力 | 0.602 | 3.10° | 1.14 |
| 0.87 | 临界 | 0.665 | 3.50° | **1.09** |

- **稳档表现与改造前完全一致**（偏移 0）→ 不影响现有手感。
- 枪 Y 从 1.71 → 1.09（下降 0.62）→ 玩家一定看得见"枪被压下去"。
- 松手后破防条回落 → 档位回退 → **表现可逆**（枪会弹回原位）。

## 5.2 ★ 2026-11-12：恢复非线性 + 破防脱手（已实现并实测）

### 问题 1：格挡恢复不线性、复位「两段瞬移」

**根因（两处）**：
1. **档位闸门**：`ApplyStrain` 开头 `if (level == Steady) return;` ⇒ 下沉/下垂是「档位内线性、档位边界阶跃」。
   破防值回落时跨过 0.8 / 0.45 两个阈值 ⇒ 位置**跳两下**（旧值推算约 0.16 与 0.20）。
2. **松手瞬间清零**：收枪时 `Phase` 离开 `Defending` ⇒ 应变偏移**一帧内全没** ⇒ 枪「啪」地跳回原位。

**修法**：
- 下沉/下垂改成**线性跟随 `MeterRatio`**（不再按档位硬切）⇒ 回落全程平滑；
  ⚠ 代价：「稳档 = 偏移 0」这条 2026-11-09 的口径**不再成立**（低档也按比例微沉）——为满足「恢复线性」而改。
- 收枪/破防时叠加偏移（后坐/应变/抖动）被**吸收**进起点：起点直接取**视觉位置**，
  并把偏移**归零** ⇒ ① 从被命中后的位置无缝继续 ② 轨迹不再被偏移污染；
  （原先的「收枪时淡出」方案已废弃：吸收同样能消除「松手瞬间跳回原位」，且轨迹更干净）
- 临界抖动加**淡入淡出包络**（`_shakeBlend`）⇒ 进/出临界不「啪」地出现/消失；
- 格挡后退收尾改**平滑插值** ⇒ 最后一帧不归零跳变。

**实测（Battle 场景 Editor Play，脚本驱动；强制快衰减逼它跨两个档位）**：
```
旧（推算）：跨档跳 0.16 + 0.20；松手一帧跳 ~0.13
新（实测）：90 帧强制衰减  maxΔY/帧=0.0123  maxΔrot/帧=0.00°  跳变帧数=0
            松手后前 8 帧 Y：1.154 1.187 1.219 1.250 1.280 1.309 1.337 1.365（连续）
            跨档点：Critical→Strained(ratio 0.796)、Strained→Steady(0.442)
```

### 问题 2：破防要有**专属动作**（不要回退成收枪）

**用户口径（2026-11-12）**：破防时不是「沿原路把枪收走」，而是
「**以破防为止**让长枪沿**世界 Z 轴逆时针旋转** + **轻微 X 左移**离开屏幕」。

**实现**（`PlayerWeaponStance`）：
- 新增 `StancePhase.Broken` 与 `BeginBreak()`：`PlayerGuard.Break` 改调它（不再 `BeginExit`）。
- 破防起点 = **破防那一刻的视觉姿态**（含应变/后坐偏移）⇒「以破防为止」。
- 动作 = **世界空间**绕 `Vector3.forward` 前乘旋转（屏幕 +X 右 / +Y 上 ⇒ 正向 Z 旋转 = 屏幕逆时针）
  + `Vector3.left` 轻微漂移；因支点偏移用 pose 解算 ⇒ **枪尾留在原地、整杆翻转**。
- 参数进资产（`AttackSkillConfig`）：`parryStanceBreakSpinDegrees` 230° /
  `parryStanceBreakDrift` 0.8 / `parryStanceBreakSeconds` 0.55s，并已接进
  `Tools ▸ 三国杀戮 ▸ 招架姿态调参` 窗口。

**实测（Editor Play 脚本触发破防）**：
```
guardState=Broken  stancePhase=Broken
枪身轴角：42° → 73° → 111° → 156° → 204° → 255° → 268°（连续递增 = 屏幕逆时针）
累计旋转 ≈ 226°（配置 230°）；枪尾最大位移/帧 = 0.0246（= 以枪尾为支点，没被甩飞）
枪最终位置 x=-8.9 y=-7.8（已出画）⇒ 出画后销毁
```

## 5.3 ★ 2026-11-12 用户反馈的三个问题（问题 1 **已验收**；问题 2 **追加时缓+镜头**·待验收；问题 3 待修）

> 这三条是同一条表现链（格挡→受击→破防→收枪）上的问题，互相牵连。
> ⚠️ **问题 2 目前只有 Editor Play 的脚本驱动数值实测，尚未经用户在真实战斗里验收。**
> 交接与复跑方法见 `plan/guard-break-handoff-20261112.md`。

### ✅ 问题 1（**已改 2026-11-12 · ✅ 用户已验收**）：被命中后松手，「收枪」表现丢失

- **现象**：防御中挨一下（长枪后退）→ 取消防御 ⇒ 收枪的动作看不出来。
- **根因（三层）**：
  1. `MoveTo` 的起点取的是**原始插值位置**（`CurrentRoot()`），不含后坐/应变；
     而后坐/应变是 `ApplyPose` 里**逐帧叠加**的层 ⇒ 收枪不是「从枪现在在的地方继续」。
  2. **后坐与收枪在时间与方向上打架**：后坐是 **−Z（朝镜头）** 的位移，收枪是 **+Z（进画面深处）** 的位移
     ⇒ 两者几乎抵消 ⇒ 收枪被吃掉。
     实测（修前）：松手后 16 帧只挪了 (Δx −0.01, Δy +0.16, Δz +0.64)，且这些位移**全部来自偏移层**。
  3. **资产里的收枪参数本身偏弱**（`Zhangfei_Parry.asset` 真值，与 C# 默认值差很多）：
     `parryStanceExitRootOffset = (0,0,0.7)`、`parryStanceExitAngleDegrees = 30`（斜举角 42）、
     `parryStanceEntryAngleDegrees = 30` / `EntryRollDegrees = 90`、`parryStanceHeadAnchor = (4.7,5.5,-4.7)`
     ⇒ 收枪 = 原地翻 90° 滚一下，只挪 0.7 的 Z ⇒ 本来就没有明显「挥出画面」。
- **修法**：收枪/破防的起点改为**视觉位置**并把叠加偏移**吸收**（归零）进起点
  （`MoveTo(..., absorbOffsets: true)`）；破防起点同样吸收后坐。
- **验证（修后）**：同一场景（挡一下→立刻松手）收枪轨迹
  `z −5.16 → −4.34 → −3.58 → −2.88 → −2.25 → −1.70 → +1.15`、
    `x 0.71 → −2.47`、`y 1.64 → −1.13` ⇒ **真的挥出画面了**（修前 16 帧只挪 0.64）。
- **✅ 2026-11-12 用户在真实战斗里确认修复**（「问题1已修复」）—— 本条关闭。

### ✅ 问题 2（**已改 2026-11-12 · 待验收**）：瞬间破防应先做「后退」再破防

- **现象**：被「瞬间破防」时，枪直接开始旋转脱手，看不到被打退的那一下。
- **根因**：受击反馈与破防反馈是**并行**而非**串行**——
  `PlayerGuard.TryAbsorbDamage` 同一帧里先 `Recoil()`（0.18s×倍率）再 `Break()`，
  破防动画立刻接管整杆枪的姿态 ⇒ 0.18s 的后退被 0.55s 的旋转盖住。
- **修法**（`PlayerWeaponStance`）：
  - `BeginBreak()` 的起点改为**基准姿态**（含应变、**不含后坐**），且**不归零后坐**
    ⇒ 后坐留给等待期自己播完；
  - 新增 `_brokenWaitForRecoil`：破防后**等 `_recoilTimer` 归零**才起旋转
    （等待期 `_brokenT` 仍为 0 ⇒ 旋转/漂移都还没开始，但「被顶开」的位移可见）；
  - 后坐播完时把后坐归零（此时位置已回到破防起点）再起旋转 ⇒ 无跳变。
- **实测（Editor Play，一次 120 伤同时触发后坐与破防）**：
```
逐帧 (z | 枪身轴角)：[-5.49|38°] [-5.47|38°] [-5.42|38°] [-5.37|38°] [-4.70|56°] [-4.70|60°] …
旋转开始于第 4 帧（= 后坐 0.29s 全部播完之后；前 4 帧角度恒定 38° ⇒ 旋转确实没提前）
```
⇒ 现在的顺序：**被顶开 → 弹回 → 旋转脱手出画**。

### ✅ 问题 2 追加（2026-11-12 用户反馈：「破防不像玩家破防，像玩家主动收枪」）

- **用户原话**：「问题2这个动作有点不像是玩家破防？可能是因为破防那一刻没有时间减缓等效果？
  导致当前破防时像是玩家主动收枪了一样，缺乏打击感？」（用户自己把问题指到了「时间层」——判断正确）
- **根因**：破防帧给玩家的反馈与「一次普通格挡」**完全一样**
  （枪后退 + 攻击者卡肉 0.12s + 镜头 heavy 震 + 同一个 `Guard_Block` 音），
  且防御**不扣血** ⇒ `PlayerHitFeedback` 的 `OnHealthChanged` 不触发 ⇒ **连屏幕边框闪都没有**；
  加上破防动作本身是**干净的单调解**（`BreakSpinCurve` 前慢后快 + 匀速左漂），
  而「主动收枪」恰好也是一条干净的单调弧线 ⇒ 两者读起来一模一样。
- **修法（❌ 已撤回 · 现行做法见下方「第三轮」）**：
  1. ~~**全局时缓**（`CombatTimeDilation`）~~ —— 破防帧把 `Time.timeScale` 压到 0.02 再回正。
     **已删除**：全局慢动作让所有东西一起停 ⇒ 没有对比 ⇒ 读成掉帧（用户：「完全没有时停感」）。
  2. ~~**镜头升级**（`CameraFeedbackController.RequestGuardBreak()`，0.22s/0.075 ⇒ 旋转 6°）~~ ——
     **已撤回**：它的旋转项是「整个世界在抖、背景不动」的最大来源（实测见 `memory/hit-feedback-system.md`）。
  3. ~~**顿帧期间镜头跟着停**（`PlayFeedback` 改 scaled）~~ —— 已回滚。

- ★★ **2026-11-12 用户实测反馈：「没有顿帧感，一点都没有受击卡顿」** ⇒ 触发方向复盘（❌ 已撤回的方案）：
  - **当时判断的根因**：① 0.1× 的慢速里**本来就没有多少东西在动**（攻击者敌人已被自己的 0.12s 卡肉冻住、
    其它敌人静止、枪只退 0.5 单位）；② 镜头震动走 **unscaled** ⇒ 顿帧期间屏幕在**满速抖动**。
  - **实测**（当时）：`frozenFrames=7`、镜头每帧 0.0007、枪身角 0°/帧 ⇒ 整屏静止成立，
    但**用户仍然读不出顿帧感** ⇒ 证明「整屏齐停」本身就是错的读法。
  - ⚠ **改 C# 默认值不够**：Unity 域重载会**保留 ScriptableObject 的内存值** ⇒ 新字段必须
    **写进资产并 SaveAssets**，否则跑起来还是旧值（本轮踩过：代码改成 0.02，运行时仍是 0.1）。

- ★★★ **第三轮（现行）：局部顿 + 受击慢放（不动全局 timeScale）**
  - 依据：`memory/hit-feedback-system.md` §「2026-11-12：方向复盘（局部优先）」——
    顿感来自**对比**（被打的定住、其它还在动）；传统做法是 **hit pause（局部定格）**，
    不是 hit slow（全局慢动作）。
  - **命中定格**：`PlayerWeaponStance.ApplyHitStop()` —— 只把**持枪姿态**定住，世界照常跑。

  - **破防受击慢放**：只把持枪姿态放慢到 **0.35×**，持续 **0.15s** 真实时间。
  - **后坐命中即写入**：原来偏移是在衰减段里算的 ⇒ 定格帧显示的不是「被顶开」的姿态，
    而是定格结束后突然跳出去；现在 `Recoil()` 命中即写入 ⇒ 定格帧摆的就是被击中的那一帧。

### ❌ 问题 3（**待修**）：受击缺卡肉（敌人侧也缺）

- **现象**：玩家受击除了长枪震动没有卡肉停顿；敌人侧也像没有 ⇒ 打击感很弱。
- **根因**：卡肉体系（`HitFeedbackManager`）**只覆盖「玩家打敌人」这一个方向**——
  `HitFeedbackContext.enemy` 指的是「**被打的那个敌人**」⇒ `ApplyHitStop` 挂起的是**敌人的 Animator**。
  | 方向 | 受击者 | 攻击者 | 镜头 |
  |---|---|---|---|
  | 玩家打敌人 | 敌人 Animator 卡肉 + 缩放 + 闪白 ✓ | 玩家攻击视觉同步暂停 ✓ | ✓ |
  | **敌人打玩家（真挨打）** | **只有边框闪 + 镜头 heavy 抖**（`PlayerHitFeedback`），无卡肉/缩放/闪白 | **完全没有** | ✓ |
  | 敌人打玩家（**防御挡下**） | 镜头重击抖 ✓ | **有** `source.ApplyHitStop(0.12f)`（`PlayerGuard` 里手动加的） | ✓ |
- **约束（2026-11-12 实测更正）**：Battle 场景里玩家对象 `Player` 的组件只有
  `Transform + PlayerHitFeedback + ThornArmorEffect + ChargeStabVisual + PierceAimIndicator + PlayerMoveStateMachine`
  —— **连 SpriteRenderer 都没有** ⇒ 「玩家侧缩放挤压 / 闪白 / Animator 停速」在当前结构下**没有载体**；
  玩家侧可用的手牌只有四样：**枪的姿态 / 屏幕（`Assets/Sprites/BatlleHUD/hitted.png` 全屏红边框图）/ 镜头 / 时间**。
  ⇒ 本轮的「全局时缓」基础设施（`CombatTimeDilation`）正好是第 4 张牌：
  「玩家真挨打」时可直接复用（把攻击者停住 + 世界挂一拍），不必照搬敌人的 Animator 停速。
- **设计依据**：`design/combat-hit-feedback-direction.md` 早已写明要做「受击者/攻击者/镜头」三层协同，
  并特别提醒「**不要把『敌人停了』误认为完整打击感**」——现状正好只做了其中一层的一个方向。

`Zhangfei_Parry.asset` 里的 parry 姿态参数与 `AttackSkillConfig` 的 **C# 默认值差很多**（见上表），
且 `parryGuardWeaponPrefab` 是空的（走 `attackWavePrefab` 兜底）。
⇒ 调参必须改**资产**（`Tools ▸ 三国杀戮 ▸ 招架姿态调参` 窗口），看代码默认值会得出错误结论。

## 6. 敌人的破防值怎么配（2026-11-09 计算，不考虑局外成长）

### 6.1 模型

- 破防条：阈值 **120**，**每帧回落 30/秒**（`parryGuardDecayPerSecond`）。
- 敌人一次命中给破防条加 **c = 伤害 D + 破防权重 b**（防御期间伤害不扣血，全额转破防条）。
- 两次命中之间条子衰减 `30 × 攻击间隔 T` → **单只敌人的稳态峰值 = c**（只要 c ≤ 30T）。
- **长期速率**（同屏 k 只、攻击相位错开）：`R = k × (c / T) − 30`（每秒）。
- 真实伤害压力（实测日志）：1011 单击 **22~26**（含督战号令 +30%）、1051 单击 5、玩家 HP 100 → **挨 4 下就死**。

### 6.2 设计目标

| # | 目标 | 判据 |
|---|---|---|
| G1 | **单只普通敌人永远破不了防**，且**峰值不进「吃力」档** | c ≤ 45%×120 = **54** |
| G2 | **2 只围攻**能进「吃力」但**破防要 8~12 秒** → 给玩家"该换手段"的窗口 | R ≈ +10~13 /s |
| G3 | **3 只围攻**约 **4 秒**破防 | R ≈ +30 /s |
| G4 | **109 一次冲锋必破防** | c ≥ 120 |
| G5 | **不动敌人的伤害**（破防权重与伤害解耦）→ 不引入新的数值冲击 | D 不变 |

### 6.3 求解：统一「每次命中的破防贡献 c = 50」

由 G1 定 c ≤ 54；再由 G2/G3 反推：c = 50 时
- 近战（1011/1012，T=2.5s）：单只 20/s → 净 −10/s（**不涨**）；2 只 +10/s（12 秒破）；3 只 +30/s（**4 秒破**）✓
- 远程（1051，T=3.3s）：单只 15/s；4 只 +30/s（4 秒破）→ **远程靠数量，不靠单只** ✓
- 远程（105，T=4.0s）：单只 12.5/s；5 只 +32/s ✓
- 慢速（103/102/1021，T=5.0s）：单只 10/s；7 只 +40/s ✓

⇒ **结论：统一 c = 50 → b = 50 − D**（每次命中的"破防感"一致，差别只在频率 → 远程是消耗战、近战是压迫感）

### 6.6 两个必须一起看的约束

1. **回落率 30/秒 是全局锚** —— 改它，上面所有秒数全要重算（b = 50−D 也不变，但围攻破防时间会变）。
2. **「吃力」阈值 45% / 「临界」80% 是表现层档位**（`PlayerGuard.StrainedThreshold` / `CriticalThreshold`）—— 改它们不影响数值，但会让"单只"也可能进档（当前 c=50 = 42% < 45% → 单只绝不会进「吃力」，这是特意留的余量）。
3. **以后加局外成长**（比如玩家韧性提高 → 阈值从 120 变高）：届时应把 **阈值与敌人贡献同步缩放**（b ∝ 阈值），而不是只拉高阈值 —— 否则后期玩家又会变成"打不破"。

1. ~~要不要 HUD 破防条~~ → **用户 2026-11-09 定：不要**（不显示数值，用枪的表现）。
2. **破防瞬间要不要"脱手飞出"**（T2）？现在的"收枪出画"读起来像主动收枪，不像被打爆。用户说「可以考虑」→ 待定。
3. **临界段的屏幕红闪 / 描边泛红**要不要做（还是只靠枪的表现）？—— 红闪在移动端很容易被忽略。
4. **数值**：上面的插值端点（后退 0.5→1.25、下沉 0.25→0.62、枪尖 42°→38°）是按现有资产值推的，需要真机看手感再定。
5. **格挡音效变闷**（音 pitch）本轮**没做**：`AudioManager.PostEvent(string)` 没有 pitch/音量参数，需要新的音频接口或新 clip。
