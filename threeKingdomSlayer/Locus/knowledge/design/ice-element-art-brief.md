# 冰系机制与美术制作需求（美术依据文档）

> 规则权威版：`design/ice-element-link.md`；实现计划与进度：`plan/ice-element-implementation.md`。
> 跨对话接手先读：`plan/ice-element-handoff-20261018.md`。
> 本文回答三个问题：**玩家能看到什么 → 需要哪些素材 → 每个素材的规格与接入点**。
> 后续冰系（以及复用同一容器的其它元素）的美术素材，一律按本文交付。

## 1. 玩家实际看到的三段体感

| 阶段 | 玩家看到 | 玩家感受到 |
|---|---|---|
| **喷冰** | 玩家前方喷出一道**扇形冰流**，约 0.9s 内左右扫过；被扫到的敌人连续跳小伤害数字（同一目标约每 0.2s 再吃一次） | "我在往一群敌人里灌冰" |
| **冻结** | 敌人**定格不动**：不推进、不出招、不补齐；身上有冰的表现 | "我把它按住了" |
| **破冰** | 重攻击命中冻结敌人：敌人被**向后顶开一段**（被挡住则停在阻挡者前），撞击点两边的敌人**同时跳伤害数字**，命中那一下伤害**翻倍**；随后冰**碎开**（破冰动画 + 受击动作同步播），敌人恢复行动 | "我把冰打碎了，还撞了人" |

关键认知：**冻结概率对玩家不可见**。不做进度条、不做描边强度。玩家只应该感到"喷得越久越容易冻住"，而不是在盯一个百分比。

## 2. 时间轴

### 2.1 施放冰雾

```
0s ──────────────── 0.9s  扫射时长（左右扫过，sweepAngle 35°）
   每 0.2s 对同一目标可再结算一次冰伤害（sweepHitInterval）
   每次命中：叠冻结概率 → 按当前累计概率掷骰 → 掷中即进入冻结
```

### 2.2 冻结

```
进入冻结 ── 4s ── 自然解冻（从暂停处续播原动作）
      ↑
   冻结中再被冻：时长重置为满值，进度保留（不播任何额外表现）
```

### 2.3 破冰（同一帧内按序结算）

```
命中帧：
   ① 向后顶开（最多 3 排，被挡则停在阻挡者前一排）
   ② 碰撞：双方各跳一次碰撞伤害数字（跳字在碰撞瞬间）
   ③ 原始命中伤害 ×2（跳字在命中瞬间）
   ④ 破冰动画 0.4s  +  该敌人的受击（hitted）动画同步播放
   ⑤ 动画播完 → 解除冻结 → 恢复正常状态机
   ⑥ 动画结束 + 1.2s → 回到自己的原槽（走现有击退回位通道）
```

## 3. 状态可视化表

| 状态 | 是否需要可见表现 | 说明 |
|---|---|---|
| 冻结概率累积 | **不需要** | 明确不做进度条/描边 |
| 冻结中 | 需要（A3） | 定格 + 冰的表现 |
| 破冰瞬间 | 需要（A4 + A5） | 冰碎 + 受击同步 |
| 碰撞点 | 需要（A6，可先复用现有命中火花） | 撞击点 → 双方跳字 |
| 破冰回位（1.2s 后） | 不需要新素材 | 复用现有击退回位移动 |

## 5. 规格与工程约定

- **像素规范**：以 `design/pixel-character-and-enemy-animation-spec.md` 为准（16-bit 街机像素、1–3px 深色外轮廓、禁止柔光/厚涂/AI 插画感）。
- **冷色映射**：冰系主色建议 青白（高光）→ 冰蓝（主体）→ 深靛（暗部），**不要**整体纯蓝滤镜。
- **锚点与脚底**：所有贴地元素沿用 `design/visual-yoffset-system.md` 的脚底对齐思路，不要逐帧改 Sprite Editor 锚点。
- **A3 必须做成覆盖层而不是新敌人立绘**：现有敌人是 101/1011/1021/103/105/106/109 + 3 个 BOSS，逐个画冻结立绘成本高且会随敌人重做而失效。覆盖层 + 材质染色可以一套通吃。
- **A4 不做逐敌人 Animator clip**：破冰时长是代码字段（`iceBreakAnimDuration`），美术只交一个通用特效；敌人自身的受击动作由现有 hitted 表现负责，两者**同步播放**。
- **命名与目录**：统一前缀 `Ice_`，特效类放现有攻击/命中特效所在目录（与火焰特效同级），避免新建平行目录。
- **导入设置**：与同目录现有特效保持一致（PPU、Filter Mode、Compression、Alpha Is Transparency）。

## 6. 禁止项

1. 不做冻结概率进度条、不做"快要冻住了"的描边/闪烁提示。
2. 不用整体蓝色滤镜覆盖角色，导致伤害跳字和打击反馈对比度下降。
3. 破冰动画里**不要画位移**——位置由代码结算，动画只做冰碎与形变。
4. 不把冰系做成"冰属性伤害 +X%"，元素必须靠"冻结→破冰"的机制表达。
5. 冻结表现不得依赖敌人当前精灵朝向（左/右）而露出破绽；覆盖层需左右都能用。

## 7. 验收标准（与规则文档"爽感三问"对应）

| 问题 | 检查方式 |
|---|---|
| **确认感** | 破冰那一下的卡肉 + 双倍跳字 + 冰碎，是否明显强于普通重攻击命中？ |
| **连锁感** | 撞到人时，被撞者与推动者的两个数字是否同一瞬间可读？ |
| **掌控感** | 玩家是否会为了"把冰喷在要打的那一列"而调整站位/选招？ |

三问有一个不过 → 先调表现，不进入下一个元素。

1. **A1 冰雾喷流**（可先用现有火焰精灵做冷色染色占位，先让技能能看）
2. **A4 + A5 破冰**（决定"这一下有没有打到"的读感，收益最大）

5. **A7 / A8 图标**

### 敌人贴图尺寸陷阱（2026-10-18 实测）

敌人素材普遍是**大画布 + 角色居中**：1011 的画布是 1108×1108（世界尺寸 5.76×5.76），而角色实际只占 `textureRect` 约 610×714（55%×64%）。

因此覆盖层**不能**用 `SpriteRenderer.bounds` 定尺寸，否则冰块会比角色大近一倍；代码改为用 `textureRect / rect` 的比例同时修正尺寸与中心（含翻转符号），实际输出 3.56×4.16（画布的 0.617×，已含 1.12 倍率）。

美术制作 A3 时也应按“角色可见轮廓”做，而不是按贴图画布。

## 9. 依赖与待定

### 免费素材调研结论（2026-10-18）

已实际检索 OpenGameArt：

- 最匹配的 `ice block`（digit1024）是 **CC-BY-SA 3.0**，具有传染性（衍生作品必须同协议开源），**不适合商用项目**。
- CC0 筛选下的命中多是 tileset / 粒子包 / 插画风格，与高清像素画风不匹配，也没有现成的“冰块 + 碎裂帧”。

因此当前采用**程序化占位**（纯代码生成，无版权风险）：

- 冻结：一张 192px 倒角冰块贴图，点采样，半透明主体 + 冷色内圈 + 斜切高光 + 斜向裂纹；自动后合包围盒、呼吸闪烁。
- 破冰：把同一张冰块贴图按 3×3 切分，九片沿切口向外飞散、旋转、淡出。

美术只需交付 A3（冰块图 / Prefab）与 A4（碎裂序列或特效 Prefab），接上就替掉占位；若确实想用 CC-BY-SA 素材，需先确认项目对衍生素材的开源义务可以接受。

- 敌人尺寸区间表（做 A3 时参考；当前已由包围盒自适应，非阻塞）。

## 10. 素材制作交接单（定稿 2026-10-18）

> 本文是交给美术侧的最终需求。素材由 AI 出图，工程侧只负责播放与切换。

### 10.1 要做的三套素材

| 编号 | 名称 | 触发时机 | 表现要求 | 帧数 / 帧率 | 时长 |
|---|---|---|---|---|---|
| **A3** | 冻结冰块（静态） | 敌人被冻结时一直盖在身上 | 不规则多边形冰壳（不是方块），内部半透明能看清角色，边缘亮白，2–3 条裂纹 | 单张（不做动画） | 常驻（代码做呼吸闪烁） |
| **A4** | 破冰碎裂序列 | 玩家用重攻击打破冰冻 | **向外爆散**：闪白 → 裂成 3–4 大块 → 碎片外飞旋转 → 变小淡出 | **8 帧 @ 12fps**（实际交付 7 帧 00–06） | ≈ 0.58s |
| **A10** | 自然解冻·融化序列 | 冻结时间到时自动解冻 | **从上往下化**：头顶先出水、先化掉 → 水沿冰壳往下流 → 下半截还留在同一条脚底线上 → 最后脚边一滩水和水汽 | **6 帧 @ 10fps** | ≈ 0.6s |

A4 与 A10 必须能一眼区分：一个是“炸开”，一个是“从头顶化下来”。

**A10 方向以用户验收为准，覆盖本节旧描述。** 旧稿写的“向下塔陷 / 底部先裂”不符合播放用法：代码只在角色可见中心播一整段序列，不逐帧裁切、不改位置。玩家要看到的是头顶先化、下半截还包着身体，不是从脚底掏空。

### 10.2 通用规格

- 格式：PNG，透明背景，**同一套素材画布尺寸统一**
- 建议画布：**256 × 256**（冰块居中，四周留透明边安全距）
- 颜色：高光 `#E8F6FF` / 主体 `#7FC4F2` / 暗部 `#3C7FB8`，外轮廓 2–3px 亮白
- 像素风按 `design/pixel-character-and-enemy-animation-spec.md`；导入用 **Point (no filter)**
- 命名：
  - `Ice_FreezeBlock.png`
  - `Ice_Break_00.png` … `Ice_Break_07.png`
  - `Ice_Melt_00.png` … `Ice_Melt_05.png`
- 存放位置：现有攻击/命中特效同级目录，统一前缀 `Ice_`

### 10.3 逐帧内容描述

**A4 破冰（8 帧，向外爆）**

| 帧 | 内容 |
|---|---|
| 0 | 完整冰块 + 全白闪（亮到接近纯白） |
| 1 | 主体裂成 3–4 大块，缝隙发白发光 |
| 2 | 大块开始向外移位 |
| 3–4 | 碎片继续外飞、带轻微旋转，伴随细碎冰屑 |
| 5 | 碎片变小、透明度下降 |
| 6 | 只剩外圈残片 |
| 7 | 冰屑基本淡到看不见（避免硬切消失） |

**A10 自然解冻（6 帧，从上往下化）**

每一帧自己画出“冰还剩哪一段”。剩余冰壳的下沿必须落在同一条水平线上，不能逐帧上移。

| 帧 | 内容 |
|---|---|
| 0 | 完整冰壳，只有头顶开始出水 |
| 1 | 上沿化掉，水沿两侧往下流；下半截仍实，脚底线不变 |
| 2–3 | 上半截消失，只留下半截；顶边湿、不规则；水滴从顶边往下掉 |
| 4 | 冰壳几乎消失，脚边一滩融水和少量残冰，仍在同一条脚底线上 |
| 5 | 冰壳消失，水汽散开，可留一两滴水落进水滩 |

禁止：底部先裂、从脚底掏空、整块下塌。那是已否决的旧描述。

### 10.4 接入方式（美术/策划照做即可，不用改代码）

| 素材 | 做法 | 拖到哪里 |
|---|---|---|
| A3 冰块 | 新建 Prefab：SpriteRenderer + 冰块 Sprite | 共享配置 `FreezePresentation.freezeOverlayPrefab` |
| A4 破冰 | 新建 Prefab：SpriteRenderer + **SpriteSequenceEffect**（frames 拖 7 帧，fps=12，destroyOnFinish ✓） | 共享配置 `FreezePresentation.iceBreakEffectPrefab` |
| A10 解冻 | 新建 Prefab：SpriteRenderer + **SpriteSequenceEffect**（frames 拖 6 帧，fps=10，destroyOnFinish ✓） | 共享配置 `FreezePresentation.freezeMeltEffectPrefab` |

> 配置资产：`Assets/ScriptableObjects/Combat/FreezePresentation.asset`。**所有敌人共用一份**，12 个敌人预制体已全部引用；换美术只改这一处。

要点：

- A3 不用自己做缩放/位移：代码按角色**实际可见区域**（贴图 tight 区域）**等比**缩放（高度 = 可见高度 × 0.825）并居中，绝不拉伸素材长宽比。
- A3 不用自己做呼吸动画，代码会在冻结期间做透明度呼吸。
- 一旦配了 A4 / A10 Prefab，代码会**自动停用程序化占位表现**，不会两套叠着放。
